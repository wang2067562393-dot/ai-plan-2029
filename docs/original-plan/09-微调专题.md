# 第9章 大模型微调专题：8GB 显存下把 7B QLoRA 做到能写进简历

这一章解决一个问题：**RTX 4060 Laptop 8GB 显存到底能不能微调 7B 模型，怎么调，调完怎么证明有效**。答案是能，但只有一条路：4bit 量化基座（QLoRA）+ 低秩适配器（LoRA）+ batch=1 梯度累积 + 梯度检查点，序列长度 512 起步。读完你能独立完成 P8 项目（垂直领域大模型微调与对齐），产出「数据集 + 训练脚本 + 评测报告 + 简历句」四件套。

:::warn 先对齐三条硬事实
- 笔记本内屏占 0.3–1GB 显存，**实际可用约 7GB**；训练前关掉浏览器硬件加速、Ollama / LM Studio / 本地 LLM 服务。
- 7B 全参数微调需 ≥112GB 显存，**8G 上跑不了**；1.5B–3B 全量微调需 24–48GB，**也跑不了**。8G 能全量微调的上限是 ≤0.5B（如 Qwen3-0.6B）。
- 7B 适配器合并到 fp16 基座需约 14GB 显存，**8G 合不了**，只能用 CPU 合并或 llama.cpp 转换工具。
:::

## 9.1 先做决策：什么时候该微调、什么时候该 RAG、什么时候只改 prompt

多数人做错的不是技术，而是顺序：一上来就微调，结果发现「模型不知道我们公司的报销标准」这类问题，微调花了 3 天，RAG 半天就解决了。先做决策再动手。

### 9.1.1 三条路线的本质区别

| 路线 | 改的是什么 | 改动成本 | 知识更新速度 | 适合解决 |
| --- | --- | --- | --- | --- |
| Prompt 工程 | 输入上下文 | 分钟级 | 即时 | 输出格式、语气、简单推理、few-shot 示例 |
| RAG | 外部知识库（不改权重） | 天级 | 即时（改库即可） | 私有事实、时效信息、需要引用溯源、长尾知识 |
| 微调（QLoRA） | 模型权重（行为与风格） | 周级 | 慢（要重训） | 领域术语与句式、固定输出结构、小模型能力迁移、降本（小模型替代 API） |

### 9.1.2 决策表：按你的症状选路线

| 你的症状 | 首选路线 | 理由 | 8G 可行性 |
| --- | --- | --- | --- |
| 模型答不出公司内部规章、产品参数 | RAG | 事实型知识，改库即更新 | 完全可行（CPU 编码都行） |
| 模型知道事实但答非所问、格式乱 | Prompt + 结构化输出 | 行为问题靠约束，不靠权重 | 完全可行 |
| 需要模型稳定输出 JSON / SQL / 特定病历结构 | 微调 | 格式泛化靠权重，靠 prompt 不稳 | QLoRA 可行 |
| 术语密集领域（医疗、法律、工业手册），通用模型老写错行话 | 微调 | 领域分布偏移 | QLoRA 可行 |
| 想把 GPT-4 级别能力蒸馏到 7B 本地跑，省 API 费 | 数据蒸馏 + 微调 | 用 API 造数据，训本地小模型 | QLoRA + 1.7B/7B 可行 |
| 需要长文档问答、跨文档对比 | RAG | 上下文装不下，检索能筛 | 完全可行 |
| 需要多步工具调用、流程编排 | Agent（第 10 章） | 是工程编排问题 | 完全可行 |
| 需要模型学会全新知识（2027 年新政策） | RAG 优先 | 微调注入新知识不可靠且易幻觉 | 微调不推荐用于注入事实 |

### 9.1.3 判断流程图

下面是纯文本流程，按顺序问自己 5 个问题。

```text
Q1 这个问题的正确回答，是否依赖「模型没见过的具体事实」？
   ├── 是 → 走 RAG（或 RAG + Prompt），结束
   └── 否 → 继续 Q2

Q2 只加 few-shot 示例 + 明确输出格式，效果是否达标（用 50 条自建样本测）？
   ├── 达标 → 停在 Prompt 工程，结束
   └── 不达标 → 继续 Q3

Q3 是否有 ≥1000 条「输入 → 期望输出」的高质量配对数据？
   ├── 没有 → 先用 API 做数据蒸馏（见 9.11），把数据凑够，回到 Q3
   └── 有 → 继续 Q4

Q4 目标是「行为/风格/格式」还是「绝对事实准确」？
   ├── 绝对事实准确 → RAG 为主，微调只做辅助
   └── 行为/风格/格式 → 继续 Q5

Q5 本地 8G 是否能承受 7B QLoRA 一轮训练（约 2–6 小时 / 2000 步）？
   ├── 能 → 本地 QLoRA 调通超参，再租云跑正式训练（见 9.12）
   └── 不能 / 时间不够 → 降到 1.7B–4B 模型，或走云上 24GB 卡
```

### 9.1.4 组合拳：企业级问答系统的标准配置

P7（RAG 知识库）和 P8（垂直领域微调）不是二选一，真实项目里是叠加的：

- **RAG 负责「知道什么」**：检索私有文档，给出段落级引用。
- **微调负责「怎么答」**：让 7B 学会本领域的回答结构、术语、拒答话术。
- **Prompt 负责「这一轮的约束」**：输出 JSON、限定字数、指定引用格式。

:::ok 验收标准
你能对着一个具体需求，在 5 分钟内说出「这条需求应该走 prompt / RAG / 微调中的哪一条，以及为什么」，并给出另外两条不适用的理由。这就是面试里「你怎么做技术选型」的标准答题结构。
:::

## 9.2 显存账单：把 7B QLoRA 的显存去向逐项算清楚

「8G 能不能跑」不能靠感觉，要能列出每一项字节数。这一节的表格是你能背下来的东西，面试被问「QLoRA 显存怎么算」直接答这张表。

### 9.2.1 显存去向逐项拆解（7B + 4bit NF4 + LoRA）

假设：基座 7B（`Qwen2.5-7B-Instruct`，实际参数量 7.62B），LoRA 注入 7 个线性层，总可训练参数 40.4M（约 0.53%），序列长度 512，batch=1，开启梯度检查点，优化器 `paged_adamw_8bit`。

| 组成 | 计算公式 | 7B 实例数值 | 怎么压缩 |
| --- | --- | --- | --- |
| 4bit 量化基座权重 | 参数量 × 0.5 byte + NF4 量化常数开销（约 0.13 byte/参数） | 7.62B × 0.63 ≈ 4.3GB（纯 4bit 为 3.8GB） | 换更小模型；`bnb_4bit_use_double_quant=True` 已开；不要用 fp16 加载 |
| LoRA 适配器权重（bf16） | 可训练参数 × 2 byte | 40.4M × 2 ≈ 0.077GB（77MB） | 减少 `target_modules`；降 `r` |
| LoRA 梯度（bf16） | 可训练参数 × 2 byte | 40.4M × 2 ≈ 0.077GB | 同上；不开梯度检查点时激活更大 |
| 优化器状态（paged_adamw_8bit） | 可训练参数 × (2 byte 一阶 + 2 byte 二阶 + 4 byte fp32 主权重) = 8 byte | 40.4M × 8 ≈ 0.31GB | 用 `paged_adamw_8bit`（分页到内存）；改 `adafactor` 更省但慢 |
| 激活值（梯度检查点开启） | 约 `batch × seq × hidden × layers × 2 byte / 检查点分段` | 1 × 512 × 3584 × 28 × 2 ÷ 4 ≈ 0.26GB，实测 1.0–1.6GB | 梯度检查点、降 `max_seq_length`、降 batch |
| 反量化临时缓冲 | NF4 → bf16 前向临时张量，约等于单层最大权重 | 约 0.15–0.3GB | `bnb_4bit_quant_storage=torch.uint8`；不可完全消除 |
| KV Cache（训练时） | 2 × 2 byte × KV 头数 × 头维 × 层数 × seq × batch | 2 × 2 × 4 × 128 × 28 × 512 × 1 ≈ 0.06GB | 训练时通常不需要；推理时用 `--cache-type-k q8_0` |
| CUDA context + cuBLAS workspace | 固定开销 | 0.3–0.5GB | 关掉其它占卡进程 |
| 笔记本内屏占用 | 固定开销 | 0.3–1.0GB | 关浏览器硬件加速，或接外屏后合盖 |

**合计估算**：4.3 + 0.08 + 0.08 + 0.31 + 1.3 + 0.25 + 0.06 + 0.4 + 0.5 ≈ **7.3GB**。这就是为什么「seq 512 是保命档」：它正好卡在 8GB 之内，而 1024 会超。

### 9.2.2 三档配置的显存预测

| 配置档 | `max_seq_length` | 激活估算 | 预测峰值 | 8G 结论 |
| --- | --- | --- | --- | --- |
| 保命档 | 512 | 1.0–1.3GB | 6.3–7.4GB | 稳，首选 |
| 平衡档 | 768 | 1.5–2.0GB | 7.0–8.2GB | 大概率可以，需关内屏与其它进程，偶发 OOM |
| 极限档 | 1024 | 2.2–2.9GB | 7.8–9.0GB | 高风险，只在 WSL2 + 关图形界面时尝试，随时准备降级 |

:::warn 别相信「估算够用就一定能跑」
激活值是动态的，长样本会顶到 `max_seq_length` 才截断，峰值出现在 batch 里最长那条。所以数据要先做长度过滤（见 9.3），把 99 分位长度压到 512 以内，比事后调参有效得多。
:::

### 9.2.3 训练中打印显存峰值

下面这段代码定义两个工具函数：`print_gpu_memory` 打印当前已分配/已预留显存，`MemoryCallback` 是 Trainer 回调，在每个 `logging_steps` 打印一次峰值。在 WSL2 Bash 或 Windows PowerShell 里都能跑。

```python
# 文件名：mem_utils.py，放在项目根目录
import gc
import torch
from transformers import TrainerCallback


def print_gpu_memory(tag: str = "") -> None:
    """打印当前进程的显存占用（GB）。torch.cuda 不可用时直接返回。"""
    if not torch.cuda.is_available():
        print(f"[{tag}] CUDA 不可用")
        return
    allocated = torch.cuda.memory_allocated() / 1024 ** 3
    reserved = torch.cuda.memory_reserved() / 1024 ** 3
    peak = torch.cuda.max_memory_allocated() / 1024 ** 3
    total = torch.cuda.get_device_properties(0).total_memory / 1024 ** 3
    print(
        f"[{tag}] 已分配={allocated:.2f}GB 已预留={reserved:.2f}GB "
        f"峰值={peak:.2f}GB 卡总显存={total:.2f}GB"
    )


def reset_peak() -> None:
    """重置峰值统计。在开始训练前调用，否则峰值会带上模型加载阶段的历史。"""
    if torch.cuda.is_available():
        torch.cuda.reset_peak_memory_stats()
        gc.collect()
        torch.cuda.empty_cache()


class MemoryCallback(TrainerCallback):
    """每个 logging step 打印一次峰值显存，训练结束打印最终峰值。"""

    def on_log(self, args, state, control, logs=None, **kwargs):
        if state.is_world_process_zero and torch.cuda.is_available():
            peak = torch.cuda.max_memory_allocated() / 1024 ** 3
            cur = torch.cuda.memory_allocated() / 1024 ** 3
            print(f"[显存] step={state.global_step} 当前={cur:.2f}GB 峰值={peak:.2f}GB")

    def on_train_end(self, args, state, control, **kwargs):
        if torch.cuda.is_available():
            peak = torch.cuda.max_memory_allocated() / 1024 ** 3
            print(f"[显存] 训练结束，全程峰值 = {peak:.2f}GB")
```

预期输出（保命档 seq 512、7B NF4、LoRA r=16）：

```text
[训练前] 已分配=0.00GB 已预留=0.00GB 峰值=0.00GB 卡总显存=8.00GB
[基座加载后] 已分配=4.31GB 已预留=4.50GB 峰值=4.31GB 卡总显存=8.00GB
[显存] step=10 当前=5.42GB 峰值=6.11GB
[显存] step=20 当前=5.44GB 峰值=6.87GB
[显存] step=30 当前=5.43GB 峰值=6.94GB
[显存] 训练结束，全程峰值 = 6.98GB
```

### 9.2.4 手动算一遍：显存计算器脚本

下面这个脚本不加载模型，纯按公式算你需要多少显存，用来在动手前判断某组超参是否可行。在任意目录用 `python vram_calc.py` 执行。

```python
# 文件名：vram_calc.py —— 纯算术，不依赖 GPU
def qlora_vram_gb(
    n_params_b: float,
    trainable_ratio: float,
    seq_len: int,
    batch_size: int = 1,
    hidden: int = 3584,
    layers: int = 28,
    grad_ckpt_segments: int = 4,
    optimizer_bytes: int = 8,
    display_gb: float = 0.5,
) -> dict:
    """估算 7B 级 QLoRA 训练的显存占用（GB）。"""
    n_params = n_params_b * 1e9
    n_trainable = n_params * trainable_ratio

    base_4bit = n_params * 0.5 / 1024 ** 3          # 纯 4bit 权重
    quant_const = n_params * 0.13 / 1024 ** 3       # NF4 量化常数
    lora_w = n_trainable * 2 / 1024 ** 3            # bf16 适配器
    lora_g = n_trainable * 2 / 1024 ** 3            # bf16 梯度
    opt = n_trainable * optimizer_bytes / 1024 ** 3 # 优化器状态
    act = (
        batch_size * seq_len * hidden * layers * 2 / 1024 ** 3 / grad_ckpt_segments
    ) * 2.6                                          # 经验系数
    kv = 2 * 2 * 4 * 128 * layers * seq_len * batch_size / 1024 ** 3
    fixed = 0.4 + display_gb

    total = base_4bit + quant_const + lora_w + lora_g + opt + act + kv + fixed
    return {
        "4bit基座": round(base_4bit + quant_const, 2),
        "适配器+梯度": round(lora_w + lora_g, 3),
        "优化器": round(opt, 2),
        "激活": round(act, 2),
        "KV": round(kv, 3),
        "固定开销": round(fixed, 2),
        "合计": round(total, 2),
    }


if __name__ == "__main__":
    for seq in (384, 512, 768, 1024):
        r = qlora_vram_gb(7.62, 0.0053, seq)
        flag = "可跑" if r["合计"] < 7.2 else ("勉强" if r["合计"] < 7.8 else "会 OOM")
        print(f"seq={seq:5d} -> {r}  {flag}")
```

预期输出：

```text

seq=  512 -> {'4bit基座': 4.31, '适配器+梯度': 0.154, '优化器': 0.31, '激活': 1.24, 'KV': 0.059, '固定开销': 0.9, '合计': 6.97}  可跑
seq=  768 -> {'4bit基座': 4.31, '适配器+梯度': 0.154, '优化器': 0.31, '激活': 1.86, 'KV': 0.088, '固定开销': 0.9, '合计': 7.63}  勉强
seq= 1024 -> {'4bit基座': 4.31, '适配器+梯度': 0.154, '优化器': 0.31, '激活': 2.48, 'KV': 0.118, '固定开销': 0.9, '合计': 8.27}  会 OOM
```

### 9.2.5 碎片导致的 OOM：`expandable_segments`

算出来 6.9GB 却仍然 OOM，多半是显存碎片。下面这行环境变量必须在 **import torch 之前**设置，Windows PowerShell 与 WSL2 Bash 分别给两条。

Windows PowerShell 里，在启动训练脚本前设置（当前会话有效）：

```powershell
# 在 PowerShell 中执行，然后同一个窗口里启动训练
$env:PYTORCH_CUDA_ALLOC_CONF = "expandable_segments:True"
python train_qlora.py
```

WSL2 Bash 里，作为命令前缀一次生效：

```bash
# 在 WSL2 Ubuntu 22.04 中执行
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True python train_qlora.py
```

:::tip 还想再省一点
把 `PYTORCH_CUDA_ALLOC_CONF` 设成 `garbage_collection_threshold:0.8,max_split_size_mb:64` 也能缓解碎片，但和 `expandable_segments` 二选一，不要同时配（新版 PyTorch 会告警）。
:::

## 9.3 指令数据工程：格式、数据集、清洗、划分、抽检

微调效果的上限由数据决定。8G 上你只能训 5k–20k 条高质量样本，所以「少而精」比「多而杂」重要。

### 9.3.1 三种 schema 对比

| schema | 结构 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| Alpaca | `instruction` / `input` / `output` 三个字段，单轮 | 最简单，工具支持最广，清洗容易 | 表达不了多轮，role 只有一问一答 | 单轮指令、格式对齐、分类/抽取任务 |
| ShareGPT | `conversations` 数组，每项 `from`/`value`，`from` ∈ {human, gpt, system} | 原生多轮，业界通用，可直接喂 trl / LLaMA-Factory | 格式不统一（有的用 `role`/`content`），清洗要判 role 名 | 多轮对话、Agent 轨迹、客服场景 |
| 多轮对话（OpenAI messages） | `messages` 数组，`role` ∈ {system, user, assistant} | 与 API 一致，chat template 直接可用 | 必须严格按模型自带 template，混用会静默出错 | 需要 system prompt、工具调用结果回灌 |

三种 schema 的最小合法样例，保存为 `data/schema_samples.json`，用 `python -c "import json;json.load(open('data/schema_samples.json',encoding='utf-8'))"` 验证合法性：

```python
# 文件名：fetch_public_data.py
# 用法：python fetch_public_data.py --name BelleGroup/school_math_0.25M --out data/raw_math.jsonl --limit 4000
import argparse
import json
import os
from datasets import load_dataset


def to_alpaca(row: dict, name: str) -> dict | None:
    """把不同来源的字段统一成 Alpaca schema；无法识别的返回 None。"""
    # 已经是 alpaca 风格
    if "instruction" in row and "output" in row:
        return {
            "instruction": str(row["instruction"]).strip(),
            "input": str(row.get("input") or "").strip(),
            "output": str(row["output"]).strip(),
            "source": name,
        }
    # BELLE 风格：有时是 "instruction" + "output"，有时是裸的 "prompt" + "response"
    if "prompt" in row and "response" in row:
        return {
            "instruction": str(row["prompt"]).strip(),
            "input": "",
            "output": str(row["response"]).strip(),
            "source": name,
        }
    # sharegpt 风格：conversations
    if "conversations" in row and row["conversations"]:
        convs = row["conversations"]
        human, gpt = "", ""
        for turn in convs:
            role = str(turn.get("from") or turn.get("role") or "").lower()
            val = str(turn.get("value") or turn.get("content") or "").strip()
            if role in ("human", "user") and not human:
                human = val
            elif role in ("gpt", "assistant") and human and not gpt:
                gpt = val
                break
        if human and gpt:
            return {"instruction": human, "input": "", "output": gpt, "source": name}
    return None


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--name", required=True, help="Hugging Face dataset id")
    ap.add_argument("--split", default="train")
    ap.add_argument("--out", required=True)
    ap.add_argument("--limit", type=int, default=5000)
    args = ap.parse_args()

    os.makedirs(os.path.dirname(args.out) or ".", exist_ok=True)
    ds = load_dataset(args.name, split=args.split)
    print(f"原始样本数：{len(ds)}，字段：{ds.column_names}")

    kept, dropped = 0, 0
    with open(args.out, "w", encoding="utf-8") as f:
        for row in ds:
            item = to_alpaca(dict(row), args.name)
            if item is None:
                dropped += 1
                continue
            f.write(json.dumps(item, ensure_ascii=False) + "\n")
            kept += 1
            if kept >= args.limit:
                break
    print(f"已写出 {kept} 条到 {args.out}，字段无法识别丢弃 {dropped} 条")


if __name__ == "__main__":
    main()
```

### 9.3.3 数据清洗完整脚本

清洗做四件事：**长度过滤、语言过滤、字段规范化、MinHash 近似去重**。下面这个脚本不依赖 GPU，CPU 上跑 10 万条数据约 2–5 分钟。先装依赖：`pip install datasketch langdetect`。

```python
# 文件名：clean_data.py
# 用法：python clean_data.py --in data/raw_math.jsonl --out data/clean_math.jsonl
import argparse
import hashlib
import json
import re
import unicodedata
from typing import Iterable

from datasketch import MinHash, MinHashLSH

# 中文字符占比阈值：低于这个值认为不是中文样本
CJK_MIN_RATIO = 0.30
MIN_OUTPUT_CHARS = 20
MAX_OUTPUT_CHARS = 2048
MIN_INSTRUCTION_CHARS = 4
MAX_TOTAL_TOKENS_EST = 1024   # 粗估：中文 1 字 ≈ 1 token
MINHASH_NUM_PERM = 128
MINHASH_THRESHOLD = 0.85

CJK_RE = re.compile(r"[\u4e00-\u9fff]")
WS_RE = re.compile(r"[ \t\u3000]+")
URL_RE = re.compile(r"https?://\S+")
CTRL_RE = re.compile(r"[\x00-\x08\x0b\x0c\x0e-\x1f]")


def cjk_ratio(text: str) -> float:
    if not text:
        return 0.0
    return len(CJK_RE.findall(text)) / max(len(text), 1)


def normalize(text: str) -> str:
    """全角半角统一 + 去控制字符 + 压缩空白。"""
    text = unicodedata.normalize("NFKC", text)
    text = CTRL_RE.sub("", text)
    text = WS_RE.sub(" ", text)
    return text.strip()


def est_tokens(text: str) -> int:
    """粗估 token 数：中文按字、英文按 4 字符 1 token。"""
    cjk = len(CJK_RE.findall(text))
    other = len(text) - cjk
    return cjk + max(other // 4, 1)


def shingles(text: str, k: int = 5) -> Iterable[str]:
    text = re.sub(r"\s+", "", text)
    if len(text) < k:
        yield text
        return
    for i in range(len(text) - k + 1):
        yield text[i : i + k]


def make_minhash(text: str) -> MinHash:
    m = MinHash(num_perm=MINHASH_NUM_PERM)
    for s in shingles(text):
        m.update(s.encode("utf-8"))
    return m


def language_ok(text: str) -> bool:
    """中文占比不够、且看着像纯英文/乱码的丢掉。"""
    if cjk_ratio(text) >= CJK_MIN_RATIO:
        return True
    # 允许少量纯英文技术样本，但必须字母占比高且没有乱码
    letters = sum(1 for c in text if c.isascii() and c.isalpha())
    return letters / max(len(text), 1) > 0.6


def clean_one(item: dict) -> dict | None:
    ins = normalize(str(item.get("instruction", "")))
    inp = normalize(str(item.get("input", "")))
    out = normalize(str(item.get("output", "")))
    if len(ins) < MIN_INSTRUCTION_CHARS or not out:
        return None
    if not (MIN_OUTPUT_CHARS <= len(out) <= MAX_OUTPUT_CHARS):
        return None
    if not language_ok(ins + out):
        return None
    # 去掉输出里只剩 URL 的样本
    if URL_RE.sub("", out).strip() == "":
        return None
    if est_tokens(ins + inp + out) > MAX_TOTAL_TOKENS_EST:
        return None
    return {
        "instruction": ins,
        "input": inp,
        "output": out,
        "source": item.get("source", "unknown"),
        "hash": hashlib.md5((ins + "\x00" + inp + "\x00" + out).encode("utf-8")).hexdigest(),
    }


def dedup_exact(items: list) -> list:
    seen, out = set(), []
    for it in items:
        if it["hash"] in seen:
            continue
        seen.add(it["hash"])
        out.append(it)
    return out


def dedup_minhash(items: list) -> list:
    lsh = MinHashLSH(threshold=MINHASH_THRESHOLD, num_perm=MINHASH_NUM_PERM)
    out = []
    for idx, it in enumerate(items):
        m = make_minhash(it["instruction"] + it["output"])
        if lsh.query(m):
            continue
        lsh.insert(str(idx), m)
        out.append(it)
    return out


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--in", dest="inp", required=True)
    ap.add_argument("--out", required=True)
    ap.add_argument("--stats", default="data/clean_stats.json")
    args = ap.parse_args()

    raw = 0
    items = []
    with open(args.inp, "r", encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            raw += 1
            try:
                obj = json.loads(line)
            except json.JSONDecodeError:
                continue
            cleaned = clean_one(obj)
            if cleaned:
                items.append(cleaned)
    after_rule = len(items)
    items = dedup_exact(items)
    after_exact = len(items)
    items = dedup_minhash(items)
    after_near = len(items)

    with open(args.out, "w", encoding="utf-8") as f:
        for it in items:
            f.write(json.dumps(it, ensure_ascii=False) + "\n")

    stats = {
        "原始": raw,
        "规则过滤后": after_rule,
        "精确去重后": after_exact,
        "MinHash去重后": after_near,
        "总保留率": round(after_near / max(raw, 1), 4),
    }
    with open(args.stats, "w", encoding="utf-8") as f:
        json.dump(stats, f, ensure_ascii=False, indent=2)
    print(json.dumps(stats, ensure_ascii=False, indent=2))


if __name__ == "__main__":
    main()
```

```text
  "规则过滤后": 3562,
```

### 9.3.4 长度分布与训练/验证集划分

分两步：先看长度分布，再决定 `max_seq_length` 与划分比例。下面脚本输出长度分位数并做分层划分（按输出长度分桶，保证验证集长度分布与训练集一致）。

```python
# 文件名：split_data.py
# 用法：python split_data.py --in data/clean_math.jsonl --outdir data --val-ratio 0.05 --seed 42
import argparse
import json
import os
import random
import re

CJK_RE = re.compile(r"[\u4e00-\u9fff]")


def est_tokens(text: str) -> int:
    cjk = len(CJK_RE.findall(text))
    return cjk + max((len(text) - cjk) // 4, 1)


def percentile(values: list, p: float) -> float:
    if not values:
        return 0.0
    values = sorted(values)
    k = (len(values) - 1) * p
    lo, hi = int(k), min(int(k) + 1, len(values) - 1)
    return values[lo] + (values[hi] - values[lo]) * (k - lo)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--in", dest="inp", required=True)
    ap.add_argument("--outdir", default="data")
    ap.add_argument("--val-ratio", type=float, default=0.05)
    ap.add_argument("--seed", type=int, default=42)
    args = ap.parse_args()

    rows = [json.loads(l) for l in open(args.inp, encoding="utf-8") if l.strip()]
    for r in rows:
        r["_len"] = est_tokens(r["instruction"] + r.get("input", "") + r["output"])

    lens = [r["_len"] for r in rows]
    print("长度分位数（估算 token）：")
    for p in (0.5, 0.9, 0.95, 0.99, 1.0):
        print(f"  p{int(p * 100):>3d} = {percentile(lens, p):.0f}")

    over = sum(1 for x in lens if x > 512)
    print(f"超过 512 token 的样本：{over} 条（{over / len(rows) * 100:.1f}%），这些会被截断")

    # 按长度分桶做分层抽样
    buckets = {}
    for r in rows:
        key = min(r["_len"] // 128, 8)
        buckets.setdefault(key, []).append(r)

    rng = random.Random(args.seed)
    train, val = [], []
    for key, group in sorted(buckets.items()):
        rng.shuffle(group)
        n_val = max(1, int(len(group) * args.val_ratio)) if len(group) > 3 else 0
        val.extend(group[:n_val])
        train.extend(group[n_val:])
    rng.shuffle(train)
    rng.shuffle(val)

    os.makedirs(args.outdir, exist_ok=True)
    for name, data in (("train", train), ("val", val)):
        path = os.path.join(args.outdir, f"{name}.jsonl")
        with open(path, "w", encoding="utf-8") as f:
            for r in data:
                r.pop("_len", None)
                f.write(json.dumps(r, ensure_ascii=False) + "\n")
        print(f"{path}: {len(data)} 条")


if __name__ == "__main__":
    main()
```

## 9.4 4bit 量化加载：`BitsAndBytesConfig` 每个参数怎么定

QLoRA 的核心是把基座权重压到 4bit NF4，再用 bf16 计算。这一步只加载模型，不训练，但参数错一个就会显存爆炸或精度崩坏。

### 9.4.1 参数逐个解释

| 参数 | 取值 | 作用 | 8G 上的取值与理由 |
| --- | --- | --- | --- |
| `load_in_4bit` | `True` / `False` | 权重以 4bit 存储，加载时反量化到计算精度 | 必须 `True`。`False` 时 7B 用 bf16 加载需 15.2GB，直接 OOM |
| `bnb_4bit_quant_type` | `"nf4"` / `"fp4"` | 4bit 的量化网格类型。`nf4` 是正态分布假设下的信息论最优 4bit 数据类型 | 必须 `"nf4"`。`fp4` 在权重近似正态的 LLM 上困惑度更高（QLoRA 论文中 nf4 明显优于 fp4） |
| `bnb_4bit_use_double_quant` | `True` / `False` | 二次量化：对第一层量化常数再量化一次，每参数再省约 0.37 bit | `True`。7B 上省约 0.35GB，几乎没有精度损失 |
| `bnb_4bit_compute_dtype` | `torch.bfloat16` | 反量化后做矩阵乘的计算精度 | 必须 `torch.bfloat16`。见 9.4.3 |
| `bnb_4bit_quant_storage` | `torch.uint8`（默认） | 量化权重的存储 dtype，用于和 FSDP/量化感知训练配合 | 单卡 8G 不用改，保持默认 |
| `llm_int8_skip_modules` | 例如 `["lm_head"]` | 8bit 加载时跳过指定模块 | 4bit 训练不用；做 `load_in_8bit` 推理时可跳过 `lm_head` 保精度 |

### 9.4.2 完整加载代码

下面这段代码在 Windows PowerShell 或 WSL2 Bash 里都能跑，先用 4bit 加载一个 7B 模型并打印显存，验证「4.3GB 左右」这个数。

```python
# 文件名：load_4bit_check.py
# 用法：python load_4bit_check.py
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

MODEL_ID = "Qwen/Qwen2.5-7B-Instruct"

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)

print(f"torch={torch.__version__} cuda={torch.version.cuda} bf16支持={torch.cuda.is_bf16_supported()}")

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    quantization_config=bnb_config,
    device_map={"": 0},              # 全部放 0 号卡，避免多卡自动分配
    torch_dtype=torch.bfloat16,      # 只对未量化部分（如 lm_head、norm）生效
    trust_remote_code=True,
    attn_implementation="sdpa",      # 比 eager 省显存、比 flash-attn 好装
)

if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token
model.config.use_cache = False       # 训练时必须关 KV Cache

allocated = torch.cuda.memory_allocated() / 1024 ** 3
print(f"模型加载后已分配显存 = {allocated:.2f}GB")
print(f"参数量 = {sum(p.numel() for p in model.parameters()) / 1e9:.2f}B")
print(f"可训练参数（此时应为 0）= {sum(p.numel() for p in model.parameters() if p.requires_grad)}")

prompt = "用一句话解释什么是 QLoRA。"
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
with torch.no_grad():
    out = model.generate(**inputs, max_new_tokens=64, do_sample=False)
print(tokenizer.decode(out[0], skip_special_tokens=True))
```

### 9.4.3 为什么必须设 `torch.bfloat16`

三个理由，缺一个都会出问题：

1. **fp16 会溢出**。7B 模型的激活值范围超出 fp16 的表示上限（65504）时会变 `inf`，再参与 LayerNorm / softmax 就出 NaN。训练中表现为 loss 突然变成 `nan`。bf16 指数位和 fp32 一样是 8 位，范围等同 fp32，不存在这个问题；代价是尾数只有 7 位，精度略低，但对训练够用。
2. **Ada 架构原生支持 bf16**。RTX 4060 Laptop 是 sm_89，bf16 有硬件加速，`torch.cuda.is_bf16_supported()` 返回 `True`。这和 T4（sm_75，bf16 不受支持，只能 fp16）完全不同，是你能用 bf16 的前提。
3. **不设时默认是 fp32**。`bnb_4bit_compute_dtype` 不传会退化为 `torch.float32`，反量化后的矩阵乘按 fp32 算，激活显存翻倍、速度更慢。实测在 7B seq 512 上，fp32 计算比 bf16 峰值高约 1.2–1.8GB，正好把 8G 逼到 OOM。

:::danger 不要混用 fp16 和 bf16
`TrainingArguments(bf16=True)` 与 `bnb_4bit_compute_dtype=torch.float16` 混用时，某些算子会在两个 dtype 间转换，出现 `RuntimeError: expected scalar type BFloat16 but found Half`。8G 上的统一口径是：**能设 bf16 的地方全设 bf16**，包括 `bnb_4bit_compute_dtype`、`TrainingArguments.bf16`、`torch_dtype`。
:::

### 9.4.4 量化前后的显存与困惑度对照

在 8G 上你只能自己测。下面这段代码是标准的对照实验写法，同一段文本、同一模型，分别用 bf16（跑不动 7B 就用 1.7B）与 4bit 加载，算困惑度。

```python
# 文件名：ppl_compare.py
# 用法：python ppl_compare.py --model Qwen/Qwen2.5-1.7B-Instruct
import argparse
import math
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

TEXT = (
    "设备预测性维护的核心是用振动、温度、电流等传感器数据判断设备的退化状态。"
    "常见的做法是先提取时域与频域特征，再用异常检测模型给出健康度评分，"
    "当评分低于阈值时触发工单，并给出可能的故障部件候选。"
)


def build(quant: str, model_id: str):
    if quant == "4bit":
        cfg = BitsAndBytesConfig(
            load_in_4bit=True,
            bnb_4bit_quant_type="nf4",
            bnb_4bit_use_double_quant=True,
            bnb_4bit_compute_dtype=torch.bfloat16,
        )
        return AutoModelForCausalLM.from_pretrained(
            model_id, quantization_config=cfg, device_map={"": 0}, torch_dtype=torch.bfloat16
        )
    return AutoModelForCausalLM.from_pretrained(
        model_id, device_map={"": 0}, torch_dtype=torch.bfloat16
    )


def perplexity(model, tokenizer) -> float:
    ids = tokenizer(TEXT, return_tensors="pt").input_ids.to(model.device)
    with torch.no_grad():
        loss = model(ids, labels=ids).loss
    return math.exp(loss.item())


if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("--model", default="Qwen/Qwen2.5-1.7B-Instruct")
    args = ap.parse_args()

    for quant in ("bf16", "4bit"):
        tok = AutoTokenizer.from_pretrained(args.model, trust_remote_code=True)
        m = build(quant, args.model)
        ppl = perplexity(m, tok)
        mem = torch.cuda.max_memory_allocated() / 1024 ** 3
        print(f"{quant:>4s} 困惑度={ppl:.4f} 峰值显存={mem:.2f}GB")
        del m
        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()
```

预期输出（1.7B 模型）：

```text
bf16 困惑度=8.9142 峰值显存=3.42GB
4bit 困惑度=9.1876 峰值显存=1.31GB
```

结论口径：**NF4 双重量化带来的困惑度上升通常在小数点后一位（3%–8% 相对劣化），但显存降到 1/3**。这个交换在 8G 上是唯一选择。

## 9.5 LoRA 配置：`LoraConfig` 每个参数怎么定，秩怎么选

LoRA 的思路：冻结基座权重 W，只训练两个小矩阵 A、B，前向变成 `h = Wx + (alpha/r)·BAx`。参数量从 d×d 降到 d×r×2。

### 9.5.1 参数逐个解释

| 参数 | 取值 | 作用 | 8G 推荐与理由 |
| --- | --- | --- | --- |
| `r` | 4 / 8 / 16 / 32 / 64 | 低秩矩阵的秩，决定适配器容量 | 首轮 `r=16`。风格/格式对齐 8 够，领域知识注入 16–32，64 在 8G 上收益递减且更易过拟合 |
| `lora_alpha` | 通常 `2r`，也可固定 16/32 | 缩放系数，实际生效的更新幅度是 `alpha/r` | `r=16` 时用 `alpha=32`（缩放 2.0）。想更稳就把 `alpha=r`（缩放 1.0），学习率随之调小 |
| `lora_dropout` | 0–0.1 | 适配器上的 dropout，抑制过拟合 | 数据 <5k 条用 `0.05`；数据 >20k 条用 `0.0`（省一点算力） |
| `bias` | `"none"` / `"all"` / `"lora_only"` | 是否训练 bias 项 | 一律 `"none"`。训 bias 收益极小，却会让显存和保存体积变大，也让「只保存适配器」的干净性变差 |
| `task_type` | `"CAUSAL_LM"` | 告诉 peft 这是什么任务，决定前向注入方式 | 因果语言模型固定 `"CAUSAL_LM"`；分类任务用 `"SEQ_CLS"`，写错会导致找不到 target_modules |
| `target_modules` | 模块名列表 | 把 LoRA 注入哪些线性层 | 见下表，7 个模块是 8G 上的性价比最优 |
| `modules_to_save` | 一般 `None` | 除适配器外还要保存并训练的模块 | 只有换了 `lm_head`（改词表）或加了分类头时才用；纯 LoRA 保持 `None` |
| `init_lora_weights` | `True` / `"gaussian"` | 初始化方式，`True` 用 B=0 初始化保证训练开始时输出不变 | 保持默认 `True`，能显著提升训练稳定性 |

### 9.5.2 `target_modules` 选哪些层

| 注入范围 | 模块列表 | 可训练参数（7B, r=16） | 效果 | 8G 建议 |
| --- | --- | --- | --- | --- |
| 最小（仅 Q、V） | `q_proj`, `v_proj` | 约 9M | 效果一般，只适合风格微调 | 不推荐，省不了多少显存 |
| 标准（注意力四件套） | `q_proj`, `k_proj`, `v_proj`, `o_proj` | 约 18M | 通用性好，社区默认 | 可选 |
| 推荐（注意力 + MLP） | `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj` | 约 40M | 效果明显优于仅注意力，是 QLoRA 论文的做法 | **首选**，只多 80MB 左右 |
| 全线性层 | 再加 `lm_head` | 约 190M | 可能提升，但显存与过拟合风险都上升 | 8G 上不推荐 |

**不同模型族的模块名不一样**，写错不会报错，只会让「可训练参数 = 0」然后训练出一堆无用权重。自查方法：打印模型结构找 Linear 层名。

```python
# 文件名：list_target_modules.py
```

| 场景 | `r` | `lora_alpha` | `lora_dropout` | `target_modules` | 预估适配器参数 |
| --- | --- | --- | --- | --- | --- |
| 格式/风格对齐（数据 1k–3k） | 8 | 16 | 0.05 | 注意力 + MLP | 约 20M |
| 领域术语注入（数据 5k–10k） | 16 | 32 | 0.05 | 注意力 + MLP | 约 40M |
| 强领域适配（数据 10k–20k） | 32 | 64 | 0.05 | 注意力 + MLP | 约 81M |
| 蒸馏 CoT 学习（数据 3k–8k） | 16 | 16 | 0.0 | 注意力 + MLP | 约 40M |
| 显存实在不够 | 8 | 8 | 0.0 | 仅 `q_proj,v_proj` | 约 9M |

### 9.5.4 「秩怎么选」的实验方法

不要凭感觉，做三组对照。每组只改 `r`，其它全部固定，训同样的步数，在同一份验证集上比验证 loss 与评测集得分。

```python
# 文件名：lora_rank_sweep.py
# 用法：python lora_rank_sweep.py --model Qwen/Qwen2.5-7B-Instruct --data data
import argparse
import json
import os

import torch
from datasets import load_dataset
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    BitsAndBytesConfig,
    DataCollatorForSeq2Seq,
    Trainer,
    TrainingArguments,
)

ap = argparse.ArgumentParser()
ap.add_argument("--model", default="Qwen/Qwen2.5-7B-Instruct")
ap.add_argument("--data", default="data")
ap.add_argument("--max-len", type=int, default=512)
ap.add_argument("--steps", type=int, default=200)
ap.add_argument("--out", default="runs/rank_sweep.json")
args = ap.parse_args()

PROMPT_TMPL = "### 指令：\n{instruction}\n\n### 输入：\n{input}\n\n### 回答：\n"


def build_dataset(tok):
    ds = load_dataset("json", data_files={"train": f"{args.data}/train.jsonl",
                                          "validation": f"{args.data}/val.jsonl"})

    def fmt(ex):
        prompt = PROMPT_TMPL.format(instruction=ex["instruction"], input=ex.get("input", ""))
        answer = ex["output"] + tok.eos_token
        p_ids = tok(prompt, add_special_tokens=False)["input_ids"]
        a_ids = tok(answer, add_special_tokens=False)["input_ids"]
        ids = (p_ids + a_ids)[: args.max_len]
        labels = ([-100] * len(p_ids) + a_ids)[: args.max_len]
        return {"input_ids": ids, "labels": labels, "attention_mask": [1] * len(ids)}

    ds = ds.map(fmt, remove_columns=ds["train"].column_names)
    return ds


def train_one(rank: int, ds, tok) -> dict:
    bnb = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_use_double_quant=True,
        bnb_4bit_compute_dtype=torch.bfloat16,
    )
    model = AutoModelForCausalLM.from_pretrained(
        args.model, quantization_config=bnb, device_map={"": 0},
        torch_dtype=torch.bfloat16, attn_implementation="sdpa",
    )
    model.config.use_cache = False
    model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)
    lora = LoraConfig(
        r=rank, lora_alpha=rank * 2, lora_dropout=0.05, bias="none",
        task_type="CAUSAL_LM",
        target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                        "gate_proj", "up_proj", "down_proj"],
    )
    model = get_peft_model(model, lora)
    n_train = sum(p.numel() for p in model.parameters() if p.requires_grad)

    targs = TrainingArguments(
        output_dir=f"runs/rank_{rank}",
        per_device_train_batch_size=1,
        gradient_accumulation_steps=8,
        max_steps=args.steps,
        learning_rate=2e-4,
        lr_scheduler_type="cosine",
        warmup_ratio=0.03,
        bf16=True,
        logging_steps=20,
        save_strategy="no",
        report_to=[],
        gradient_checkpointing=True,
        gradient_checkpointing_kwargs={"use_reentrant": False},
        optim="paged_adamw_8bit",
        remove_unused_columns=False,
    )
    trainer = Trainer(
        model=model,
        args=targs,
        train_dataset=ds["train"],
        eval_dataset=ds["validation"],
        data_collator=DataCollatorForSeq2Seq(tok, padding=True, label_pad_token_id=-100),
    )
    trainer.train()
    metrics = trainer.evaluate()
    peak = torch.cuda.max_memory_allocated() / 1024 ** 3
    del model, trainer
    torch.cuda.empty_cache()
    torch.cuda.reset_peak_memory_stats()
    return {
        "r": rank,
        "可训练参数": n_train,
        "验证loss": round(metrics["eval_loss"], 4),
        "峰值显存GB": round(peak, 2),
    }


if __name__ == "__main__":
    tok = AutoTokenizer.from_pretrained(args.model, trust_remote_code=True)
    if tok.pad_token is None:
        tok.pad_token = tok.eos_token
    ds = build_dataset(tok)
    results = []
    for r in (8, 16, 32):
        print(f"=== 开始训练 r={r} ===")
        results.append(train_one(r, ds, tok))
    os.makedirs(os.path.dirname(args.out), exist_ok=True)
    json.dump(results, open(args.out, "w", encoding="utf-8"), ensure_ascii=False, indent=2)
    for row in results:
        print(row)
```

预期输出（200 步、seq 512、约 2.6 万条训练样本的子集）：

```text
=== 开始训练 r=8 ===
{'r': 8, '可训练参数': 20430848, '验证loss': 1.0621, '峰值显存GB': 6.71}
=== 开始训练 r=16 ===
{'r': 16, '可训练参数': 40861696, '验证loss': 1.0287, '峰值显存GB': 6.98}
=== 开始训练 r=32 ===
{'r': 32, '可训练参数': 81723392, '验证loss': 1.0203, '峰值显存GB': 7.34}
```

**判读方法**：`r` 从 8 到 16 验证 loss 降幅明显（约 0.03），从 16 到 32 降幅很小（约 0.008）但显存多 0.36GB。所以 **8G 上 `r=16` 是拐点**，`r=32` 只在数据量 >10k 且必须榨效果时才用。同时必须看评测集成绩，验证 loss 低不等于业务指标好。

:::ok 关于 LoRA 的一个常被问到的点
LoRA 适配器可以「热插拔」：同一份 4bit 基座，切换不同 `adapter_name` 就能换能力，不需要重新加载基座（省 4.3GB 加载时间和显存）。这在面试里是加分点，代码用 `model.load_adapter(path, adapter_name="medical")` 与 `model.set_adapter("medical")` 实现。
:::

## 9.6 训练参数：`TrainingArguments` 逐参数解释

### 9.6.1 参数逐个解释

| 参数 | 8G 取值 | 作用 | 调错的后果 |
| --- | --- | --- | --- |
| `per_device_train_batch_size` | `1` | 单卡每步样本数 | 设 2 在 seq 512 上峰值 +0.8–1.2GB，多半 OOM |
| `gradient_accumulation_steps` | `8`（保命档）/`16` | 累积多少步再更新一次，等效 batch = batch × 累积 | 太小则等效 batch 小、梯度噪声大；太大则一个 epoch 更新次数少，学不动 |
| `max_seq_length`（在 `SFTTrainer` 里）或用 tokenize 时截断 | `512` / `768` / `1024` | 单条样本最大 token 数 | 与显存线性相关，是**最有效的显存开关** |
| `gradient_checkpointing` | `True` | 前向不保存中间激活，反向重算，激活显存降约 60–70%，速度降 15–25% | 关掉在 8G 上直接 OOM |
| `gradient_checkpointing_kwargs` | `{"use_reentrant": False}` | 用新版检查点实现，与 PEFT 配合更稳 | 用默认值时会报 `None of the inputs have requires_grad=True` 或梯度为 None |
| `optim` | `"paged_adamw_8bit"` | 8bit AdamW + 分页，优化器状态从 8 byte/参数降到约 2 byte 并可在显存紧张时分页到内存 | 用 `adamw_torch` 时 7B LoRA 优化器状态从 0.31GB 涨到 1.2GB 级别，且更易碎片 OOM |
| `learning_rate` | `2e-4`（QLoRA 常规）/`1e-4`（保守） | 学习率 | 5e-5 太小学不动，1e-3 容易震荡甚至发散到 NaN |
| `lr_scheduler_type` | `"cosine"` | 学习率曲线。cosine 平滑收尾，linear 也行 | `constant` 收尾时 loss 抖动大 |
| `warmup_ratio` | `0.03` | 前 3% 步数线性升温，避免一开始就大步长破坏预训练权重 | 为 0 时早期 loss 可能尖峰 |
| `num_train_epochs` | `2`–`3`（数据 <10k 用 3，>20k 用 1–2） | 训练轮数 | 轮数过多，模型开始复读训练集、泛化变差 |
| `bf16` | `True` | bf16 混合精度训练 | 设 `fp16=True` 会与 4bit 计算 dtype 冲突；两者都开报错 |
| `fp16` | `False` | fp16 混合精度 | RTX 4060 上没必要，且有溢出风险 |
| `save_steps` | `50` 或 `100` | 每隔多少步存一次检查点 | 太密浪费时间与磁盘；太稀则 OOM 后白跑 |
| `save_total_limit` | `2` | 最多保留几个检查点 | 不设会存满硬盘（每个 7B LoRA 检查点约 160MB，优化器状态另算约 320MB） |
| `logging_steps` | `10` | 打印 loss 的间隔 | 太小刷屏，太大看不到趋势 |
| `eval_steps` | `50` | 验证间隔 | 太密拖慢训练（验证也要跑前向） |
| `eval_strategy` | `"steps"` | 按步验证 | 设 `"epoch"` 时若一个 epoch 很长，中途无法发现问题 |
| `report_to` | `["tensorboard"]` 或 `["wandb"]` | 实验追踪 | 离线环境用 tensorboard；`wandb` 需要联网登录 |
| `remove_unused_columns` | `False` | 保留数据集里的自定义列 | 用 `SFTTrainer` 时保持默认 True 也行；自写 tokenize 时设 False 避免丢字段 |
| `dataloader_num_workers` | `0`（Windows）/`2`（WSL2） | 数据加载进程数 | Windows 下 >0 常在脚本入口缺 `if __name__ == "__main__"` 时炸；WSL2 可以开 2 |
| `dataloader_pin_memory` | `True` | 锁页内存加速 H2D 拷贝 | 保持默认 |
| `group_by_length` | `True` | 把长度相近的样本放同一批，减少 padding 浪费 | 8G 上建议开，能明显降低平均激活 |
| `max_grad_norm` | `0.3`（QLoRA 常用）/`1.0` | 梯度裁剪 | QLoRA 论文用 0.3 更稳；太大时早期容易出现 loss 尖峰 |

### 9.6.2 三档配置完整参数表

| 参数 | 保命档（seq 512） | 平衡档（seq 768） | 极限档（seq 1024） |
| --- | --- | --- | --- |
| `max_seq_length` | 512 | 768 | 1024 |
| `per_device_train_batch_size` | 1 | 1 | 1 |
| `gradient_accumulation_steps` | 8 | 16 | 16 |
| 等效 batch size | 8 | 16 | 16 |
| LoRA `r` / `alpha` | 16 / 32 | 16 / 32 | 16 / 32 |
| `target_modules` | 注意力 + MLP（7 个） | 注意力 + MLP | 注意力 + MLP |
| `learning_rate` | 2e-4 | 1.5e-4 | 1e-4 |
| `lr_scheduler_type` | cosine | cosine | cosine |
| `warmup_ratio` | 0.03 | 0.03 | 0.05 |
| `num_train_epochs` | 3 | 2 | 2 |
| `bf16` | True | True | True |
| `optim` | paged_adamw_8bit | paged_adamw_8bit | paged_adamw_8bit |
| `gradient_checkpointing` | True | True | True |
| `max_grad_norm` | 0.3 | 0.3 | 0.3 |
| `group_by_length` | True | True | True |
| `save_steps` / `save_total_limit` | 50 / 2 | 50 / 2 | 100 / 1 |
| `logging_steps` / `eval_steps` | 10 / 50 | 10 / 50 | 10 / 100 |
| `dataloader_num_workers` | 0（Win）/ 2（WSL2） | 同左 | 同左 |
| 预测峰值显存 | 6.3–7.0GB | 7.0–7.8GB | 7.8–8.6GB |
| 2000 步耗时（估算） | 2.0–3.0 小时 | 3.0–4.5 小时 | 4.5–6.5 小时 |
| 风险 | 低 | 中（需关内屏与其它占卡进程） | 高（随时准备降级到平衡档） |

:::warn 极限档的真实含义
极限档不是「推荐档」。它的意义是：当你的数据 99 分位长度是 900+，截断到 512 会丢掉关键信息时，才值得冒 OOM 风险。做法是先用保命档把流程跑通，再单独试一次极限档，记录是否成功，然后写进实验报告——这本身就是简历里「做过显存边界实验」的素材。
:::

### 9.6.3 显存不够时按顺序砍

砍的顺序有讲究，先砍影响最小的：

1. `max_seq_length` 1024 → 768 → 512（收益最大，效果损失可控）。
2. `per_device_train_batch_size` 保持 1，改大 `gradient_accumulation_steps`（等效 batch 不变，几乎无效果损失）。
3. `target_modules` 从 7 个减到 4 个（省约 20M 参数，效果损失中等）。
4. `r` 16 → 8（省 20M 参数，效果损失较小）。
5. 换更小模型：7B → 4B → 1.7B（效果损失最大，但一定能跑）。
6. 换硬件：租云 24GB 卡（见 9.12）。

下面是训练脚本本体：

```python
# 文件名：train_qlora.py
# Windows 用法：python train_qlora.py --config configs/seq512.yaml
# WSL2 用法：   python train_qlora.py --config configs/seq512.yaml
import argparse
import json
import os
import time

import torch
from datasets import load_dataset
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    BitsAndBytesConfig,
    DataCollatorForSeq2Seq,
    Trainer,
    TrainerCallback,
    TrainingArguments,
    set_seed,
)

PROMPT_TMPL = "### 指令：\n{instruction}\n\n### 输入：\n{input}\n\n### 回答：\n"


def parse_args():
    ap = argparse.ArgumentParser()
    ap.add_argument("--model", default="Qwen/Qwen2.5-7B-Instruct")
    ap.add_argument("--train-file", default="data/train.jsonl")
    ap.add_argument("--val-file", default="data/val.jsonl")
    ap.add_argument("--output-dir", default="outputs/qwen7b-qlora")
    ap.add_argument("--max-seq-length", type=int, default=512)
    ap.add_argument("--batch-size", type=int, default=1)
    ap.add_argument("--grad-accum", type=int, default=8)
    ap.add_argument("--lr", type=float, default=2e-4)
    ap.add_argument("--epochs", type=float, default=3.0)
    ap.add_argument("--lora-r", type=int, default=16)
    ap.add_argument("--lora-alpha", type=int, default=32)
    ap.add_argument("--lora-dropout", type=float, default=0.05)
    ap.add_argument("--max-steps", type=int, default=-1)
    ap.add_argument("--save-steps", type=int, default=50)
    ap.add_argument("--logging-steps", type=int, default=10)
    ap.add_argument("--eval-steps", type=int, default=50)
    ap.add_argument("--seed", type=int, default=42)
    ap.add_argument("--resume", action="store_true", help="从最新检查点续训")
    return ap.parse_args()


class MemoryCallback(TrainerCallback):
    """打印当前与峰值显存；当峰值超过阈值时发警告（不中断训练）。"""

    def __init__(self, warn_gb: float = 7.3):
        self.warn_gb = warn_gb
        self.t0 = time.time()

    def on_log(self, args, state, control, logs=None, **kwargs):
        if not torch.cuda.is_available() or not state.is_world_process_zero:
            return
        cur = torch.cuda.memory_allocated() / 1024 ** 3
        peak = torch.cuda.max_memory_allocated() / 1024 ** 3
        elapsed = (time.time() - self.t0) / 60
        msg = (f"[显存] step={state.global_step} 当前={cur:.2f}GB 峰值={peak:.2f}GB "
               f"已耗时={elapsed:.1f}分钟")
        if logs:
            msg += f" loss={logs.get('loss', float('nan')):.4f} lr={logs.get('learning_rate', 0):.2e}"
        print(msg)
        if peak > self.warn_gb:
            print(f"[警告] 峰值显存 {peak:.2f}GB 已超过警戒线 {self.warn_gb}GB，"
                  f"考虑降 max_seq_length 或降 lora_r")

    def on_train_end(self, args, state, control, **kwargs):
        if torch.cuda.is_available():
            print(f"[显存] 训练结束流程，全程峰值 = "
                  f"{torch.cuda.max_memory_allocated() / 1024 ** 3:.2f}GB")


def build_tokenizer(model_id: str):
    tok = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True, use_fast=True)
    if tok.pad_token is None:
        tok.pad_token = tok.eos_token
    tok.padding_side = "right"
    return tok


def build_dataset(tok, args):
    ds = load_dataset(
        "json",
        data_files={"train": args.train_file, "validation": args.val_file},
    )
    print(f"原始数据：train={len(ds['train'])} val={len(ds['validation'])}")

    def tok_fn(ex):
        prompt = PROMPT_TMPL.format(
            instruction=ex["instruction"], input=ex.get("input", "") or ""
        )
        answer = ex["output"] + tok.eos_token
        p_ids = tok(prompt, add_special_tokens=False)["input_ids"]
        a_ids = tok(answer, add_special_tokens=False)["input_ids"]
        ids = (p_ids + a_ids)[: args.max_seq_length]
        labels = ([-100] * len(p_ids) + a_ids)[: args.max_seq_length]
        if all(x == -100 for x in labels):
            # 截断后答案全丢了，这种样本必须丢弃，否则 loss 恒为 0 影响统计
            return {"input_ids": [], "labels": [], "attention_mask": []}
        return {"input_ids": ids, "labels": labels, "attention_mask": [1] * len(ids)}

    ds = ds.map(tok_fn, remove_columns=ds["train"].column_names, desc="tokenize")
    before = len(ds["train"])
    ds = ds.filter(lambda x: len(x["input_ids"]) > 0)
    print(f"截断后仍保留答案的样本：{len(ds['train'])}/{before}")
    return ds


def build_model(tok, args):
    bnb = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_use_double_quant=True,
        bnb_4bit_compute_dtype=torch.bfloat16,
        bnb_4bit_quant_storage=torch.uint8,
    )
    model = AutoModelForCausalLM.from_pretrained(
        args.model,
        quantization_config=bnb,
        device_map={"": 0},
        torch_dtype=torch.bfloat16,
        trust_remote_code=True,
        attn_implementation="sdpa",
    )
    model.config.use_cache = False
    model.config.pretraining_tp = 1
    model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)
    lora = LoraConfig(
        r=args.lora_r,
        lora_alpha=args.lora_alpha,
        lora_dropout=args.lora_dropout,
        bias="none",
        task_type="CAUSAL_LM",
        target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                        "gate_proj", "up_proj", "down_proj"],
    )
    model = get_peft_model(model, lora)
    model.print_trainable_parameters()
    return model


def main():
    args = parse_args()
    set_seed(args.seed)
    os.makedirs(args.output_dir, exist_ok=True)

    # 记录本次实验配置，方便对比
    with open(os.path.join(args.output_dir, "run_args.json"), "w", encoding="utf-8") as f:
        json.dump(vars(args), f, ensure_ascii=False, indent=2)

    if torch.cuda.is_available():
        torch.cuda.reset_peak_memory_stats()
        print(f"设备：{torch.cuda.get_device_name(0)} "
              f"总显存={torch.cuda.get_device_properties(0).total_memory / 1024 ** 3:.2f}GB "
              f"bf16={torch.cuda.is_bf16_supported()}")

    tok = build_tokenizer(args.model)
    ds = build_dataset(tok, args)
    model = build_model(tok, args)

    targs = TrainingArguments(
        output_dir=args.output_dir,
        per_device_train_batch_size=args.batch_size,
        per_device_eval_batch_size=1,
        gradient_accumulation_steps=args.grad_accum,
        max_steps=args.max_steps,
        num_train_epochs=args.epochs,
        learning_rate=args.lr,
        lr_scheduler_type="cosine",
        warmup_ratio=0.03,
        optim="paged_adamw_8bit",
        bf16=True,
        fp16=False,
        gradient_checkpointing=True,
        gradient_checkpointing_kwargs={"use_reentrant": False},
        max_grad_norm=0.3,
        logging_steps=args.logging_steps,
        eval_strategy="steps",
        eval_steps=args.eval_steps,
        save_strategy="steps",
        save_steps=args.save_steps,
        save_total_limit=2,
        load_best_model_at_end=True,
        metric_for_best_model="eval_loss",
        greater_is_better=False,
        group_by_length=True,
        dataloader_num_workers=0 if os.name == "nt" else 2,
        dataloader_pin_memory=True,
        report_to=["tensorboard"],
        remove_unused_columns=False,
        seed=args.seed,
        ddp_find_unused_parameters=False,
    )

    trainer = Trainer(
        model=model,
        args=targs,
        train_dataset=ds["train"],
        eval_dataset=ds["validation"],
        data_collator=DataCollatorForSeq2Seq(tok, padding=True, label_pad_token_id=-100),
        callbacks=[MemoryCallback()],
    )

    # 断点续训：从 output_dir 下最新检查点继续
    resume_from = None
    if args.resume:
        ckpts = [d for d in os.listdir(args.output_dir) if d.startswith("checkpoint-")]
        if ckpts:
            resume_from = os.path.join(
                args.output_dir, sorted(ckpts, key=lambda x: int(x.split("-")[-1]))[-1]
            )
            print(f"从检查点续训：{resume_from}")

    t0 = time.time()
    trainer.train(resume_from_checkpoint=resume_from)
    minutes = (time.time() - t0) / 60

    # 只保存适配器，体积约 80–320MB，不保存 4bit 基座
    trainer.save_model(args.output_dir)
    tok.save_pretrained(args.output_dir)
    peak = torch.cuda.max_memory_allocated() / 1024 ** 3 if torch.cuda.is_available() else 0
    summary = {
        "耗时分钟": round(minutes, 1),
        "峰值显存GB": round(peak, 2),
        "最终eval_loss": round(trainer.state.best_metric or 0, 4),
        "全局步数": trainer.state.global_step,
    }
    with open(os.path.join(args.output_dir, "train_summary.json"), "w", encoding="utf-8") as f:
        json.dump(summary, f, ensure_ascii=False, indent=2)
    print("训练完成：", summary)
    print(f"适配器已保存到 {args.output_dir}（adapter_model.safetensors）")


if __name__ == "__main__":
    main()
```

### 9.8.1 加载适配器推理（8G 可行）

基座用 4bit 加载，再挂上适配器，总显存约 4.4GB，可以边推理边开浏览器。下面脚本支持单条与批量，并打印耗时和显存。

```python
# 文件名：infer_adapter.py
# 用法：python infer_adapter.py --adapter outputs/qwen7b-seq512
import argparse
import time

import torch
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

BASE = "Qwen/Qwen2.5-7B-Instruct"


def load(adapter: str):
    bnb = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_use_double_quant=True,
        bnb_4bit_compute_dtype=torch.bfloat16,
    )
    tok = AutoTokenizer.from_pretrained(adapter, trust_remote_code=True)
    base = AutoModelForCausalLM.from_pretrained(
        BASE, quantization_config=bnb, device_map={"": 0},
        torch_dtype=torch.bfloat16, attn_implementation="sdpa",
    )
    model = PeftModel.from_pretrained(base, adapter, device_map={"": 0})
    model.eval()
    model.config.use_cache = True   # 推理时开启，省重复计算
    return tok, model


def chat(tok, model, user: str, system: str = "你是一名工业设备运维专家。", max_new_tokens: int = 256):
    messages = [{"role": "system", "content": system}, {"role": "user", "content": user}]
    text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tok(text, return_tensors="pt").to(model.device)
    t0 = time.time()
    with torch.no_grad():
        out = model.generate(
            **inputs,
            max_new_tokens=max_new_tokens,
            do_sample=True,
            temperature=0.7,
            top_p=0.9,
            repetition_penalty=1.05,
            pad_token_id=tok.pad_token_id,
        )
    n_new = out.shape[1] - inputs["input_ids"].shape[1]
    dt = time.time() - t0
    answer = tok.decode(out[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
    return answer, n_new, dt


if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("--adapter", default="outputs/qwen7b-seq512")
    ap.add_argument("--question", default="泵体振动值从 2.1mm/s 升到 6.8mm/s，如何处置？")
    args = ap.parse_args()

    tok, model = load(args.adapter)
    print(f"加载完成，显存={torch.cuda.memory_allocated() / 1024 ** 3:.2f}GB")
    ans, n_new, dt = chat(tok, model, args.question)
    print("=== 回答 ===")
    print(ans)
    print(f"=== 生成 {n_new} tokens，耗时 {dt:.2f}s，速度 {n_new / dt:.1f} tok/s ===")
```

```text
1) 立即记录当前工况：流量、转速、进出口压力与介质温度。
2) 做三向振动测量并做频谱分析，重点看 1× 转频与高频包络谱。
3) 1× 占主导时检查对中与地脚螺栓；出现 2× 及谐波时检查联轴器与轴承间隙。
4) 达到停机阈值前每 30 分钟复测一次，并准备备用泵切换方案。
```

### 9.8.2 CPU 合并适配器

8G 合不了 fp16 基座（fp16 7B 需约 15GB 显存）。正确做法是**在 CPU 上加载 fp32/fp16 基座做合并，输出到磁盘**。需要 16GB 以上内存，若内存只有 16GB，用 `device_map="cpu"` + `low_cpu_mem_usage=True` 并在合并后立刻 `del`。

```python
# 文件名：merge_adapter_cpu.py
# 用法：python merge_adapter_cpu.py --adapter outputs/qwen7b-seq512 --out merged/qwen7b-merged
import argparse
import os

import torch
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

ap = argparse.ArgumentParser()
ap.add_argument("--base", default="Qwen/Qwen2.5-7B-Instruct")
ap.add_argument("--adapter", default="outputs/qwen7b-seq512")
ap.add_argument("--out", default="merged/qwen7b-merged")
args = ap.parse_args()

os.makedirs(args.out, exist_ok=True)
print("在 CPU 上加载基座（fp32，约需 30GB 内存；内存不足请改 float16 并接受轻微精度损失）")
base = AutoModelForCausalLM.from_pretrained(
    args.base,
    torch_dtype=torch.float32,
    device_map="cpu",
    low_cpu_mem_usage=True,
)
tok = AutoTokenizer.from_pretrained(args.base, trust_remote_code=True)
model = PeftModel.from_pretrained(base, args.adapter, device_map="cpu")
merged = model.merge_and_unload()
merged.save_pretrained(args.out, safe_serialization=True)
tok.save_pretrained(args.out)
print(f"合并完成，输出目录：{args.out}")
```

## 9.9 评测：自建评测集、指标、LLM Judge、打分表

「微调后效果变好了」必须有数字支撑。8G 上做不了大规模 benchmark，但**自建 100–300 条领域评测集**完全够用，而且面试更爱看这个。

### 9.9.1 怎么造 100–300 条评测集

三种来源组合，保证覆盖度：

| 来源 | 数量 | 做法 | 优点 |
| --- | --- | --- | --- |
| 训练集外的手写题 | 30–50 条 | 你自己根据业务文档出题，写「标准答案要点」而非全文 | 最贴近真实需求 |
| 公开测试集抽样 | 50–100 条 | 从领域公开测试集（如医疗、法律 QA）抽，剔除与训练集重叠的 | 有客观答案 |
| API 大模型合成 + 人工筛 | 50–150 条 | 让强模型根据文档生成问答题，人工删掉错题 | 快速扩充 |

下面脚本把三种来源合并成标准评测集，字段固定为 `id / question / reference / key_points / category / difficulty`。

```python
# 文件名：build_eval_set.py
# 用法：python build_eval_set.py --in data/eval_raw.jsonl --out data/eval_set.jsonl
import argparse
import json
import re


def to_record(idx: int, raw: dict) -> dict:
    """把任意来源的记录规范成评测集 schema；key_points 用 | 分隔。"""
    kp = raw.get("key_points") or []
    if isinstance(kp, str):
        kp = [x.strip() for x in re.split(r"[|；;]", kp) if x.strip()]
    return {
        "id": f"E{idx:04d}",
        "question": str(raw["question"]).strip(),
        "reference": str(raw.get("reference") or raw.get("answer") or "").strip(),
        "key_points": kp,
        "category": str(raw.get("category") or "未分类"),
        "difficulty": str(raw.get("difficulty") or "中"),
    }


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--in", dest="inp", required=True)
    ap.add_argument("--out", default="data/eval_set.jsonl")
    ap.add_argument("--min-points", type=int, default=1)
    args = ap.parse_args()

    out, seen = [], set()
    for line in open(args.inp, encoding="utf-8"):
        line = line.strip()
        if not line:
            continue
        raw = json.loads(line)
        rec = to_record(len(out) + 1, raw)
        if len(rec["key_points"]) < args.min_points:
            print(f"跳过（无要点）：{rec['question'][:30]}")
            continue
        if rec["question"] in seen:
            continue
        seen.add(rec["question"])
        out.append(rec)

    with open(args.out, "w", encoding="utf-8") as f:
        for rec in out:
            f.write(json.dumps(rec, ensure_ascii=False) + "\n")

    cats = {}
    for rec in out:
        cats[rec["category"]] = cats.get(rec["category"], 0) + 1
    print(f"评测集共 {len(out)} 条，类别分布：{cats}")
    if len(out) < 100:
        print(f"[提醒] 只有 {len(out)} 条，建议补到 100 条以上，否则指标波动太大")
    if len(out) > 300:
        print(f"[提醒] {len(out)} 条偏多，人工复核成本高，建议精简到 300 条以内")


if __name__ == "__main__":
    main()
```

预期输出：

```text
评测集共 156 条，类别分布：{'故障诊断': 48, '参数设置': 37, '安全规范': 31, '术语解释': 40}
```

### 9.9.2 指标定义

| 指标 | 定义 | 计算方式 | 目标值 |
| --- | --- | --- | --- |
| 格式合规率 | 输出符合预期结构（如固定小节、JSON 合法）的比例 | 正则 / `json.loads` 成功数 ÷ 总数 | ≥ 95% |
| 关键点覆盖率 | 参考答案要点被回答覆盖的比例 | `命中要点数 ÷ 总要点数`，逐条求均值 | ≥ 0.70 |
| 事实错误率 | 回答中出现与参考矛盾或编造的陈述的比例 | LLM Judge 或人工判定 | ≤ 10% |
| 幻觉率 | 出现参考中没有、且无法从上下文推出的具体事实 | 人工抽检 50 条 | ≤ 5% |
| 平均长度 | 输出 token 数均值 | tokenizer 统计 | 80–300，过长要压缩 |
| Judge 总分 | LLM Judge 1–5 分均值 | 见 9.9.3 | ≥ 4.0 |
| 拒答正确率 | 应当拒答的题目真的拒答了 | 拒答题集上统计 | ≥ 80% |
| 推理延迟 | 单条平均生成耗时 | 计时 | ≤ 8s（256 token 以内） |

### 9.9.3 LLM Judge 打分 prompt 模板

Judge 用强模型（API），一次评一条，要求输出 JSON。模板如下：

```text
你是严格的答案评审员。请依据【参考答案要点】对【模型回答】打分。

【问题】
{question}

【参考答案要点】
{key_points}

【模型回答】
{answer}

评分维度与标准：
1. 要点覆盖 coverage（1-5）：5=全部要点完整覆盖；4=覆盖大部分要点（≥80%）；3=覆盖一半（50%-80%）；2=只覆盖少量（<50%）；1=完全未覆盖。
2. 事实正确 correctness（1-5）：5=无任何事实错误；3=有轻微不准确但不影响结论；1=存在关键事实错误或编造。
3. 遵循指令 instruction_following（1-5）：5=完全按要求的结构与范围作答；3=结构基本符合但有冗余；1=答非所问。
4. 简洁性 conciseness（1-5）：5=无冗余；3=有少量重复；1=大量复读或跑题。

判定规则：
- 如果回答包含参考答案未提及、且无法从常识推出的具体数字、型号、条款，则 correctness 最高给 3，并在 hallucination 中列出。
- 如果回答拒绝作答而问题本可作答，instruction_following 最高给 2。

只输出一行 JSON，不要任何解释文字，格式：
{"coverage": 4, "correctness": 5, "instruction_following": 5, "conciseness": 4, "hallucination": [], "reason": "20字以内理由"}
```

下面脚本用 OpenAI 兼容接口批量打分并汇总。先用 `pip install openai`。

```python
# 文件名：judge_eval.py
# 用法：python judge_eval.py --eval data/eval_set.jsonl --pred preds.jsonl --out reports/judge.jsonl
import argparse
import json
import os
import re
import time
from concurrent.futures import ThreadPoolExecutor, as_completed

from openai import OpenAI

JUDGE_PROMPT = """你是严格的答案评审员。请依据【参考答案要点】对【模型回答】打分。

【问题】
{question}

【参考答案要点】
{key_points}

【模型回答】
{answer}

评分维度与标准：
1. 要点覆盖 coverage（1-5）：5=全部要点完整覆盖；4=覆盖大部分要点（≥80%）；3=覆盖一半（50%-80%）；2=只覆盖少量（<50%）；1=完全未覆盖。
2. 事实正确 correctness（1-5）：5=无任何事实错误；3=有轻微不准确但不影响结论；1=存在关键事实错误或编造。
3. 遵循指令 instruction_following（1-5）：5=完全按要求的结构与范围作答；3=结构基本符合但有冗余；1=答非所问。
4. 简洁性 conciseness（1-5）：5=无冗余；3=有少量重复；1=大量复读或跑题。

判定规则：
- 如果回答包含参考答案未提及、且无法从常识推出的具体数字、型号、条款，则 correctness 最高给 3，并在 hallucination 中列出。
- 如果回答拒绝作答而问题本可作答，instruction_following 最高给 2。

只输出一行 JSON，不要任何解释文字，格式：
{{"coverage": 4, "correctness": 5, "instruction_following": 5, "conciseness": 4, "hallucination": [], "reason": "20字以内理由"}}
"""

JSON_RE = re.compile(r"\{.*\}", re.S)


def judge_one(client: OpenAI, model: str, rec: dict, answer: str, retries: int = 3) -> dict:
    prompt = JUDGE_PROMPT.format(
        question=rec["question"],
        key_points=" | ".join(rec["key_points"]) or rec["reference"],
        answer=answer[:4000],
    )
    last_err = ""
    for attempt in range(retries):
        try:
            resp = client.chat.completions.create(
                model=model,
                messages=[{"role": "user", "content": prompt}],
                temperature=0,
                max_tokens=300,
            )
            text = resp.choices[0].message.content.strip()
            m = JSON_RE.search(text)
            if not m:
                last_err = f"返回不是 JSON：{text[:80]}"
                continue
            data = json.loads(m.group(0))
            dims = [data.get(k, 0) for k in
                    ("coverage", "correctness", "instruction_following", "conciseness")]
            data["score"] = round(sum(dims) / 4, 3)
            data["id"] = rec["id"]
            data["question"] = rec["question"]
            data["answer"] = answer
            return data
        except Exception as e:                      # noqa: BLE001
            last_err = f"{type(e).__name__}: {e}"
            time.sleep(1.5 * (attempt + 1))
    return {"id": rec["id"], "question": rec["question"], "answer": answer,
            "score": None, "error": last_err}


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--eval", default="data/eval_set.jsonl")
    ap.add_argument("--pred", required=True, help="jsonl，字段 id 与 answer")
    ap.add_argument("--out", default="reports/judge.jsonl")
    ap.add_argument("--model", default="gpt-4o-mini")
    ap.add_argument("--workers", type=int, default=4)
    args = ap.parse_args()

    client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
    recs = {json.loads(l)["id"]: json.loads(l) for l in open(args.eval, encoding="utf-8") if l.strip()}
    preds = [json.loads(l) for l in open(args.pred, encoding="utf-8") if l.strip()]

    os.makedirs(os.path.dirname(args.out), exist_ok=True)
    results = []
    with ThreadPoolExecutor(max_workers=args.workers) as pool:
        futs = {
            pool.submit(judge_one, client, args.model, recs[p["id"]], p["answer"]): p["id"]
            for p in preds if p["id"] in recs
        }
        for fut in as_completed(futs):
            results.append(fut.result())

    with open(args.out, "w", encoding="utf-8") as f:
        for r in results:
            f.write(json.dumps(r, ensure_ascii=False) + "\n")

    ok = [r for r in results if r.get("score") is not None]
    if ok:
        print(f"有效评分 {len(ok)}/{len(results)} 条")
        for key in ("score", "coverage", "correctness", "instruction_following", "conciseness"):
            avg = sum(r[key] for r in ok) / len(ok)
            print(f"  {key} 均值 = {avg:.3f}")
        hall = sum(1 for r in ok if r.get("hallucination"))
        print(f"  含幻觉条目 = {hall} 条（{hall / len(ok) * 100:.1f}%）")
    else:
        print("没有有效评分，先检查 API key 与模型名")


if __name__ == "__main__":
    main()
```

预期输出：

```text
有效评分 156/156 条
  score 均值 = 4.112
  coverage 均值 = 3.974
  correctness 均值 = 4.372
  instruction_following 均值 = 4.391
  conciseness 均值 = 3.712
  含幻觉条目 = 11 条（7.1%）
```

## 9.10 对齐：DPO / ORPO / SimPO 在 8G 上的取舍

监督微调（SFT）教模型「怎么答」，偏好对齐教模型「哪种答更好」。DPO 需要同时驻留策略模型和参考模型，显存约 2 倍，8G 上很紧张；ORPO 和 SimPO 把偏好优化并入单模型训练，是 8G 的现实选择。

### 9.10.1 三者对照

| 维度 | DPO | ORPO | SimPO |
| --- | --- | --- | --- |
| 是否需要参考模型 | 需要（策略 + 参考，约 2× 显存） | 不需要（在 SFT loss 上加 odds ratio 项） | 不需要 |
| 显存（7B QLoRA，seq 512） | 参考模型可用 4bit，合计约 8.5–10GB → **8G 基本不可行** | 约 6.5–7.6GB → **可行（需谨慎）** | 约 6.3–7.4GB → **可行** |
| 数据要求 | 偏好对 `(prompt, chosen, rejected)`，通常 ≥5k 对 | 同 DPO，但**可以只用 chosen，ORPO 自带 SFT 目标** | 同 ORPO |
| 稳定性 | 对学习率敏感，β 需调；易出现 chosen/rejected 概率同降 | 较稳，一个模型一次训练搞定 SFT + 对齐 | 稳，但 `gamma` 参数需调，过大易过拟合 |
| 训练时长（相对 SFT） | 约 2.5–3× | 约 1.2× | 约 1.1× |
| 8G 结论 | 不用（除非降到 1.7B 或上云） | **首选** | 备选，效果与 ORPO 接近 |
| 实现库 | `trl.DPOTrainer` | `trl.ORPOTrainer` | `trl.CPTOTrainer`（SimPO 用 CPOTrainer 配 `loss_type="simpo"`） |

:::warn 偏好数据的现实困难
8G 上最缺的不是算力而是偏好对数据。自己造 rejected 的可行做法：用基线模型对同一 prompt 生成 4 个回答，人工或 Judge 排序，取最好为 chosen、最差为 rejected。1000 对大约需要 4000 次生成（约 6 小时）加 2 小时人工。也可以直接用公开偏好数据集（如 `llamafactory/orpo_zh_demo`，用于跑通流程）。
:::

### 9.10.2 ORPO 完整可运行代码

先造一份最小可跑的偏好数据，再跑 ORPO。数据 schema：`prompt / chosen / rejected`。

```python
# 文件名：make_pref_data.py
# 用法：python make_pref_data.py --in data/train.jsonl --out data/pref_train.jsonl --n 800
import argparse
import json
import random

# 这份脚本给出「用规则构造 rejected」的最小可用做法：
# chosen 用数据里的标准答案，rejected 用「截断一半 + 加空话」的劣化版本。
# 真实项目请换成「基线模型生成 + 人工/Judge 排序」。

FILLER = "总的来说，这个问题比较复杂，建议你多查阅资料，结合实际情况综合考虑。"


def degrade(text: str) -> str:
    cut = max(len(text) // 2, 10)
    return text[:cut].rstrip("，。；、") + "。" + FILLER


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--in", dest="inp", default="data/train.jsonl")
    ap.add_argument("--out", default="data/pref_train.jsonl")
    ap.add_argument("--n", type=int, default=800)
    args = ap.parse_args()

    rows = [json.loads(l) for l in open(args.inp, encoding="utf-8") if l.strip()]
    random.Random(42).shuffle(rows)
    rows = rows[: args.n]

    out = []
    for r in rows:
        prompt = f"### 指令：\n{r['instruction']}\n\n### 输入：\n{r.get('input', '')}\n\n### 回答：\n"
        chosen = r["output"].strip()
        rejected = degrade(chosen)
        if len(chosen) < 60 or chosen == rejected:
            continue
        out.append({"prompt": prompt, "chosen": chosen, "rejected": rejected})

    with open(args.out, "w", encoding="utf-8") as f:
        for row in out:
            f.write(json.dumps(row, ensure_ascii=False) + "\n")
    print(f"写出 {len(out)} 条偏好对到 {args.out}")
    print("样例：", json.dumps(out[0], ensure_ascii=False)[:300])


if __name__ == "__main__":
    main()
```

```python
)

if tok.pad_token is None:
    tok.pad_token = tok.eos_token

print(f"偏好对数量：{len(ds)}")

    per_device_train_batch_size=1,
    gradient_accumulation_steps=16,
    num_train_epochs=args.epochs,
    learning_rate=args.lr,
    lr_scheduler_type="cosine",
    warmup_ratio=0.05,
    optim="paged_adamw_8bit",
    bf16=True,
    beta=args.beta,
    max_length=args.max_len,
    max_prompt_length=args.max_prompt_len,
    max_completion_length=args.max_len - args.max_prompt_len,
    logging_steps=10,
    save_steps=50,
    save_total_limit=2,
    gradient_checkpointing=True,
    gradient_checkpointing_kwargs={"use_reentrant": False},
    report_to=[],
    remove_unused_columns=False,
    dataloader_num_workers=0 if os.name == "nt" else 2,
)
```

## 9.11 数据蒸馏与数据合成：8G 做推理类效果最现实的路径

8G 训不出「更强的模型」，但可以用 API 强模型造出**高质量 CoT 数据**，再 QLoRA 到 7B 本地模型上。这条路线的性价比远高于硬凑参数：花 10–50 元 API 费用，换来一份 3k–8k 条的高质量数据集，微调后本地模型在领域推理任务上接近 API 效果。

### 9.11.1 为什么这是 8G 最现实的路径

| 对比项 | 自己标数据 | 用便宜模型生成 | 用强模型蒸馏 CoT |
| --- | --- | --- | --- |
| 1000 条成本 | 约 20 小时人工 | 约 3–8 元 | 约 15–60 元 |
| 推理链质量 | 取决于标注者 | 中等，常跳步 | 高，含完整推理过程 |
| 领域贴合 | 最好 | 一般 | 需要你提供领域种子与判据 |
| 8G 训练可行性 | 可行 | 可行 | 可行（数据量小，长样本多，注意截断） |
| 综合推荐 | 少量高价值题 | 扩量 | **主力方案** |

### 9.11.2 完整蒸馏脚本（并发 + 去重 + 质量过滤 + 成本估算）

用 OpenAI 兼容接口（`openai` SDK 可接任意兼容服务）。核心设计：异步并发 + 指数退避重试 + 结果即时落盘（中断可续）+ MinHash 去重 + 规则化质量过滤 + token 计费估算。

```python
# 文件名：distill_cot.py
# 用法（PowerShell）：
#   $env:OPENAI_API_KEY="sk-xxx"; $env:OPENAI_BASE_URL="https://api.openai.com/v1"
#   python distill_cot.py --seeds data/seeds.jsonl --out data/cot_raw.jsonl --concurrency 8
import argparse
import asyncio
import json
import os
import re
import time

from openai import AsyncOpenAI

SYSTEM_PROMPT = (
    "你是一名工业设备运维专家。回答必须："
    "1) 先用「分析：」写出推理过程，逐步列出依据；"
    "2) 再用「结论：」给出结构化、可执行的最终答案；"
    "3) 不编造具体标准编号、型号与数值，不确定时明确说明需要现场核实。"
)

USER_TMPL = """请回答下面的问题，并给出完整推理过程。

问题：{question}
"""


def build_client() -> AsyncOpenAI:
    return AsyncOpenAI(
        api_key=os.environ["OPENAI_API_KEY"],
        base_url=os.environ.get("OPENAI_BASE_URL", "https://api.openai.com/v1"),
        timeout=90.0,
        max_retries=0,   # 重试由我们自己控制，便于记录
    )


async def gen_one(client: AsyncOpenAI, model: str, seed: dict, sem: asyncio.Semaphore,
                  max_retries: int = 4) -> dict:
    async with sem:
        question = seed["question"]
        last_err = ""
        for attempt in range(max_retries):
            try:
                t0 = time.time()
                resp = await client.chat.completions.create(
                    model=model,
                    messages=[
                        {"role": "system", "content": SYSTEM_PROMPT},
                        {"role": "user", "content": USER_TMPL.format(question=question)},
                    ],
                    temperature=0.7,
                    top_p=0.9,
                    max_tokens=1200,
                )
                answer = resp.choices[0].message.content.strip()
                usage = resp.usage
                return {
                    "instruction": question,
                    "input": seed.get("input", ""),
                    "output": answer,
                    "category": seed.get("category", "未分类"),
                    "source": f"distill:{model}",
                    "latency_s": round(time.time() - t0, 2),
                    "prompt_tokens": getattr(usage, "prompt_tokens", 0),
                    "completion_tokens": getattr(usage, "completion_tokens", 0),
                }
            except Exception as e:                    # noqa: BLE001
                last_err = f"{type(e).__name__}: {e}"
                await asyncio.sleep(min(2 ** attempt, 20))
        return {"instruction": question, "output": "", "error": last_err}


def quality_ok(item: dict, min_len: int = 80, max_len: int = 2200) -> bool:
    out = item.get("output", "")
    if not out or not (min_len <= len(out) <= max_len):
        return False
    if "分析：" not in out or "结论：" not in out:
        return False
    # 明显拒答/空洞的丢掉
    bad = ("我无法", "作为一个AI", "抱歉，我不能", "无法回答该问题")
    if any(b in out for b in bad):
        return False
    # 复读检测：连续重复 20 字以上
    if re.search(r"(.{20,})\1{2,}", out):
        return False
    return True


def dedup(items: list, threshold: float = 0.85) -> list:
    from datasketch import MinHash, MinHashLSH

    lsh = MinHashLSH(threshold=threshold, num_perm=128)
    kept = []
    for i, it in enumerate(items):
        m = MinHash(num_perm=128)
        text = re.sub(r"\s+", "", it["instruction"] + it["output"])
        for j in range(max(len(text) - 4, 1)):
            m.update(text[j : j + 5].encode("utf-8"))
        if lsh.query(m):
            continue
        lsh.insert(str(i), m)
        kept.append(it)
    return kept


async def main_async(args):
    client = build_client()
    seeds = [json.loads(l) for l in open(args.seeds, encoding="utf-8") if l.strip()]
    print(f"种子问题 {len(seeds)} 条，并发 {args.concurrency}，模型 {args.model}")

    sem = asyncio.Semaphore(args.concurrency)
    os.makedirs(os.path.dirname(args.out) or ".", exist_ok=True)
    done_questions = set()
    if args.resume and os.path.exists(args.out):
        for l in open(args.out, encoding="utf-8"):
            if l.strip():
                done_questions.add(json.loads(l)["instruction"])
        print(f"续跑模式：已有 {len(done_questions)} 条结果，跳过这些种子")

    todo = [s for s in seeds if s["question"] not in done_questions]
    t0 = time.time()
    cache = []
    with open(args.out, "a", encoding="utf-8") as f:
        tasks = [gen_one(client, args.model, s, sem) for s in todo]
        for coro in asyncio.as_completed(tasks):
            item = await coro
            if item.get("output"):
                f.write(json.dumps(item, ensure_ascii=False) + "\n")
                f.flush()
                cache.append(item)
            else:
                print(f"[失败] {item['instruction'][:30]} -> {item.get('error')}")

    elapsed = time.time() - t0
    all_items = [json.loads(l) for l in open(args.out, encoding="utf-8") if l.strip()]
    good = [x for x in all_items if quality_ok(x)]
    deduped = dedup(good)

    pt = sum(x.get("prompt_tokens", 0) for x in all_items)
    ct = sum(x.get("completion_tokens", 0) for x in all_items)
    cost = pt / 1e6 * args.price_in + ct / 1e6 * args.price_out

    print(f"耗时 {elapsed / 60:.1f} 分钟，成功 {len(all_items)}/{len(seeds)} 条")
    print(f"质量过滤后 {len(good)} 条，去重后 {len(deduped)} 条，保留率 {len(deduped) / max(len(seeds), 1):.1%}")
    print(f"token：输入 {pt} 输出 {ct}；按 ${args.price_in}/M 输入、${args.price_out}/M 输出估算成本 = ${cost:.2f}")

    with open(args.out.replace(".jsonl", "_final.jsonl"), "w", encoding="utf-8") as f:
        for it in deduped:
            f.write(json.dumps(it, ensure_ascii=False) + "\n")


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--seeds", default="data/seeds.jsonl")
    ap.add_argument("--out", default="data/cot_raw.jsonl")
    ap.add_argument("--model", default="gpt-4o-mini")
    ap.add_argument("--concurrency", type=int, default=8)
    ap.add_argument("--resume", action="store_true")
    ap.add_argument("--price-in", type=float, default=0.15, help="每百万输入 token 价格（美元）")
    ap.add_argument("--price-out", type=float, default=0.60, help="每百万输出 token 价格（美元）")
    args = ap.parse_args()
    asyncio.run(main_async(args))


if __name__ == "__main__":
    main()
```

```python
# 文件名：make_seeds.py
# 用法：python make_seeds.py --doc data/domain_notes.txt --out data/seeds.jsonl --n 1000
import argparse
import json
import re

SPLIT_RE = re.compile(r"[。！？\n]+")


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--doc", required=True, help="领域纯文本，每段一件事")
    ap.add_argument("--out", default="data/seeds.jsonl")
    ap.add_argument("--n", type=int, default=1000)
    args = ap.parse_args()

    text = open(args.doc, encoding="utf-8").read()

    print(f"从文档切出 {len(chunks)} 个语义片段")

        "如果{topic}，应该按什么顺序排查？",
        "解释{topic}涉及的原理与判据。",
    ]
    seeds = []
    for i, chunk in enumerate(chunks):
        topic = chunk[:40]
        tmpl = templates[i % len(templates)]
        seeds.append({
            "question": tmpl.format(topic=topic),
            "input": "",
            "category": "领域知识",
            "source_chunk": chunk[:200],
        })
        if len(seeds) >= args.n:
            break

    with open(args.out, "w", encoding="utf-8") as f:
        for s in seeds:
            f.write(json.dumps(s, ensure_ascii=False) + "\n")
```

## 9.12 租云跑一次正式训练：AutoDL 全流程

本地 8G 的价值是**把流程跑通、把超参调好**；正式训练（更大数据、更长序列、更多 epoch）租一张 24GB 卡跑，成本可控。这一节是完整的操作顺序。

### 9.12.1 选卡与预算

| 卡型 | 显存 | 参考单价（元/小时） | 适合任务 | 训练 6 小时估算 |
| --- | --- | --- | --- | --- |
| RTX 4090 | 24GB | 约 2–3 | 7B QLoRA seq 1024、batch 2 | 12–18 元 |
| RTX A5000 | 24GB | 约 2–3 | 同上，稳定性好 | 12–18 元 |
| A100 40G | 40GB | 约 6–10 | 13B QLoRA、7B 全参（勉强） | 36–60 元 |
| A100 80G | 80GB | 约 10–15 | 7B 全参数微调、32B QLoRA | 60–90 元 |

**你只需要租 4090 24GB 跑 7B QLoRA**：seq 1024 + batch 2 + r=32 在 24GB 上有充足余量，4–8 小时花费 10–25 元。这比在本地和 OOM 纠缠一周便宜得多。

:::danger 花钱纪律（照做）
1. 本地先把 `train_qlora.py` 用 `--max-steps 20` 跑通，确认数据和脚本没问题，再上云。
2. 数据提前传好（网盘 / 对象存储 / `scp`），不要在实例里现下数据集。
3. 开实例后立刻设自动关机：AutoDL 控制台有「定时关机」，或自己跑 `shutdown -h +400`。
4. 训练脚本里设 `save_steps=200`、`save_total_limit=3`，避免实例被回收后全丢。
5. 拿到检查点立刻下载到本地，确认文件完整后再释放实例。
6. 释放实例前确认已下载，**释放后数据不可恢复**。
:::

### 9.12.2 全流程步骤

**步骤 1：注册与选镜像**。在 AutoDL 控制台选「RTX 4090 / 24GB」，镜像选 PyTorch 基础镜像（选带 CUDA 12.1/12.4 的 PyTorch 2.4+ 版本），不要选「无卡模式」跑训练。

**步骤 2：本地打包数据上传**。先在本地把数据打成一个压缩包（Windows PowerShell）：

```powershell

```

## 9.13 报错与显存问题排查表

下面每一条都是实际跑 8G QLoRA 会遇到的报错，按「报错原文 / 原因 / 解决」组织。

| 报错原文 | 原因 | 解决 |
| --- | --- | --- |
| `torch.cuda.OutOfMemoryError: CUDA out of memory. Tried to allocate 256.00 MiB (GPU 0; 8.00 GiB total capacity; 6.98 GiB already allocated)` | 显存峰值超限，通常 `max_seq_length` 太大或 batch>1 | 先设 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`；再把 `max_seq_length` 降到 512、`per_device_train_batch_size` 保持 1、`gradient_accumulation_steps` 调大 |

| `UserWarning: torch.utils.checkpoint: please pass in use_reentrant=True or use_reentrant=False explicitly` | PyTorch 2.x 的检查点 API 变更 | 设 `gradient_checkpointing_kwargs={"use_reentrant": False}` |

| `KeyError: 'q_proj'` 或训练后发现 `trainable params: 0` | `target_modules` 名字与模型不匹配（如 GLM 用 `query_key_value`） | 用 `list_target_modules.py` 打印 Linear 层名，改成实际存在的名字 |

| `ImportError: Using bitsandbytes 4-bit quantization requires accelerate` | 缺 `accelerate` | `pip install -U accelerate` |

| `Process finished with exit code -1073741819`（Windows） | DataLoader 多进程与 Windows spawn 冲突 | 确保脚本有 `if __name__ == "__main__":` 入口；`dataloader_num_workers=0` |
| `Killed`（WSL2 里，无 Python traceback） | 主机内存不足，OOM Killer 杀了进程 | 降 `dataloader_num_workers`；关掉其它程序；`free -h` 查内存；把 `save_total_limit` 降为 1 减少写盘峰值 |

## 9.14 简历写法与面试要点

### 9.14.1 三条带数字的简历句

**句 1（项目主体，8G 硬约束 + 量化结果）**

**句 2（数据工程 + 蒸馏，体现成本和规模意识）**

### 9.14.2 八个必被问到的微调问题及答题要点

**1. QLoRA 为什么能在 8G 上微调 7B？显存去向说清楚。**

答题要点：4bit NF4 双重量化把权重压到 0.63 byte/参数（7B ≈ 4.3GB），只训练 0.5% 的低秩适配器（40M 参数），优化器用 8bit 分页 AdamW（8 byte/参数 → 0.31GB），激活值靠梯度检查点降到 1.0–1.3GB，加上固定开销峰值约 7GB。关键是把「权重、梯度、优化器、激活」四项分开讲。

**2. NF4 和 FP4 有什么区别，为什么默认 NF4？**

答题要点：NF4 假设权重近似正态分布，量化点按分位数分布；FP4 是等间距浮点网格。LLM 权重近似零均值正态，所以 NF4 的信息损失更小，QLoRA 论文中困惑度更低。加上双重量化（对量化常数再量化）每参数再省约 0.37 bit。

**3. LoRA 的 r 和 alpha 分别控制什么？alpha/r 的意义？**

答题要点：`r` 是低秩分解的秩，控制容量与参数量（参数量 ∝ r）；`alpha` 是缩放系数，实际更新乘以 `alpha/r`。所以 `alpha=2r` 时缩放恒为 2，改 `r` 不会突然改变更新幅度，这是 `alpha=2r` 这个惯例的由来。我做过 r=8/16/32 的对照：验证 loss 1.062/1.029/1.020，显存 6.71/6.98/7.34GB，8G 上 r=16 是拐点。

**4. `target_modules` 为什么建议加到 MLP 层？**

答题要点：只注入 `q_proj/v_proj` 时参数量约 9M，容量不足；QLoRA 论文对所有线性层注入。加到 7 个模块（注意力四件套 + gate/up/down）参数量约 40M，只多约 80MB 显存，效果提升明显。不能盲目加 `lm_head`，会引入大量参数且容易过拟合。

**5. 梯度检查点省了多少显存、代价是什么？**

答题要点：前向不保存中间激活、反向重算，激活显存降 60–70%，代价是训练慢 15–25%。必须配合 `use_reentrant=False` 才能和 PEFT 正常协作，否则会报梯度为 None 的错误。

**6. 显存不够时你的降级顺序是什么？**

答题要点：按「效果损失从小到大」排：`max_seq_length` → 等效 batch（改累积步数不动 batch） → `target_modules` 范围 → `r` → 换更小模型 → 租云。这个顺序是原则，能体现你懂哪些参数是「容量参数」哪些是「效率参数」。

**7. 怎么证明微调有效？**

答题要点：自建 100–300 条领域评测集（手写 + 公开集抽样 + API 合成后人工筛），指标用格式合规率、关键点覆盖率、事实错误率、Judge 总分，基线要有「原版 + prompt」和「原版 + few-shot」两档。我用 LLM Judge 全量评 + 人工盲评 30 条校验一致率（83%），报告里给 before/after 表而不是形容词。

**8. 什么时候不微调？**

答题要点：需要注入可更新的具体事实（走 RAG）、few-shot 就能达标（走 prompt）、没有 ≥1000 条配对数据（先蒸馏数据）、显存时间都不够（走 RAG 单点突破或小模型）。这题考的是判断力，答「什么都能微调」是减分项。
