# 第11章 推理部署与量化专题：让模型在 8GB 上跑得动、跑得快、跑得稳

这一章解决一个具体矛盾：你手上只有 RTX 4060 Laptop 的 8GB 显存（扣掉内屏占用实际约 7GB），但招聘方要的是「能把模型部署上线并交出对比报告」的人。读完这一章，你要能独立完成四件事：把视觉模型导出成 ONNX 并做 INT8 静态量化、把 LLM 转成 GGUF 并选出合适的量化档位、给 `llama.cpp` 与 ONNX Runtime 写出可复现的压测脚本、把推理服务包成带 SSE 流式的 FastAPI 并给出 TTFT/TPOT/吞吐的完整数据表。

口径统一说明：本章所有「能跑/跑不了」的判断，都以共享事实简报为准 —— 8GB 显存、内屏占 0.3–1GB、可用约 7GB；本地推理首选 `llama.cpp` / Ollama（GGUF Q4_K_M）；部署导出跨平台先 ONNX Runtime，NVIDIA 专属再 TensorRT（engine 与显卡架构绑定）；vLLM 在 8G 上实用性低且 Windows 需要 WSL2，本章只做选型对比不作为主线。

## 11.1 性能指标体系：TTFT、TPOT、端到端延迟、吞吐、P50/P95/P99、显存峰值、功耗

### 11.1.1 七个指标的定义与测量位置

推理性能不是一个数字，是一组互相牵制的数字。面试时最容易被追问的是「你这个 45 tok/s 是在什么条件下测的」。先把这个表背下来，测的时候按表对照。

| 指标 | 英文全称 | 定义 | 单位 | 在哪测 |
| --- | --- | --- | --- | --- |
| TTFT | Time To First Token | 从发出请求到收到第一个 token 的时长，含排队、预处理、prefill | ms | 客户端计时，服务端可再埋点 |
| TPOT | Time Per Output Token | 首 token 之后，平均每个输出 token 的时长，等价于 1/解码速度 | ms/token | 客户端（首 token 之后计时） |
| ITL | Inter-Token Latency | 相邻两个 token 的时长分布，比 TPOT 多一份 P95 信息 | ms | 客户端逐 token 打点 |
| 端到端延迟 | End-to-End Latency | 首个字节到最后一个字节的总时长 = TTFT + TPOT × (N-1) | ms | 客户端 |
| 吞吐 | Throughput | 单位时间完成的请求数或产出的 token 数（并发下才有意义） | req/s、tok/s | 压测脚本按并发分别统计 |
| 分位数 | P50/P95/P99 | 把延迟从小到大排序后第 50/95/99 百分位的值，反映长尾体验 | ms | 客户端聚合，样本建议 ≥200 次 |
| 显存峰值 | Peak VRAM | 进程生命周期内显存占用最高点 | GB | `torch.cuda.max_memory_allocated` 或 `nvidia-smi` 采样 |
| 功耗 | Power Draw | 整卡或整机的平均/峰值功耗，端侧场景必测 | W | `nvidia-smi --query-gpu=power.draw` 循环采样 |

两个容易搞错的口径：

- **tok/s 要区分 prefill 与 decode**。LLM 报告里常写的 40 tok/s 通常是 decode 速度（TPOT 的倒数）；如果把 prefill 的几百上千 tok/s 混进去平均，数字会虚高。压测脚本必须把 prompt 处理与生成分开计时。
- **并发下的 tok/s 有两种**：单请求吞吐（latency-oriented）与系统总吞吐（throughput-oriented）。8G 显存上并发 4 路时单请求 TPOT 会明显变差，但系统总 tok/s 可能上升。两个数字都要报，不能只报一个。

### 11.1.2 怎么测才可信：五条纪律

1. **预热**：GPU 有频率爬坡，第一次前向通常慢 2–5 倍。LLM 至少要跑 3 次预热请求，视觉模型跑 20 次预热迭代，之后才开始计时。
2. **多次重复取分位数**：单次测量没有意义。至少 30 次（视觉）、200 次（LLM 单请求）或固定时长 60 秒（并发压测），报 P50/P95/P99 而不是只报均值。
3. **固定输入长度**：LLM 明确 prompt token 数（如 256/512/1024）与输出 token 数（如 128）；视觉模型固定输入分辨率与 batch size。输入长度一变，所有数字都不可比。
4. **记录环境**：显卡型号与驱动版本、CUDA/cuDNN 版本、PyTorch 或推理引擎版本、功耗模式（笔记本必须插电 + 设为「高性能」）、后台占用（浏览器、Ollama、Windows Defender 扫描）。
5. **同步**：GPU 是异步执行，`time.time()` 包住一次前向会低估延迟。PyTorch 必须 `torch.cuda.synchronize()`；ONNX Runtime / TensorRT 的 `session.run` 本身是同步的，不用额外处理。

### 11.1.3 环境信息采集脚本

下面这段代码用来固定「记录环境」这一步，跑完把输出贴进实验报告的表头。文件保存为 `bench_env.py`，在 PowerShell 里执行。

```python
# bench_env.py —— 采集推理性能测试所需的环境信息
# 执行位置：PowerShell（已激活部署环境）
import platform
import subprocess
import sys

import torch


def sh(cmd):
    try:
        return subprocess.check_output(cmd, shell=True, text=True, stderr=subprocess.STDOUT).strip()
    except Exception as exc:  # 命令不存在或执行失败
        return "unavailable: %s" % exc


def main():
    print("Python      :", sys.version.split()[0])
    print("OS          :", platform.platform())
    print("PyTorch     :", torch.__version__)
    print("CUDA build  :", torch.version.cuda)
    print("cuDNN       :", torch.backends.cudnn.version())
    if torch.cuda.is_available():
        prop = torch.cuda.get_device_properties(0)
        print("GPU         :", prop.name)
        print("Compute cap : sm_%d%d" % (prop.major, prop.minor))
        print("Total VRAM  : %.2f GB" % (prop.total_memory / 1024 ** 3))
    else:
        print("GPU         : 不可用")
    print("nvidia-smi  :", sh("nvidia-smi --query-gpu=driver_version,power.limit --format=csv,noheader"))
    print("电源模式    :", sh("powercfg /getactivescheme"))


if __name__ == "__main__":
    main()
```

预期输出（4060 Laptop 参考值）：`Compute cap : sm_89`、`Total VRAM : 8.00 GB`、`driver_version` 形如 `5xx.xx`，电源模式里有「高性能」。把这段输出存成 `env.txt`，后面每一张性能表都标注它。

:::warn 笔记本的两个隐藏变量
同一个模型同一份代码，插电与不插电可以差 40% 以上的 tok/s。原因：电池模式下 GPU 功耗墙会被压到 35W 左右且核心频率被限制。测性能前必须插电、把 Windows 电源模式设为「高性能」、关掉浏览器硬件加速与本地 LLM 服务。这三个动作要写进报告的「测试条件」，否则数据不可复现。
:::

### 11.1.4 延迟分位数的计算

分位数不要手写排序逻辑，`numpy.percentile` 用线性插值即可；关键是样本量要够。下面的代码把「原始延迟样本 → 分位数表」这一步固定下来，后面每个压测脚本都复用它。

```python
# stats_util.py —— 延迟样本的分位数统计工具
# 执行位置：Python 脚本内 import，或 PowerShell 里 python stats_util.py 自测
import statistics

import numpy as np


def summarize(name, samples_ms, unit="ms"):
    """把一组延迟样本压成 P50/P90/P95/P99 + 均值 + 标准差。"""
    arr = np.asarray(samples_ms, dtype=np.float64)
    if arr.size == 0:
        raise ValueError("样本为空")
    p50, p90, p95, p99 = np.percentile(arr, [50, 90, 95, 99])
    return {
        "指标": name,
        "样本数": int(arr.size),
        "均值": round(float(arr.mean()), 2),
        "标准差": round(float(statistics.pstdev(arr.tolist())), 2),
        "P50": round(float(p50), 2),
        "P90": round(float(p90), 2),
        "P95": round(float(p95), 2),
        "P99": round(float(p99), 2),
        "最大值": round(float(arr.max()), 2),
        "单位": unit,
    }


def print_table(rows):
    """打印对齐的文本表，方便直接贴进 Markdown。"""
    cols = list(rows[0].keys())
    print("| " + " | ".join(cols) + " |")
    print("| " + " | ".join(["---"] * len(cols)) + " |")
    for row in rows:
        print("| " + " | ".join(str(row[c]) for c in cols) + " |")


if __name__ == "__main__":
    fake = np.random.default_rng(0).normal(320, 25, 500).clip(200, None).tolist()
    print_table([summarize("端到端延迟", fake)])
```

预期输出是一张 Markdown 表格，`P50` 约 319、`P95` 约 360、`P99` 约 377。注意 `P99` 与 `P50` 的差距就是「长尾」——面试里被问到「你的服务卡不卡」，正确答案是报 P99 而不是均值。

### 11.1.5 显存峰值的测量

PyTorch 有内置计数器，比 `nvidia-smi` 更准（只统计本进程分配的显存）。测量前必须重置峰值计数，否则会带上加载模型的开销。

```python
# vram_probe.py —— 测量一次前向的显存峰值
# 执行位置：PowerShell（部署环境）
import torch

print("当前已分配  : %.2f GB" % (torch.cuda.memory_allocated() / 1024 ** 3))
torch.cuda.empty_cache()
torch.cuda.reset_peak_memory_stats()   # 关键：重置峰值，否则会累计

model = torch.nn.Sequential(
    torch.nn.Conv2d(3, 64, 3, stride=2, padding=1),
    torch.nn.ReLU(),
    torch.nn.AdaptiveAvgPool2d(1),
    torch.nn.Flatten(),
    torch.nn.Linear(64, 10),
).cuda().eval()

with torch.no_grad():
    x = torch.randn(8, 3, 224, 224, device="cuda")
    torch.cuda.synchronize()
    _ = model(x)
    torch.cuda.synchronize()

print("峰值已分配  : %.3f GB" % (torch.cuda.max_memory_allocated() / 1024 ** 3))
print("峰值已预留  : %.3f GB" % (torch.cuda.max_memory_reserved() / 1024 ** 3))
```

预期输出：`当前已分配` 接近 0，`峰值已分配` 约 0.05–0.15 GB（小模型 + batch 8）。注意「已分配」与「已预留」的差异就是缓存碎片，预留远大于分配时，加上 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 可以缓解。

### 11.1.6 功耗采样

笔记本端侧场景要报「每 token 能耗」，这是嵌入式岗位关注的点。采样命令在 PowerShell 里循环执行，间隔 0.2 秒。

```powershell
# 在 PowerShell 中采样功耗 60 秒，结果写入 power_log.csv
$log = "power_log.csv"
"timestamp,power_w,util_pct,mem_used_mb" | Out-File -Encoding utf8 $log
$end = (Get-Date).AddSeconds(60)
while ((Get-Date) -lt $end) {
    $line = & nvidia-smi --query-gpu=power.draw,utilization.gpu,memory.used --format=csv,noheader,nounits
    "$(Get-Date -Format o),$line" | Add-Content -Encoding utf8 $log
    Start-Sleep -Milliseconds 200
}
"采样结束，共 $((Get-Content $log).Count - 1) 条"
```

预期输出最后一行形如「采样结束，共 300 条」。用 Pandas 读数后算 `power_w` 的均值与 P95：`df["power_w"].mean()` 与 `df["power_w"].quantile(0.95)`。4060 Laptop 整卡功耗范围 35–115W，推理负载下通常落在 45–90W。

:::tip 每 token 能耗怎么算
每 token 能耗（J/token）= 平均功耗（W）× 测试时长（s）÷ 生成的 token 总数。这个数字在端侧与移动端岗位很有说服力：同一模型 INT4 与 FP16 的 J/token 差距可以到 2 倍以上。
:::

## 11.2 量化基础：FP16/BF16/INT8/INT4、PTQ 与 QAT、对称与非对称、per-tensor 与 per-channel、精度损失来源

### 11.2.1 数值格式对照

| 格式 | 位数 | 表示方式 | 权重体积（相对 FP32） | 典型用途 | 8G 上的位置 |
| --- | --- | --- | --- | --- | --- |
| FP32 | 32 | 1 符号 + 8 指数 + 23 尾数 | 100% | 训练主权重 | 推理时不用 |
| TF32 | 19 | 指数 8 位，尾数 10 位 | — | Ampere 后矩阵乘加速 | 训练加速，非量化 |
| FP16 | 16 | 1 + 5 + 10 | 50% | GPU 推理、混合精度训练 | 视觉模型推理首选 |
| BF16 | 16 | 1 + 8 + 7 | 50% | 训练（动态范围同 FP32） | 4060 支持，训练更稳 |
| INT8 | 8 | 整数 + scale（+ zero point） | 25% | CV 模型 PTQ 主力 | ONNX Runtime / TensorRT |
| INT4 | 4 | 整数 + 分组 scale | 12.5%（实际含元数据约 15–20%） | LLM 端侧 | GGUF / AWQ / GPTQ |
| NF4 | 4 | 正态分布分位点查表 | 同上 | QLoRA 训练 | bitsandbytes 4bit |

关键区分：**FP16/BF16 是浮点，动态范围大、精度损失只来自有效位；INT8/INT4 是定点，必须给每个张量（或每组权重）配一个 scale**，把浮点范围映射到整数范围。量化的全部工程量都花在「scale 怎么算、算多细」上。

一个常被问到的点：BF16 尾数只有 7 位，精度比 FP16 低，为什么训练还用它？因为 BF16 的指数位与 FP32 相同，动态范围不会溢出，梯度下溢/上溢风险小；FP16 训练需要 loss scaling 就是这个原因。**推理时 FP16 更准**（尾数 10 位），**训练时 BF16 更稳**。

### 11.2.2 PTQ 与 QAT

- **PTQ（Post-Training Quantization，训练后量化）**：拿训练好的 FP32/FP16 模型，用一小批校准数据统计激活分布，直接算出 scale 完成量化。不需要重新训练，成本分钟级。缺点是遇到激活分布跨度大的模型（如 Transformer 的注意力输出）掉点明显。
- **QAT（Quantization-Aware Training，量化感知训练）**：在训练图里插入伪量化节点（forward 时模拟取整误差，backward 用 STE 直通估计），让模型学会适应量化噪声。精度明显好于 PTQ，但需要完整训练流程与算力。

选择口径很简单：**数据不缺、算力缺 → PTQ；PTQ 掉点超过可接受阈值、训练管线现成 → QAT**。CV 小模型（MobileNet、ResNet、YOLO）在 8G 上 PTQ 通常就够；LLM 做 INT4 时，工程界普遍用「PTQ + 逐组 scale（group-wise）」而不是 QAT，因为 LLM 的 QAT 成本太高。

### 11.2.3 对称与非对称

| 类型 | 公式 | zero point | 适用 | 备注 |
| --- | --- | --- | --- | --- |
| 对称量化 | `q = round(x / scale)`，`scale = max(|x|) / 127` | 固定 0 | 权重、有正负的激活 | 实现简单，卷积权重默认 |
| 非对称量化 | `q = round(x / scale) + zp`，`scale = (max - min) / 255` | 由 min/max 算出 | 激活（ReLU 后全为非负） | 能利用满 0–255 范围 |

ONNX Runtime 的 `QuantFormat.QOperator` 默认对权重用对称、对激活用非对称，这是工业默认配置；一般不需要手工改。`QuantType.QInt8` 是有符号 int8（-128~127），`QuantType.QUInt8` 是无符号 uint8（0~255）。TensorRT 的 INT8 更偏好对称 + 校准（Entropy/MinMax 校准器）。

### 11.2.4 per-tensor 与 per-channel

- **per-tensor**：整个张量共用一个 scale。存储最省，误差最大。激活一般只能 per-tensor（运行时统计）。
- **per-channel**：每个输出通道一个 scale（卷积权重沿输出通道维切）。误差显著更小，几乎是免费收益，是 ONNX Runtime 与 TensorRT 的权重默认。
- **per-group / group-wise**：LLM 权重量化把一行权重按 32/64/128 个元素一组，每组一个 scale（GGUF 的 K-quant 就是这种思路的进化版）。组越小越准，元数据越多。

### 11.2.5 精度损失的五个来源

1. **舍入误差**：`round` 的固有误差，与量化位宽成反比。INT8 的最大相对误差约 1/127 ≈ 0.8%，INT4 约 1/7 ≈ 14%。
2. **离群值拖累**：一个极大值会把 per-tensor scale 撑大，导致其余 99% 的数值精度骤降。这是 LLM 量化的头号敌人，解法是逐组 scale、AWQ 的激活感知缩放、SmoothQuant 的通道均衡。
3. **校准集不代表性**：ONNX Runtime 静态量化的 scale 完全由校准集决定。用 100 张纯风景图去校准人脸模型，掉点是必然的。
4. **饱和截断**：超出 scale 范围的激活会被 clip 到边界。ReLU6、SiLU 等非线性层前后最容易发生。
5. **逐层误差累积**：单层 0.5% 误差、50 层叠加后可能到 10% 以上。深层网络对量化更敏感，这也是 QAT 存在的理由。

### 11.2.6 量化档位决策表

| 场景 | 首选方案 | 备选 | 不要用 | 理由 |
| --- | --- | --- | --- | --- |
| CV 小模型（分类/检测）上端侧 | **INT8 PTQ（ONNX Runtime 静态量化 + per-channel）** | TensorRT INT8（NVIDIA 专属） | QAT（除非 PTQ 掉点 >2%） | 掉点通常 <1%，体积降到 1/4，延迟降 1.5–3 倍 |
| LLM 端侧推理（≤14B） | **W4A16 GGUF（Q4_K_M）** | AWQ/GPTQ + vLLM（显存够时） | FP16（7B 就要 14GB） | 权重 4bit、激活 16bit，8G 上唯一实用的组合 |
| LLM 高质量要求（服务器） | W8A8（如 TensorRT-LLM / vLLM FP8/INT8） | BF16 | INT4 | 长上下文与并发下 INT4 的 KV Cache 精度问题更明显 |
| QLoRA 微调 | NF4 + 双重量化（bitsandbytes） | INT4 GPTQ 基座 | INT8 训练（省显存不明显） | 简报口径：7B NF4 权重约 3.9–4.3GB |
| 视觉 ViT / 大 Transformer | FP16 推理 | INT8 PTQ（需 QAT 兜底） | INT4 | 注意力层离群值多，INT4 掉点严重 |

:::ok 结论口径
面试时把这句话说出来：**视觉小模型优先 INT8 PTQ（per-channel、对称权重 + 非对称激活），LLM 端侧优先 W4A16 GGUF（Q4_K_M 起步）**。这两条覆盖 8G 上 90% 的真实需求。
:::

## 11.3 视觉模型 INT8 量化全流程

### 11.3.1 流程总览

四步：**导出 FP32 ONNX → 准备校准集（100–500 张真实分布图片）→ ONNX Runtime 静态量化 → 三方对比（精度/延迟/体积）**。

先装依赖。这一段在 PowerShell 里执行，部署环境与微调环境必须分开（简报口径）。

```powershell
# 在 PowerShell 中执行：创建独立部署环境并装依赖
uv venv .venv-deploy --python 3.11
.\.venv-deploy\Scripts\Activate.ps1
uv pip install "torch==2.6.*" --index-url https://download.pytorch.org/whl/cu124
uv pip install "onnx==1.17.*" "onnxruntime-gpu==1.20.*" "onnxruntime==1.20.*" "onnxscript==0.1.*"
uv pip install "timm==1.0.*" "numpy<2.2" "pillow" "pandas"
python -c "import onnxruntime as ort; print(ort.get_available_providers())"
```

预期输出形如 `['TensorrtExecutionProvider', 'CUDAExecutionProvider', 'CPUExecutionProvider']`。如果只有 `CPUExecutionProvider`，说明装成了 CPU 版 `onnxruntime`；两个包同时存在时 `onnxruntime-gpu` 的文件会被覆盖，需要先 `uv pip uninstall onnxruntime` 再重装 `onnxruntime-gpu`。

:::warn 两个 onnxruntime 包不能共存
`onnxruntime` 与 `onnxruntime-gpu` 共享同一个导入名 `onnxruntime`，后装的覆盖先装的。正确做法是只装 `onnxruntime-gpu`（它自带 CPU provider）。检验方法就是上面那句 `get_available_providers()`。
:::

### 11.3.2 导出 ONNX（含动态轴）

下面的脚本把 timm 的 MobileNetV3 导出成 ONNX。执行位置：PowerShell。注意 `opset_version=17` 之后 PyTorch 走新的导出器，需要 `onnxscript`；如果报找不到导出器就退回 `dynamo=False`。

```python
# export_onnx.py —— 把 timm 模型导出为 FP32 ONNX
# 执行位置：PowerShell（.venv-deploy 已激活）
import torch
import timm

MODEL_NAME = "mobilenetv3_small_100"
OUT_PATH = "mobilenetv3_small_fp32.onnx"


def main():
    model = timm.create_model(MODEL_NAME, pretrained=True, num_classes=1000)
    model.eval().cuda()

    dummy = torch.randn(1, 3, 224, 224, device="cuda")

    with torch.no_grad():
        torch.onnx.export(
            model,
            dummy,
            OUT_PATH,
            input_names=["input"],
            output_names=["logits"],
            opset_version=17,
            do_constant_folding=True,
            # 三根轴全部动态：batch、高、宽；量化时再固定成静态形状
            dynamic_axes={
                "input": {0: "batch", 2: "height", 3: "width"},
                "logits": {0: "batch"},
            },
        )

    import onnx
    graph = onnx.load(OUT_PATH)
    onnx.checker.check_model(graph)
    print("导出成功：", OUT_PATH)
    print("文件体积： %.2f MB" % (onnx.load(OUT_PATH).ByteSize() / 1024 ** 2))
    print("输入：", [i.name for i in graph.graph.input])
    print("输出：", [o.name for o in graph.graph.output])


if __name__ == "__main__":
    main()
```

预期输出形如：`导出成功： mobilenetv3_small_fp32.onnx`、`文件体积： 10.24 MB`。MobileNetV3-Small 的 FP32 体积约 10MB，INT8 后约 2.6MB。

**动态轴的两面性**：动态轴让同一个模型能接受任意 batch 与分辨率，便于先跑通；但 INT8 静态量化需要固定形状，且动态形状在 TensorRT 上会让 kernel 选择变差。工程做法是**导出两份**：`dynamic` 一份用于功能验证，`static`（固定 batch=1、224×224）一份用于量化与 benchmark。

### 11.3.3 校准集构造

校准集要求三条：**数量 100–500 张、分布与线上一致、预处理与训练时完全一致（含归一化）**。下面脚本从本地图片目录抽样生成校准数据，输出 `calib.npy`。

```python
# make_calib.py —— 构造 INT8 静态量化的校准集
# 执行位置：PowerShell；图片目录请换成你自己的路径
import glob
import os

import numpy as np
from PIL import Image

IMG_DIR = r"C:\Users\<用户名>\datasets\calib_imgs"   # 校准图片目录（jpg/png 混放即可）
OUT_NPY = "calib.npy"
N_SAMPLES = 200          # 校准样本数：先用 100 验证流程，正式实验用 300–500
SIZE = 224

MEAN = np.array([0.485, 0.456, 0.406], dtype=np.float32)
STD = np.array([0.229, 0.224, 0.225], dtype=np.float32)


def preprocess(path):
    img = Image.open(path).convert("RGB").resize((SIZE, SIZE), Image.BILINEAR)
    arr = np.asarray(img, dtype=np.float32) / 255.0          # 归一化到 0-1
    arr = (arr - MEAN) / STD                                  # 与训练一致的标准归一化
    return np.transpose(arr, (2, 0, 1))                       # HWC -> CHW


def main():
    files = sorted(glob.glob(os.path.join(IMG_DIR, "*.jpg")) +
                   glob.glob(os.path.join(IMG_DIR, "*.png")))
    if len(files) < 20:
        raise SystemExit("图片太少：%d 张，至少 20 张，推荐 100–500 张" % len(files))
    picked = files[:N_SAMPLES] if len(files) >= N_SAMPLES else files
    batch = np.stack([preprocess(p) for p in picked]).astype(np.float32)
    np.save(OUT_NPY, batch)
    print("校准集已保存：%s  形状=%s  体积=%.2f MB" %
          (OUT_NPY, batch.shape, batch.nbytes / 1024 ** 2))


if __name__ == "__main__":
    main()
```

预期输出形如：`校准集已保存：calib.npy  形状=(200, 3, 224, 224)  体积=115.20 MB`。

:::tip 没有真实图片时的过渡方案
研一阶段可以先用 ImageNet 验证集的 200 张（`torchvision.datasets.ImageNet(split="val")`）或 `CIFAR-10` 转尺寸代替。但写报告时必须注明「校准集为公开数据集，与目标域存在分布差异」，这是诚实的做法，也是面试官爱追问的点。
:::

### 11.3.4 ONNX Runtime 静态量化完整代码

```python
# quantize_onnx.py —— ONNX Runtime 静态量化（INT8，per-channel 权重）
# 执行位置：PowerShell（.venv-deploy 已激活）
import numpy as np
from onnxruntime.quantization import (
    CalibrationDataReader,
    CalibrationMethod,
    QuantFormat,
    QuantType,
    quantize_static,
)

FP32_PATH = "mobilenetv3_small_fp32.onnx"
INT8_PATH = "mobilenetv3_small_int8.onnx"
CALIB_NPY = "calib.npy"


class NumpyCalibReader(CalibrationDataReader):
    """把 numpy 校准集喂给量化器：每次返回一个 feed dict。"""

    def __init__(self, npy_path, input_name="input"):
        self.data = np.load(npy_path).astype(np.float32)
        self.input_name = input_name
        self.index = 0

    def get_next(self):
        if self.index >= len(self.data):
            return None
        sample = self.data[self.index:self.index + 1]   # 逐张喂，形状 (1,3,224,224)
        self.index += 1
        return {self.input_name: sample}

    def rewind(self):
        self.index = 0


def main():
    reader = NumpyCalibReader(CALIB_NPY, input_name="input")
    quantize_static(
        model_input=FP32_PATH,
        model_output=INT8_PATH,
        calibration_data_reader=reader,
        quant_format=QuantFormat.QOperator,      # QDQ 更通用、QOperator 更省内存
        activation_type=QuantType.QUInt8,        # 激活非对称 uint8
        weight_type=QuantType.QInt8,             # 权重对称 int8
        per_channel=True,                        # 逐通道 scale，掉点更小
        reduce_range=False,                      # 非 VNNI CPU 上可设 True
        calibrate_method=CalibrationMethod.MinMax,   # 也可用 Entropy
        extra_options={
            "ActivationSymmetric": False,
            "WeightSymmetric": True,
            "QuantizeBias": True,
        },
    )
    import os
    print("量化完成：%s  %.2f MB" % (INT8_PATH, os.path.getsize(INT8_PATH) / 1024 ** 2))


if __name__ == "__main__":
    main()
```

预期输出：`量化完成：mobilenetv3_small_int8.onnx  2.68 MB`。

参数逐个解释：

| 参数 | 取值 | 作用与影响 |
| --- | --- | --- |
| `quant_format` | `QOperator` / `QDQ` | QDQ 在图里插入 QuantizeLinear/DequantizeLinear 节点，兼容 TensorRT 与更多后端；QOperator 用融合算子，体积小、CPU 上更快 |
| `activation_type` | `QUInt8` | 激活用无符号 8 位；若后端只支持有符号则改 `QInt8` |
| `weight_type` | `QInt8` | 权重有正负，用有符号 int8 对称量化 |
| `per_channel` | `True` | 逐输出通道 scale；`False` 时是 per-tensor，掉点更大 |
| `reduce_range` | `False` | `True` 会把范围压到 7 位，给旧 CPU 的 VNNI 缺失兜底，精度更差 |
| `calibrate_method` | `MinMax` / `Entropy` | MinMax 快；Entropy 对离群值更鲁棒，慢 3–5 倍 |
| `QuantizeBias` | `True` | 偏置也量化，省体积；极端情况关掉可保精度 |

**动态量化对比**：如果不想准备校准集，可以用 `quantize_dynamic`（只量化 MatMul/Gemm 权重，激活运行时算）。对 Transformer 类模型有效，对卷积网络在 CPU 上反而可能变慢（因为 Conv 的动态量化支持有限）。CV 模型请优先静态量化。

```python
# quantize_dynamic_demo.py —— 动态量化（无需校准集，仅作对比）
# 执行位置：PowerShell
from onnxruntime.quantization import QuantType, quantize_dynamic

quantize_dynamic(
    model_input="mobilenetv3_small_fp32.onnx",
    model_output="mobilenetv3_small_dyn_int8.onnx",
    weight_type=QuantType.QInt8,
    per_channel=True,
)
print("动态量化完成")
```

预期输出 `动态量化完成`，体积也在 2.7MB 左右，但卷积层未被量化，实测延迟通常只比 FP32 快 10–20%。

### 11.3.5 精度 / 延迟 / 体积三方对比表模板

先准备一段测精度与延迟的脚本：FP32 ONNX 与 INT8 ONNX 在同一个验证集上跑，输出 top-1 与 P50/P95 延迟。

```python
# compare_fp32_int8.py —— 同一验证集上对比 FP32 与 INT8 的精度与延迟
# 执行位置：PowerShell
import time

import numpy as np
import onnxruntime as ort
import torch
from torchvision import datasets, transforms

FP32_PATH = "mobilenetv3_small_fp32.onnx"
INT8_PATH = "mobilenetv3_small_int8.onnx"
N_IMAGES = 500
WARMUP = 20


def make_session(path, use_cuda=True):
    providers = (["CUDAExecutionProvider", "CPUExecutionProvider"]
                 if use_cuda else ["CPUExecutionProvider"])
    opts = ort.SessionOptions()
    opts.graph_optimization_level = ort.GraphOptimizationLevel.ORT_ENABLE_ALL
    opts.intra_op_num_threads = 4
    return ort.InferenceSession(path, sess_options=opts, providers=providers)


def load_val(n):
    tf = transforms.Compose([
        transforms.Resize(256),
        transforms.CenterCrop(224),
        transforms.ToTensor(),
        transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
    ])
    ds = datasets.ImageNet(r"C:\Users\<用户名>\datasets\imagenet", split="val", transform=tf)
    xs, ys = [], []
    for i in range(n):
        x, y = ds[i]
        xs.append(x.numpy())
        ys.append(y)
    return np.stack(xs).astype(np.float32), np.asarray(ys)


def evaluate(sess, xs, ys):
    input_name = sess.get_inputs()[0].name
    correct = 0
    lat = []
    for i in range(len(xs)):
        x = xs[i:i + 1]
        if i >= WARMUP:
            t0 = time.perf_counter()
        out = sess.run(None, {input_name: x})[0]
        if i >= WARMUP:
            lat.append((time.perf_counter() - t0) * 1000)
        if int(out.argmax(axis=1)[0]) == int(ys[i]):
            correct += 1
    top1 = correct / len(xs)
    lat = np.asarray(lat)
    return top1, float(np.percentile(lat, 50)), float(np.percentile(lat, 95))


def main():
    xs, ys = load_val(N_IMAGES)
    for tag, path in [("FP32", FP32_PATH), ("INT8", INT8_PATH)]:
        sess = make_session(path)
        top1, p50, p95 = evaluate(sess, xs, ys)
        import os
        print("%s  top1=%.4f  P50=%.2fms  P95=%.2fms  体积=%.2fMB"
              % (tag, top1, p50, p95, os.path.getsize(path) / 1024 ** 2))


if __name__ == "__main__":
    main()
```

预期输出两行，形如 `FP32  top1=0.7820  P50=6.80ms  P95=8.10ms  体积=10.24MB` 与 `INT8  top1=0.7760  P50=3.10ms  P95=3.80ms  体积=2.68MB`。INT8 掉点 0.5% 以内、延迟降低到 1/2 左右，属于典型结果。

把结果填进下面这张表（模板，`填入` 处换成你的实测值）：

| 模型 | 精度格式 | 后端/Provider | Top-1 | P50 延迟(ms) | P95 延迟(ms) | 体积(MB) | 显存峰值(MB) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| mobilenetv3_small | FP32 | CUDAExecutionProvider | 填入 | 填入 | 填入 | 10.24 | 填入 |
| mobilenetv3_small | INT8 PTQ | CUDAExecutionProvider | 填入 | 填入 | 填入 | 2.68 | 填入 |
| mobilenetv3_small | INT8 PTQ | CPUExecutionProvider | 填入 | 填入 | 填入 | 2.68 | 0 |
| mobilenetv3_small | INT8 QAT | CUDAExecutionProvider | 填入 | 填入 | 填入 | 2.70 | 填入 |

## 11.4 LLM GGUF 量化

### 11.4.1 为什么 LLM 端侧走 GGUF

GGUF（GPT-Generated Unified Format）是 `llama.cpp` 的模型容器格式，把权重、分词器、对话模板、超参全部打包进一个文件。它的优势是：**一个文件即可加载**、**CPU/GPU 混合推理**、**量化档位齐全（Q2 到 Q8 与 IQ 系列）**、**内存映射（mmap）加载快且省内存**。8G 显存的现实是：7B FP16 需要 14GB，根本装不下；Q4_K_M 约 4.4GB 权重 + 1–2GB KV Cache ≈ 6GB，刚好可用，实测约 30–50 tok/s（简报口径）。

### 11.4.2 安装方式一：预编译（推荐先用这条跑通）

Windows 原生最省事的做法是下载官方预编译包，或装 Python 侧的 `llama-cpp-python` 预编译 wheel。

```powershell

.\.venv-llamacpp\Scripts\Activate.ps1
uv pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124
python -c "from llama_cpp import Llama; print('llama-cpp-python 可用')"
```

预期输出 `llama-cpp-python 可用`。这条路的优点是 3 分钟装完；缺点是版本可能滞后于上游 `llama.cpp`，新量化类型（如 IQ 系列的新变种）未必支持。

第二种预编译方式是直接下载 `llama.cpp` 的官方 release 压缩包（含 `llama-cli.exe` / `llama-server.exe` / `llama-quantize.exe`），解压后把 `bin` 目录加进 `PATH`。

上表 tok/s 是「参考量级」，不是绝对真理：受量化档位、上下文长度、是否 `-ngl 99` 全量卸载、驱动版本、电源模式共同影响。你自己的报告里必须重新测。

## 11.5 llama.cpp 推理与压测

### 11.5.1 `llama-cli` 关键参数逐条解释

```powershell
# 在 PowerShell 中执行：单轮对话推理
& "C:\Users\<用户名>\tools\llama\llama-cli.exe" `
  -m C:\Users\<用户名>\models\qwen2.5-7b-Q4_K_M.gguf `
  -ngl 99 -c 4096 -b 512 -t 8 `
  --cache-type-k q8_0 --cache-type-v q8_0 `
  -cnv -p "用三句话解释什么是 KV Cache。" `
  -n 256 --temp 0.7 --top-p 0.9 -no-cnv
```

预期输出：先打印模型加载信息（`load_tensors: CUDA0 model buffer size = ...`），然后逐 token 流式打印回答，末尾给出 `llama_perf_context_print: eval time = ...` 统计块。

| 参数 | 含义 | 该怎么设 | 设错的后果 |
| --- | --- | --- | --- |
| `-m` | 模型文件路径 | 指向 `.gguf` | 路径含空格要加引号，否则报 `failed to load model` |
| `-ngl N` | 卸载到 GPU 的层数 | 7B Q4_K_M 用 `99`（全部）；14B 从 99 往下调 | 设 0 全走 CPU，tok/s 掉到 3–6；设太高直接 OOM |
| `-c N` | 上下文长度（prompt + 生成） | 4096 起步；长文用 8192 | 设 32768 会让 KV Cache 撑爆 8G；设太小会截断 prompt |
| `-b N` | 逻辑批大小（一次处理的 token 数） | 512（prefill 吞吐好） | 设 2048 会浪费显存且可能变慢 |
| `-ub N` | 物理批大小（micro-batch） | 默认 512，OOM 时降到 128 | 与 `-b` 冲突时以 `-ub` 为准 |
| `-t N` | CPU 线程数 | 物理核数（8 核 CPU 就写 8） | 超过物理核数会因为抢占变慢 |
| `--cache-type-k` / `--cache-type-v` | KV Cache 数值类型 | `q8_0`（KV 显存约减半）或 `f16` | 都设 `q8_0` 后长上下文更稳，但精度略降 |
| `--mlock` | 锁定内存，禁止换页到磁盘 | 内存 ≥16GB 且模型 ≤5GB 时可用 | 内存不足时进程被系统杀掉 |
| `-n` | 最多生成 token 数 | 压测固定 128 或 256 | 不固定则 tok/s 不可比 |
| `-p` | 提示词 | 压测用固定长度 prompt | 长度变化会让 TTFT 不可比 |
| `-cnv` | 进对话模式 | 手动聊天时用 | 脚本化压测不要用，会等键盘输入 |
| `-fa` | 开启 Flash Attention | Ada 架构建议开 | 老版本不支持某些量化组合时报错 |

:::tip KV Cache 量化是 8G 的救命参数
简报口径：7B Q4_K_M 权重约 4.4GB + KV 1–2GB ≈ 6GB；加 `--cache-type-k q8_0 --cache-type-v q8_0` 可把 KV 砍半。在 8192 上下文下这个差别的实际意义是「能跑」与「OOM」。
:::

### 11.5.3 完整压测脚本

下面这个脚本用 Python 客户端对 `llama-server` 做流式压测，逐 token 计时，统计 TTFT/TPOT/吞吐/P95。执行位置：PowerShell（另开一个窗口，服务保持运行）。

```python
# bench_llamacpp.py —— 对 llama-server 做流式压测，统计 TTFT / TPOT / 吞吐
# 执行位置：PowerShell（服务已在 127.0.0.1:8080 运行）
import argparse
import json
import statistics
import time

import numpy as np
import requests


def one_request(url, prompt, n_predict, timeout=600):
    """发一次流式请求，返回 (ttft_ms, tpot_ms, e2e_ms, n_tokens, first_text)。"""
    payload = {
        "prompt": prompt,
        "n_predict": n_predict,
        "temperature": 0.0,      # 压测要确定性输出
        "top_k": 1,
        "stream": True,
        "cache_prompt": False,   # 每次都是冷启动 prefill，TTFT 才可比
    }
    t0 = time.perf_counter()
    ttft = None
    n_tok = 0
    last = t0
    first_text = ""
    with requests.post(url, json=payload, stream=True, timeout=timeout) as resp:
        resp.raise_for_status()
        for raw in resp.iter_lines(decode_unicode=True):
            if not raw:
                continue
            if raw.startswith("data: "):
                raw = raw[6:]
            try:
                obj = json.loads(raw)
            except json.JSONDecodeError:
                continue
            piece = obj.get("content", "")
            if piece:
                now = time.perf_counter()
                if ttft is None:
                    ttft = (now - t0) * 1000
                    first_text = piece
                n_tok += 1
                last = now
            if obj.get("stop"):
                break
    e2e = (last - t0) * 1000
    if ttft is None or n_tok < 2:
        raise RuntimeError("没有拿到足够 token，检查服务是否正常")
    tpot = (last - t0) * 1000 / (n_tok - 1) - ttft / max(n_tok - 1, 1)
    return ttft, max(tpot, 0.0), e2e, n_tok, first_text


def make_prompt(target_tokens):
    """构造近似固定长度的 prompt：中文 1 字约 1 token，英文 1 词约 1.3 token。"""
    unit = "请结合上下文逐步推理并给出结论，不要省略任何中间步骤。"
    reps = max(1, target_tokens // len(unit))
    return unit * reps


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--url", default="http://127.0.0.1:8080/completion")
    ap.add_argument("--prompt-tokens", type=int, default=512)
    ap.add_argument("--n-predict", type=int, default=128)
    ap.add_argument("--repeat", type=int, default=20)
    ap.add_argument("--warmup", type=int, default=3)
    args = ap.parse_args()

    prompt = make_prompt(args.prompt_tokens)
    print("prompt 字符数 =", len(prompt))

    for i in range(args.warmup):
        one_request(args.url, prompt, 8)
        print("预热 %d/%d 完成" % (i + 1, args.warmup))

    ttfts, tpots, e2es, tps = [], [], [], []
    t_start = time.perf_counter()
    for i in range(args.repeat):
        ttft, tpot, e2e, n_tok, _ = one_request(args.url, prompt, args.n_predict)
        ttfts.append(ttft)
        tpots.append(tpot)
        e2es.append(e2e)
        tps.append(n_tok / (e2e / 1000.0))
        print("第 %2d 次: TTFT=%7.1fms TPOT=%6.2fms 端到端=%7.1fms tok/s=%5.2f"
              % (i + 1, ttft, tpot, e2e, tps[-1]))
    wall = time.perf_counter() - t_start

    def line(name, arr, unit="ms"):
        a = np.asarray(arr)
        print("%-8s P50=%8.1f P90=%8.1f P95=%8.1f P99=%8.1f 均值=%8.1f 标准差=%7.1f %s"
              % (name, np.percentile(a, 50), np.percentile(a, 90), np.percentile(a, 95),
                 np.percentile(a, 99), a.mean(), statistics.pstdev(a.tolist()), unit))

    print("---- 汇总（单请求串行，repeat=%d） ----" % args.repeat)
    line("TTFT", ttfts)
    line("TPOT", tpots)
    line("端到端", e2es)
    line("tok/s", tps, "tok/s")
    print("总耗时 %.1fs，平均 %d token/请求" % (wall, args.n_predict))


if __name__ == "__main__":
    main()
```

执行命令与预期输出：

```powershell

```

预期输出末尾形如：

```text

TPOT     P50=    24.8 P90=    26.9 P95=    27.5 P99=    28.1 均值=    25.1 标准差=    1.2 ms
端到端   P50=  3560.1 P90=  3840.2 P95=  3920.7 P99=  3990.4 均值=  3601.8 标准差=  112.6 ms
tok/s    P50=    40.3 P90=    37.2 P95=    36.4 P99=    35.8 均值=    39.8 标准差=    1.9 tok/s
```

### 11.6.3 OpenAI 兼容端点调用

Ollama 默认在 `http://127.0.0.1:11434` 提供 OpenAI 兼容接口（`/v1/chat/completions`）与原生接口（`/api/chat`）。这样你后面写的 FastAPI 服务可以随时在「本地 Ollama」与「云 API」之间切换。

```python
# ollama_client.py —— 用 OpenAI SDK 调本地 Ollama，附带流式与计时
# 执行位置：PowerShell
import time

from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:11434/v1", api_key="ollama")  # api_key 随便填


def stream_once(prompt):
    t0 = time.perf_counter()
    ttft = None
    n = 0
    buf = []
    stream = client.chat.completions.create(
        model="qwen2.5:7b-instruct-q4_K_M",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.2,
        max_tokens=256,
        stream=True,
    )
    for chunk in stream:
        delta = chunk.choices[0].delta.content or ""
        if delta:
            if ttft is None:
                ttft = (time.perf_counter() - t0) * 1000
            n += 1
            buf.append(delta)
    e2e = (time.perf_counter() - t0) * 1000
    tpot = (e2e - ttft) / max(n - 1, 1)
    print("TTFT=%.1fms TPOT=%.2fms 端到端=%.1fms tokens=%d" % (ttft, tpot, e2e, n))
    print("回答：", "".join(buf)[:120])


if __name__ == "__main__":
    stream_once("用三句话解释 KV Cache 为什么占显存。")
```

预期输出形如 `TTFT=380.5ms TPOT=26.10ms 端到端=6980.2ms tokens=254`。注意 Ollama 的 TTFT 通常比裸 `llama-server` 略大，因为多了一层 HTTP 与模板处理。

| `llama3.1:8b-instruct-q4_K_M` | 4.9GB | 可跑 | 6.0–7.0GB | 8B 比 7B 更吃显存 |

:::warn 显存占用不等于文件体积
Ollama 的 `ollama ps` 里显示的 SIZE 包含权重 + KV Cache + 计算缓冲。文件 4.4GB 的模型在 4096 上下文下常驻 6GB 左右。判断「能不能跑」要看这个数字，不是文件大小。
:::

## 11.7 ONNX Runtime 部署

### 11.7.1 导出参数：opset 与动态轴

`opset_version` 选多少？规律是：**能用 17 就用 17**（PyTorch 2.6 默认走新导出器，算子覆盖最全）；需要 TensorRT 8.x 老版本兼容时降到 13–16；需要 `LayerNormalization`、`RMSNormalization` 等新算子时用 18–20。

动态轴的取舍见 11.3.2。这里补一份「静态形状导出」的代码，量化与 benchmark 用这份：

```python
    model, dummy, "mobilenetv3_small_static.onnx",
    input_names=["input"], output_names=["logits"],
    opset_version=17, do_constant_folding=True,
```

预期输出 `静态导出完成`，文件体积与动态版一致。

### 11.7.2 图优化级别

| 级别 | 枚举值 | 做了什么 | 何时用 |
| --- | --- | --- | --- |
| 禁用 | `ORT_DISABLE_ALL` | 不做任何融合 | 调试数值差异时 |
| 基础 | `ORT_ENABLE_BASIC` | 常量折叠、冗余节点消除 | 快速验证 |
| 扩展 | `ORT_ENABLE_EXTENDED` | 加算子融合（Conv+BN+ReLU） | 一般够用 |
| 全部 | `ORT_ENABLE_ALL` | 加布局优化（NCHW→NHWC 等） | **默认选择** |

`ORT_ENABLE_ALL` 会把 Conv+BN+ReLU 融合成一个节点，在 CUDA 上通常再快 10–25%。

### 11.7.3 Providers 选择与回退

优先级列表决定谁能接管算子：`CUDAExecutionProvider` → `TensorrtExecutionProvider` → `CPUExecutionProvider`。**列表里没被接管的算子会自动回退到 CPU**，这是「跑了但很慢」的常见原因。检查方式是把 `session.get_providers()` 的输出贴进报告，并用 `onnxruntime` 的 profiling 看哪些节点跑在 CPU 上。

```python
# ort_providers.py —— 查看实际生效的 provider 与节点分配
# 执行位置：PowerShell
import onnxruntime as ort

print("可用 provider：", ort.get_available_providers())

sess = ort.InferenceSession(
    "mobilenetv3_small_static.onnx",
    providers=["CUDAExecutionProvider", "CPUExecutionProvider"],
)
print("生效 provider：", sess.get_providers())
for node in sess.get_inputs():
    print("输入：", node.name, node.shape, node.type)
```

预期输出形如 `生效 provider： ['CUDAExecutionProvider', 'CPUExecutionProvider']`。

### 11.7.4 CUDA Provider 选项与线程数

```python
# ort_session_opts.py —— 完整的 SessionOptions 与 CUDA provider 选项
# 执行位置：PowerShell
import onnxruntime as ort

opts = ort.SessionOptions()
opts.graph_optimization_level = ort.GraphOptimizationLevel.ORT_ENABLE_ALL
opts.intra_op_num_threads = 4      # 单个算子内部的并行线程（CPU 上影响大）
opts.inter_op_num_threads = 2      # 算子之间的并行度
opts.execution_mode = ort.ExecutionMode.ORT_SEQUENTIAL
opts.enable_mem_pattern = True     # 复用显存缓冲，减少碎片
opts.enable_cpu_mem_arena = True
opts.log_severity_level = 3        # 0=verbose 3=warning

cuda_options = {
    "device_id": 0,
    "arena_extend_strategy": "kSameAsRequested",   # 显存按需增长，8G 上更友好
    "gpu_mem_limit": 6 * 1024 ** 3,                # 硬上限 6GB，超了报错而不是拖垮系统
    "cudnn_conv_algo_search": "HEURISTIC",         # 8G 上别用 EXHAUSTIVE，太吃显存
    "do_copy_in_default_stream": True,
}

sess = ort.InferenceSession(
    "mobilenetv3_small_static.onnx",
    sess_options=opts,
    providers=[("CUDAExecutionProvider", cuda_options), "CPUExecutionProvider"],
)
print("会话就绪：", sess.get_providers())
```

预期输出 `会话就绪： ['CUDAExecutionProvider', 'CPUExecutionProvider']`。

:::tip cudnn_conv_algo_search 的坑
`EXHAUSTIVE` 会为每个卷积层试遍所有算法以找最快的，第一次推理可能耗时数十秒且显存峰值暴涨，在 8G 上极易 OOM。用 `HEURISTIC`；只有在服务稳定、输入形状固定、且你已经把最优算法结果缓存（`enable_mem_pattern` + `ORT` 的 tuning cache）时才考虑 `EXHAUSTIVE`。
:::

### 11.7.5 完整推理代码（含图像预处理与前后处理）

```python
# ort_infer.py —— ONNX Runtime 完整推理：读图、预处理、推理、后处理
# 执行位置：PowerShell
import numpy as np
import onnxruntime as ort
from PIL import Image

MODEL = "mobilenetv3_small_static.onnx"
MEAN = np.array([0.485, 0.456, 0.406], dtype=np.float32)
STD = np.array([0.229, 0.224, 0.225], dtype=np.float32)


def build_session(model_path=MODEL):
    opts = ort.SessionOptions()
    opts.graph_optimization_level = ort.GraphOptimizationLevel.ORT_ENABLE_ALL
    opts.intra_op_num_threads = 4
    return ort.InferenceSession(
        model_path,
        sess_options=opts,
        providers=[("CUDAExecutionProvider", {"gpu_mem_limit": 6 * 1024 ** 3}),
                   "CPUExecutionProvider"],
    )


def preprocess(image_path, size=224):
    img = Image.open(image_path).convert("RGB").resize((size, size), Image.BILINEAR)
    arr = np.asarray(img, dtype=np.float32) / 255.0
    arr = (arr - MEAN) / STD
    arr = np.transpose(arr, (2, 0, 1))[None, ...]     # (1,3,H,W)
    return np.ascontiguousarray(arr, dtype=np.float32)


def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)


def infer(sess, image_path, topk=5):
    x = preprocess(image_path)
    input_name = sess.get_inputs()[0].name
    logits = sess.run(None, {input_name: x})[0]
    probs = softmax(logits, axis=1)[0]
    idx = np.argsort(-probs)[:topk]
    return [(int(i), float(probs[i])) for i in idx]


if __name__ == "__main__":
    session = build_session()
    for i, p in infer(session, r"C:\Users\<用户名>\datasets\demo.jpg"):
        print("类别 %4d  置信度 %.4f" % (i, p))
```

预期输出形如 `类别  281  置信度 0.8123`（281 是 ImageNet 的 tabby cat）。这段代码可直接复用到 MobileNetV3 / ResNet / YOLO 分类分支。

## 11.8 TensorRT：trtexec 转换与 benchmark、架构绑定、已知坑

### 11.8.1 什么时候用 TensorRT

只有当以下三条同时满足才值得上 TensorRT：**目标机就是 NVIDIA 显卡**、**输入形状固定或范围可控**、**愿意接受 engine 与显卡架构绑定**。它的收益是相对 ONNX Runtime CUDA 再快 1.2–2 倍（FP16）或 2–4 倍（INT8）；代价是构建耗时长（7B 级模型可能 10–30 分钟）、engine 不可跨架构、量化需要校准器。

跨卡不可用是硬约束：**在 4060（sm_89）上构建的 engine 拿到 A100（sm_80）或 T4（sm_75）上直接加载失败**。所以工程上 engine 属于「构建产物」而不是「交付物」，CI 里要按目标卡分别构建。

### 11.8.2 安装

INT8 需要校准器（`--int8 --calib=<校准缓存文件>`），校准缓存的生成要用 Python API：

```python
# trt_int8_calibrator.py —— 用 Python API 做 INT8 校准并保存缓存
# 执行位置：PowerShell
import numpy as np
import tensorrt as trt

CALIB_NPY = "calib.npy"
CACHE = "calib.cache"
ONNX_PATH = "mobilenetv3_small_static.onnx"


class NumpyCalibrator(trt.IInt8EntropyCalibrator2):
    def __init__(self, data, batch_size=1, cache_file=CACHE):
        super().__init__()
        self.data = data
        self.batch_size = batch_size
        self.cache_file = cache_file
        self.index = 0
        self.device_input = None

    def get_batch_size(self):
        return self.batch_size

    def get_batch(self, names):
        if self.index + self.batch_size > len(self.data):
            return None
        import pycuda.driver as cuda
        batch = np.ascontiguousarray(self.data[self.index:self.index + self.batch_size])
        self.index += self.batch_size
        if self.device_input is None:
            self.device_input = cuda.mem_alloc(batch.nbytes)
        cuda.memcpy_htod(self.device_input, batch)
        return [int(self.device_input)]

    def read_calibration_cache(self):
        import os
        if os.path.exists(self.cache_file):
            with open(self.cache_file, "rb") as f:
                return f.read()
        return None

    def write_calibration_cache(self, cache):
        with open(self.cache_file, "wb") as f:
            f.write(cache)


def build_int8_engine():
    logger = trt.Logger(trt.Logger.WARNING)
    builder = trt.Builder(logger)
    network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
    parser = trt.OnnxParser(network, logger)
    with open(ONNX_PATH, "rb") as f:
        if not parser.parse(f.read()):
            for i in range(parser.num_errors):
                print(parser.get_error(i))
            raise SystemExit("ONNX 解析失败")
    config = builder.create_builder_config()
    config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 2 << 30)   # 2GB workspace
    config.set_flag(trt.BuilderFlag.INT8)
    config.set_flag(trt.BuilderFlag.FP16)
    calib = NumpyCalibrator(np.load(CALIB_NPY))
    config.int8_calibrator = calib
    serialized = builder.build_serialized_network(network, config)
    if serialized is None:
        raise SystemExit("engine 构建失败")
    with open("mobilenetv3_int8.engine", "wb") as f:
        f.write(serialized)
    print("INT8 engine 已保存，体积 %.2f MB" % (len(serialized) / 1024 ** 2))


if __name__ == "__main__":
    import pycuda.autoinit  # noqa: F401  必须导入以初始化 CUDA 上下文
    build_int8_engine()
```

预期输出 `INT8 engine 已保存，体积 3.10 MB`。

### 11.8.4 Windows 与 WSL2 的差异与已知坑

| 项目 | Windows 原生 | WSL2 |
| --- | --- | --- |
| 安装难度 | 需匹配 zip 包与驱动，容易踩 DLL 缺失 | `pip install tensorrt` 更顺，apt 装 CUDA 也可 |
| `trtexec` | release 包里自带 exe | 需手动加 `PATH` 或从 tar 包解压 |
| 显存可见性 | 独占 | 与 Windows 侧共享，Windows 的 Ollama 会抢显存 |
| 文件 IO | 直接读写 NTFS | 读写 `/mnt/c/...` 很慢，engine 构建建议放 `~/` |
| engine 兼容 | 同一台机器内可用 | 与 Windows 构建的 engine 不通用（版本/驱动差异） |
| 已知坑 | `cudnn_conv_algo_search` 默认策略导致首次构建显存峰值高 | WSL2 内核的 `nvidia_uvm` 未加载时 `cudaGetDeviceCount` 返回 0 |

:::warn engine 跨卡/跨版本的三个报错原文
- `[E] Error Code 3: API Usage Error ... serialized engine version mismatch` —— engine 是用别的 TensorRT 版本构建的，必须重build。
- `[E] Error Code 1: Cuda Runtime (no kernel image is available for execution on the device)` —— engine 的目标架构与当前显卡不符（典型的跨卡问题）。
- `[E] Error Code 6: ... out of memory` —— workspace 设太大或 batch 太大，先降 `--workspace` 到 1024 再试。
:::

### 11.9.1 什么时候用

### 11.9.2 CPU 推理完整代码

```python
# openvino_infer.py —— OpenVINO 读 ONNX，在 CPU/GPU 上推理并统计延迟
# 执行位置：PowerShell
import time

import numpy as np
import openvino as ov

MODEL = "mobilenetv3_small_static.onnx"


def build(model_path=MODEL, device="CPU"):
    core = ov.Core()
    print("可用设备：", core.available_devices)
    model = core.read_model(model_path)
    config = {}
    if device == "CPU":
        config = {
            "INFERENCE_NUM_THREADS": 8,      # CPU 线程数
            "PERFORMANCE_HINT": "LATENCY",   # 或 THROUGHPUT
            "NUM_STREAMS": 1,
        }
    elif device == "GPU":
        config = {"PERFORMANCE_HINT": "LATENCY", "NUM_STREAMS": 2}
    compiled = core.compile_model(model, device, config)
    return compiled


def benchmark(compiled, batch=1, iters=100, warmup=20):
    input_layer = compiled.input(0)
    x = np.random.randn(batch, 3, 224, 224).astype(np.float32)
    for _ in range(warmup):
        compiled([x])
    lat = []
    for _ in range(iters):
        t0 = time.perf_counter()
        compiled([x])
        lat.append((time.perf_counter() - t0) * 1000)
    lat = np.asarray(lat)
    print("batch=%d  P50=%.2fms  P95=%.2fms  P99=%.2fms  吞吐=%.1f FPS"
          % (batch, np.percentile(lat, 50), np.percentile(lat, 95),
             np.percentile(lat, 99), 1000.0 / np.percentile(lat, 50)))


if __name__ == "__main__":
    for dev in ["CPU", "GPU"]:
        try:
            bench = build(MODEL, dev)
            print("设备：", dev)
            benchmark(bench)
        except Exception as exc:
            print("设备 %s 不可用：%s" % (dev, exc))
```

预期输出形如：

```text
可用设备： ['CPU', 'GPU']
设备： CPU
batch=1  P50=8.42ms  P95=10.13ms  P99=11.204ms  吞吐=118.8 FPS
设备： GPU
batch=1  P50=3.95ms  P95=4.60ms  P99=5.12ms  吞吐=253.2 FPS
```

**无 GPU 场景的参考延迟**（MobileNetV3-Small，224×224，batch=1，桌面级 8 核 CPU）：P50 约 6–12ms，即 80–160 FPS。这个数字足以支撑「CPU 上也能实时」的结论，写进报告时标注 CPU 型号与线程数。

### 11.9.3 2026.1 起支持 GGUF

OpenVINO 2026.1 开始支持直接加载 GGUF 权重做 LLM 推理，这给「没有 NVIDIA 显卡但想跑 7B」提供了新路径。用法（保持你在 `llama.cpp` 侧已经转换好的 Q4_K_M 文件）：

## 11.10 端侧约束模拟：限显存、限线程、限功耗

### 11.10.1 为什么要模拟

你的开发机是 4060 + 32GB 内存，目标岗位的部署环境可能是 Jetson Orin（8GB 共享内存）、工业盒子（4 核 CPU + 4GB 内存）、手机端（6GB 内存）。**面试官会问「你怎么知道它在 4GB 的设备上也能跑」**。答案是用约束模拟先做一轮压力测试，把「最低可用配置」找出来。

### 11.10.2 限制 PyTorch 显存

```python
# limit_vram.py —— 用 per_process_memory_fraction 模拟小显存设备
# 执行位置：PowerShell
import torch

# 只允许本进程使用 GPU 总显存的 50%（8G 卡 => 4GB）
torch.cuda.set_per_process_memory_fraction(0.5, device=0)

# 关键：必须在设置之后 import / 构建模型，且不要在别处调用 empty_cache 前的预留
print("可用显存上限：%.2f GB" % (torch.cuda.get_device_properties(0).total_memory * 0.5 / 1024 ** 3))

model = torch.nn.Sequential(
    torch.nn.Conv2d(3, 64, 3, padding=1),
    torch.nn.ReLU(),
    torch.nn.Conv2d(64, 128, 3, stride=2, padding=1),
    torch.nn.ReLU(),
    torch.nn.AdaptiveAvgPool2d(1),
    torch.nn.Flatten(),
    torch.nn.Linear(128, 10),
).cuda()

try:
    x = torch.randn(64, 3, 512, 512, device="cuda")   # 故意开大，触发上限
    y = model(x)
    torch.cuda.synchronize()
    print("通过：峰值 %.2f GB" % (torch.cuda.max_memory_allocated() / 1024 ** 3))
except RuntimeError as exc:
    print("命中显存上限（预期行为）：", str(exc)[:160])
```

预期输出会是 `命中显存上限（预期行为）： CUDA out of memory. ...`，这就是模拟成功——说明一旦设备只有 4GB，这个 batch/分辨率组合就跑不动。把 batch 一路降到能通过，得到「最低可行配置」，写进报告的「端侧适配结论」。

:::warn set_per_process_memory_fraction 的两个限制
- 它只限制 PyTorch 的缓存分配器，**不限制 cuDNN / cuBLAS 的 workspace 分配**，所以实际可能略微超限。
- 必须在任何 CUDA 内存分配之前调用（通常紧跟 `import torch` 之后），否则不生效。
:::

## 11.11 服务化与压测：FastAPI + SSE

### 11.11.1 流式推理服务完整代码

SSE（Server-Sent Events）是 LLM 服务的标准流式协议。下面这份服务同时支持「本地 Ollama」与「任意 OpenAI 兼容云端」，通过环境变量切换。保存为 `app.py`。

```python
# app.py —— FastAPI + SSE 流式推理服务，支持本地 Ollama 与云端 API 切换
# 执行位置：PowerShell（uvicorn app:app --host 127.0.0.1 --port 8000）
import json
import os
import time
from typing import AsyncIterator

import httpx
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field

BACKEND = os.environ.get("BACKEND", "ollama")            # ollama | openai
OLLAMA_BASE = os.environ.get("OLLAMA_BASE", "http://127.0.0.1:11434")
OPENAI_BASE = os.environ.get("OPENAI_BASE", "https://api.deepseek.com/v1")
OPENAI_KEY = os.environ.get("OPENAI_KEY", "")
LOCAL_MODEL = os.environ.get("LOCAL_MODEL", "qwen2.5:7b-instruct-q4_K_M")
REMOTE_MODEL = os.environ.get("REMOTE_MODEL", "deepseek-chat")

app = FastAPI(title="Local LLM Gateway", version="1.0.0")


class ChatRequest(BaseModel):
    prompt: str = Field(..., min_length=1, max_length=8000)
    max_tokens: int = Field(256, ge=1, le=2048)
    temperature: float = Field(0.2, ge=0.0, le=2.0)
    system: str | None = None


class ChatResponse(BaseModel):
    text: str
    ttft_ms: float
    tpot_ms: float
    e2e_ms: float
    tokens: int
    backend: str


def sse(data: dict) -> str:
    return "data: %s\n\n" % json.dumps(data, ensure_ascii=False)


async def stream_local(req: ChatRequest) -> AsyncIterator[str]:
    messages = []
    if req.system:
        messages.append({"role": "system", "content": req.system})
    messages.append({"role": "user", "content": req.prompt})
    payload = {
        "model": LOCAL_MODEL,
        "messages": messages,
        "stream": True,
        "temperature": req.temperature,
        "max_tokens": req.max_tokens,
    }
    t0 = time.perf_counter()
    ttft = None
    n = 0
    async with httpx.AsyncClient(timeout=600) as client:
        async with client.stream("POST", OLLAMA_BASE + "/v1/chat/completions", json=payload) as resp:
            if resp.status_code != 200:
                body = await resp.aread()
                yield sse({"error": "后端返回 %d: %s" % (resp.status_code, body[:200].decode("utf-8", "ignore"))})
                return
            async for line in resp.aiter_lines():
                if not line or not line.startswith("data: "):
                    continue
                chunk = line[6:]
                if chunk.strip() == "[DONE]":
                    break
                try:
                    obj = json.loads(chunk)
                except json.JSONDecodeError:
                    continue
                delta = (obj.get("choices") or [{}])[0].get("delta", {}).get("content") or ""
                if not delta:
                    continue
                now = time.perf_counter()
                if ttft is None:
                    ttft = (now - t0) * 1000
                n += 1
                yield sse({"delta": delta, "index": n})
    e2e = (time.perf_counter() - t0) * 1000
    yield sse({"done": True, "ttft_ms": round(ttft or 0, 2),
               "tpot_ms": round(((e2e - (ttft or 0)) / max(n - 1, 1)), 2),
               "e2e_ms": round(e2e, 2), "tokens": n, "backend": "ollama"})


async def stream_remote(req: ChatRequest) -> AsyncIterator[str]:
    if not OPENAI_KEY:
        yield sse({"error": "未设置 OPENAI_KEY 环境变量"})
        return
    messages = []
    if req.system:
        messages.append({"role": "system", "content": req.system})
    messages.append({"role": "user", "content": req.prompt})
    payload = {"model": REMOTE_MODEL, "messages": messages, "stream": True,
               "temperature": req.temperature, "max_tokens": req.max_tokens}
    headers = {"Authorization": "Bearer " + OPENAI_KEY}
    t0 = time.perf_counter()
    ttft = None
    n = 0
    async with httpx.AsyncClient(timeout=600) as client:
        async with client.stream("POST", OPENAI_BASE + "/chat/completions",
                                 json=payload, headers=headers) as resp:
            if resp.status_code != 200:
                body = await resp.aread()
                yield sse({"error": "云端返回 %d: %s" % (resp.status_code, body[:200].decode("utf-8", "ignore"))})
                return
            async for line in resp.aiter_lines():
                if not line or not line.startswith("data: "):
                    continue
                chunk = line[6:]
                if chunk.strip() == "[DONE]":
                    break
                try:
                    obj = json.loads(chunk)
                except json.JSONDecodeError:
                    continue
                delta = (obj.get("choices") or [{}])[0].get("delta", {}).get("content") or ""
                if not delta:
                    continue
                now = time.perf_counter()
                if ttft is None:
                    ttft = (now - t0) * 1000
                n += 1
                yield sse({"delta": delta, "index": n})
    e2e = (time.perf_counter() - t0) * 1000
    yield sse({"done": True, "ttft_ms": round(ttft or 0, 2),
               "tpot_ms": round(((e2e - (ttft or 0)) / max(n - 1, 1)), 2),
               "e2e_ms": round(e2e, 2), "tokens": n, "backend": "openai"})


@app.get("/healthz")
async def healthz():
    ok = True
    detail = {}
    try:
        async with httpx.AsyncClient(timeout=3) as client:
            r = await client.get(OLLAMA_BASE + "/api/tags")
            detail["ollama"] = r.status_code == 200
            ok = ok and detail["ollama"]
    except Exception as exc:
        detail["ollama"] = False
        detail["ollama_error"] = str(exc)[:120]
        ok = False
    return {"status": "ok" if ok else "degraded", "backend": BACKEND, "detail": detail}


@app.post("/v1/chat/stream")
async def chat_stream(req: ChatRequest):
    gen = stream_local(req) if BACKEND == "ollama" else stream_remote(req)
    return StreamingResponse(gen, media_type="text/event-stream",
                             headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})


@app.post("/v1/chat", response_model=ChatResponse)
async def chat(req: ChatRequest):
    t0 = time.perf_counter()
    text_parts = []
    ttft = None
    n = 0
    gen = stream_local(req) if BACKEND == "ollama" else stream_remote(req)
    async for event in gen:
        payload = json.loads(event[6:].strip())
        if "error" in payload:
            raise HTTPException(status_code=502, detail=payload["error"])
        if "delta" in payload:
            if ttft is None:
                ttft = (time.perf_counter() - t0) * 1000
            text_parts.append(payload["delta"])
            n += 1
    e2e = (time.perf_counter() - t0) * 1000
    return ChatResponse(text="".join(text_parts), ttft_ms=round(ttft or 0, 2),
                        tpot_ms=round((e2e - (ttft or 0)) / max(n - 1, 1), 2),
                        e2e_ms=round(e2e, 2), tokens=n, backend=BACKEND)


if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

### 11.11.2 并发压测脚本

```python
# bench_service.py —— 对 FastAPI 服务做并发压测，统计 TTFT/TPOT/吞吐/错误率
# 执行位置：PowerShell（服务已启动）
import argparse
import asyncio
import json
import time

import aiohttp
import numpy as np


async def one(session, url, prompt, max_tokens):
    payload = {"prompt": prompt, "max_tokens": max_tokens, "temperature": 0.0}
    t0 = time.perf_counter()
    ttft = None
    n = 0
    try:
        async with session.post(url, json=payload) as resp:
            if resp.status != 200:
                return {"ok": False, "error": "HTTP %d" % resp.status}
            async for raw in resp.content:
                line = raw.decode("utf-8", "ignore").strip()
                if not line.startswith("data: "):
                    continue
                obj = json.loads(line[6:])
                if "error" in obj:
                    return {"ok": False, "error": obj["error"][:120]}
                if "delta" in obj:
                    if ttft is None:
                        ttft = (time.perf_counter() - t0) * 1000
                    n += 1
    except Exception as exc:
        return {"ok": False, "error": type(exc).__name__ + ": " + str(exc)[:100]}
    e2e = (time.perf_counter() - t0) * 1000
    return {"ok": True, "ttft": ttft or 0.0, "e2e": e2e, "tokens": n,
            "tpot": (e2e - (ttft or 0.0)) / max(n - 1, 1)}


async def run_level(url, prompt, max_tokens, concurrency, duration_s):
    """固定并发跑 duration_s 秒，返回该并发级别下的所有样本。"""
    results = []
    stop_at = time.perf_counter() + duration_s
    conn = aiohttp.TCPConnector(limit=concurrency * 2)
    timeout = aiohttp.ClientTimeout(total=900)
    async with aiohttp.ClientSession(connector=conn, timeout=timeout) as session:
        async def worker():
            while time.perf_counter() < stop_at:
                results.append(await one(session, url, prompt, max_tokens))
        await asyncio.gather(*[worker() for _ in range(concurrency)])
    return results


def report(level, results):
    ok = [r for r in results if r["ok"]]
    bad = [r for r in results if not r["ok"]]
    if not ok:
        print("并发 %d：全部失败，示例错误：%s" % (level, bad[0]["error"] if bad else "无"))
        return None
    ttft = np.array([r["ttft"] for r in ok])
    tpot = np.array([r["tpot"] for r in ok])
    e2e = np.array([r["e2e"] for r in ok])
    toks = sum(r["tokens"] for r in ok)
    span = max(r["e2e"] for r in ok) / 1000.0
    row = {
        "并发": level,
        "请求数": len(results),
        "成功率": "%.1f%%" % (100.0 * len(ok) / len(results)),
        "TTFT_P50": round(float(np.percentile(ttft, 50)), 1),
        "TTFT_P95": round(float(np.percentile(ttft, 95)), 1),
        "TPOT_P50": round(float(np.percentile(tpot, 50)), 2),
        "端到端_P95": round(float(np.percentile(e2e, 95)), 1),
        "系统吞吐(tok/s)": round(toks / span, 1),
        "错误示例": (bad[0]["error"][:40] if bad else "-"),
    }
    print(row)
    return row


async def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--url", default="http://127.0.0.1:8000/v1/chat/stream")
    ap.add_argument("--levels", default="1,2,4,8")
    ap.add_argument("--duration", type=float, default=30.0)
    ap.add_argument("--max-tokens", type=int, default=128)
    ap.add_argument("--prompt", default="请解释什么是 KV Cache，并给出一个数值例子。")
    args = ap.parse_args()

    rows = []
    for level in [int(x) for x in args.levels.split(",")]:
        res = await run_level(args.url, args.prompt, args.max_tokens, level, args.duration)
        row = report(level, res)
        if row:
            rows.append(row)
        await asyncio.sleep(3)     # 让后端卸载上一轮的缓存，避免相互污染

    print("---- Markdown 汇总 ----")
    if rows:
        cols = list(rows[0].keys())
        print("| " + " | ".join(cols) + " |")
        print("| " + " | ".join(["---"] * len(cols)) + " |")
        for r in rows:
            print("| " + " | ".join(str(r[c]) for c in cols) + " |")


if __name__ == "__main__":
    asyncio.run(main())
```

## 11.12 端云级联：小模型先判 + 大模型兜底

### 11.12.1 策略设计

端云级联（cascade）的核心是：**大部分请求用本地小模型解决（零成本、低延迟），只把「本地没把握」的请求送给云端大模型（贵、慢但质量高）**。三条判定依据：

1. **难度分类器**：用 0.5B 模型或轻量规则先判「这个请求本地能不能搞定」。
2. **置信度阈值**：本地生成时统计 token 的平均 logprob，低于阈值就升级。
3. **自检（self-check）**：让本地模型对自己的答案打分，低于阈值就升级。

工程上最稳的是「难度分类器 + 自检」组合，因为 logprob 在量化模型上不可靠（4bit 权重的 logprob 已经失真）。

### 11.12.2 完整路由代码

```python
# cascade_router.py —— 端云级联路由：本地小模型先判，云端大模型兜底
# 执行位置：PowerShell；需要设置 OPENAI_KEY 才能走云端
import json
import os
import re
import time
from dataclasses import dataclass, field

from openai import OpenAI

LOCAL = OpenAI(base_url="http://127.0.0.1:11434/v1", api_key="ollama")
REMOTE = OpenAI(base_url=os.environ.get("OPENAI_BASE", "https://api.deepseek.com/v1"),
                api_key=os.environ.get("OPENAI_KEY", "none"))

LOCAL_MODEL = "qwen2.5:1.5b-instruct-q4_K_M"     # 端侧小模型
REMOTE_MODEL = "deepseek-chat"                    # 云端大模型


@dataclass
class RouteResult:
    answer: str
    route: str                    # local | remote
    reason: str
    local_ms: float = 0.0
    remote_ms: float = 0.0
    local_tokens: int = 0
    remote_tokens: int = 0
    confidence: float = 0.0
    extras: dict = field(default_factory=dict)


# ---------- 判定规则 ----------

HARD_PATTERNS = [
    r"证明", r"推导", r"数学归纳", r"复杂度分析", r"形式化",
    r"写一段.{0,10}(完整|生产|可运行)", r"重构", r"架构设计",
    r"比较.{0,6}种方案", r"权衡",
]
LONG_INPUT_TOKENS = 400          # 输入超过这个长度就交给云端（本地上下文有限）


def rule_score(prompt):
    """规则打分：返回 0-1 的「难度」分数，越高越该走云端。"""
    score = 0.0
    for pat in HARD_PATTERNS:
        if re.search(pat, prompt):
            score += 0.35
    if len(prompt) > 300:
        score += 0.15
    if len(prompt) > LONG_INPUT_TOKENS:
        score += 0.25
    if re.search(r"(最新|2027|2028|2029)", prompt):
        score += 0.20     # 本地小模型知识截止早
    return min(score, 1.0)


def local_answer(prompt, max_tokens=256):
    t0 = time.perf_counter()
    resp = LOCAL.chat.completions.create(
        model=LOCAL_MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.2, max_tokens=max_tokens,
    )
    ms = (time.perf_counter() - t0) * 1000
    text = resp.choices[0].message.content or ""
    n = resp.usage.completion_tokens if resp.usage else len(text)
    return text, ms, n


def self_check(prompt, answer):
    """让本地小模型自评：返回 0-1 的置信度，低于阈值就升级到云端。"""
    judge = (
        "请评估下面这个回答是否完整、准确、无编造。只输出一个 0 到 1 之间的小数，"
        "1 表示完全可信，0 表示明显不可信。不要输出其他内容。\n"
        "问题：%s\n回答：%s\n评分：" % (prompt, answer)
    )
    try:
        resp = LOCAL.chat.completions.create(
            model=LOCAL_MODEL,
            messages=[{"role": "user", "content": judge}],
            temperature=0.0, max_tokens=8,
        )
        raw = (resp.choices[0].message.content or "").strip()
        m = re.search(r"(0\.\d+|1\.0|0|1)", raw)
        return float(m.group(1)) if m else 0.5
    except Exception:
        return 0.5


def remote_answer(prompt, max_tokens=512):
    if not os.environ.get("OPENAI_KEY"):
        return "[未设置 OPENAI_KEY，云端不可用]", 0.0, 0
    t0 = time.perf_counter()
    resp = REMOTE.chat.completions.create(
        model=REMOTE_MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.2, max_tokens=max_tokens,
    )
    ms = (time.perf_counter() - t0) * 1000
    text = resp.choices[0].message.content or ""
    n = resp.usage.completion_tokens if resp.usage else len(text)
    return text, ms, n


def route(prompt, hard_threshold=0.6, conf_threshold=0.65):
    """级联入口：先规则打分，再本地作答 + 自检，不达标则升级云端。"""
    score = rule_score(prompt)
    result = RouteResult(answer="", route="local", reason="", confidence=0.0)
    result.extras["rule_score"] = score

    if score >= hard_threshold:
        result.route = "remote"
        result.reason = "规则判定为难题（score=%.2f）" % score
        result.answer, result.remote_ms, result.remote_tokens = remote_answer(prompt)
        return result

    local_text, local_ms, local_tok = local_answer(prompt)
    conf = self_check(prompt, local_text)
    result.local_ms = local_ms
    result.local_tokens = local_tok
    result.confidence = conf

    if conf >= conf_threshold:
        result.route = "local"
        result.reason = "本地自检通过（conf=%.2f, score=%.2f）" % (conf, score)
        result.answer = local_text
        return result

    result.route = "remote"
    result.reason = "自检不达标（conf=%.2f < %.2f）" % (conf, conf_threshold)
    result.answer, result.remote_ms, result.remote_tokens = remote_answer(prompt)
    return result


if __name__ == "__main__":
    cases = [
        "把这句英文翻译成中文：The model is quantized to 4 bits.",
        "请证明：任意 a>0，a + 1/a >= 2，并给出取等条件。",
        "写一段完整的、可直接投入生产的 FastAPI 推理服务代码，包含鉴权、限流、指标。",
        "今天是几号？",
    ]
    for c in cases:
        r = route(c)
        print(json.dumps({
            "问题": c[:28],
            "路由": r.route,
            "原因": r.reason,
            "本地耗时ms": round(r.local_ms, 1),
            "云端耗时ms": round(r.remote_ms, 1),
            "本地tokens": r.local_tokens,
            "云端tokens": r.remote_tokens,
            "置信度": r.confidence,
            "规则分": r.extras.get("rule_score"),

```

### 11.12.3 成本节省公式与算例

**公式**：

```text
云调用比例 r = 走云端的请求数 / 总请求数
单请求平均成本 C_avg = r × (C_in × T_in_cloud + C_out × T_out_cloud) + (1 - r) × C_local_电费
月成本 = Q × C_avg                （Q = 月请求数）
节省率 = 1 - C_avg / C_baseline   （C_baseline = 全部走云端的单请求成本）
```

其中 `C_local_电费` = 本地推理每秒功耗（W）× 单请求耗时（s）÷ 3.6e6 × 电价（元/kWh）。以 60W、3 秒、0.6 元/kWh 计算：60 × 3 ÷ 3.6e6 × 0.6 ≈ 0.00003 元，可忽略。

**算例**（写进简历前先算一遍你自己的数）：

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 月请求数 Q | 30,000 | 假设每天 1000 次 |
| 输入 token（平均） | 400 | prompt |
| 输出 token（平均） | 300 | 回答 |
| 云端输入价 C_in | 0.001 元/1k token | 按你实际用的 API 价格替换 |
| 云端输出价 C_out | 0.002 元/1k token | 同上 |
| 走云比例 r（基线） | 1.00 | 全部走云 |
| 走云比例 r（级联） | 0.22 | 实测 22% 需要升级 |
| 单请求云成本 | 0.4×0.001 + 0.3×0.002 = 0.001 元 | 400/1000×0.001 + 300/1000×0.002 |
| 基线月成本 | 30000 × 0.001 = 30.0 元 | — |
| 级联月成本 | 30000 × 0.22 × 0.001 + 0.9 ≈ 6.6 + 0.9 = 7.5 元 | 0.9 元为本地电费 |
| 节省率 | 1 - 7.5/30.0 = 75.0% | — |
| 延迟代价 | 本地命中 P95 1.2s；升级请求 P95 6.5s | 报告里必须给出这个权衡 |

:::ok 简历里怎么写才可信
不要写「节省 90% 成本」。要写：**「设计端云级联路由（规则打分 + 自检置信度），在 1,000 条真实 query 上使云端调用占比从 100% 降到 22%，按当月 API 单价折算月成本从 30 元降至 7.5 元（-75%），本地命中请求 P95 延迟 1.2s」**。数字要有样本量与单价依据，否则面试官一句「你怎么算的」就露怯。
:::

### 11.15.2 十个必问问题与答题要点

1. **「INT8 量化后精度掉了多少？为什么会掉？」**
   要点：给具体数字（Top-1 -0.6pp）+ 说明掉点来自舍入误差、离群值拖累 per-tensor scale、校准集分布偏差、逐层误差累积；再补一句「改用 per-channel 与 Entropy 校准后从 -2.1pp 收敛到 -0.6pp」，这能证明你是调过的不是碰巧。

2. **「PTQ 和 QAT 怎么选？QAT 的代价是什么？」**
   要点：PTQ 分钟级、无需训练管线；QAT 需要完整训练 + 伪量化节点 + STE，精度更好。判据是「PTQ 掉点是否超过业务阈值（通常 1–2pp）」。LLM 做 INT4 时业界普遍用 PTQ + 分组 scale，因为 QAT 成本过高。

3. **「对称量化和非对称量化分别用在哪？zero point 是什么？」**
   要点：权重用对称（分布近似零均值、实现快），激活用非对称（ReLU/SiLU 后非负，能利用满 0–255）。zero point 是把浮点 0 映射到整数域的偏移量，非对称才有。

4. **「per-channel 为什么比 per-tensor 好？代价是什么？」**
   要点：每输出通道一个 scale，避免一个通道的极端值撑大全局 scale。代价是 scale 存储与 kernel 复杂度略增（可忽略），激活无法 per-channel（运行时才知道分布）。

5. **「GGUF 的 Q4_K_M 和 Q4_0 有什么区别？为什么 K 系列更准？」**
   要点：K-quant 是混合精度 + 分组 + 分层（super-block 与 sub-block 两级 scale/min）方案，对不同张量用不同位宽；Q4_0 是简单分块。同体积下 K 系列精度更好，解包开销略高。

6. **「你的 tok/s 是怎么测的？为什么不是绝对真理？」**
   要点：给口径（prompt 512 / 生成 128 / `-ngl 99` / KV q8_0 / 3 次预热 + 20 次取 P50 / 插电高性能），再列误差源（驱动、上下文、热降频、后台占用、采样参数）。

7. **「TTFT 和 TPOT 分别受什么影响？怎么优化？」**
   要点：TTFT 主要受 prefill 计算与 prompt 长度影响 → 优化手段是 prompt 缓存（`cache_prompt`）、批处理、更小的量化位宽；TPOT 主要受显存带宽限制（decode 是 memory-bound）→ 优化手段是 KV Cache 量化、减少卸载层数、Flash Attention。

8. **「TensorRT 的 engine 为什么不给别的机器用？」**
   要点：engine 是按目标 GPU 架构（sm_89）、TensorRT 版本、驱动版本编译的，包含为特定 SM 数量与寄存器文件调优的 kernel 选择。跨卡会报 `no kernel image is available`。所以 engine 是构建产物，部署时要按目标卡构建（CI 里做）。

9. **「8G 显存怎么塞下 7B 模型？显存都花在哪？」**
   要点：Q4_K_M 权重 4.4GB + KV Cache（4096 上下文约 1–2GB，`q8_0` 后减半）+ 计算缓冲 0.3–0.8GB ≈ 5.6–6.6GB。要减就减 KV（量化、缩上下文）与卸载层数。要能背出简报的 KV 公式：`2 × 2 字节 × KV 头数 × 头维 × 层数 × 序列长 × batch`。

10. **「本地模型和云端 API 怎么选？你的级联路由怎么设计？」**
    要点：按「延迟敏感度 / 数据合规 / 成本 / 质量要求」四维判断。级联设计讲三件事：难度分类器（规则或小模型）、置信度阈值（自检或 logprob）、兜底策略（云端 + 失败重试 + 降级文案）。最后给实测的走云比例与成本节省数字。
