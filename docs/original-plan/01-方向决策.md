# 第1章 方向决策：四个方向全景对比与推荐组合

方向选错的代价是 6 个月。这一章用 20 分钟帮你把方向定下来，之后第 5、6 章的 24 周计划就是按这一章的组合设计的。

## 1.1 四个方向各自在解决什么问题

| 方向 | 一句话定位 | 典型岗位 | 核心问题 |
| --- | --- | --- | --- |
| ① AIOps 智能运维 | 用算法与大模型让系统自己发现故障、定位根因、自动止损 | 智能运维算法工程师、AIOps 算法工程师、SRE 可观测性工程师 | 系统挂了，能不能在用户投诉前自己发现、自己定位、自己修 |
| ② 深度学习 + 边缘计算 | 把模型压到端侧设备上跑得动、跑得快、跑得稳 | 边缘 AI 算法工程师、嵌入式 AI 部署、推理优化 / 高性能计算 | 模型在云上很强，怎么让它在手机、摄像头、机器人上 30ms 出结果 |
| ③ Agent 开发 | 让大模型会用工具、有记忆、能多步完成任务 | 大模型应用开发、Agent 工程师、AI 应用后端 | 怎么让模型从「会聊天」变成「能干活」 |
| ④ NLP / LLM | 训练、微调、评测语言模型本身 | NLP 算法工程师、大模型算法工程师、LLM 训练与对齐 | 语言模型为什么有效，怎么把它调成你要的样子 |

## 1.3 关键洞察：这四个方向不在同一层

:::ok 正确的问法不是「四选一」，而是「底座选谁、主攻选谁、差异化选谁、场景选谁」
- **NLP/LLM 是技术底座**：不懂注意力、微调、评测，Agent 只能停留在复制 prompt 模板。
- **Agent 开发是技术外壳与工种**：把底座变成产品的地方，岗位最多。
- **边缘计算与推理部署是能力差异化**：决定你是「调 API 的」还是「能让模型在真实环境跑起来的」。
- **AIOps 是垂直落地场景**：把你的技术投入一个有真实数据、真实故障、竞争者少的行业问题。
:::

所以：**场景 + 技术的组合才有溢价。单独学场景会变成运维，单独学技术会变成只会调包。**

## 1.4 推荐组合（按硕士 + 单卡 8G + 需要稳妥就业的处境）

| 角色 | 方向 | 投入占比 | 为什么是它 | 可投岗位 |
| --- | --- | --- | --- | --- |
| 知识底座 | ④ NLP / LLM | 35% | Transformer、微调、评测、推理是通用货币；哪怕做 Agent，面试也会问注意力机制与 LoRA 原理 | NLP 算法、LLM 微调 |
| 就业主攻 | ③ Agent 开发 | 30% | 岗位最多、门槛最友好、对显存几乎无要求、作品可视化程度高 | 大模型应用、Agent 工程师、AI 后端 |
| 差异化 | ② 边缘部署（深度学习的工程侧） | 20% | 「会部署、会量化、会算延迟与显存」的人远少于「会调 API」的人，且完全在 4060 能力范围内 | 边缘 AI 部署、推理优化 |
| 落地场景 | ① AIOps | 15% | 提供「非玩具」的完整业务闭环（数据 → 模型 → 平台 → 告警），让简历有故事线 | AIOps 算法、SRE 智能化 |

### 一个项目三种卖法

同样的项目经历，投不同岗位时换不同的讲法：

| 投什么岗 | 主打什么 | 必须报出的数字 |
| --- | --- | --- |
| Agent / 大模型应用 | 企业知识库 Agent + 多工具编排 + 评测体系 | RAG 召回率、任务成功率、单次成本下降幅度 |
| NLP / LLM 算法 | 垂直领域 7B QLoRA 微调 + 自建评测 + 对齐 + 推理加速 | 评测集提升幅度、峰值显存、训练时长 |
| 部署 / 边缘 | 量化导出 + INT8/INT4 + 端侧延迟功耗优化 + 端云级联 | ms 级延迟、内存占用曲线、精度损失 |
| AIOps | 指标异常检测 + 日志模板挖掘 + 告警根因 + ChatOps | 误报率下降、MTTR 缩短、告警收敛率 |

## 1.6 三个非技术判断标准（比评分表更重要）

1. **看你导师和实验室在做什么。** 能用实验室的服务器、数据集、横向项目，胜过自己埋头学半年。实验室做 CV/工业质检，边缘部署就是你的天然赛道；做 NLP/知识图谱，就顺势做 LLM 微调。
2. **看你所在城市的产业结构。** 杭州/北京/深圳：Agent 与 LLM 应用、云厂商 AIOps 机会多；上海/苏州/无锡：芯片、车企、机器人；成都/西安/武汉：运营商、军工、国企数字化（AIOps、私有化 LLM）。
3. **看你能不能坚持 6 个月。** 选一个能忍受 6 个月的主线，另外两个只作为加分项。三线并行、样样稀松，是应届求职最常见的死法。

## 1.7 三种必须避免的选法

:::danger 一、四线并行
同时开四个方向的课，结果每个都停在「看过教程」。正确做法：底座 35% + 主攻 30% 是硬性配比，其余两项只在特定周集中攻。
:::

:::danger 二、只学不产
把「学完 Transformer」当目标。正确目标是「W12 交付一个从零实现的小型 GPT，在中文语料上训练并能生成通顺句子」。
:::

:::danger 三、追新框架
每周换一个 Agent 框架、每周换一个量化工具。正确做法：主线工具链一经选定（见第 4 章）半年不动，新框架只做了解。
:::

## 1.8 两周内验证你的方向（动手做，别只用想的）

选方向不要靠感觉，用下面这个两周小实验来验证。做完你就知道自己适不适合。

- [ ] **第 1 天**：把本机环境装好（第 3 章），跑通一次 `torch.cuda.is_available()` 并记录显存总量。
- [ ] **第 2–3 天**：找一份你自己领域的真实文本或数据（论文 PDF、工单记录、日志、传感器数据都行），用第 4 章的 `sentence-transformers` 做一次向量检索，回答「我能不能三行代码把它变成可检索的知识」。
- [ ] **第 4–5 天**：按第 10 章最小可用 RAG 实现（约 60 行），把这批文档做成一个能问答的小系统，记录回答正确的比例（10 个问题里对几个）。
- [ ] **第 6–7 天**：用第 9 章的 QLoRA 脚本，拿 `Qwen/Qwen3-0.6B` 在你的 100 条数据上跑通一次微调（这一版只是跑通流程，不看效果），记录耗时与峰值显存。
- [ ] **第 8–9 天**：按第 11 章把上面任一个模型导出 ONNX 或 GGUF，测出延迟与显存占用。
- [ ] **第 10 天**：写一页复盘：哪一个环节你做得最顺手、最想做第二个项目、最不想再碰。
- [ ] **第 11–14 天**：拿着这份复盘对照 1.5 的人物画像表，定下主攻方向，写进你的日历，然后进入第 5 章 W1 的正式计划。

:::tip 判断标准
- 第 4–5 天你**愿意继续加功能**（加引用、加多轮、加评测）→ 主攻 Agent。
- 第 6–7 天你**盯着 loss 曲线觉得有意思**，想知道为什么 → 底座往 NLP/LLM 算法靠。
- 第 8–9 天你**为了 5ms 反复调参不觉得烦** → 差异化走边缘部署。
- 第 2–3 天你**更关心数据本身怎么来的、故障怎么发生的** → 场景走 AIOps。
:::
