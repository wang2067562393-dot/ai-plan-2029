# 第3章 开发环境搭建：从裸机到跑通第一个训练（Windows 11 + WSL2 + 4060 8GB）

这一章解决一个非常具体的问题：把一台只装了 Windows 11 的笔记本，变成一台能跑深度学习训练、能跑 Docker 中间件、能管理模型缓存、能按周提交代码的**开发机**。你会拿到两条完整路径——Windows 原生（PowerShell）与 WSL2 Ubuntu 22.04（Bash），每条命令都写明在哪执行、预期看到什么。读完这一章，你能独立完成：驱动与 CUDA 自检、uv 虚拟环境、PyTorch cu124 安装与显存验证、WSL2 直通 CUDA、GitHub SSH 推送、VS Code 断点调试、GPU 容器、模型缓存与磁盘规划。按部就班做完大约需要 **2 个工作日（合计 8–11 小时）**，其中真正下载等待的时间可以并行穿插别的任务。做完之后，你手上会有一份 **3.10 节的 `check_env.py` 体检表**，任何一台新机器都能一次性验证全部环节。

## 3.1 装机总流程

这一节把 3.2–3.10 的全部动作压成一张两天的执行表。原则是：**先验硬件，再装软件；先 Windows，再 WSL2；先跑通，再谈优化**。不要跳步，也不要第一天就把所有东西装完——驱动和 WSL2 都需要重启，重启后验证比赶进度重要得多。

## 3.2 硬件与驱动体检

在装任何 Python 包之前，先用 20 分钟把这张卡的底细摸清。后面所有「8G 能不能跑」的判断，都建立在这一节的三个数字上：**显存总量、可用显存、功耗墙**。

### 3.2.1 `nvidia-smi` 逐字段解读

下面这条命令打印显卡型号、驱动版本、CUDA 版本、显存占用和当前运行进程，是排查一切 GPU 问题的第一现场。在 **PowerShell 执行**（WSL2 里也能执行，见 3.5.3）：

```powershell
# 在 PowerShell 执行：查看显卡与驱动概况
nvidia-smi
```

一块 RTX 4060 Laptop 8GB 的典型输出如下（你的数值会略有差异，字段含义不变）：

```text
+-----------------------------------------------------------------------------------------+
| NVIDIA-SMI 566.14                 Driver Version: 566.14         CUDA Version: 12.7     |
|-----------------------------------------+------------------------+----------------------+
| GPU  Name                  Driver-Model | Bus-Id          Disp.A | Volatile Uncorr. ECC |
| Fan  Temp   Perf          Pwr:Usage/Cap |           Memory-Usage | GPU-Util  Compute M. |
|                                         |                        |               MIG M. |
|=========================================+========================+======================|
|   0  NVIDIA GeForce RTX 4060 ...  WDDM  |   00000000:01:00.0 Off |                  N/A |
| N/A   48C    P8              5W /  80W  |     512MiB /   8188MiB |      0%      Default |
|                                         |                        |                  N/A |
+-----------------------------------------+------------------------+----------------------+
| Processes:                                                                              |
|  GPU   GI   CI        PID   Type   Process name                              GPU Memory |
|        ID   ID                                                               Usage      |
|=========================================================================================|
|    0   N/A  N/A     12345    C+G   ...s\Google\Chrome\Application\chrome.exe     N/A    |
+-----------------------------------------------------------------------------------------+
```

| 字段 | 含义 | 对你的意义 |
| --- | --- | --- |
| `NVIDIA-SMI 566.14` | 工具自身版本 | 与驱动同版本号，不重要 |
| `Driver Version: 566.14` | 已安装的 NVIDIA 驱动版本 | **决定你能装哪一版 CUDA 轮子**，必须 ≥ 525 |
| `CUDA Version: 12.7` | 该驱动**支持的最高** CUDA 运行时版本 | 这不是你已装的 CUDA，而是上限；装 cu124 轮子完全合法 |
| `GPU Name ... WDDM` | 显卡名与 Windows 显示驱动模型 | WSL2 内这里会显示 `WDDM` 或省略，属正常 |
| `Bus-Id 00000000:01:00.0` | PCIe 总线地址 | 多卡时用 `CUDA_VISIBLE_DEVICES` 挑卡 |
| `Disp.A Off` | 是否有显示器接在这张卡上 | 笔记本内屏走核显时显示 `Off`，但仍然占用显存（见 3.2.5） |
| `Fan N/A` | 风扇转速 | 笔记本常为 `N/A`，由 EC 控制 |
| `Temp 48C` | GPU 核心温度 | 训练时低于 85℃ 安全，高于 90℃ 说明散热或功耗墙有问题 |
| `Perf P8` | 性能状态，P0 最高、P8/P12 最低 | 空闲时 `P8`，训练时会跳到 `P0` |
| `Pwr:Usage/Cap 5W / 80W` | 当前功耗 / 当前功耗墙 | **4060 Laptop 常见 35–115W**，80W 说明厂商设了中间档 |
| `Memory-Usage 512MiB / 8188MiB` | 已用 / 总显存 | 空闲应低于 1GB；总显存不会等于 8192MiB |
| `GPU-Util 0%` | 计算利用率 | 训练时应长期 > 60%，否则是数据加载瓶颈 |
| `Processes` 表 | 占用显存的进程 PID 与名称 | 排查「显存被谁占了」的唯一权威来源 |

:::tip 为什么总显存不是 8192MiB
`nvidia-smi` 报的是**驱动可用显存**，不是颗粒容量。8GB 卡普遍显示 8188MiB 左右；再加上 WDDM 会预留一小块，`torch.cuda.get_device_properties(0).total_memory` 通常返回约 8.0–8.6GB 字节数，两者口径不同但都对。
:::

### 3.2.2 功耗墙与降频检查

笔记本显卡的性能上限由厂商设定的功耗墙决定，而不是芯片本身。下面这条命令列出功率相关的全部寄存器值，在 **PowerShell 执行**：

```powershell
# 在 PowerShell 执行：查看功耗墙、默认墙与物理上限
nvidia-smi -q -d POWER
```

关键输出片段与解读如下：

```text
    Power Readings
        Power Management                              : Supported
        Power Draw                                    : 6.42 W
        Power Limit                                   : 80.00 W
        Default Power Limit                           : 80.00 W
        Enforced Power Limit                          : 80.00 W
        Min Power Limit                               : 35.00 W
        Max Power Limit                               : 115.00 W
    Clocks
        Graphics                                      : 210 MHz
        SM                                            : 210 MHz
        Memory                                        : 405 MHz
        Video                                         : 555 MHz
    Clocks Event Reasons
        SW Power Cap                                  : Not Active
        HW Slowdown                                   : Not Active
        HW Thermal Slowdown                           : Not Active
        SW Thermal Slowdown                           : Not Active
```

| 字段 | 含义 | 判断标准 |
| --- | --- | --- |
| `Power Draw` | 实时功耗 | 空闲 3–10W；训练 60–115W |
| `Power Limit` | 当前生效的功耗墙 | 若等于 `Min Power Limit`，说明被锁在最低档 |
| `Default Power Limit` | 厂商默认值 | 通常 60–80W |
| `Max Power Limit` | 该机型物理最大可设值 | **若远高于 `Power Limit`，可以去 NVIDIA 控制面板或厂商工具解锁** |
| `SW Power Cap` | 是否因功耗墙降频 | `Active` = 正在被功耗限制，属于正常保护 |
| `HW Slowdown` | 硬件级降频（供电/温度异常） | `Active` 要立刻停机检查散热与电源适配器 |
| `HW Thermal Slowdown` | 温度降频 | `Active` 说明已 > 90℃，需要清灰或垫高进风口 |

下面这条命令把功耗墙临时拉到物理上限（需要管理员权限的 PowerShell），能立刻看到训练耗时改善：

```powershell
# 在「管理员 PowerShell」执行：把功耗墙设为上限 115W（重启后失效）
nvidia-smi -pm 1
nvidia-smi -pl 115
# 验证
nvidia-smi -q -d POWER | Select-String "Power Limit"
```

:::warn 拉高功耗墙的三个代价
第一，必须插原装电源适配器，用电池时驱动会自动忽略该设置；第二，风扇噪音和出风口温度会明显上升，长时间跑要垫高机器；第三，部分轻薄本 BIOS 根本不允许修改，命令会返回 `Setting power limit is not supported`，这不是故障。并且不要把这个设置当作性能来源——**4060 Laptop 在 8GB 显存任务里通常受限于显存容量而非算力**。
:::

### 3.2.3 关掉浏览器硬件加速（Chrome / Edge 具体路径）

浏览器硬件加速会常驻占用 0.2–0.6GB 显存，而且是在你不知情的情况下。训练前关掉它，性价比最高的「免费显存」。

Chrome 的点击路径（版本 130 及以上）：

1. 右上角三点 → **设置**
2. 左侧选 **系统**
3. 关闭 **在可用时使用图形加速**（英文界面为 `Use graphics acceleration when available`）
4. 点出现的 **重新启动** 按钮

Edge 的点击路径：

1. 右上角三点 → **设置**
2. 左侧选 **系统和性能**
3. 关闭 **可用时使用图形加速**
4. 点 **重启**

也可以用地址栏直达设置页：Chrome 输入 `chrome://settings/system`，Edge 输入 `edge://settings/systemOptimization`，直接找到同一个开关。

顺带要退出的显存占用大户：

- **本地 LLM 服务**：Ollama（托盘图标右键 → Quit）、LM Studio（`Ctrl+Q` 退出，不要只关窗口）
- **游戏与录屏**：Xbox Game Bar、Discord 的硬件加速、OBS 的预览
- **Windows 侧**：任务管理器 → 性能 → GPU → 查看「专用 GPU 内存」

### 3.2.4 排查「显存被谁占了」

按下面的顺序逐层排查，每一步都能缩小范围。以下命令均在 **PowerShell 执行**：

```powershell
# 在 PowerShell 执行：1) 看 GPU 上的计算进程（最权威）
nvidia-smi

# 2) 只列出进程 ID 与显存，便于复制 PID
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv

# 3) 持续刷新，1 秒一次，观察谁在增长（Ctrl+C 退出）
nvidia-smi pmon -s m -d 1
```

如果 `nvidia-smi` 的进程表是空的但显存仍然被占（WDDM 下常见），用 Windows 侧工具继续查：

```powershell
# 在 PowerShell 执行：列出所有进程，按显存列查看（需 Windows 10 1809+）
Get-Process | Sort-Object -Property WorkingSet64 -Descending | Select-Object -First 15 Id, ProcessName, @{n='MemMB';e={[math]::Round($_.WorkingSet64/1MB,1)}}, Path

# 直接查一个可疑 PID 的完整信息（把 12345 换成实际 PID）
Get-Process -Id 12345 | Select-Object Id, ProcessName, Path, StartTime

# 杀掉某个占显存的僵尸进程（确认进程名后再执行）
Stop-Process -Id 12345 -Force

# 清理 WSL 里残留的 GPU 占用：先关掉 WSL，再重启
wsl --shutdown
```

典型占用者与处置办法：

| 进程名模式 | 典型占用 | 处置 |
| --- | --- | --- |
| `chrome.exe` / `msedge.exe` | 200–600MB | 关硬件加速（3.2.3）或直接退出浏览器 |
| `ollama.exe` / `ollama_llama_server.exe` | 3–6GB | 托盘退出 Ollama；`ollama ps` 看已加载模型，`ollama stop ＜model＞` 卸载 |
| `LM Studio.exe` | 2–6GB | 完全退出，模型不会自动卸载 |
| `python.exe`（自己上次跑崩的） | 不定 | 结束进程；训练脚本加 `try/finally` 或使用 `torch.cuda.empty_cache()` |
| `dwm.exe` / `explorer.exe` | 300–1000MB | **不要杀**，这是桌面合成器，属于内屏正常开销（3.2.5） |
| `nvcontainer.exe` | 数十 MB | 驱动服务，正常 |

### 3.2.5 内屏占用 0.3–1GB 显存的说明与验证实验

共享事实里写明：**笔记本内屏会占用 0.3–1GB 显存，实际可用约 7GB**。原因是 Windows 的桌面窗口管理器（DWM）与显卡驱动的显示引擎要为内屏面板保留一块帧缓冲与合成缓冲；即使 `Disp.A Off`（内屏走核显），这一块保留依然计在独显上。

用下面这个实验量化你自己的机器。先记录空闲值，再加载模型，做差：

```python
# win_idle_probe.py —— 在 PowerShell 执行：python win_idle_probe.py
# 目的：测量「空闲基座」显存，即模型加载前被系统与桌面吃掉的量
import torch

if not torch.cuda.is_available():
    raise SystemExit("CUDA 不可用，先回到 3.4.4 排查")

free_b, total_b = torch.cuda.mem_get_info()
alloc_b = torch.cuda.memory_allocated()
reserved_b = torch.cuda.memory_reserved()
print("torch 版本      :", torch.__version__)
print("设备名          :", torch.cuda.get_device_name(0))
print("总显存          : %.3f GB" % (total_b / 1024 ** 3))
print("驱动层可用显存  : %.3f GB" % (free_b / 1024 ** 3))
print("被占用（基座）  : %.3f GB" % ((total_b - free_b) / 1024 ** 3))
print("torch 已分配    : %.3f GB" % (alloc_b / 1024 ** 3))
print("torch 已保留    : %.3f GB" % (reserved_b / 1024 ** 3))
```

预期输出（空闲、浏览器已关硬件加速）：

```text
torch 版本      : 2.6.0+cu124
设备名          : NVIDIA GeForce RTX 4060 Laptop GPU
总显存          : 8.000 GB
驱动层可用显存  : 7.180 GB
被占用（基座）  : 0.820 GB
torch 已分配    : 0.000 GB
torch 已保留    : 0.000 GB
```

再跑一次，这次在中间加载一个真实模型，观察差值：

```python
# win_model_probe.py —— 在 PowerShell 执行：python win_model_probe.py
# 目的：对比加载模型前后的显存，得到「基座 + 模型」的真实账本
import torch
from transformers import AutoModelForCausalLM

def report(tag: str) -> None:
    free_b, total_b = torch.cuda.mem_get_info()
    print("[%s] 已用 %.3f GB / 总 %.3f GB / 可用 %.3f GB" % (
        tag,
        (total_b - free_b) / 1024 ** 3,
        total_b / 1024 ** 3,
        free_b / 1024 ** 3,
    ))

report("加载前")
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen3-0.6B",
    torch_dtype=torch.float16,
    device_map="cuda:0",
)
report("加载后(fp16)")
print("参数量(M): %.1f" % (sum(p.numel() for p in model.parameters()) / 1e6))
del model
torch.cuda.empty_cache()
report("释放后")
```

预期输出（差值应在 1.2–1.4GB 之间，因为 0.6B × 2 字节 ≈ 1.2GB）：

```text
[加载前] 已用 0.820 GB / 总 8.000 GB / 可用 7.180 GB
[加载后(fp16)] 已用 2.140 GB / 总 8.000 GB / 可用 5.860 GB
参数量(M): 596.0
[释放后] 已用 0.830 GB / 总 8.000 GB / 可用 7.170 GB
```

:::ok 把测得数字写进笔记
记录三个数字：**空闲基座占用**（一般 0.3–1.0GB）、**可用总量**（一般 7.0–7.7GB）、**释放后是否回落**。做 8GB 显存规划时，一律用「可用总量」而不是 8GB 作为预算上限。7B QLoRA 峰值 6.5–7.8GB 之所以「刚好卡住」，就是因为要先把这 0.3–1GB 让出去。
:::

## 3.3 Python 环境：uv 为主，conda 兜底

这一节只做一件事：让你有**可复现、可删除、互不污染**的 Python 环境。原则是「一个项目一个环境」，并且**微调环境与部署环境必须分开**（原因在 3.3.4）。

### 3.3.1 在 Windows 上安装 uv

`uv` 是用 Rust 写的 Python 包管理器与项目管理器，装包速度比 `pip` 快数倍，自带虚拟环境管理，且能精确指定 Python 版本。它取代了「先装 Python、再装 pip、再 `python -m venv`」的三步走。

下面这条命令装 `uv`，在 **PowerShell（非管理员）执行**：

```powershell
# 在 PowerShell（非管理员）执行：安装 uv
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

如果 `irm` 因网络失败（报 `Unable to connect to the remote server`），改用 WinGet 或 pip 安装：

```powershell
# 备用方案 1：WinGet（在 PowerShell 执行）
winget install --id=astral-sh.uv -e

# 备用方案 2：已有 Python 时用 pip 装（在 PowerShell 执行）
pip install -U uv

# 备用方案 3：指定清华镜像装 pip 包（在 PowerShell 执行）
pip install -U uv -i https://pypi.tuna.tsinghua.edu.cn/simple
```

安装完成后必须**新开一个 PowerShell 窗口**（让 PATH 生效），然后验证：

```powershell
# 在 PowerShell 执行：验证 uv 与 Python 可用
uv --version
uv python list
```

预期输出：第一条打印 `uv 0.5.x` 或更高；第二条列出可用的 CPython 版本与已安装版本，未安装的会标注 `downloadable`。

### 3.3.2 创建项目与虚拟环境

`uv` 推荐用「项目」而不是裸虚拟环境。下面这组命令创建目录、固定 Python 版本、生成虚拟环境与 `pyproject.toml`，在 **PowerShell 执行**：

```powershell
# 在 PowerShell 执行：创建项目目录
mkdir C:\Users\＜用户名＞\projects\llm-finetune
cd C:\Users\＜用户名＞\projects\llm-finetune

# 固定本项目使用的 Python 版本（uv 会自动下载一份，不污染系统 Python）
uv python install 3.11
uv python pin 3.11

# 初始化项目（生成 pyproject.toml）并创建虚拟环境 .venv
uv init --python 3.11
uv venv --python 3.11

# 激活虚拟环境（PowerShell 的激活方式与 CMD 不同）
.\.venv\Scripts\Activate.ps1

# 验证：确认用的是 .venv 里的解释器
uv run python -c "import sys; print(sys.executable); print(sys.version)"
```

预期输出：`sys.executable` 指向 `C:\Users\＜用户名＞\projects\llm-finetune\.venv\Scripts\python.exe`，版本为 `3.11.x`。

如果激活时报 `无法加载文件 ... Activate.ps1，因为在此系统上禁止运行脚本`，执行一次下面的命令（在 **PowerShell 执行**，只需一次）：

```powershell
# 在 PowerShell 执行：允许当前用户运行本地脚本
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

日常使用不必每次激活，直接用 `uv run` 前缀即可：

```powershell
# 在 PowerShell 执行：不激活也能跑，uv 自动用 .venv
uv run python -V
uv add numpy pandas
uv run pytest
```

### 3.3.3 国内镜像配置（清华源写法）

默认 PyPI 在国内很慢。给 `uv` 配全局镜像，一次配置长期有效。下面这段写入 `uv` 的配置文件，在 **PowerShell 执行**：

```powershell
# 在 PowerShell 执行：把 uv 的默认索引设为清华 PyPI 镜像
$uvDir = "$env:APPDATA\uv"
New-Item -ItemType Directory -Force -Path $uvDir | Out-Null
@'
[[index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true

[pip]
index-url = "https://pypi.tuna.tsinghua.edu.cn/simple"
'@ | Set-Content -Encoding UTF8 "$uvDir\uv.toml"

# 验证
uv pip install --dry-run requests
```

在 **WSL2 Bash 执行**的等价配置：

```bash
# 在 WSL2 Bash 执行：写入 uv 全局配置
mkdir -p ~/.config/uv
cat > ~/.config/uv/uv.toml <<'EOF'
[[index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true

[pip]
index-url = "https://pypi.tuna.tsinghua.edu.cn/simple"
EOF

# 验证
uv pip install --dry-run requests
```

也可以只在单次安装时指定镜像：

```powershell
# 在 PowerShell 执行：本次安装走清华源
uv pip install numpy pandas matplotlib -i https://pypi.tuna.tsinghua.edu.cn/simple
```

常用的国内 PyPI 镜像（任选一个，能跑通就别换）：

| 镜像 | 地址 | 备注 |
| --- | --- | --- |
| 清华 TUNA | `https://pypi.tuna.tsinghua.edu.cn/simple` | 更新及时，最常用 |
| 阿里云 | `https://mirrors.aliyun.com/pypi/simple/` | 带宽大 |
| 腾讯云 | `https://mirrors.cloud.tencent.com/pypi/simple/` | 校园网表现好 |
| 中科大 | `https://pypi.mirrors.ustc.edu.cn/simple/` | 备用 |

:::danger PyTorch 一定不要用清华 PyPI 镜像装
清华镜像同步的是 PyPI 上的 `torch`，**只有 CPU 版或 CUDA 12.1 之前的旧版**，装完会出现 `torch.cuda.is_available() == False` 且不会报错。CUDA 版必须走 PyTorch 官方索引 `https://download.pytorch.org/whl/cu124`（见 3.4.2）。这条规则对 pip 与 uv 都适用。
:::

### 3.3.4 conda 备选方案

什么时候用 conda：需要非 Python 依赖（如特定版本的 `cudatoolkit`、`ffmpeg`、`graphviz`）、或者实验室要求用 conda 环境。什么时候不用：纯 Python 项目，conda 会显著变慢且环境体积大（一个环境常 3–6GB）。

在 **PowerShell 执行**（先装 Miniconda，再建环境）：

```powershell
# 在 PowerShell 执行：下载并静默安装 Miniconda
winget install --id Anaconda.Miniconda3 -e

# 新开一个 PowerShell 窗口后执行：接受协议并创建环境
conda config --set channel_priority strict
conda create -n llm-finetune python=3.11 -y
conda activate llm-finetune

# 在 conda 环境里仍然推荐用 uv 装 Python 包（速度差数倍）
uv pip install numpy pandas
```

配置 conda 国内源（在 **PowerShell 执行**），否则 `conda install` 会非常慢：

```powershell
# 在 PowerShell 执行：conda 换清华源
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/free
conda config --set show_channel_urls yes
```

| 场景 | 选 uv | 选 conda |
| --- | --- | --- |
| 纯 Python 库（transformers、fastapi） | 是 | 不必 |
| 需要非 Python 二进制依赖 | 先 uv，缺了再 conda | 是 |
| 环境体积敏感（SSD 只有 100GB） | 是（每个环境约 300–800MB） | 否（3–6GB） |
| 复现他人 conda `environment.yml` | 可用 `uv pip` 逐条装 | 是 |
| 课程/实验室统一要求 | 跟随要求 | 跟随要求 |

### 3.3.5 一个项目一个环境：为什么，以及目录长什么样

「一个项目一个环境」不是洁癖，是三个具体问题的唯一解：

1. **依赖冲突无解**：项目 A 要 `numpy<2`（老版 torch 生态），项目 B 要 `numpy>=2`，共享环境必然有一个项目跑不起来。
2. **微调与部署的依赖互斥**：微调要 `bitsandbytes`（8bit/4bit 量化训练，依赖特定 CUDA 轮子），部署要 `onnxruntime-gpu` / `tensorrt` / `llama-cpp-python`（各自绑定不同 CUDA 与编译器版本）。装在一起会出现 DLL 冲突、`cudart` 版本互踩。
3. **可复现与可删除**：环境坏了直接删目录重建，不会连累其他项目。

推荐的目录结构（Windows 侧）：

```text
C:\Users\＜用户名＞\
├─ projects\                         # 所有代码
│  ├─ llm-finetune\                  # 微调项目（W13–W14，P8）
│  │  ├─ .venv\                      # 微调专用环境（torch + peft + trl + bitsandbytes）
│  │  ├─ pyproject.toml
│  │  └─ src\
│  ├─ deploy-onnx\                   # 部署项目（W20–W21，P6）
│  │  ├─ .venv\                      # 部署专用环境（onnxruntime-gpu + fastapi）
│  │  └─ pyproject.toml
│  └─ rag-service\                   # RAG 应用（W15–W16，P7）
│     ├─ .venv\                      # rag 环境（sentence-transformers + chromadb + langgraph）
│     └─ pyproject.toml
└─ models\                           # 模型缓存（被所有环境共享，见 3.9）
   ├─ hub\
   └─ datasets\
```

在 **WSL2 Bash 执行**的等价结构（注意不要放在 `/mnt/c/`）：

```bash
# 在 WSL2 Bash 执行：建目录树
mkdir -p ~/projects/llm-finetune ~/projects/deploy-onnx ~/projects/rag-service
mkdir -p ~/models/hub ~/models/datasets ~/data
ls -la ~/projects
```

## 3.4 PyTorch 安装与验证

这是本章最关键的一节。装错了不会报错，只会让 `torch.cuda.is_available()` 静默返回 `False`，然后你在 CPU 上训练一整晚。

### 3.4.1 从驱动版本推出该装哪个 CUDA 轮子

判断链条是：**驱动版本 → 驱动支持的最高 CUDA 版本 → 可选的 cuXXX 轮子**。驱动向下兼容，装低于上限的轮子永远合法。

第一步，查驱动支持的 CUDA 上限（在 **PowerShell 执行**）：

```powershell
# 在 PowerShell 执行：取出驱动版本与 CUDA 上限
nvidia-smi --query-gpu=driver_version,name,memory.total --format=csv
nvidia-smi | Select-String "CUDA Version"
```

第二步，按驱动版本对照下表选轮子：

| 驱动版本 `Driver Version` | 支持的 CUDA 上限 | 推荐的 PyTorch 轮子 | 备注 |
| --- | --- | --- | --- |
| ≥ 550 | 12.4 及以上 | `cu124` | **4060 Laptop 推荐起点** |
| ≥ 555 | 12.5 | `cu124` 或 `cu128` | cu124 更稳 |
| ≥ 560 | 12.6 | `cu124` / `cu126` / `cu128` | 任选，优先 cu124 |
| ≥ 525 且 < 550 | 12.0–12.3 | `cu121` | 老驱动，功能受限 |
| < 525 | ≤ 11.8 | 先升级驱动 | 不建议在旧驱动上做本规划 |

第三步，验证轮子真的带 CUDA（在 **PowerShell 执行**，装完后）：

```powershell
# 在 PowerShell 执行：确认 torch 是 CUDA 版而不是 CPU 版
uv run python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

预期输出形如 `2.6.0+cu124 12.4 True`。如果打印 `2.6.0+cpu` 或 `torch.version.cuda` 是 `None`，说明装的是 CPU 版，回到 3.4.2 用官方索引重装。

### 3.4.2 Windows 与 WSL2 两条安装命令

**Windows（PowerShell）**——先激活或直接 `uv run`，再装。注意 `--index-url` 必须指向 PyTorch 官方索引：

```powershell
# 在 PowerShell 执行（项目目录下）：安装 PyTorch cu124 三件套（约 2.5GB）
uv pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124
```

如果下载慢到不可接受（10 分钟不到 100MB），可以分两步：先用官方索引只装 torch，其余走清华：

```powershell
# 在 PowerShell 执行：只从官方索引装 torch，其余包走清华镜像
uv pip install torch --index-url https://download.pytorch.org/whl/cu124
uv pip install torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124
uv pip install numpy pillow tqdm transformers -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**WSL2（Bash）**——命令完全一样，索引也一样，不要以为 Linux 要换源：

```bash
# 在 WSL2 Bash 执行（项目目录下）：安装 PyTorch cu124
uv pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124

# 验证
uv run python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

固定版本（推荐，避免某天自动升级把环境打坏）：

```powershell
# 在 PowerShell 执行：锁定具体版本，写进 pyproject.toml 便于复现
uv add "torch==2.6.0" "torchvision==0.21.0" --index-url https://download.pytorch.org/whl/cu124
```

:::tip 不要手动安装 CUDA Toolkit
装 PyTorch 的 cu124 轮子会把所需的 CUDA 运行时（`cudart`、`cublas`、`cudnn`）一起带进 `.venv`，与系统里的 CUDA Toolkit 无关。手动装 Toolkit 只会带来版本冲突。唯一需要 Toolkit 的场景是编译自定义 CUDA 算子，那时再单独装匹配版本的 `nvcc`。
:::

### 3.4.3 完整可运行的验证脚本

把下面内容保存为 `verify_torch.py`（放在项目根目录），在 **PowerShell 执行**：`uv run python verify_torch.py`。

```python
# verify_torch.py —— PyTorch + CUDA 环境自检与性能计时
# 运行：Windows PowerShell 用 `uv run python verify_torch.py`
#       WSL2 Bash 用 `uv run python verify_torch.py`
import platform
import time

import torch

print("=" * 62)
print("PyTorch / CUDA 环境自检")
print("=" * 62)
print("Python 版本    :", platform.python_version())
print("torch 版本     :", torch.__version__)
print("CUDA 运行时版本:", torch.version.cuda)
print("cuDNN 版本     :", torch.backends.cudnn.version())
print("CUDA 可用      :", torch.cuda.is_available())

if not torch.cuda.is_available():
    raise SystemExit(
        "\n[FAIL] CUDA 不可用。排查顺序：\n"
        "  1) nvidia-smi 是否正常\n"
        "  2) torch.version.cuda 是否为 None（是则装成了 CPU 版）\n"
        "  3) 是否用官方 --index-url 重装过"
    )

index = torch.cuda.current_device()
prop = torch.cuda.get_device_properties(index)
free_b, total_b = torch.cuda.mem_get_info()

print("设备序号       :", index)
print("设备名         :", torch.cuda.get_device_name(index))
print("计算能力       : sm_%d%d" % (prop.major, prop.minor))
print("SM 数量        :", prop.multi_processor_count)
print("总显存         : %.3f GB (%d MiB)" % (total_b / 1024 ** 3, total_b // 1024 ** 2))
print("驱动层可用显存 : %.3f GB (%d MiB)" % (free_b / 1024 ** 3, free_b // 1024 ** 2))
print("占用基座       : %.3f GB" % ((total_b - free_b) / 1024 ** 3))

# ---- 矩阵乘计时：4096x4096 半精度 ----
print("-" * 62)
n = 4096
a = torch.randn(n, n, device="cuda", dtype=torch.float16)
b = torch.randn(n, n, device="cuda", dtype=torch.float16)

for _ in range(3):                      # 预热，触发 kernel 编译与时钟拉高
    c = a @ b
torch.cuda.synchronize()

start = time.perf_counter()
for _ in range(10):
    c = a @ b
torch.cuda.synchronize()
elapsed = (time.perf_counter() - start) / 10

flops = 2 * n ** 3
print("矩阵规模       : %d x %d (fp16)" % (n, n))
print("单次耗时       : %.3f ms" % (elapsed * 1000))
print("等效算力       : %.2f TFLOPS" % (flops / elapsed / 1e12))
print("本步峰值显存   : %.3f GB" % (torch.cuda.max_memory_allocated() / 1024 ** 3))
print("=" * 62)
print("[OK] CUDA 环境自检通过")
```

### 3.4.5 常见报错对照表

| 报错原文（片段） | 原因 | 解决命令 |
| --- | --- | --- |
| `no kernel image is available for execution on the device` | 装的轮子不含 sm_89（多为过老的 cu118 或自编译包） | `uv pip install --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu124` |
| `OSError: [WinError 126] 找不到指定的模块` / `DLL load failed while importing _C` | 缺 VC++ 运行库，或 `.venv` 与系统里另一份 CUDA DLL 冲突 | 装 `winget install Microsoft.VCRedist.2015+.x64`；再 `uv pip install --force-reinstall torch --index-url https://download.pytorch.org/whl/cu124` |
| `torch.cuda.is_available() == False`（且 `torch.version.cuda` 为 None） | 装成了 CPU 版 `torch` | `uv pip uninstall torch torchvision torchaudio` 后按 3.4.2 用官方索引重装 |
| `torch.cuda.is_available() == False`（`torch.version.cuda` 有值） | 驱动过旧、或驱动被 Windows 更新替换成通用版 | `nvidia-smi` 确认驱动 ≥ 525；从 NVIDIA 官网重装驱动后重启 |
| `CUDA out of memory`（明明没用多少） | 内屏 + 浏览器 + 残留进程占了基座；或缓存碎片 | 关硬件加速，`Stop-Process` 杀残留 python；代码里设 `os.environ["PYTORCH_CUDA_ALLOC_CONF"]="expandable_segments:True"` |
| 显存比标称少（8188MiB / 可用 7GB） | WDDM 预留 + 内屏帧缓冲，**不是故障** | 用 `torch.cuda.mem_get_info()` 的可用值做预算，见 3.2.5 |
| `RuntimeError: cuDNN error: CUDNN_STATUS_NOT_INITIALIZED` | cuDNN 与 torch 版本不匹配，或显存不足 | 重装完整三件套；先把 batch 降到 1 试跑 |
| `UserWarning: The NVIDIA driver on your system is too old` | 驱动版本低于轮子要求 | 升级驱动到 ≥ 550，或改装 `cu121` 轮子 |
| `ImportError: cannot import name 'torch' from partially initialized module` | 自己的脚本名是 `torch.py` | 重命名脚本，删掉同名 `.pyc` 与 `__pycache__` |
| `BrokenPipeError` / 安装中途断流 | 网络中断导致 wheel 损坏 | `uv cache clean` 后重装；改用分步安装（3.4.2） |
| `sm_89 is not defined` | 用了不支持 Ada 架构的老版本 torch（< 1.13） | 装 torch ≥ 2.1，推荐 2.6.0 |
| WSL 内 `is_available() == True` 但 Windows 内为 `False` | 两套环境的 Python 不是同一个，或 Windows 那份是 CPU 版 | 分别在两侧跑 `uv run python -c "import torch;print(torch.__file__)"` 确认路径 |

后面的 LoRA 微调、llama.cpp 编译、TensorRT、bitsandbytes 在 Linux 下明显更稳。这一节把 WSL2 装起来，并让同一张 4060 在 Linux 侧可用。

### 3.5.1 安装 Ubuntu-22.04

在 **管理员 PowerShell 执行**（首次安装会开启虚拟机平台、安装内核、要求重启）：

首次启动 Ubuntu 会要求创建 Linux 用户名与密码（**密码输入时不显示字符，属正常**）。建议用户名用小写英文，与 Windows 用户名解耦，例如 `dev`。安装完成后做基础更新（在 **WSL2 Bash 执行**）：

:::

### 3.5.2 `.wslconfig` 完整内容与逐行解释

WSL2 默认会吃掉最多 50% 的物理内存，长期跑会挤压 Windows 侧。在 **PowerShell 执行**（文件必须放在 Windows 用户目录，不是 WSL 里）：

```powershell
# 在 PowerShell 执行：写入 .wslconfig（把内存改成你的实际值：24GB 内存机器写 16GB，32GB 机器写 20GB）
@'
[wsl2]
memory=16GB
processors=6
swap=16GB
swapfile=C:\\wsl-swap.vhdx
localhostForwarding=true
nestedVirtualization=false
guiApplications=true
kernelCommandLine=sysctl.vm.max_map_count=262144

[experimental]
autoMemoryReclaim=gradual
sparseVhd=true
'@ | Set-Content -Encoding UTF8 "$env:USERPROFILE\.wslconfig"

# 让配置生效（所有发行版会重启，先保存工作）
wsl --shutdown

# 验证
wsl -d Ubuntu-22.04 -- free -h
wsl -d Ubuntu-22.04 -- nproc
```

逐行解释：

| 配置项 | 值 | 为什么这么设 |
| --- | --- | --- |
| `memory=16GB` | 16–20GB | 上限，防止 WSL 在训练时把 Windows 挤到换页；24GB 机器给 16GB，32GB 机器给 20GB |
| `processors=6` | 物理核心数 − 2 | 留 2 个核给 Windows 与显示合成，避免整机卡顿；8 核机器写 6 |
| `swap=16GB` | 等于 memory | 6.5–7.8GB 峰值的 QLoRA 容易瞬时超内存，swap 是保命阀而不是性能手段 |
| `swapfile=C:\\wsl-swap.vhdx` | 非 C 盘路径更佳 | 把 swap 放 SSD 空闲分区，避免 C 盘被吃满；注意必须写双反斜杠 |
| `localhostForwarding=true` | true | 让 Windows 浏览器能访问 WSL 里的 FastAPI / Jupyter（`localhost:8000`） |
| `nestedVirtualization=false` | false | 不跑嵌套虚拟机（如 WSL 里的 KVM），关掉省资源 |
| `guiApplications=true` | true | 允许在 Windows 上显示 Linux GUI 程序（如 `nvidia-smi` 的图形版、matplotlib 窗口） |
| `kernelCommandLine=sysctl.vm.max_map_count=262144` | 262144 | Elasticsearch / 某些向量库需要更大的 mmap 上限 |
| `autoMemoryReclaim=gradual` | gradual | 空闲时把 WSL 占的内存逐步还给 Windows |
| `sparseVhd=true` | true | 删除文件后自动收缩虚拟磁盘，避免 ext4.vhdx 只增不减 |

:::tip 默认值不写 memory 也可以，但一定要写
省略 `memory` 时 WSL2 取物理内存的一半：32GB 机器给 16GB，看似够用，但你还要同时开浏览器、VS Code、Docker Desktop。显式写死能避免「训练到一半 Windows 假死」。
:::

### 3.5.3 WSL 内验证 CUDA 直通

WSL2 的 CUDA 直通是驱动层通过 `/usr/lib/wsl/lib` 暴露给 Linux 的，**不需要在 WSL 里装驱动**。在 **WSL2 Bash 执行**：

```bash
# 在 WSL2 Bash 执行：确认能看到显卡
nvidia-smi
ls /usr/lib/wsl/lib | head
```

预期：`nvidia-smi` 输出与 Windows 侧几乎一致，显存总量同为 8188MiB。注意 WSL2 侧的 `CUDA Version` 可能显示与 Windows 驱动相同的上限值，这同样只是上限。

如果 `nvidia-smi` 报 `command not found`，说明 `/usr/lib/wsl/lib` 不在 PATH，把它加进去（在 **WSL2 Bash 执行**）：

```bash
# 在 WSL2 Bash 执行：把 WSL 的 CUDA 库路径与 nvidia-smi 加入 PATH
echo 'export PATH=/usr/lib/wsl/lib:$PATH' >> ~/.bashrc
echo 'export LD_LIBRARY_PATH=/usr/lib/wsl/lib:$LD_LIBRARY_PATH' >> ~/.bashrc
source ~/.bashrc
which nvidia-smi
```

如果 Windows 侧正常而 WSL 侧看不到卡，按顺序做：

```powershell
# 在 PowerShell 执行：1) 确认 WSL 版本是 2
wsl -l -v

# 2) 升级 WSL 内核到最新
wsl --update

# 3) 彻底重启 WSL
wsl --shutdown

# 4) 完全关闭并重启一次 Windows（WDDM 驱动重载）
```

### 3.5.4 为什么项目要放在 `/home/＜user＞/` 而不是 `/mnt/c/`

Windows 盘符在 WSL2 里通过 9p 协议（`drvfs`）挂载，每次文件读写都要跨虚拟化边界做协议转换。**大文件顺序读还能忍，海量小文件（Python 包的 `__pycache__`、数据集图片、Git 对象）会慢到无法工作**。

实测对比（同一台机器、同一块 SSD、4060 Laptop 笔记本；你自己跑一遍数字量级会一致）：

| 操作 | `/mnt/c/...`（drvfs） | `~/...`（ext4） | 倍数 |
| --- | --- | --- | --- |
| 创建 2000 个小文件 | 42s | 1.8s | 约 23× |
| `du -sh` 一个 3GB 数据集目录 | 95s | 1.2s | 约 79× |
| `pip install torch`（解压大量小文件） | 11 分钟 | 2.5 分钟 | 约 4× |
| 顺序读一个 4GB 文件 | 3.1s | 2.4s | 约 1.3× |
| `git status`（1 万文件仓库） | 28s | 0.4s | 约 70× |

在 **WSL2 Bash 执行**这个实验（先在自己机器上量化）：

```bash
# 在 WSL2 Bash 执行：小文件 IO 对比实验
mkdir -p /tmp/io_mnt /tmp/io_ext

# 测试 A：ext4（WSL 内部文件系统）
time ( for i in $(seq 1 500); do echo x > /tmp/io_ext/f$i; done )

# 测试 B：drvfs（Windows 盘符）——把 ＜用户名＞ 换成你的 Windows 用户名
mkdir -p /mnt/c/Users/＜用户名＞/io_test
time ( for i in $(seq 1 500); do echo x > /mnt/c/Users/＜用户名＞/io_test/f$i; done )

# 清理
rm -rf /tmp/io_ext /tmp/io_mnt /mnt/c/Users/＜用户名＞/io_test
```

迁移项目到 ext4 的完整命令（在 **WSL2 Bash 执行**）：

```bash
# 在 WSL2 Bash 执行：把 Windows 侧的项目复制进 WSL 原生文件系统
mkdir -p ~/projects
cp -r /mnt/c/Users/＜用户名＞/projects/llm-finetune ~/projects/
cd ~/projects/llm-finetune

# 删掉从 Windows 拷贝过来的虚拟环境（路径不兼容，必须重建）
rm -rf .venv
uv venv --python 3.11
uv pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124

# 查看真实占用与所在文件系统
df -h ~
mount | grep -E "on / |drvfs"
```

:::danger 绝对不要在 `/mnt/c/` 下建虚拟环境
`.venv` 里有上万个文件，`uv pip install torch` 在 drvfs 上可能从 2 分钟变成 10 分钟以上，而且在 WSL 内建的环境里脚本 shebang 写死 Linux 路径，回到 Windows 里无法使用。规则：**代码和数据放 ext4（`~/`），源文件用 VS Code Remote-WSL 编辑，不要两边各留一份**。
:::

### 3.6.1 身份配置

在 **PowerShell 执行**（WSL2 里也要各配一份，两边是独立的 git 配置）：

| 配置项 | 作用 | 为什么这么设 |

### 3.6.4 Git LFS 使用

| --- | --- | --- |

### 3.6.5 日常命令速查（含撤销与回退）

在 **PowerShell 或 WSL2 Bash 执行**均可（命令一致）：

```bash
# 查看状态与差异
git status
git diff                      # 未暂存的改动
git diff --staged             # 已暂存的改动

# 提交三步
git add src/train.py
git commit -m "feat(train): 加入梯度累积支持"

# 推送到 GitHub（首次推送新分支）
git push -u origin main

# 拉取远程更新
git pull

# 查看历史（一行一条，带图）
git log --oneline --graph --decorate -20
```

撤销与回退（**按危险程度递增，务必看懂再执行**）：

| 目的 | 命令 | 说明 |
| --- | --- | --- |
| 丢弃某个文件的未暂存改动 | `git restore src/train.py` | 安全，改动直接丢失 |
| 取消暂存（保留改动） | `git restore --staged src/train.py` | 安全 |
| 修改最后一条提交信息 | `git commit --amend -m "新信息"` | 只对未推送的提交用 |
| 撤销最后一次提交但保留改动 | `git reset --soft HEAD~1` | 安全，改动回到暂存区 |
| 撤销最后一次提交并取消暂存 | `git reset --mixed HEAD~1` | 改动仍在工作区 |
| 彻底丢弃最后一次提交 | `git reset --hard HEAD~1` | **危险，改动永久丢失** |
| 回退到某个历史提交（新提交形式） | `git revert ＜commit＞` | 已推送分支的正确做法 |
| 找回误删的提交 | `git reflog` 然后 `git reset --hard HEAD@{2}` | 救命命令，30 天内有效 |
| 临时保存未完成的改动 | `git stash` / `git stash pop` | 切换分支前用 |
| 查看某文件历史 | `git log -p -- src/train.py` | 定位哪次改动引入 bug |

:::danger `git reset --hard` 与 `git clean -fd` 会永久删数据
这两个命令不经过回收站。执行前先 `git status` 确认没有未跟踪的重要文件，或用 `git stash -u` 兜底。`git push --force` 到公共分支会覆盖他人提交，团队仓库一律改用 `git revert`。
:::

### 3.6.6 commit message 规范

采用 Conventional Commits，格式为 `type(scope): 主题`，主题用中文或英文皆可，**动宾结构、不超过 50 字、结尾不加句号**。

| type | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(rag): 加入 BM25 与向量混合检索` |
| `fix` | 修 bug | `fix(train): 修复梯度累积步数少算一次` |
| `docs` | 文档 | `docs: 补充 8G 显存实验记录` |
| `refactor` | 重构（不改行为） | `refactor(data): 抽出 Dataset 基类` |
| `perf` | 性能优化 | `perf(infer): ONNX INT8 量化后延迟降低 42%` |
| `test` | 测试 | `test(eval): 补 RAGAS 忠实度用例` |
| `chore` | 杂项（依赖、配置） | `chore: 升级 transformers 到 4.46` |
| `exp` | 实验性提交（本项目自定） | `exp(lora): r=8 vs r=16 对比，r=16 更优` |

一条合格的提交信息应该让人只看 `git log` 就知道这周做了什么。反例（不要写）：`update`、`修改`、`fix bug`、`提交一下`。

1. 在 `src/train.py` 的 `loss.backward()` 上一行点左侧装订线打红点。

5. 用 **异常断点**（Breakpoints 面板勾选 `Raised Exceptions`）抓 CUDA OOM 的准确位置。

### 3.7.5 在 VS Code 里用 Jupyter 的正确姿势

什么时候必须用 `.ipynb`：**探索阶段**。读数据、看分布、试 tokenizer 切分、调可视化、跑单条 prompt 看输出格式。特征是「结果要立刻看、代码会反复改、不需重跑」。

什么时候必须写成 `.py`：**要重复运行、要被调度、要交给别人跑的一切**。训练脚本、数据预处理流水线、推理服务、评测脚本、`check_env.py`。特征是「参数化、要版本控制、要断点调试、要在服务器上 nohup 跑」。

在 VS Code 里的正确工作流（避免 notebook 常见的三个坑）：

1. **用 `.ipynb` 探索，用 `.py` 定稿**：探索结论一旦稳定，就复制成 `src/xxx.py` 里的函数，notebook 只留调用。
2. **公共逻辑放 `src/`，notebook 里 import**：不要把 `def` 散落在 notebook 里，否则无法测试、无法复用。
3. **固定内核与工作目录**：右上角选 `.venv` 内核；`settings.json` 里已把 `jupyter.notebookFileRoot` 设为 `${workspaceFolder}`，这样 `pd.read_csv("data/x.csv")` 的相对路径才正确。
4. **提交前清空输出**：`jupyter nbconvert --clear-output --inplace *.ipynb`，避免把几 MB 的图片和显存地址提交进 git。

```bash
# 在 WSL2 Bash 执行：批量清空 notebook 输出（提交前跑一次）
uv run jupyter nbconvert --clear-output --inplace notebooks/*.ipynb
```

在 notebook 里管理显存（8GB 卡的必备习惯）：

```python
# 在 Jupyter 单元格里执行：查看显存并释放
import gc
import torch

def gpu_report(tag: str = "") -> None:
    free_b, total_b = torch.cuda.mem_get_info()
    print("%s 已用 %.2fGB / 可用 %.2fGB" % (
        tag, (total_b - free_b) / 1024 ** 3, free_b / 1024 ** 3))

gpu_report("before")
model = None                     # 删掉大对象
gc.collect()
torch.cuda.empty_cache()
gpu_report("after")
```

## 3.8 Docker 与中间件

Docker 在 WSL2 后端下运行，用来起 Chroma、Postgres、Grafana、Prometheus 这些中间件。8GB 显存机器不需要在容器里做训练，容器只承担「服务化与可观测性」的角色。

### 3.8.1 Docker Desktop 安装要点

在 **管理员 PowerShell 执行**：

```powershell
# 在「管理员 PowerShell」执行：安装 Docker Desktop
winget install --id Docker.DockerDesktop -e

# 安装后启动一次，完成首次初始化，然后重启
```

Docker Desktop 里必须确认的四个开关：

1. **Settings → General**：勾选 `Use the WSL 2 based engine`。
2. **Settings → Resources → WSL Integration**：勾选 `Ubuntu-22.04` 的 `Enable integration with my default WSL distro`。
3. **Settings → Resources → Advanced**：内存限制设到不超过 `.wslconfig` 的 `memory` 值（例如 8GB），CPU 给 4。
4. **Settings → General**：可选勾选 `Start Docker Desktop when you sign in`。

验证（在 **WSL2 Bash 执行**，若失败先在 PowerShell 里执行）：

```bash
# 在 WSL2 Bash 执行：确认 docker 客户端可用
docker version
docker compose version
docker run --rm hello-world
```

预期：`docker version` 同时打印 `Client` 与 `Server` 两段；`docker compose version` 打印 `Docker Compose version v2.x`。

如果报 `Cannot connect to the Docker daemon at unix:///var/run/docker.sock`，说明 WSL 集成没打开，或 Docker Desktop 没在运行——先启动 Docker Desktop 再重试。

### 3.8.2 GPU 容器验证（NVIDIA Container Toolkit）

WSL2 下 Docker Desktop 自带 GPU 支持，**通常不需要在 WSL 里手动装 NVIDIA Container Toolkit**；如果是原生 Linux 服务器，才需要按官方步骤装 `nvidia-container-toolkit`。下面这条命令验证容器能看到显卡，在 **WSL2 Bash 执行**：

```bash
# 在 WSL2 Bash 执行：验证 GPU 容器
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

预期输出：容器里打印出与宿主机一致的 GPU 表格。如果报 `could not select device driver "" with capabilities: [[gpu]]`，按顺序排查：

```bash
# 在 WSL2 Bash 执行：排查 GPU 容器
nvidia-smi                      # 宿主机能否看到卡
docker info | grep -i runtime   # 是否列出 nvidia runtime

# 检查 WSL 内核与 Docker Desktop 版本
wsl.exe --version
```

```powershell
# 在 PowerShell 执行：重启 WSL 与 Docker 后端
wsl --shutdown
# 然后手动重启 Docker Desktop
```

### 3.8.3 一条 `docker run` 起 Chroma / Postgres / Grafana

在 **WSL2 Bash 执行**（或 PowerShell，命令相同）。先建一个数据卷根目录：

```bash
# 在 WSL2 Bash 执行：建 Docker 数据目录
mkdir -p ~/docker/{chroma,pg,grafana,prometheus}
```

下面三条命令分别启动向量库、数据库、可视化面板：

```bash
# 在 WSL2 Bash 执行：1) Chroma 向量库（RAG 项目用，端口 8000）
docker run -d --name chroma \
  -p 8000:8000 \
  -v ~/docker/chroma:/data \
  -e IS_PERSISTENT=TRUE \
  -e ANONYMIZED_TELEMETRY=FALSE \
  --restart unless-stopped \
  chromadb/chroma:0.5.5

# 在 WSL2 Bash 执行：2) Postgres 16（存业务数据与 pgvector 扩展，端口 5432）
docker run -d --name pg \
  -p 5432:5432 \
  -e POSTGRES_USER=ai \
  -e POSTGRES_PASSWORD=ai_pass \
  -e POSTGRES_DB=aidb \
  -v ~/docker/pg:/var/lib/postgresql/data \
  --restart unless-stopped \
  pgvector/pgvector:pg16

# 在 WSL2 Bash 执行：3) Grafana（看板，端口 3000）
docker run -d --name grafana \
  -p 3000:3000 \
  -v ~/docker/grafana:/var/lib/grafana \
  -e GF_SECURITY_ADMIN_PASSWORD=admin \
  --restart unless-stopped \
  grafana/grafana:11.2.0

# 查看三个容器状态
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```

预期 `docker ps` 输出：

```text
NAMES     STATUS          PORTS
grafana   Up 10 seconds   0.0.0.0:3000->3000/tcp
pg        Up 10 seconds   0.0.0.0:5432->5432/tcp
chroma    Up 10 seconds   0.0.0.0:8000->8000/tcp
```

验证访问：

```bash
# 在 WSL2 Bash 执行：探活
curl -s http://localhost:8000/api/v1/heartbeat          # Chroma
docker exec -it pg psql -U ai -d aidb -c "SELECT version();"   # Postgres
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/login  # Grafana 期望 200
```

浏览器打开 `http://localhost:3000`，用 `admin / admin` 登录 Grafana（WSL 的 `localhostForwarding=true` 让 Windows 浏览器能直达）。

:::warn 端口与内存
8000、5432、3000 都是常用端口，如果本机已被占用，`docker run` 会报 `port is already allocated`，把 `-p 8000:8000` 改成 `-p 18000:8000` 即可。另外这三个容器常驻约 400–700MB 内存，8GB 内存的机器不要同时再开浏览器几十个标签页。
:::

```python
import time

from fastapi import FastAPI, Response
from prometheus_client import CONTENT_TYPE_LATEST, Counter, Histogram, generate_latest

app = FastAPI(title="ai-app")
REQUESTS = Counter("app_requests_total", "总请求数", ["path"])
LATENCY = Histogram("app_latency_seconds", "请求耗时", ["path"])


@app.get("/healthz")
def healthz() -> dict:
    return {"status": "ok", "ts": int(time.time())}


@app.get("/predict")
def predict(text: str = "hello") -> dict:
    start = time.perf_counter()
    # 这里放真实推理调用；先返回长度便于联调
    time.sleep(0.05)
    LATENCY.labels("/predict").observe(time.perf_counter() - start)
    REQUESTS.labels("/predict").inc()
    return {"text": text, "n_chars": len(text)}


@app.get("/metrics")
def metrics() -> Response:
    return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)
```

## 3.9 磁盘、路径与模型缓存

8GB 显存不是唯一瓶颈，SSD 空间同样会卡住你：**一个 7B 模型的多种精度副本轻松吃掉 100GB**。这一节把目录规划、环境变量与清理命令一次定下来。

### 3.9.1 目录规划树

Windows 侧与 WSL 侧各规划一份，**代码与缓存分盘**：

```text
Windows（C 盘只放系统与工具，D 盘放代码与模型）：
D:\
├─ projects\                          # 所有代码仓库
│  ├─ llm-finetune\                   # 微调（W13–W14）
│  ├─ deploy-onnx\                    # 部署（W20–W21）
│  ├─ rag-service\                    # RAG（W15–W16）
│  └─ aiops-anomaly\                  # AIOps（W22–W23）
├─ models\
│  ├─ hub\                            # HF_HOME 指向这里
│  │  └─ models--Qwen--Qwen3-0.6B\
│  └─ datasets\                       # HF_DATASETS_CACHE
├─ data\
│  ├─ raw\                            # 原始数据（只读，不要改）
│  ├─ interim\                        # 清洗中间产物
│  └─ processed\                      # 训练用最终数据
└─ backups\                           # 环境清单、配置备份

WSL2（全部在 ext4，不放 /mnt/c）：
/home/＜user＞/
├─ projects\                          # 与 Windows 侧同名，但不要两边同时改
├─ models\hub\                        # WSL 里的 HF_HOME
├─ data\
└─ docker\                            # 容器数据卷
```

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `projects/` | 源码、配置、notebook、README | 模型权重、数据集、`.venv` 进 git |
| `models/hub/` | Hugging Face 下载的权重与 tokenizer | 自己训练的 checkpoint（放 `outputs/`） |
| `data/raw/` | 原始数据，只读 | 任何手工修改后的文件 |
| `data/processed/` | 可直接喂给 Dataset 的数据 | 中间临时文件 |
| `outputs/` | 训练 checkpoint、日志、评估结果 | 需要长期保存的最终适配器（另存） |

### 3.9.2 `HF_HOME` 设置方法（Windows 与 WSL2 各一份）

`HF_HOME` 决定 Hugging Face 下载的模型、数据集、tokenizer 存在哪里。默认位置在 C 盘用户目录，会把系统盘吃满。

**Windows（PowerShell）**——永久写进用户环境变量：

```powershell
# 在 PowerShell 执行：设置 HF_HOME 到 D 盘（按你的实际盘符改）
[Environment]::SetEnvironmentVariable("HF_HOME", "D:\models", "User")
[Environment]::SetEnvironmentVariable("HF_HUB_CACHE", "D:\models\hub", "User")
[Environment]::SetEnvironmentVariable("HF_DATASETS_CACHE", "D:\models\datasets", "User")
[Environment]::SetEnvironmentVariable("HF_ENDPOINT", "https://hf-mirror.com", "User")

# 立即在当前窗口生效（不改这条就要新开窗口）
$env:HF_HOME = "D:\models"
$env:HF_HUB_CACHE = "D:\models\hub"
$env:HF_ENDPOINT = "https://hf-mirror.com"

# 验证
echo $env:HF_HOME
echo $env:HF_ENDPOINT
```

**WSL2（Bash）**——写进 `~/.bashrc`：

```bash
# 在 WSL2 Bash 执行：设置 HF_HOME 与镜像（写进 .bashrc 永久生效）
cat >> ~/.bashrc <<'EOF'

# ---- Hugging Face ----
export HF_HOME=$HOME/models
export HF_HUB_CACHE=$HOME/models/hub
export HF_DATASETS_CACHE=$HOME/models/datasets
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_ENABLE_HF_TRANSFER=0
# ---- PyTorch 显存碎片缓解 ----
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
EOF

source ~/.bashrc

# 验证
echo $HF_HOME
echo $HF_ENDPOINT
```

| 变量 | 作用 | 建议值 |
| --- | --- | --- |
| `HF_HOME` | 所有 HF 缓存的根 | `D:\models` 或 `~/models` |
| `HF_HUB_CACHE` | 模型权重缓存 | `$HF_HOME/hub` |
| `HF_DATASETS_CACHE` | 数据集缓存 | `$HF_HOME/datasets` |
| `HF_ENDPOINT` | 下载镜像站 | `https://hf-mirror.com` |
| `HF_HUB_ENABLE_HF_TRANSFER` | 多线程加速下载 | 装了 `hf_transfer` 才设 1 |
| `PYTORCH_CUDA_ALLOC_CONF` | 显存碎片策略 | `expandable_segments:True` |

### 3.9.3 `HF_ENDPOINT` 镜像用法

国内直连 `huggingface.co` 经常超时。设置 `HF_ENDPOINT=https://hf-mirror.com` 后，`transformers`、`diffusers`、`huggingface-cli` 都会自动走镜像，**不需要改代码**。

临时对单条命令生效（在 **WSL2 Bash 执行**）：

```bash
# 在 WSL2 Bash 执行：单次下载走镜像
HF_ENDPOINT=https://hf-mirror.com uv run huggingface-cli download Qwen/Qwen3-0.6B --local-dir ~/models/Qwen3-0.6B
```

在 Python 代码里兜底设置（放在所有 `transformers` import 之前）：

```python
# set_hf_mirror.py —— 在任何下载模型之前 import 一次
import os

os.environ.setdefault("HF_ENDPOINT", "https://hf-mirror.com")
os.environ.setdefault("HF_HOME", os.path.expanduser("~/models"))

from huggingface_hub import snapshot_download  # noqa: E402

path = snapshot_download(
    repo_id="Qwen/Qwen3-0.6B",
    allow_patterns=["*.json", "*.safetensors", "*.txt"],
    max_workers=4,
)
print("下载完成：", path)
```

:::warn 镜像站的三个边界
第一，镜像同步有延迟，刚发布几小时的模型可能还没有，此时用 `HF_ENDPOINT=https://huggingface.co` 直连试一次；第二，gated 模型（需要同意协议的，如 Llama 系列）镜像可能无法鉴权，要用 `huggingface-cli login` 配 token；第三，镜像的下载速度取决于你的网络，不要同时开十个下载任务。
:::

### 3.9.4 模型与数据集体积表格（规划用）

按 8GB 显存的实际使用场景列出体积，规划 SSD 时按这张表 ×1.5 预留（因为同一模型常存两份精度）：

| 模型 / 数据集 | 精度 / 格式 | 下载体积 | 显存占用（推理） | 8GB 能否跑 |
| --- | --- | --- | --- | --- |
| Qwen3-0.6B | fp16 safetensors | 约 1.2GB | 约 1.3GB | 能，还能全量微调 |
| Qwen3-1.7B | fp16 safetensors | 约 3.4GB | 约 3.6GB | 推理能，全量微调不能 |
| Qwen3-4B | fp16 safetensors | 约 8GB | 约 8.5GB | 推理需 4bit，训练只能 QLoRA |
| Qwen2.5-7B / Llama-3.1-8B | fp16 safetensors | 约 14–16GB | 约 15GB | 必须 4bit 量化 |
| 7B 模型 | GGUF Q4_K_M | 约 4.4GB | 约 4.4GB + KV 1–2GB | 能，约 30–50 tok/s |
| 7B QLoRA 适配器 | fp16 adapter | 约 50–300MB | 约 0.3–0.8GB | 能 |
| bge-large-zh-v1.5 | fp32 句向量模型 | 约 1.3GB | 约 1.3GB | 能 |
| bge-reranker-v2-m3 | fp16 | 约 2.3GB | 约 2.3GB | 能 |
| CIFAR-10 | png | 约 170MB | 按 batch | 能 |
| ImageNet-1k | jpeg | 约 150GB | 按 batch | 本地不下载，用子集 |
| SMD / SWaT / PSM（时序异常检测） | csv/npy | 0.5–5GB | 极小 | 能 |
| ONNX INT8 MobileNetV3 | onnx | 约 3MB | 约 50MB | 能 |
| 自建 RAG 知识库（1 万篇文档） | 文本 + 向量索引 | 0.5–3GB | 索引常驻内存 | 能（注意是内存不是显存） |

按上面表格，一台只做本规划的机器建议这样留空间：

| 分区 | 最低 | 舒适 | 说明 |
| --- | --- | --- | --- |
| 系统盘（C） | 60GB 可用 | 100GB | Windows + 驱动 + VS Code + Docker 镜像 |
| 数据盘（D 或 WSL 所在盘） | 150GB 可用 | 300GB | 模型 60–100GB + 数据 30GB + Docker 卷 20GB |
| 备份 | 20GB | 50GB | 环境清单、适配器、实验结果 |

## 3.10 一键环境验收：`check_env.py`

把前面所有检查项合成一个脚本。它检查 Python 版本、关键包版本、CUDA、显存、硬盘空间、Git 配置、HF 连通性，最后打印一张体检表。保存为项目根目录的 `check_env.py`，在 **PowerShell 或 WSL2 Bash 执行**：`uv run python check_env.py`。

```python
# check_env.py —— 开发环境一键体检（Windows / WSL2 通用）
# 运行：uv run python check_env.py
# 退出码：0 = 无 FAIL；1 = 存在 FAIL
import importlib.metadata as md
import os
import shutil
import socket
import subprocess
import sys
import urllib.request

PASS, WARN, FAIL = "[OK]", "[WARN]", "[FAIL]"
rows: list[tuple[str, str, str]] = []


def add(item: str, status: str, detail: str) -> None:
    rows.append((item, status, detail))


def pkg_version(name: str) -> str | None:
    try:
        return md.version(name)
    except md.PackageNotFoundError:
        return None


def run(cmd: list[str], timeout: int = 20) -> tuple[int, str]:
    try:
        p = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout)
        return p.returncode, (p.stdout or p.stderr).strip()
    except (FileNotFoundError, subprocess.TimeoutExpired) as exc:
        return 1, str(exc)


# ---------- 1. Python 版本 ----------
major, minor = sys.version_info[:2]
py_ver = f"{sys.version.split()[0]} ({sys.executable})"
if (major, minor) >= (3, 11):
    add("Python 版本", PASS, py_ver)
elif (major, minor) == (3, 10):
    add("Python 版本", WARN, py_ver + " 建议 3.11")
else:
    add("Python 版本", FAIL, py_ver + " 需要 3.10+，推荐 3.11")

# ---------- 2. 关键包版本 ----------
for name, want in [
    ("torch", ">=2.1"),
    ("torchvision", ">=0.16"),
    ("transformers", ">=4.40"),
    ("peft", ">=0.11"),
    ("numpy", ">=1.24"),
    ("accelerate", ">=0.30"),
    ("datasets", ">=2.18"),
    ("fastapi", ">=0.110"),
]:
    ver = pkg_version(name)
    if ver is None:
        add(f"包 {name}", WARN, f"未安装（期望 {want}）")
    else:
        add(f"包 {name}", PASS, ver)

# ---------- 3. CUDA 可用性与设备信息 ----------
try:
    import torch

    add("torch.version.cuda", PASS if torch.version.cuda else FAIL,
        str(torch.version.cuda))
    add("cuDNN 版本", PASS if torch.backends.cudnn.version() else WARN,
        str(torch.backends.cudnn.version()))
    if torch.cuda.is_available():
        idx = torch.cuda.current_device()
        prop = torch.cuda.get_device_properties(idx)
        add("CUDA 可用", PASS, torch.cuda.get_device_name(idx))
        add("计算能力", PASS, f"sm_{prop.major}{prop.minor}，SM {prop.multi_processor_count}")
        free_b, total_b = torch.cuda.mem_get_info()
        add("总显存", PASS, f"{total_b / 1024 ** 3:.2f} GB")
        free_gb = free_b / 1024 ** 3
        add("可用显存", PASS if free_gb >= 6.5 else WARN, f"{free_gb:.2f} GB")
    else:
        add("CUDA 可用", FAIL, "torch.cuda.is_available() == False")
        add("计算能力", FAIL, "跳过")
        add("总显存", FAIL, "跳过")
        add("可用显存", FAIL, "跳过")
except ImportError as exc:
    add("CUDA 可用", FAIL, f"无法 import torch：{exc}")
    add("torch.version.cuda", FAIL, "跳过")
    add("cuDNN 版本", FAIL, "跳过")
    add("计算能力", FAIL, "跳过")
    add("总显存", FAIL, "跳过")
    add("可用显存", FAIL, "跳过")

# ---------- 4. 硬盘空间 ----------
home = os.path.expanduser("~")
for label, path in [("用户目录", home), ("当前目录", os.getcwd())]:
    try:
        usage = shutil.disk_usage(path)
        free_gb = usage.free / 1024 ** 3
        status = PASS if free_gb >= 50 else (WARN if free_gb >= 20 else FAIL)
        add(f"磁盘 {label}", status, f"可用 {free_gb:.1f} GB（{path}）")
    except OSError as exc:
        add(f"磁盘 {label}", FAIL, str(exc))

# ---------- 5. Git 配置 ----------
code, git_ver = run(["git", "--version"])
if code != 0:
    add("Git 安装", FAIL, "未找到 git")
else:
    add("Git 安装", PASS, git_ver)
    for key in ("user.name", "user.email"):
        c, out = run(["git", "config", "--global", key])
        add(f"Git {key}", PASS if c == 0 and out else WARN, out or "未设置")
    c, out = run(["git", "remote", "get-url", "origin"])
    add("Git remote", PASS if c == 0 else WARN, out or "未配置 origin")

# ---------- 6. Hugging Face 连通性 ----------
endpoint = os.environ.get("HF_ENDPOINT", "https://huggingface.co")
add("HF_ENDPOINT", PASS if endpoint else WARN, endpoint)
try:
    req = urllib.request.Request(endpoint, method="HEAD")
    with urllib.request.urlopen(req, timeout=8) as resp:
        add("HF 连通性", PASS if resp.status < 400 else WARN, f"HTTP {resp.status}")
except Exception as exc:  # noqa: BLE001
    add("HF 连通性", WARN, f"不可达：{type(exc).__name__}；可用 HF_ENDPOINT=https://hf-mirror.com")
for var in ("HF_HOME", "HF_HUB_CACHE", "PYTORCH_CUDA_ALLOC_CONF"):
    add(f"环境变量 {var}", PASS if os.environ.get(var) else WARN,
        os.environ.get(var, "未设置"))

# ---------- 7. nvidia-smi 与端口 ----------
code, out = run(["nvidia-smi", "--query-gpu=driver_version,memory.total", "--format=csv,noheader"])
add("nvidia-smi", PASS if code == 0 else FAIL, out.splitlines()[0] if out else "不可用")

for name, port in [("Chroma", 8000), ("Grafana", 3000), ("Postgres", 5432)]:
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.settimeout(0.5)
        busy = s.connect_ex(("127.0.0.1", port)) == 0
    add(f"端口 {port} ({name})", WARN if busy else PASS,
        "已被占用" if busy else "空闲")

# ---------- 输出体检表 ----------
width = max(len(r[0]) for r in rows) + 2
print("=" * (width + 52))
print("开发环境体检表   平台: %s" % sys.platform)
print("=" * (width + 52))
for item, status, detail in rows:
    print(f"{item:<{width}}{status:<8}{detail}")
print("-" * (width + 52))

fails = sum(1 for _, s, _ in rows if s == FAIL)
warns = sum(1 for _, s, _ in rows if s == WARN)
print(f"合计 {len(rows)} 项：OK {len(rows) - fails - warns} / WARN {warns} / FAIL {fails}")
if fails:
    print("存在 FAIL，请回到第 3 章对应小节修复后再继续。")
    sys.exit(1)
print("全部关键项通过，可以进入第 4 章。")
```

## 3.11 常见错误速查表

遇到报错先在这里搜关键词。**所有命令都注明执行位置**，直接复制即可。

| 症状 | 原因 | 解决命令 |
| --- | --- | --- |
| `nvidia-smi` 不是内部或外部命令 | 驱动没装或 PATH 未刷新 | 重装 NVIDIA 驱动并重启；PowerShell 里确认 `C:\Windows\System32\nvidia-smi.exe` 存在 |
| `nvidia-smi` 报 `No devices were found` | 驱动异常，或显卡被禁用 | 设备管理器启用 GPU；`pnputil /enum-devices /class Display` 排查；重装驱动 |
| 显存空闲只有 5GB 多 | 浏览器硬件加速 + 本地 LLM 占着 | 关 Chrome/Edge 硬件加速（3.2.3）；`ollama ps` 后 `ollama stop ＜model＞`；`Stop-Process -Id ＜PID＞ -Force` |
| `nvidia-smi` 进程表为空但显存被占 | WDDM 下显示驱动占用，不显进程 | 用 `Get-Process | Sort-Object WorkingSet64 -Descending` 找大户；`wsl --shutdown` 清残留 |
| `torch.cuda.is_available()` 为 `False`，`torch.version.cuda` 为 `None` | 装了 CPU 版 torch | `uv pip uninstall torch torchvision torchaudio` 后按 3.4.2 用官方 `--index-url` 重装 |
| `torch.cuda.is_available()` 为 `False`，`torch.version.cuda` 有值 | 驱动过旧或被 Windows 更新降级 | `nvidia-smi` 看版本，< 525 就从 NVIDIA 官网重装并重启 |
| `no kernel image is available for execution on the device` | 轮子不含 sm_89 | `uv pip install --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu124` |
| `DLL load failed while importing _C` / `WinError 126` | 缺 VC++ 运行库或 DLL 冲突 | `winget install Microsoft.VCRedist.2015+.x64`；重装 torch；关掉其它 CUDA 程序的 PATH 注入 |
| `CUDA out of memory`（还没加载模型） | 基座占用过高或残留进程 | 关硬件加速；`Stop-Process` 杀残留 python；设 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` |
| `CUDA out of memory`（训练中） | batch/seq 过大或显存碎片 | 降 `per_device_train_batch_size=1`、加 `gradient_accumulation_steps`、`max_len=512`、开梯度检查点 |
| `RuntimeError: CUDA error: an illegal memory access` | 版本不匹配或自定义 kernel 越界 | 重装匹配版本三件套；`CUDA_LAUNCH_BLOCKING=1` 定位第一个出错算子 |
| `bitsandbytes` 导入报 `libbitsandbytes_cuda*.so` 找不到 | bnb 与 CUDA 版本不匹配（Windows 尤其常见） | WSL2 里装：`uv pip install bitsandbytes>=0.43`；Windows 侧改用 WSL2 跑 QLoRA |
| `uv: command not found` / `无法将"uv"项识别为...` | PATH 未刷新 | 新开终端；或 `$env:Path += ";$env:USERPROFILE\.local\bin"`（PowerShell） |
| `uv pip install` 卡住或超时 | 没配国内镜像 | 按 3.3.3 写 `uv.toml`；或临时加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| `Activate.ps1 ... 禁止运行脚本` | PowerShell 执行策略限制 | `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` |
| `wsl --install` 报 `0x80370102` | BIOS 未开虚拟化 | 进 BIOS 开启 Intel VT-x / AMD SVM；或 `Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform` |
| WSL 里 `nvidia-smi: command not found` | `/usr/lib/wsl/lib` 不在 PATH | `echo 'export PATH=/usr/lib/wsl/lib:$PATH' >> ~/.bashrc && source ~/.bashrc` |
| WSL 里看不到 GPU（Windows 侧正常） | WSL 内核过旧或 WSL 未重启 | `wsl --update` 然后 `wsl --shutdown`；仍不行则重启 Windows |
| WSL 训练时 Windows 卡死 | `.wslconfig` 没限制内存 | 按 3.5.2 写 `memory=16GB` 与 `swap=16GB`，`wsl --shutdown` 生效 |
| `/mnt/c` 下 `pip install` 慢到不可接受 | drvfs（9p）小文件性能差 | 把项目迁到 `~/projects`（3.5.4），在 ext4 里重建 `.venv` |
| `C:` 盘空间持续减少，删了文件也没释放 | WSL 的 `ext4.vhdx` 只增不减 | `wsl --shutdown` 后 `Optimize-VHD -Mode Full`；`.wslconfig` 开 `sparseVhd=true` |
| `docker: Cannot connect to the Docker daemon` | Docker Desktop 未启动或 WSL 集成未开 | 启动 Docker Desktop；Settings → Resources → WSL Integration 勾选 Ubuntu-22.04 |
| `docker run --gpus all` 报 `could not select device driver` | 未启用 GPU 支持 | 升级 Docker Desktop 到最新；`nvidia-smi` 在 WSL 正常后重试；`wsl --shutdown` 重启后端 |
| `port is already allocated` | 端口被占用 | 改用高位端口：`-p 18000:8000`；PowerShell 查占用：`Get-NetTCPConnection -LocalPort 8000` |
| `huggingface-cli download` 连接超时 | 直连 HF 被墙 | `export HF_ENDPOINT=https://hf-mirror.com`；或 `HF_ENDPOINT=... uv run huggingface-cli download ＜repo＞` |
| `git push` 报 `Permission denied (publickey)` | SSH key 未加或加错 | `ssh -T git@github.com` 自测；`cat ~/.ssh/id_ed25519.pub` 重新添加到 GitHub |
| `git push` 报 `remote: Support for password authentication was removed` | 用了密码而非 token | 改用 SSH（3.6.2）或 Personal Access Token |
| `git push` 报 `file is 156.00 MB; exceeds GitHub's file size limit of 100.00 MB` | 误提交模型权重 | `git rm --cached ＜file＞`，加进 `.gitignore`，必要时 `git lfs track` |
| `ssh -T git@github.com` 超时（22 端口被封） | 校园网/公司网封 22 | 在 `~/.ssh/config` 里改用 `HostName ssh.github.com` + `Port 443`（3.6.2） |
| VS Code 里 import 全红但终端能跑 | 解释器选错（选到系统 Python） | `Ctrl+Shift+P` → `Python: Select Interpreter` → 选 `.venv` 里的那个 |
| VS Code 调试断点不停（灰点） | `justMyCode` 限制或代码路径不一致 | `launch.json` 设 `"justMyCode": false`；确认断点所在文件就是当前 `program` |
| matplotlib 中文显示成方框 | 缺中文字体 | 装字体并在代码里设 `plt.rcParams["font.sans-serif"]=["Microsoft YaHei"]`（Windows）或 `["Noto Sans CJK SC"]`（WSL） |
| Jupyter 里 `ModuleNotFoundError` 但终端有该包 | 内核选错 | 右上角切到 `.venv` 内核；或 `uv run python -m ipykernel install --user --name llm-finetune` |
| 训练时 `GPU-Util` 长期低于 30% | 数据加载是瓶颈 | `DataLoader(num_workers=4, pin_memory=True, persistent_workers=True)`；把数据放本地 SSD |
| 训练第一轮很慢之后变快 | 首次 kernel 编译与缓存预热 | 正常现象；用 `torch.compile` 时第一次编译更要等几十秒 |

:::ok 排查的通用顺序
遇到问题的固定顺序：**① `nvidia-smi` 能不能出表 → ② `torch.version.cuda` 是不是 None → ③ `torch.cuda.is_available()` → ④ `torch.cuda.mem_get_info()` 看可用显存 → ⑤ 跑 `check_env.py` 看哪一项 FAIL**。这五步能覆盖本章 90% 以上的故障，不要一上来就重装系统或重装驱动。
:::
