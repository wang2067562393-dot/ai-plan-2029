### 14.2.1 通用答题流程（每一题都按这五步走）

1. **确认输入输出**：张量形状、dtype、device、是否含 batch 维、是否需要 mask。
2. **讲思路** 30 秒：先说数学式，再说张量形状变化。
3. **写代码**：先写形状注释，再写实现；变量名用 `q` `k` `v` 这类通用名。
4. **自测**：用一个小例子跑一遍，打印 shape 与数值范围。
5. **说边界**：fp16 溢出、序列长度为 1、mask 全 0、空输入。

### 14.2.2 第 1 题：多头自注意力（Multi-Head Self-Attention）

要求不调用 `nn.MultiheadAttention`，自己写 Q/K/V 投影、拆头、缩放点积、合并头。

```python
import math

import torch
import torch.nn as nn
import torch.nn.functional as F


class MultiHeadSelfAttention(nn.Module):
    def __init__(self, d_model: int = 512, n_heads: int = 8, dropout: float = 0.0):
        super().__init__()
        assert d_model % n_heads == 0, "d_model 必须能被 n_heads 整除"
        self.d_model = d_model
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads          # 每个头的维度，512/8 = 64

        # 一次线性层同时算出 Q/K/V，输出维度 3*d_model
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=True)
        self.out_proj = nn.Linear(d_model, d_model, bias=True)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor, attn_mask: torch.Tensor = None):
        # x: (batch, seq_len, d_model)
        b, s, _ = x.shape

        # 1) 投影并拆成 3 份：每个 (b, s, d_model)
        qkv = self.qkv(x)
        q, k, v = qkv.chunk(3, dim=-1)

        # 2) 拆头：把 d_model 拆成 (n_heads, head_dim)，再把头维换到前面
        #    (b, s, d_model) -> (b, s, n_heads, head_dim) -> (b, n_heads, s, head_dim)
        def split_heads(t):
            return t.view(b, s, self.n_heads, self.head_dim).transpose(1, 2)

        q, k, v = split_heads(q), split_heads(k), split_heads(v)

        # 3) 缩放点积注意力：softmax(QK^T / sqrt(head_dim)) V
        #    (b, h, s, hd) @ (b, h, hd, s) -> (b, h, s, s)
        scale = 1.0 / math.sqrt(self.head_dim)
        scores = torch.matmul(q, k.transpose(-2, -1)) * scale

        # 4) 加 mask：被屏蔽位置填 -inf，softmax 后权重为 0
        if attn_mask is not None:
            scores = scores.masked_fill(attn_mask == 0, float("-inf"))

        attn = F.softmax(scores, dim=-1)             # 在最后一维（key 维）归一化
        attn = self.dropout(attn)
        ctx = torch.matmul(attn, v)                  # (b, h, s, hd)

        # 5) 合并头：(b, h, s, hd) -> (b, s, h, hd) -> (b, s, d_model)
        ctx = ctx.transpose(1, 2).contiguous().view(b, s, self.d_model)
        return self.out_proj(ctx), attn


if __name__ == "__main__":
    torch.manual_seed(0)
    mha = MultiHeadSelfAttention(d_model=512, n_heads=8)
    x = torch.randn(2, 16, 512)
    y, a = mha(x)
    print("out:", tuple(y.shape), "attn:", tuple(a.shape), "row-sum:", a.sum(-1)[0, 0, 0].item())
```

预期输出：`out: (2, 16, 512) attn: (2, 8, 16, 16) row-sum: 1.0`。

逐行要点：

- `head_dim = d_model // n_heads`：多头不增加参数量，只是把 512 维拆成 8 个 64 维，让不同子空间学不同关系。
- 一次 `qkv` 线性层代替三个独立线性层：省一次 kernel 启动，参数总量相同。
- `view + transpose`：`view` 只做形状重塑（要求内存连续），`transpose` 交换轴会改变 stride，所以后面合并时要 `contiguous()`。
- `1/sqrt(head_dim)`：把点积的方差拉回 1 附近。若 Q、K 各维独立同分布、方差为 1，点积方差是 `head_dim`，开方缩放后标准差回到 1。
- `masked_fill(-inf)`：注意 fp16 下 `-inf` 参与减法可能出 `nan`，工程上常用 `-1e9` 或 `torch.finfo(dtype).min`。
- `softmax(dim=-1)`：归一化维是 key 维，每行权重和是 1。

面试官会追问：

- **为什么缩放因子是 `sqrt(head_dim)` 而不是 `sqrt(d_model)`？** 因为点积发生在单个头内，方差由 `head_dim` 决定；用 `d_model` 会让不同头数下温度不一致。
- **不缩放会怎样？** logits 数量级变大，softmax 输出接近 one-hot，梯度接近 0，训练不稳。
- **为什么拆头时用 `transpose` 而不是直接 `view`？** 直接 `view(b, s, h, hd)` 得到的 (h, hd) 排布是对的，但要和 Q 做矩阵乘需要把 h 提到 batch 维；`view` 后不 `transpose` 会让多头混在一起算。
- **`attn` 要不要返回？** 训练通常不需要；推理可视化与可解释性分析需要，但注意显存：`(b, h, s, s)` 在 s=2048、h=32 时是 4.3 亿个 float。
- **自回归解码时怎么改？** 加 causal mask（上三角为 0），并使用 KV Cache，见第 2 题。

### 14.2.3 第 2 题：带 KV Cache 的注意力（自回归解码）

目标：生成第 t 个 token 时，不重算前 t-1 个 key/value。

```python
import math

import torch
import torch.nn as nn
import torch.nn.functional as F


class CachedAttention(nn.Module):
    """支持逐 token 解码的注意力；prefill 与 decode 走同一条路径。"""

    def __init__(self, d_model: int = 512, n_heads: int = 8):
        super().__init__()
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        self.q_proj = nn.Linear(d_model, d_model, bias=False)
        self.k_proj = nn.Linear(d_model, d_model, bias=False)
        self.v_proj = nn.Linear(d_model, d_model, bias=False)
        self.o_proj = nn.Linear(d_model, d_model, bias=False)
        self.reset_cache()

    def reset_cache(self):
        # cache[k] = (b, h, past_len, hd)
        self.cache_k = None
        self.cache_v = None

    def _split(self, t):
        b, s, _ = t.shape
        return t.view(b, s, self.n_heads, self.head_dim).transpose(1, 2)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        b, s, _ = x.shape
        q = self._split(self.q_proj(x))            # (b, h, s, hd)
        k = self._split(self.k_proj(x))            # (b, h, s, hd)
        v = self._split(self.v_proj(x))

        # 1) 把本步的 k/v 拼到缓存后面
        if self.cache_k is None:
            self.cache_k, self.cache_v = k, v
        else:
            self.cache_k = torch.cat([self.cache_k, k], dim=2)
            self.cache_v = torch.cat([self.cache_v, v], dim=2)

        # 2) q 只和「全部历史的 k」做点积，得到 (b, h, s, past+s)
        scores = torch.matmul(q, self.cache_k.transpose(-2, -1)) / math.sqrt(self.head_dim)

        # 3) causal mask：位置 i 只能看 <= i 的 key（考虑已有缓存长度）
        past = self.cache_k.shape[2] - s
        q_pos = torch.arange(past, past + s, device=x.device).unsqueeze(1)
        k_pos = torch.arange(0, past + s, device=x.device).unsqueeze(0)
        allow = k_pos <= q_pos                          # (s, past+s) 布尔
        scores = scores.masked_fill(~allow, float("-inf"))

        attn = F.softmax(scores, dim=-1)
        ctx = torch.matmul(attn, self.cache_v)          # (b, h, s, hd)
        ctx = ctx.transpose(1, 2).contiguous().view(b, s, self.n_heads * self.head_dim)
        return self.o_proj(ctx)


if __name__ == "__main__":
    torch.manual_seed(0)
    att = CachedAttention(d_model=256, n_heads=4)

    prompt = torch.randn(1, 5, 256)
    out_prefill = att(prompt)
    print("prefill out:", tuple(out_prefill.shape), "cache len:", att.cache_k.shape[2])

    for t in range(3):
        step = torch.randn(1, 1, 256)
        out = att(step)
        print(f"decode step {t + 1}: out {tuple(out.shape)} cache len {att.cache_k.shape[2]}")
```

预期输出：

```text
prefill out: (1, 5, 256) cache len: 5
decode step 1: out (1, 1, 256) cache len 6
decode step 2: out (1, 1, 256) cache len 7
decode step 3: out (1, 1, 256) cache len 8
```

逐行要点：

- **prefill 与 decode 复用同一段代码**：prefill 时 `s = prompt_len`，decode 时 `s = 1`，只是 `s` 不同。
- 缓存里存的是**已经做过 K/V 投影**的张量，不是原输入，所以每步只需一次投影。
- causal mask 用「位置比较」而不是固定上三角，因为 cache 长度在变。
- `torch.cat` 每次都会新建张量、拷数据；工程实现要用预分配缓冲（`cache[pos:pos+1] = k`），面试时说清这一点是加分项。

面试官会追问：

- **KV Cache 的显存公式？** `2 * 2 字节（fp16） * n_layers * n_kv_heads * head_dim * seq_len * batch`。7B 级模型（32 层、8 个 KV 头、head_dim 128）在 seq 4096、batch 1 时约 0.5GB，改成 4bit 缓存能再砍。
- **为什么只缓存 K/V，不缓存 Q？** Q 只用于当前 token，历史 Q 不再需要；K/V 要被后续所有 token 复用。
- **GQA/MQA 怎么影响缓存？** KV 头数变少，缓存线性变小（MQA 时 n_kv_heads = 1）。
- **长上下文如何省显存？** 量化 cache（`q8_0`）、滑动窗口注意力、分页缓存（PagedAttention）。
- **为什么不用 `torch.no_grad()` 就一定出错？** 不会出错，但会把计算图挂住，显存持续增长；推理必须 `torch.no_grad()` 或 `inference_mode()`。

### 14.2.4 第 3 题：LoRA 前向与权重合并

要求：实现 LoRA 层（A 用高斯初始化、B 用零初始化），并实现把 `B @ A * scaling` 合并进原权重的函数。

```python
import torch
import torch.nn as nn


class LoRALinear(nn.Module):
    """在冻结的线性层上挂 LoRA 旁路：y = W x + (alpha / r) * B (A x)。"""

    def __init__(self, base: nn.Linear, r: int = 16, alpha: int = 32, dropout: float = 0.0):
        super().__init__()
        self.base = base
        for p in self.base.parameters():      # 冻结基座权重
            p.requires_grad = False

        self.r = r
        self.scaling = alpha / r              # 32/16 = 2.0
        self.lora_A = nn.Linear(base.in_features, r, bias=False)
        self.lora_B = nn.Linear(r, base.out_features, bias=False)
        self.dropout = nn.Dropout(dropout)

        # A 用 kaiming/高斯初始化，B 用零初始化：训练开始时旁路输出恒为 0
        nn.init.kaiming_uniform_(self.lora_A.weight, a=5 ** 0.5)
        nn.init.zeros_(self.lora_B.weight)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        base_out = self.base(x)
        lora_out = self.lora_B(self.lora_A(self.dropout(x))) * self.scaling
        return base_out + lora_out

    @torch.no_grad()
    def merge(self) -> nn.Linear:
        """把 LoRA 权重合并进基座，返回等价的无旁路线性层（用于推理部署）。"""
        w = self.base.weight
        delta = (self.lora_B.weight @ self.lora_A.weight) * self.scaling   # (out, in)
        merged = nn.Linear(self.base.in_features, self.base.out_features,
                           bias=self.base.bias is not None)
        merged.weight.copy_(w + delta.to(w.dtype))
        if self.base.bias is not None:
            merged.bias.copy_(self.base.bias)
        return merged


if __name__ == "__main__":
    torch.manual_seed(0)
    base = nn.Linear(64, 32)
    lora = LoRALinear(base, r=8, alpha=16)
    x = torch.randn(4, 64)

    with torch.no_grad():
        before = lora(x).clone()
        print("初始阶段旁路为 0，输出应当与基座一致:",
              torch.allclose(before, base(x), atol=1e-6))

    # 手工造一个非零 B，验证 merge 前后的等价性
    with torch.no_grad():
        lora.lora_B.weight.normal_(0, 0.02)
    y1 = lora(x)
    merged = lora.merge()
    y2 = merged(x)
    print("merge 前后最大误差:", (y1 - y2).abs().max().item())
    print("可训练参数占比: %.3f%%" % (
        100 * sum(p.numel() for p in lora.parameters() if p.requires_grad)
        / sum(p.numel() for p in lora.parameters())))
```

预期输出（数值仅示意）：

```text
初始阶段旁路为 0，输出应当与基座一致: True
merge 前后最大误差: 1.1920928955078125e-07
可训练参数占比: 1.091%
```

逐行要点：

- **B 零初始化**是 LoRA 的关键：训练第 0 步模型行为与基座完全相同，避免冷启动破坏预训练能力。
- `scaling = alpha / r`：调 alpha 等价于调学习率尺度，所以换 r 时可以固定 alpha 保持有效步长。
- `merge` 里 `(out, r) @ (r, in) = (out, in)`，形状和基座权重一致，可直接相加。
- 合并后**没有精度损失**（除了浮点误差），但合并是不可逆的：想再微调必须保留原始基座与适配器。

面试官会追问：

- **r 怎么选？** 8/16/32 三组消融；本项目 r=16 是拐点，r=32 提升 0.6pt 但显存与训练时间增加约 60%。
- **LoRA 挂在哪几层？** 常见 `q_proj, k_proj, v_proj, o_proj`，也可加 `gate_proj, up_proj, down_proj`；挂 MLP 一般比只挂注意力效果好但更慢。
- **为什么 A 用高斯、B 用零，反过来行不行？** 反过来的话第一步旁路输出也是 0，但梯度会先只更新 A 的某一列方向，收敛略差；社区惯例是 A 随机、B 零。
- **合并到 fp16 的注意事项？** 7B fp16 基座约 14GB，8GB 卡上必须用 CPU 合并，或直接交付适配器 + 原基座。
- **LoRA 和 Adapter、Prefix Tuning 的区别？** LoRA 加的是并行低秩旁路、无推理延迟（可合并）；Adapter 插在层间、有串行延迟；Prefix 加的是可训练前缀，占序列长度。

### 14.2.5 第 4 题：Softmax 的数值稳定实现

```python
import numpy as np
import torch


def softmax_np(x: np.ndarray, axis: int = -1) -> np.ndarray:
    """数值稳定的 softmax：先减去最大值，避免 exp 溢出。"""
    x = x - np.max(x, axis=axis, keepdims=True)   # 最大值变成 0，其余 <= 0
    e = np.exp(x)                                 # 结果落在 (0, 1]，不会溢出
    return e / np.sum(e, axis=axis, keepdims=True)


def softmax_torch(x: torch.Tensor, dim: int = -1) -> torch.Tensor:
    x = x - x.max(dim=dim, keepdim=True).values
    e = torch.exp(x)
    return e / e.sum(dim=dim, keepdim=True)


if __name__ == "__main__":
    big = np.array([[1000.0, 1001.0, 1002.0]])

    # 不稳定的写法：exp(1000) 直接溢出为 inf
    with np.errstate(over="ignore"):
        naive = np.exp(big) / np.exp(big).sum()
    print("naive:", naive)

    print("stable:", softmax_np(big))
    print("torch  :", softmax_torch(torch.tensor(big)).numpy())
    # 极端情况：全部相等 -> 均匀分布
    print("uniform:", softmax_np(np.zeros((1, 4))))
```

预期输出：

```text
naive: [[nan nan nan]]
stable: [[0.09003057 0.24472847 0.66524096]]
torch  : [[0.09003057 0.24472847 0.66524096]]
uniform: [[0.25 0.25 0.25 0.25]]
```

逐行要点：

- 数学上 `softmax(x) = softmax(x - c)`，因为分子分母同乘 `exp(-c)`；取 `c = max(x)` 是最省事的做法。
- 减最大值后所有指数 ≤ 0，`exp` 结果落在 `(0, 1]`，不会上溢；下溢成 0 是可接受的（该位置概率本就极小）。
- `keepdims=True` 很关键，否则广播形状会出错。
- 全相等时输出均匀分布，权重 1/n。

面试官会追问：

- **减最大值和减均值有什么区别？** 都稳定，但减均值不能保证不溢出（可能仍有正的大值）；减最大值是最坏情况最稳的。
- **fp16 下为什么还会 nan？** 如果输入里已经有 `inf` 或 `nan`（例如 mask 用了 `-inf` 又做了减法），会把 nan 传播开；用 `torch.finfo(dtype).min` 更安全。
- **softmax 的反向传播？** `dL/dx_i = y_i * (dL/dy_i - sum_j(dL/dy_j * y_j))`，其中 y 是 softmax 输出。
- **手写 softmax 与 `F.softmax` 谁快？** 融合实现更快；手写会多几次读写。面试写手写版是为了证明你懂原理。
- **温度参数怎么加？** `softmax(x / T)`；T < 1 更尖锐、T > 1 更平均，采样与蒸馏都用它。

### 14.2.6 第 5 题：交叉熵损失（含 logits 与 label smoothing）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


def cross_entropy_from_scratch(logits: torch.Tensor, targets: torch.Tensor) -> torch.Tensor:
    """logits: (N, C)，targets: (N,) 的类别下标。返回 batch 平均损失。"""
    # 1) log-softmax（稳定写法）：log_softmax = x - logsumexp(x)
    x = logits - logits.max(dim=-1, keepdim=True).values
    log_sum_exp = torch.log(torch.exp(x).sum(dim=-1, keepdim=True))
    log_probs = x - log_sum_exp                       # (N, C)
    # 2) 取每个样本正确类别的 log 概率，再取负均值
    n = logits.shape[0]
    picked = log_probs[torch.arange(n, device=logits.device), targets]
    return -picked.mean()


def soft_target_ce(logits: torch.Tensor, targets: torch.Tensor, eps: float = 0.1):
    """label smoothing：把 one-hot 变成 (1-eps) + eps/C。"""
    c = logits.shape[-1]
    smooth = torch.full_like(logits, eps / c)
    smooth.scatter_(1, targets.unsqueeze(1), 1.0 - eps + eps / c)
    log_probs = F.log_softmax(logits, dim=-1)
    return -(smooth * log_probs).sum(dim=-1).mean()


if __name__ == "__main__":
    torch.manual_seed(0)
    logits = torch.randn(4, 5)
    targets = torch.tensor([0, 2, 4, 1])

    mine = cross_entropy_from_scratch(logits, targets)
    ref = F.cross_entropy(logits, targets)
    print("手写: %.6f 官方: %.6f 误差: %.2e" % (mine.item(), ref.item(), abs(mine - ref).item()))
    print("label smoothing loss: %.6f" % soft_target_ce(logits, targets).item())
    print("logits 乘 10 后的手写 loss: %.6f" % (
        cross_entropy_from_scratch(logits * 10, targets).item()))
```

预期输出（数值仅示意）：

```text
手写: 1.743421 官方: 1.743421 误差: 0.00e+00
label smoothing loss: 1.887259
logits 乘 10 后的手写 loss: 4.201176
```

逐行要点：

- 交叉熵 = `-log(softmax 在正确类别上的概率)`；等价于 `logsumexp(logits) - logit[正确类]`，这也是更稳的写法。
- 不要先 `softmax` 再 `log`：`log(softmax(x))` 在概率接近 0 时会下溢成 `-inf`；`log_softmax` 一次算完，稳定。
- `logsumexp` 技巧与 softmax 减最大值是同一套思路。
- label smoothing 相当于给非正确类别留一点概率，抑制过度自信，常配 `eps = 0.1`。

面试官会追问：

- **为什么交叉熵比 MSE 适合分类？** 交叉熵的梯度含 `(y - p)` 项，错得越离谱梯度越大；MSE 经 sigmoid/softmax 后会有梯度饱和区。
- **类别不均衡怎么办？** 用 `weight=` 传类别权重，或用 focal loss（`-(1-p)^gamma * log p`），gamma 常取 2。
- **`reduction` 三种取值的区别？** `mean` 除以有效样本数（ignore_index 的样本被排除）、`sum` 不除、`none` 返回逐样本损失。
- **大词表下的显存问题？** `(N, V)` 的 logits 在 V=15 万、N=4096 时约 2.3GB（fp16 1.15GB）；可用 fused linear cross entropy 或分块计算。
- **label smoothing 会带来什么副作用？** 降低置信度、可能让校准变差；对需要精确概率的场景要慎用。

### 14.2.7 第 6 题：BatchNorm / LayerNorm / RMSNorm

```python
import torch
import torch.nn as nn


class MyBatchNorm(nn.Module):
    """训练时用 batch 统计量，推理时用滑动平均；沿 (N, H, W) 归一化。"""

    def __init__(self, num_features: int, eps: float = 1e-5, momentum: float = 0.1):
        super().__init__()
        self.eps = eps
        self.momentum = momentum
        self.gamma = nn.Parameter(torch.ones(num_features))
        self.beta = nn.Parameter(torch.zeros(num_features))
        self.register_buffer("running_mean", torch.zeros(num_features))
        self.register_buffer("running_var", torch.ones(num_features))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x: (N, C, H, W) 或 (N, C)
        shape = (1, -1) + (1,) * (x.dim() - 2)
        if self.training:
            dims = (0,) + tuple(range(2, x.dim()))
            mean = x.mean(dim=dims)
            var = x.var(dim=dims, unbiased=False)
            with torch.no_grad():                     # 滑动平均不进计算图
                self.running_mean.mul_(1 - self.momentum).add_(self.momentum * mean)
                self.running_var.mul_(1 - self.momentum).add_(self.momentum * var)
        else:
            mean, var = self.running_mean, self.running_var
        x_hat = (x - mean.view(shape)) / torch.sqrt(var.view(shape) + self.eps)
        return x_hat * self.gamma.view(shape) + self.beta.view(shape)


class MyLayerNorm(nn.Module):
    """对每个样本的最后若干维归一化，训练与推理行为一致。"""

    def __init__(self, normalized_shape, eps: float = 1e-5):
        super().__init__()
        self.eps = eps
        self.gamma = nn.Parameter(torch.ones(normalized_shape))
        self.beta = nn.Parameter(torch.zeros(normalized_shape))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        mean = x.mean(dim=-1, keepdim=True)
        var = x.var(dim=-1, unbiased=False, keepdim=True)
        return (x - mean) / torch.sqrt(var + self.eps) * self.gamma + self.beta


class RMSNorm(nn.Module):
    """只用均方根归一化，不减均值、不加 beta，比 LayerNorm 少一次规约。"""

    def __init__(self, dim: int, eps: float = 1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        rms = torch.sqrt(x.pow(2).mean(dim=-1, keepdim=True) + self.eps)
        return x / rms * self.weight


class PreNormBlock(nn.Module):
    """Pre-Norm 结构：x = x + f(norm(x))；Post-Norm 是 x = norm(x + f(x))。"""

    def __init__(self, d_model: int = 64):
        super().__init__()
        self.norm = MyLayerNorm(d_model)
        self.ffn = nn.Sequential(nn.Linear(d_model, 4 * d_model), nn.GELU(),
                                 nn.Linear(4 * d_model, d_model))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return x + self.ffn(self.norm(x))             # Pre-Norm


if __name__ == "__main__":
    torch.manual_seed(0)
    x4 = torch.randn(8, 4, 6, 6)
    bn = MyBatchNorm(4)
    print("BN 训练:", tuple(bn(x4).shape), "running_mean:", bn.running_mean.tolist())
    bn.eval()
    print("BN 推理:", tuple(bn(x4).shape))

    x3 = torch.randn(8, 16, 32)
    ln, rms = MyLayerNorm(32), RMSNorm(32)
    y_ln, y_rms = ln(x3), rms(x3)
    print("LN 每行均值/方差:", y_ln.mean(-1).abs().max().item(), y_ln.var(-1, unbiased=False).mean().item())
    print("RMSNorm 每行均方根:", y_rms.pow(2).mean(-1).sqrt().mean().item())
    print("PreNorm 输出形状:", tuple(PreNormBlock(32)(x3).shape))
```

预期输出（数值仅示意）：

```text
BN 训练: (8, 4, 6, 6) running_mean: [0.001, -0.002, 0.000, 0.001]
BN 推理: (8, 4, 6, 6)
LN 每行均值/方差: 1.1e-07 0.9999
RMSNorm 每行均方根: 1.0
PreNorm 输出形状: (8, 16, 32)
```

逐行要点：

- **BatchNorm 沿 batch 维**做统计：`(N, C, H, W)` 时对每个通道 C 在 N/H/W 上求均值方差；因此依赖 batch 大小，小 batch 不稳，且训练/推理不一致（推理用 running 统计量）。
- **LayerNorm 沿特征维**做统计：每个 token 单独归一化，与 batch 无关，所以 Transformer 用它。
- **RMSNorm** 不减均值、不学 `beta`，只除以均方根；省掉一次规约与减法，速度提升约 5–10%，大模型（Llama、Qwen）普遍使用。
- `unbiased=False`：归一化用的是有偏方差（除以 N），推理时才用它；用 `unbiased=True` 会让训练/推理数值不一致。
- **Pre-Norm vs Post-Norm**：Pre-Norm 的残差通路无归一化，深层梯度更顺，训练更稳，是现在的主流；Post-Norm 表达力略强但需要 warmup。

面试官会追问：

- **BN 为什么在推理时要改统计量？** 推理时 batch 可能只有 1，用 batch 统计量会引入噪声并和训练分布不一致；用滑动平均才与训练期望一致。
- **BatchNorm 和 Dropout 一起用有什么问题？** 方差偏移（训练时方差被 Dropout 放大，推理时不放大），常见做法是把 Dropout 放在 BN 之后或调小 momentum。
- **LayerNorm 的反向传播会跨样本吗？** 不会，每个样本独立；这也是它能用于变长序列的原因。
- **为什么 RMSNorm 不减均值也有效？** 均值偏移可由后续线性层的 bias 吸收；真正影响尺度的是方差。
- **把 LayerNorm 换成 RMSNorm 需要改什么？** 直接替换即可，通常配合更小的 eps（1e-6）与重新调学习率 warmup。

### 14.2.8 第 7 题：IoU 与 NMS（纯 NumPy 可运行）

```python
import numpy as np


def iou_matrix(boxes_a: np.ndarray, boxes_b: np.ndarray) -> np.ndarray:
    """boxes 格式为 (x1, y1, x2, y2)。返回 (len(a), len(b)) 的 IoU 矩阵。"""
    a = boxes_a[:, None, :]                      # (A, 1, 4)
    b = boxes_b[None, :, :]                      # (1, B, 4)

    inter_x1 = np.maximum(a[..., 0], b[..., 0])
    inter_y1 = np.maximum(a[..., 1], b[..., 1])
    inter_x2 = np.minimum(a[..., 2], b[..., 2])
    inter_y2 = np.minimum(a[..., 3], b[..., 3])

    inter_w = np.clip(inter_x2 - inter_x1, 0, None)    # 不相交时为 0
    inter_h = np.clip(inter_y2 - inter_y1, 0, None)
    inter = inter_w * inter_h

    area_a = (boxes_a[:, 2] - boxes_a[:, 0]) * (boxes_a[:, 3] - boxes_a[:, 1])
    area_b = (boxes_b[:, 2] - boxes_b[:, 0]) * (boxes_b[:, 3] - boxes_b[:, 1])
    union = area_a[:, None] + area_b[None, :] - inter
    return inter / np.clip(union, 1e-9, None)


def nms(boxes: np.ndarray, scores: np.ndarray, iou_thr: float = 0.5) -> list:
    """单类别 NMS，返回保留的下标列表（按分数从高到低）。"""
    order = scores.argsort()[::-1]                # 分数降序
    keep = []
    while order.size > 0:
        i = order[0]
        keep.append(int(i))
        if order.size == 1:
            break
        ious = iou_matrix(boxes[i:i + 1], boxes[order[1:]])[0]
        order = order[1:][ious <= iou_thr]        # 压掉与当前框重叠过高的候选
    return keep


def soft_nms(boxes: np.ndarray, scores: np.ndarray, iou_thr: float = 0.3,
             sigma: float = 0.5) -> list:
    """Soft-NMS：重叠越高，分数衰减越多（高斯惩罚），不是直接丢弃。"""
    scores = scores.astype(np.float64).copy()
    idx = list(range(len(boxes)))
    keep = []
    while idx:
        k = int(np.argmax(scores[idx]))
        cur = idx.pop(k)
        if scores[cur] < 0.001:
            continue
        keep.append(cur)
        if idx:
            ious = iou_matrix(boxes[cur:cur + 1], boxes[idx])[0]
            scores[idx] *= np.exp(-(ious ** 2) / sigma)     # 高斯衰减
    return keep


if __name__ == "__main__":
    boxes = np.array([
        [10, 10, 60, 60],
        [12, 12, 62, 62],
        [100, 100, 150, 150],
        [105, 105, 155, 155],
        [200, 200, 260, 260],
    ], dtype=np.float64)
    scores = np.array([0.91, 0.85, 0.78, 0.60, 0.55])

    print("IoU(0,1) = %.4f" % iou_matrix(boxes[:1], boxes[1:2])[0, 0])
    print("NMS 保留:", nms(boxes, scores, 0.5))
    print("Soft-NMS 保留:", soft_nms(boxes, scores, sigma=0.5))
```

预期输出：

```text
IoU(0,1) = 0.8824
NMS 保留: [0, 2, 4]
Soft-NMS 保留: [0, 2, 4]
```

逐行要点：

- IoU 用广播一次算出所有框对，避免双重循环（O(A×B) 向量化）。
- `np.clip(..., 0, None)`：两个框不相交时宽或高为负数，必须截断到 0，否则交集面积会变成正数。
- NMS 是贪心：每次取最高分框，压掉与它 IoU 超阈值的框；复杂度 O(n²)。
- Soft-NMS 不丢框而是降分，密集目标场景召回率更好（COCO 上常见 +1–2pt）。

面试官会追问：

- **NMS 里阈值取 0.5 还是 0.7？** 0.5 更严格、去重更强但可能误删相邻真目标；密集小目标常放宽到 0.6–0.7。
- **为什么 IoU 不能处理「包含」关系？** 大框完全包含小框时，IoU 可能只有 0.3 但实际是同一个目标；改用 GIoU/DIoU/CIoU 或 IoA。
- **NMS 的复杂度与优化？** O(n²)；优化手段有先按分数截断候选（只留前 1000）、按类别并行、用 CUDA kernel 融合（TensorRT 的 EfficientNMS 插件）。
- **分类 NMS 与类内 NMS 的差别？** 类内只在自己类别里压，类间不压；多类别检测必须先按类别分开做。
- **训练时为什么不用 NMS？** 训练用全部 anchor 算损失；NMS 只在推理后处理阶段使用。

### 14.2.9 第 8 题：Top-k / Top-p 采样（含温度）

```python
import torch
import torch.nn.functional as F


def top_k_filter(logits: torch.Tensor, k: int) -> torch.Tensor:
    """把第 k 大之外的 logits 设为 -inf。"""
    k = min(k, logits.size(-1))
    kth = torch.topk(logits, k, dim=-1).values[..., -1, None]
    return logits.masked_fill(logits < kth, float("-inf"))


def top_p_filter(logits: torch.Tensor, p: float) -> torch.Tensor:
    """核采样：保留累积概率刚超过 p 的最小集合。"""
    sorted_logits, sorted_idx = torch.sort(logits, descending=True, dim=-1)
    probs = F.softmax(sorted_logits, dim=-1)
    cum = probs.cumsum(dim=-1)

    # 累积概率超过 p 的位置以及它后面的全部屏蔽；至少保留 1 个 token
    remove = cum - probs > p
    sorted_logits = sorted_logits.masked_fill(remove, float("-inf"))

    # 还原回原始词表顺序
    out = torch.full_like(logits, float("-inf"))
    out.scatter_(-1, sorted_idx, sorted_logits)
    return out


def sample(logits: torch.Tensor, temperature: float = 1.0,
           top_k: int = 0, top_p: float = 1.0, generator: torch.Generator = None) -> int:
    logits = logits / max(temperature, 1e-6)      # 温度：<1 更确定，>1 更随机
    if top_k and top_k > 0:
        logits = top_k_filter(logits, top_k)
    if top_p < 1.0:
        logits = top_p_filter(logits, top_p)
    probs = F.softmax(logits, dim=-1)
    return int(torch.multinomial(probs, num_samples=1, generator=generator).item())


if __name__ == "__main__":
    torch.manual_seed(0)
    logits = torch.tensor([2.0, 1.5, 0.9, 0.4, 0.1, -0.5, -2.0, -6.0])
    print("top_k=3 保留数量:", int(torch.isfinite(top_k_filter(logits, 3)).sum()))
    kept = top_p_filter(logits, 0.9)
    print("top_p=0.9 保留下标:", torch.nonzero(torch.isfinite(kept)).flatten().tolist())
    print("温度 0.2 时最高概率:", F.softmax(logits / 0.2, -1).max().item())
    print("温度 2.0 时最高概率:", F.softmax(logits / 2.0, -1).max().item())
    g = torch.Generator().manual_seed(42)
    print("采样结果:", [sample(logits, 0.8, 3, 0.9, g) for _ in range(5)])
```

预期输出（数值仅示意）：

```text
top_k=3 保留数量: 3
top_p=0.9 保留下标: [0, 1, 2, 3, 4]
温度 0.2 时最高概率: 0.9241
温度 2.0 时最高概率: 0.2987
采样结果: [0, 0, 1, 0, 0]
```

逐行要点：

- Top-k 用 `torch.topk` 拿第 k 大的值作为阈值，`masked_fill` 成 `-inf`，softmax 后概率为 0。
- Top-p 必须先排序再算累积概率；`remove = cum - probs > p` 保证「累积刚超过 p 的那个 token 保留」，总保留概率 ≥ p。
- 还原原始顺序用 `scatter_`，这一步最容易被漏掉，漏了会导致 token 与概率错位。
- 温度作用在 softmax 之前：`softmax(logits / T)`；T → 0 退化为贪心。
- **推理可复现**：给 `torch.Generator` 设种子，或调用 `torch.manual_seed`。

面试官会追问：

- **top_k 和 top_p 该用哪个？** 通常只用一个；top_p 自适应（分布尖时保留少、平时保留多），是主流默认（`top_p=0.9`）。
- **为什么温度不能设 0？** 除零；想贪心就直接 `argmax`，或设一个极小值如 1e-6。
- **重复惩罚怎么实现？** 对已出现 token 的 logits 减去 `repetition_penalty` 或乘一个系数；也可用 presence/frequency penalty。
- **为什么采样要 `multinomial` 而不是排序后取最大值？** 取最大值是贪心解码，多样性为零，长文本会重复。
- **beam search 与采样的区别？** beam search 维护 k 条候选路径、最大化总似然，适合翻译；采样适合开放式生成。beam search 有长度偏置，需要长度归一化。

### 14.2.10 第 9 题：RRF 混合检索融合（Reciprocal Rank Fusion）

```python
from typing import Dict, List, Sequence


def rrf_fuse(rankings: Sequence[Sequence[str]], k: int = 60,
             weights: Sequence[float] = None) -> List[tuple]:
    """把多路有序检索结果融合成一个有序列表。

    rankings: 每路检索结果，元素是文档 id，按相关性降序排列
    k: 平滑常数，常用 60；weights: 每路权重，默认均等
    返回按融合分数降序的 (doc_id, score) 列表
    """
    if weights is None:
        weights = [1.0] * len(rankings)

    scores: Dict[str, float] = {}
    for w, ranking in zip(weights, rankings):
        for rank, doc_id in enumerate(ranking, start=1):     # 名次从 1 开始
            scores[doc_id] = scores.get(doc_id, 0.0) + w / (k + rank)

    return sorted(scores.items(), key=lambda kv: kv[1], reverse=True)


def weighted_score_fuse(dense: List[tuple], sparse: List[tuple],
                        alpha: float = 0.5, k: int = 60) -> List[tuple]:
    """按权重融合两路的 RRF 分数（例如 0.7 向量 + 0.3 BM25）。"""
    dense_rank = [d for d, _ in dense]
    sparse_rank = [d for d, _ in sparse]
    return rrf_fuse([dense_rank, sparse_rank], k=k, weights=[alpha, 1 - alpha])


if __name__ == "__main__":
    dense = ["doc7", "doc3", "doc1", "doc9", "doc5"]      # 向量召回（名次已排好）
    sparse = ["doc3", "doc1", "doc8", "doc7", "doc2"]     # BM25 召回

    print("均等融合:", rrf_fuse([dense, sparse], k=60)[:5])
    print("0.7/0.3 融合:", weighted_score_fuse(
        [(d, 1.0 - i * 0.1) for i, d in enumerate(dense)],
        [(d, 1.0 - i * 0.1) for i, d in enumerate(sparse)], alpha=0.7)[:5])

    # 单路也能验证公式手算：doc3 在向量路第 2、BM25 路第 1 -> 1/62 + 1/61
    print("手算 doc3 = %.6f" % (1 / 62 + 1 / 61))
    print("三路融合示例:", rrf_fuse([dense, sparse, ["doc9", "doc5", "doc3"]], k=60)[:3])
```

预期输出（数值仅示意）：

```text
均等融合: [('doc3', ...), ('doc7', ...), ('doc1', ...), ('doc8', ...), ('doc9', ...)]
0.7/0.3 融合: [('doc3', ...), ('doc7', ...), ('doc1', ...), ('doc2', ...), ('doc9', ...)]
手算 doc3 = 0.032526
三路融合示例: [('doc3', ...), ('doc7', ...), ('doc9', ...)]
```

逐行要点：

- RRF 只用**名次**，不用原始分数；所以能天然融合量纲完全不同的两路（余弦相似度 vs BM25 分）。
- 公式 `score(d) = Σ w_i / (k + rank_i(d))`；`k = 60` 是原论文默认值，作用是压平头部差距，避免某一路的第 1 名独占。
- 名次从 1 开始；若某路没有该文档则该路不贡献分数（不需要补 0）。
- 只在多路都靠前的文档会被顶上来，这正是混合检索互补性的来源。
- 权重可调：中文技术文档里 BM25 对型号、编号类查询很关键，常见 0.6–0.7 给向量、0.3–0.4 给 BM25。

面试官会追问：

- **为什么不直接把分数归一化后相加？** BM25 分数没有上界、分布随语料变化，min-max 归一化在跨查询时不稳定；RRF 对分数尺度免疫。
- **k 取多大有影响？** k 越大越平等（长尾也被考虑），k 越小则只信头部；60 是经验值，可以用验证集在 {10, 30, 60, 100} 里选。
- **RRF 和加权求和（Convex Combination）哪个好？** 实测各有胜负；加权求和需要调归一化，RRF 更省事、更稳，本项目实测 Recall@5 比单路向量高 12pt。
- **加 Rerank 之后 RRF 还有用吗？** 有；RRF 负责把候选集做「召回」，reranker 负责「精排」，两阶段分工。候选集从 5 扩到 50 再重排，召回率还能涨。
- **三路以上怎么融合？** 公式不变，直接多路相加（例如向量 + BM25 + 标题字段匹配），每路可以不同权重。

### 14.2.11 第 10 题（二选一）

#### 选项 A：K 个一组反转链表

```python
from typing import Optional


class ListNode:
    def __init__(self, val: int = 0, nxt: Optional["ListNode"] = None):
        self.val = val
        self.next = nxt


def build(vals) -> Optional[ListNode]:
    dummy = ListNode(0)
    cur = dummy
    for v in vals:
        cur.next = ListNode(v)
        cur = cur.next
    return dummy.next


def to_list(head: Optional[ListNode]) -> list:
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out


def reverse_k_group(head: Optional[ListNode], k: int) -> Optional[ListNode]:
    """每 k 个节点反转一次；末尾不足 k 个保持原顺序。时间 O(n)，额外空间 O(1)。"""
    if k <= 1 or head is None:
        return head

    dummy = ListNode(0, head)
    group_prev = dummy                      # 上一组的尾节点

    while True:
        # 1) 找到本组的第 k 个节点；走不到就说明剩余不足 k 个，直接结束
        kth = group_prev
        for _ in range(k):
            kth = kth.next
            if kth is None:
                return dummy.next

        group_next = kth.next               # 下一组的头
        # 2) 组内反转：prev 从 group_next 开始，方便最后接回下一组
        prev, cur = group_next, group_prev.next
        for _ in range(k):
            nxt = cur.next
            cur.next = prev
            prev = cur
            cur = nxt

        # 3) 把上一组尾节点指向反转后的新头（原第 k 个节点）
        new_tail = group_prev.next
        group_prev.next = kth
        group_prev = new_tail

    return dummy.next


if __name__ == "__main__":
    print(to_list(reverse_k_group(build([1, 2, 3, 4, 5]), 2)))
    print(to_list(reverse_k_group(build([1, 2, 3, 4, 5]), 3)))
    print(to_list(reverse_k_group(build([1, 2, 3, 4, 5]), 1)))
    print(to_list(reverse_k_group(build([1]), 2)))
    print(to_list(reverse_k_group(build([]), 3)))
```

预期输出：

```text
[2, 1, 4, 3, 5]
[3, 2, 1, 4, 5]
[1, 2, 3, 4, 5]
[1]
[]
```

追问要点：

- **为什么先判断本组够不够 k 个？** 不足 k 个的尾巴不反转；先探路一次，避免反转后再回退。
- **`prev` 为什么从 `group_next` 开始？** 这样组内第一个节点（反转后变成组尾）的 next 自动指向下一组的头，省掉一次接链。
- **空间复杂度？** O(1) 额外指针；递归写法是 O(n/k) 栈空间。
- **链表题通用技巧？** dummy 头节点统一处理「头节点被改动」的情形；画三指针图；先写边界用例（k=1、单节点、空链表）。

#### 选项 B：滑动窗口最大值

```python
from collections import deque
from typing import List


def max_sliding_window(nums: List[int], k: int) -> List[int]:
    """单调递减双端队列，时间 O(n)、空间 O(k)。"""
    if not nums or k <= 0:
        return []
    dq = deque()          # 存下标，对应的值从队首到队尾递减
    out = []
    for i, v in enumerate(nums):
        # 1) 队尾比当前值小的全部弹出：它们不可能是未来窗口的最大值
        while dq and nums[dq[-1]] <= v:
            dq.pop()
        dq.append(i)
        # 2) 队首下标滑出窗口就弹出
        if dq[0] <= i - k:
            dq.popleft()
        # 3) 窗口形成后开始记录（i >= k-1）
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out


if __name__ == "__main__":
    print(max_sliding_window([1, 3, -1, -3, 5, 3, 6, 7], 3))
    print(max_sliding_window([1], 1))
    print(max_sliding_window([9, 8, 7, 6], 2))
    print(max_sliding_window([4, 2, 12, 3, 8], 3))
```

预期输出：

```text
[3, 3, 5, 5, 6, 7]
[1]
[9, 8, 7]
[4, 12, 12]
```

追问要点：

- **为什么是 O(n)？** 每个下标最多入队一次、出队一次，均摊 O(1)。
- **为什么用 `<=` 而不是 `<`？** 相等时保留旧值会让队首更早过期；弹出旧值不影响正确性且队列更短。
- **窗口为 1 或 k > n 会怎样？** k=1 时每个元素都是答案；k > n 时输出空列表（第 3 步永不触发）。
- **还能怎么解？** 优先队列 O(n log n)、分块预处理（稀疏表）O(n)；面试时先给 O(n log n) 再优化到 O(n) 是稳妥策略。
- **同类题有哪些？** 长度最小的子数组、无重复字符的最长子串、恰好包含 K 个不同字符的最长子串。

## 14.3 深度学习八股 40 问（问题 + 答案要点）

### 14.3.1 归一化与训练稳定性（第 1–8 问）

**1. BatchNorm 和 LayerNorm 的核心区别？**
BN 在 batch 维做统计，依赖 batch 大小，训练与推理行为不一致；LN 在特征维做统计，每条样本独立，训练推理一致。CNN 常用 BN，Transformer 用 LN。

**2. 为什么 Transformer 不用 BatchNorm？**
序列长度可变，batch 内 padding 会让统计量被无效位置污染；且文本 batch 通常很小（推理时甚至为 1），BN 统计量噪声大。

**3. Pre-Norm 与 Post-Norm 的差别？**
Pre-Norm：`x + f(norm(x))`，残差通路无归一化，深层梯度更稳，可省 warmup；Post-Norm：`norm(x + f(x))`，表达力略强但需 warmup，深层易发散。现在主流是 Pre-Norm。

**4. RMSNorm 为什么更快？**
不减均值、不学偏置，只算均方根，省掉一次规约与广播减法；速度约快 5–10%，效果相当。

**5. 内部协变量偏移（Internal Covariate Shift）这个解释还成立吗？**
现在认为 BN 有效的更主要原因是**平滑了损失曲面**、允许更大学习率，而不是单纯「让分布稳定」。面试时先说传统解释，再补一句这个更正，是加分项。

**6. 梯度消失和梯度爆炸的成因？**
深层链式相乘，若每层雅可比矩阵谱半径 < 1 则梯度指数衰减，> 1 则指数增长。tanh/sigmoid 的导数 ≤ 1（sigmoid 最大 0.25）会加速衰减。

**7. 怎么缓解梯度问题？**
残差连接、换 ReLU/GELU、归一化、梯度裁剪（`clip_grad_norm_` 1.0）、合理初始化（Xavier/He）、降学习率 + warmup、用 LSTM 门控。

**8. 梯度裁剪的两种方式？**
按值裁剪（`clip_grad_value_`）和按范数裁剪（`clip_grad_norm_`，最常用）。按范数裁剪把所有梯度整体缩放，保持方向不变；LLM 训练常用 1.0。

### 14.3.2 优化器与学习率（第 9–16 问）

**9. SGD 与 Adam 的区别？**
SGD 用统一学习率乘梯度；Adam 用一阶动量 + 二阶动量做逐参数自适应缩放，收敛快但泛化在部分视觉任务上略差。AdamW 把权重衰减从梯度里拿出来直接作用在参数上，是正确的 L2 实现。

**10. Adam 的偏差修正为什么必要？**
一阶、二阶动量初始化为 0，前几步估计偏小；除以 `1 - beta^t` 做无偏修正，否则前几步更新会异常大。

**11. Adam 里 beta1、beta2、eps 的典型值？**
beta1 = 0.9、beta2 = 0.999、eps = 1e-8（bf16 训练常放大到 1e-6 以上避免下溢）。

**12. 为什么大模型预训练常用 AdamW + 权重衰减 0.1？**
权重衰减抑制参数范数增长，配合 cosine 衰减与 warmup 更稳；0.1 是 Llama 系列的选择。

**13. 学习率 warmup 的作用？**
训练初期参数随机、梯度方向噪声大，warmup 从小学习率线性升到峰值，避免早期把参数带进坏区域，对 Post-Norm 与大批量训练尤其重要。

**14. 常见学习率调度有哪些？**
StepLR（阶梯下降）、CosineAnnealing（余弦退火）、OneCycle（先升后降）、Linear Warmup + Linear/Cosine Decay、ReduceLROnPlateau（按指标）。

**15. 为什么微调的学习率要比预训练小 1–2 个数量级？**
预训练权重已接近局部最优，大学习率会破坏已有能力（灾难性遗忘）。QLoRA 常用 1e-4～2e-4，全量微调常用 1e-5～2e-5。

**16. 梯度累积怎么工作？**
把多个小 batch 的梯度累加后再 `optimizer.step()`，等效于大 batch；注意 loss 要除以累积步数，且 BatchNorm 统计量会受影响（累积不能替代真实大 batch 的 BN）。

### 14.3.3 参数初始化与正则化（第 17–26 问）

**17. 为什么不能全零初始化？**
所有神经元的梯度相同，永远学成一模一样的参数，等于每层只有一个神经元（对称性无法打破）。

**18. Xavier 与 He 初始化的适用场景？**
Xavier（方差 2/(fan_in+fan_out)）适合 tanh/sigmoid；He（方差 2/fan_in）适合 ReLU 系，因为 ReLU 会把一半激活置零，需要更大方差。

**19. Transformer 的初始化有什么特别？**
线性层常用截断正态 `std = 0.02`；残差输出层额外除以 `sqrt(2 * n_layers)` 抑制深层方差累积；embedding 也常用 0.02。

**20. Dropout 的原理和在推理时的行为？**
训练时按概率 p 随机置零并放大 `1/(1-p)`（inverted dropout）；推理时不做任何处理，保持期望一致。

**21. 为什么 Transformer 里 dropout 常用 0.1 甚至 0？**
大模型数据量大、欠拟合不常见，dropout 过强反而拖慢收敛；微调小数据集时才需要 0.05–0.1。

**22. L1 与 L2 正则化的区别？**
L1 让参数稀疏（产生 0），L2 让参数整体变小（不产生 0）。L2 可导、优化友好，是默认选择。

**23. 早停（early stopping）怎么定指标与耐心值？**
监控验证集指标（分类看 F1、生成看验证损失或下游任务分），耐心值常取 3–5 个 epoch；恢复最佳 checkpoint 而不是最后一个。

**24. 数据增强有哪些常用手段？**
图像：随机裁剪、翻转、颜色抖动、Mixup/CutMix、RandAugment；文本：回译、同义替换、随机删除、指令改写；时序：加噪、缩放、时间扭曲、窗口滑移。

**25. Mixup 与 CutMix 的区别？**
Mixup 是两张图按比例线性混合、标签也混合；CutMix 是把一块区域粘贴过去、标签按面积比例混合。CutMix 保留局部真实像素，定位任务上通常更好。

**26. 为什么验证集和测试集分开？**
验证集用来选超参与早停，会引入选择偏差；测试集只用来最终汇报一次，保证指标无偏。

### 14.3.4 混合精度与训练工程（第 27–33 问）

**27. 混合精度为什么能加速？**
Tensor Core 上 fp16/bf16 矩阵乘吞吐是 fp32 的数倍，且显存与带宽减半。计算用半精度、累加与主权重用 fp32 保精度。

**28. fp16 与 bf16 的区别？**
fp16 有 10 位尾数、5 位指数，精度高但动态范围小，易上溢；bf16 有 7 位尾数、8 位指数，范围与 fp32 相同，训练更稳。Ampere 之后训练首选 bf16。

**29. 什么时候必须用 GradScaler？**
只有 fp16 需要：它按比例放大 loss 避免梯度下溢，发现 inf/nan 就跳过该步并调小 scale。bf16 不需要（动态范围够大）。

**30. 8GB 显存训练时省显存的手段有哪些？**
4bit 量化（NF4）、梯度检查点、paged/8bit 优化器、梯度累积代替大 batch、缩短序列长度、冻结大部分参数、CPU offload、`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 缓解碎片。

**31. 梯度检查点（activation checkpointing）的原理与代价？**
前向只保存部分激活，反向时重算被丢弃的部分；显存可降到约 `sqrt(层数)` 量级，代价是训练时间增加约 20–30%。

**32. `torch.no_grad()` 与 `torch.inference_mode()` 的区别？**
前者关闭梯度记录，仍保留版本计数等机制；后者更彻底，禁用 autograd 的元信息，速度略快、显存略省，但推理期不能对结果做需要梯度的操作。

**33. 训练中 loss 变成 nan 怎么排查？**
检查学习率是否过大、有无除零/log(0)、fp16 溢出、数据里有没有 nan/inf、mask 是否全 0；用 `torch.autograd.set_detect_anomaly(True)` 定位到具体算子。

### 14.3.5 评估指标与泛化（第 34–40 问）

**34. 准确率、精确率、召回率、F1 的关系？**
`精确率 = TP/(TP+FP)`（查得准不准）、`召回率 = TP/(TP+FN)`（查得全不全）、`F1 = 2PR/(P+R)`。类别不均衡时准确率会骗人，要看 F1 或 AUC。

**35. 宏平均、微平均、加权平均的差别？**
宏平均是各类别指标的等权平均（少数类权重被放大）；微平均把所有样本汇总后算（等价于按样本加权）；加权平均按各类样本量加权。类别不均衡时汇报宏 F1 更有意义。

**36. ROC-AUC 与 PR-AUC 怎么选？**
正负样本极不均衡时（如异常检测 1:1000）PR-AUC 更敏感、更有区分度；ROC-AUC 在均衡数据上更稳定。

**37. 过拟合的表现与对策？**
训练指标持续提升、验证指标下降。对策：加数据/增强、正则化（L2、Dropout）、减小模型、早停、降低模型容量或训练轮数、交叉验证。

**38. 欠拟合怎么办？**
增大模型或训练轮数、提高学习率、减少正则化、检查数据与标签质量、确认梯度是否真的在更新（打印参数范数变化）。

**39. 分布偏移的三种类型？**
协变量偏移（输入分布变了，`P(x)` 变）、标签偏移（`P(y)` 变）、概念偏移（`P(y|x)` 变）。对策：重采样/加权、持续再训练、监控输入分布与指标漂移。

**40. 为什么交叉验证在时序数据上不能随机划分？**
时序有自相关，随机划分会把未来信息泄露到训练集；要用滚动窗口（前向链式）划分，保证训练集永远早于验证集。

## 14.4 大模型八股 40 问

### 14.4.1 注意力与位置编码（第 1–10 问）

**1. 自注意力的时间复杂度与显存复杂度？**
时间 `O(n^2 d)`，注意力矩阵显存 `O(n^2)`（每头每层一份）。n 翻倍，注意力部分计算与显存变 4 倍，这是长上下文的核心瓶颈。

**2. KV Cache 的显存怎么估？**
`2（K 和 V）× 2 字节（fp16）× 层数 × KV 头数 × head_dim × 序列长 × batch`。7B 级（32 层、8 个 KV 头、head_dim 128）在 seq 4096、batch 1 时约 0.5GB。

**3. GQA 与 MQA 是什么？**
MQA 所有查询头共享一组 K/V（KV 头数 = 1）；GQA 折中，把查询头分组、每组共享一组 K/V（如 32 个查询头共享 8 组）。两者都能显著减小 KV Cache 与带宽压力，推理提速。

**4. 位置编码的三大类？**
绝对位置（可学习 embedding、正弦）、相对位置（T5 bias、RoPE、ALiBi）、无显式位置（靠注意力掩码隐含）。

**5. RoPE 的原理？**
把 Q、K 的相邻维度看成二维平面上的向量，按位置角度做旋转；两个位置的内积只与**相对距离**有关，天然编码相对位置，且不增加参数。

**6. RoPE 怎么做长度外推？**
位置插值（PI，把位置缩放进训练范围）、NTK-aware 缩放（按频率调整基底）、YaRN、动态 NTK。思路都是让模型在超出训练长度时也能拿到平滑的位置信号。

**7. ALiBi 的做法与优点？**
给注意力分数按头加一个与距离成正比的线性惩罚（`-m * |i - j|`，每个头一个斜率 m），无需位置 embedding，外推性好、实现零成本。

**8. 长上下文为什么贵？**
注意力是 O(n²)；KV Cache 随 n 线性增长，还要占带宽。工程手段：FlashAttention、KV 量化、滑动窗口、稀疏注意力、分页缓存。

**9. FlashAttention 解决了什么？**
通过分块计算 + 在线 softmax，不把 `n × n` 注意力矩阵写进显存，显存从 O(n²) 降到 O(n)，同时减少 HBM 读写、速度更快。它是 IO 感知优化，不是近似算法，结果与标准注意力一致（浮点误差内）。

**10. 为什么注意力要除以 `sqrt(d_k)`？**
点积方差随维度线性增长，缩放后 logits 标准差回到 1 附近，避免 softmax 饱和导致梯度消失。

### 14.4.2 架构与效率（第 11–20 问）

**11. Transformer 一层里有哪些子层？**
多头注意力 + 前馈网络（FFN），每层各配残差与归一化（Pre-Norm 时代是 `x + attn(norm(x))`、`x + ffn(norm(x))`）。

**12. FFN 的中间维度为什么是 4 倍？**
经验设定，给模型非线性变换的容量；现代 LLM 常用 `8/3 × d`（如 SwiGLU）以保持参数量相近。

**13. SwiGLU 与 GeLU 的差别？**
SwiGLU = `Swish(xW1) ⊙ (xW3)` 再乘 W2，引入门控，效果普遍优于 GeLU，代价是多一个矩阵。

**14. MoE 的稀疏激活是怎么回事？**
把 FFN 换成多个专家，每个 token 只激活 top-k 个（通常 top-2），总参数量大但每 token 计算量接近稠密小模型；训练与推理都需要负载均衡（aux loss / capacity factor）。

**15. MoE 的难点？**
路由不稳定、专家负载不均、通信开销大、显存占用高（所有专家都要常驻）。8GB 显存基本不可能训练 MoE。

**16. 为什么大模型多用 Decoder-only？**
自回归目标统一、易于 zero-shot 泛化、训练目标与推理方式一致、工程栈简单（KV Cache 一套逻辑）。Encoder-Decoder 在翻译类任务仍有优势。

**17. 分词器有哪几种？BPE / WordPiece / Unigram 的差异？**
BPE 从字符开始反复合并最高频配对；WordPiece 合并能使似然提升最大的配对；Unigram 从大词表反向删减。三者都要处理未登录词，中文常用字级 + BPE 混合。

**18. 词表大小怎么权衡？**
词表大：序列短、embedding 参数多、softmax 计算贵（`d_model × V`）；词表小：序列长、上下文被稀释。LLM 常见 32k–152k。

**19. 为什么中文 tokenizer 的 token 效率重要？**
同样一句中文，token 数越多，成本越高、上下文越短、推理越慢。可用 1 个中文字 ≈ 1.5–2 token 作为粗估。

**20. Tokenizer 会影响评测结果吗？**
会。生成长度限制按 token 计、截断位置按 token 计，换分词器后指标会漂移；评测时必须固定分词器版本。

### 14.4.3 微调与对齐（第 21–32 问）

**21. LoRA 的原理？**
冻结基座权重 W，学习低秩增量 `ΔW = B A`（`A: r×in`、`B: out×r`），前向为 `Wx + (alpha/r) B A x`。参数量从 `out×in` 降到 `r×(in+out)`。

**22. 秩 r 怎么选？**
任务越偏离预训练分布、数据越多，r 越大越好；常规指令微调 8–32 足够。用 r ∈ {8, 16, 32} 做消融，选验证指标拐点。

**23. alpha 的作用？**
`scaling = alpha / r` 是 LoRA 分支的有效尺度；增大 alpha 等价于增大该分支学习率。常用 `alpha = 2r`。

**24. QLoRA 相比 LoRA 多做了什么？**
基座用 4bit NF4 量化存储、计算时反量化到 bf16（`bnb_4bit_compute_dtype`），再用分页优化器与双重量化进一步省显存；7B 微调显存从 60GB+ 降到 8GB 级。

**25. NF4 为什么比 INT4 更适合权重？**
正态分位量化（NF4）的量化箱按正态分布的分位数放置，与预训练权重的近正态分布匹配，量化误差更小。

**26. 全量微调的显存公式？**
约 `16 bytes/参数`：bf16 权重 2 + bf16 梯度 2 + fp32 主权重 4 + AdamW 一阶 4 + 二阶 4。7B ≈ 112GB，1.5B ≈ 24GB，0.5B ≈ 8GB。

**27. SFT 的数据怎么构造？**
指令 + 输入的多样覆盖、答案风格统一、长度分布与推理场景一致、去重去噪；样本质量比数量重要，5k 条高质量常胜过 50k 条脏数据。

**28. RLHF 的三步？**
SFT → 训练奖励模型（人类偏好 pairwise 数据）→ 用 PPO 优化策略并对齐奖励（带 KL 惩罚防跑偏）。

**29. DPO 与 PPO 的差别？**
DPO 直接在偏好数据上做对比式损失，无需奖励模型、无需在线采样，训练简单稳定；PPO 需要奖励模型与价值网络，显存需求约为 DPO 的 2 倍以上，但探索能力更强。

**30. DPO 显存为什么高？**
要同时驻留策略模型与参考模型（参考模型可只做前向，但仍占权重显存）；可用 ORPO/SimPO 等参考模型无关的方法降低需求。

**31. GRPO 是什么？**
Group Relative Policy Optimization：对同一问题采样一组回答，用组内相对奖励替代价值网络估计优势，省掉 critic，适合数学/代码类可验证任务。8GB 显存只能做很小规模（≤3B 且极短序列）。

**32. 灾难性遗忘怎么缓解？**
混入通用数据（5–10% 比例）、用 LoRA 等参数高效方法、降低学习率与训练轮数、加 KL 约束、训练后做通用能力回归评测。

### 14.4.4 推理、量化与幻觉（第 33–40 问）

**33. 量化有哪些粒度？**
逐张量（per-tensor）、逐通道（per-channel）、分组（group-wise，如 group_size 128）、逐 token 激活量化。粒度越细误差越小、元数据开销越大。

**34. GPTQ / AWQ / GGUF 的差别？**
GPTQ 基于二阶信息逐层量化、适合 GPU；AWQ 按激活重要性保护显著通道，精度通常更好；GGUF 是 llama.cpp 的格式，支持 CPU/GPU 混合与 K-quant 系列（Q4_K_M 是常用平衡点）。

**35. 量化为什么掉点，怎么补救？**
异常值（outlier）与分布尾部被压平。补救：用校准集（几百条真实样本）做量化、保留部分层为 fp16、提高 group size 精度、用 AWQ 保护显著权重。

**36. 为什么首 token 延迟明显高于后续 token？**
首 token 要处理整个 prompt（prefill，计算密集），后续是逐 token decode（带宽密集）。优化 prefill 用更快的算力与 FlashAttention，优化 decode 用 KV 量化与批处理。

**37. 吞吐与延迟的权衡？**
批处理提高吞吐但拉高单请求延迟；连续批处理（continuous batching）能在不显著增加延迟的前提下提高吞吐。8GB 显存不适合 vLLM 高并发。

**38. 幻觉的成因？**
训练目标只优化下一个 token 的似然、不优化事实性；长尾知识稀薄；检索缺失时仍倾向给出流畅答案；对齐过程可能强化「讨好式」回答。

**39. 怎么降低幻觉？**
RAG 加引用与拒答、提示里要求「无依据就说不知道」、温度降低、自一致性/多次采样投票、工具调用核验事实、输出后处理做实体校验。

**40. 长上下文与 RAG 该怎么选？**
知识需要频繁更新、要求精确引用、语料远超窗口时选 RAG；需要跨文档推理、语料小且稳定时可上长上下文。工程上常见组合：RAG 召回 + 长上下文窗口容纳多段证据。

## 14.5 RAG / Agent 八股 25 问

### 14.5.1 切块与检索（第 1–9 问）

**1. 切块大小怎么定？**
按语义边界（标题、段落）优先，其次固定长度。512 token + 128 重叠是通用起点；FAQ 类短文本可 256，长技术手册 512–1024。必须做 256/512/1024 对照实验。

**2. 重叠的作用与代价？**
避免答案被切断、保持上下文连续；代价是索引膨胀（重叠 128 = 多 25% 存储）与检索重复。重叠常取块长的 10–25%。

**3. 混合检索为什么有效？**
向量召回擅长语义近似，BM25 擅长精确字面（型号、编号、专有名词），两者互补；用 RRF 融合后 Recall@5 通常比单路高 8–15pt。

**4. Rerank 的作用与代价？**
交叉编码器逐对打分，精度显著高于向量相似度（本项目 Recall@5 0.78 → 0.87），但延迟与算力增加；常用「召回 50 → 重排取 5」两段式。

**5. 主流 embedding 模型怎么选？**
中文检索优先 bge-m3（多语言、支持稠密+稀疏+多向量）或 bge-large-zh-v1.5；英文可用 e5、gte。选型必须用自己的评测集量 Recall@k。

**6. 向量索引选 FAISS 还是向量数据库？**
本地原型/单机小规模用 FAISS（零运维、快）；需要热更新、过滤、权限、多租户再用 Qdrant/Milvus/pgvector。8GB 笔记本上 FAISS + Chroma 足够演示。

**7. 查询改写有哪些手段？**
同义扩展、HyDE（先生成假答案再检索）、多查询生成、指代消解、把对话历史压缩成独立查询。代价是增加一次 LLM 调用（成本与延迟）。

**8. 父子块（small-to-big）怎么用？**
用小粒度块做检索（召回更准），命中后返回其所属的大块或相邻块给生成模型（上下文更完整），兼顾召回精度与生成质量。

**9. 元数据过滤怎么设计？**
给每块附来源文件、页码、时间、部门、密级；检索时先按权限与时间过滤再排序。企业场景里权限过滤必须在检索层做，不能只在前端做。

### 14.5.2 RAG 评测（第 10–14 问）

**10. RAGAS 的核心指标有哪些？**
忠实度（faithfulness，答案是否只依据给定上下文）、答案相关性（answer relevancy）、上下文精确率/召回率。三者分别定位「幻觉」「跑题」「检索漏」。

**11. 怎么自建评测集？**
从真实语料里造问题（人工或 LLM 生成 + 人工校验），标注标准答案与出处，覆盖事实型/多跳/拒答/表格类；规模 200 条起步，目标 1,000 条以上。

**12. 只看一个指标有什么风险？**
忠实度高可能是「什么都不答」；相关性高可能伴随幻觉。必须同时看检索侧（Recall@k）与生成侧（忠实度），再配合人工抽检。

**13. 检索指标怎么定义？**
Recall@k（top-k 里是否含正确块）、MRR（正确块的名次倒数）、NDCG（考虑名次与相关性等级）。本项目主指标是 Recall@5。

**14. LLM Judge 的偏差怎么处理？**
位置偏差（换顺序重测）、长度偏差（控制答案长度）、自偏好（别用同一个模型评自己）。让评委输出理由、抽 200 条人工对齐一致性（Spearman ≥ 0.8 可接受）。

### 14.5.3 Agent 工程（第 15–25 问）

**15. Agent 与普通 RAG 链的差别？**
RAG 链是固定流程（检索→生成）；Agent 有决策循环：观察 → 规划 → 调工具 → 观察结果 → 再决策，可多步、可回退。

**16. 工具调用失败怎么处理？**
参数校验（JSON Schema 先拦）、错误信息回灌给模型重试（最多 2 次）、幂等与超时、降级到备用工具、仍失败转人工确认。要把失败分类统计（本项目无效调用从 23% 降到 6%）。

**17. Function Calling 的原理？**
把工具名、描述、参数 schema 作为结构化上下文喂给模型；模型输出结构化的调用意图（函数名 + JSON 参数）；运行时执行并把结果作为新消息送回。

**18. MCP 是什么？**
Model Context Protocol：把工具/资源/提示以标准协议暴露给模型客户端，传输可用 stdio 或 HTTP。好处是工具与模型解耦，同一工具可被不同客户端复用。

**19. 多智能体架构的常见分工？**
Planner（任务拆解）、Executor（调工具执行）、Critic（校验结果）、Router（分派）、Memory（经验回退）。角色越多通信成本越高，2–3 个角色通常够用。

**20. Agent 的记忆怎么设计？**
短期：当前会话消息窗口（按 token 预算裁剪）；长期：把成功经验/失败教训向量化入库，按相似度回退；工作记忆：当前任务的中间产物（写进状态图而不是拼进提示）。

**21. 怎么控制 Agent 成本？**
限制最大步数、缓存工具结果、用小模型做路由与摘要、把长工具输出先摘要再入上下文、按任务难度分级（简单任务单步直答）。

**22. 提示注入怎么防？**
把外部内容放低信任区并加显式标注、工具白名单与参数白名单、敏感操作二次确认、输出前做正则/Schema 校验、不把系统提示与用户内容拼在同一信任层级。

**23. Agent 怎么评测？**
构造任务集（含成功标准与人工/B 判定），统计任务成功率、平均步数、工具调用准确率、成本与 P95 延迟，并对失败样本做分类（本项目分 5 类）。

**24. 可观测性要记什么？**
每次运行的 trace：每步输入输出、工具名与参数、token 消耗、耗时、错误堆栈、最终结果。用 Langfuse/LangSmith 或自建表，面试时能拿出 trace 截图很加分。

**25. Agent 什么时候不该用？**
流程固定、单步可解、对延迟敏感（Agent 多轮往返会到秒级）、要求确定性输出、成本敏感的场景。此时用固定 RAG 链或规则引擎更合适。

## 14.6 部署与工程八股 20 问

**1. 推理延迟由哪几部分组成？**
网络 + 排队 + prefill（算 prompt）+ decode（逐 token）+ 后处理。定位时先分层埋点，再决定优化哪一段。

**2. 怎么测延迟才可信？**
预热 ≥ 10 次（排除编译与缓存冷启动），测 ≥ 100 次，报 P50/P95/P99 而不是均值；固定输入长度与 batch，记录环境（GPU 型号、驱动、是否占用内屏显存）。

**3. 首 token 延迟与单 token 延迟谁更该优化？**
交互式聊天看首 token 延迟（体感），批量生成看吞吐与单 token 延迟。优化手段不同：prefill 靠算力与 FlashAttention，decode 靠带宽与 KV 量化。

**4. 8GB 显存部署 7B 模型的可行方案？**
GGUF Q4_K_M（约 4.4GB）+ KV Cache 量化（`--cache-type-k q8_0 --cache-type-v q8_0`）≈ 5–6GB，留出系统与浏览器的余量。测试数据：34 tok/s。

**5. 显存估算三公式是什么？**
全量微调 ≈ 16 bytes/参数；QLoRA：4bit 权重 ≈ 0.5 byte/参数（7B ≈ 3.9–4.3GB）+ 适配器/优化器 0.3–0.8GB + 激活 1–2GB；推理 KV Cache ≈ `2 × 2 字节 × KV 头数 × head_dim × 层数 × 序列长 × batch`。

**6. 量化误差怎么量化？**
同时记录量化前后：模型体积、延迟（P50/P95）、显存、任务指标（top-1 / F1 / 生成质量）。汇报必须带精度损失，例如「top-1 74.2% → 73.1%」。

**7. ONNX Runtime 与 TensorRT 怎么选？**
跨平台、可移植、CPU/GPU 都能用选 ONNX Runtime；追求 NVIDIA 极致延迟选 TensorRT。注意 TensorRT engine 与显卡架构、CUDA/TensorRT 版本强绑定，换环境必须重编。

**8. 动态 shape 与静态 shape 的取舍？**
静态 shape 的 TensorRT 优化最好但要为每个输入尺寸编一份；动态 shape 灵活但需要设置 profile 范围，超范围会回退或报错。

**9. INT8 量化的校准集怎么选？**
200–1000 条真实代表性样本（覆盖各输入长度与类别），用训练集分布的样本而不是随机噪声；校准集偏了会系统性掉点。

**10. 怎么提升推理吞吐？**
批处理、连续批处理、算子融合、KV Cache 复用、多实例并行、把 rerank 等旁路模型放 CPU。注意吞吐与延迟的权衡。

**11. Docker 在部署里解决什么问题？**
固化依赖（CUDA、TensorRT、Python 版本）避免「我这能跑」。多阶段构建 + 固定基础镜像 tag；GPU 容器需要 `--gpus all` 与匹配的驱动。

**12. 镜像怎么瘦身？**
多阶段构建（builder 装依赖、runtime 只拷产物）、用 slim 基础镜像、清理 pip 缓存、`--no-install-recommends`、模型权重不进镜像（挂载或启动时下载）。

**13. 服务怎么做健康检查与优雅退出？**
`/healthz` 返回模型是否加载完成与显存占用；捕获 SIGTERM 后停止接收新请求、等待在途请求完成、释放显存。

**14. SSE 流式输出怎么实现？**
FastAPI 用 `StreamingResponse` 或 `EventSourceResponse` 逐块 yield；设 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`；客户端断连要能取消生成。

**15. 并发上来后 OOM 怎么办？**
限制并发数（信号量）、请求排队与超时、动态批处理上限、给每个请求设置最大 token 预算、显存不够时降级到小模型或 CPU 后端。

**16. CI 应该跑什么？**
ruff 静态检查 + mypy 类型检查 + pytest 单测 + 一个 5 分钟内的 smoke 训练/推理；性能回归用固定基准，超过阈值（如 10%）失败并报警。

**17. 模型版本与数据版本怎么管理？**
模型权重与适配器打标签（v1.0.0）并存到制品库，配置文件与代码一起进 Git；评测报告随版本归档，保证任何指标可回溯到具体版本。

**18. 日志与监控要采集什么？**
请求量、延迟分位、错误率、token 消耗、显存与 GPU 利用率、队列长度；用 Prometheus 采集指标、Grafana 展示，日志集中到 Loki/ELK。

**19. 线上效果退化怎么排查？**
先看数据分布（输入长度、类型占比是否漂移），再看检索/模型版本是否变过，再看是否有上游解析失败；建立每日抽检与自动评测回归。

**20. Windows 与 WSL2 部署的差异？**
TensorRT、vLLM、部分 CUDA 扩展在 Windows 原生支持差，建议 WSL2 Ubuntu 22.04；GPU 直通需要 Windows 11 与较新驱动，显存共享给 WSL2 会占用同一块 8GB。llama.cpp/Ollama 在 Windows 原生可用，适合本地推理。

## 14.7 项目深挖问答：P1–P12 每个项目 3 问

下面 P1–P12 的编号、名称、排期与共享事实简报完全一致。每一问都给出**答题要点**，要点里必须带得出数字——面试官就是靠数字判断项目真假。

### 14.7.1 P1 从零实现 MLP 与 CNN（W5–W6，入门）

**问 1：你说手写了反向传播，怎么证明它是对的？**
用数值梯度校验：取某个参数 `w`，算 `(L(w+eps) - L(w-eps)) / (2*eps)`，与 `autograd` 给出的梯度比，相对误差在 1e-6 量级即通过。再验证两点：去掉 `autograd` 后 NumPy 版在 MNIST 上仍能到 0.964；训练 loss 曲线单调下降、验证准确率收敛到与 PyTorch 版差距 3pt 以内（0.964 vs 0.993）。差距来源我做过归因：NumPy 版没用 BatchNorm 与数据增强。

**问 2：CNN 和 MLP 在同一份数据上的差距，为什么是这个数量级？**
MNIST 上 MLP 约 0.98、CNN 0.993。原因是卷积的局部连接与权值共享带来平移等变性，且参数量更少（我的 CNN 约 42 万参数，MLP 约 67 万）。如果换成彩色自然图像，差距会拉大到 10pt 以上（CIFAR-10 上 MLP 约 0.55、ResNet 级 0.93+）。

**问 3：你的训练工程化具体包含什么，怎么验证有效？**
固定种子（`torch.manual_seed` + `numpy.random.seed` + `cudnn.deterministic`）保证两次运行指标差 < 0.2pt；checkpoint 支持断点续训（模拟进程被杀后从 epoch 8 恢复，指标曲线连续）；wandb 记录 loss/acc/学习率；pytest 11 个用例覆盖数据切分、归一化、shape 断言。耗时数据：12 epoch、batch 128，单卡 4 分 10 秒。

### 14.7.2 P2 中文文本分类与 NER 双任务基线（W10–W12，入门）

**问 1：三档基线怎么比才公平？**
同一份数据切分、同一套评测脚本、同一随机种子。结果：fastText 宏 F1 0.812（训练 38 秒）、TextCNN 0.874、BERT-base 0.921。要说明成本：BERT 训练时间是 fastText 的约 40 倍，如果线上只要 0.81 就够，就不该上 BERT。

**问 2：NER 为什么改字级标注？**
词级标注在中文分词边界上与实体边界不一致，导致实体级 F1 虚高（同一实体被切成两段后统计成部分命中）。改字级 + BIO 标签后，实体级 F1 0.886，且推理时不需要分词器版本一致。写了标签一致性校验脚本，拦截 214 条非法标签转移（如 O→I-X）。

**问 3：宏 F1 的波动怎么控制？**
单次运行波动 ±0.011，改成 3 个种子取均值后波动降到 ±0.003。汇报时给均值与区间，不给单次最优值——挑最好的一次上报是常见的作弊，面试官会追问方差。

### 14.7.3 P3 边缘端图像分类系统（W8–W9，入门）

**问 1：INT8 量化的精度损失是多少，为什么？**
top-1 0.954 → 0.948（-0.6pt），体积 9.8MB → 2.7MB，CPU 单张延迟 31.6ms → 9.4ms。损失主要来自动态范围压缩，小目标类别受影响最大（该类召回 0.91 → 0.82）。

**问 2：掉点之后你具体做了什么？**
用该类别的 500 张真实图做校准集重跑量化，召回从 0.82 恢复到 0.89。另外试过把最后一层保留 fp32（mixed precision 导出），精度 0.951，但体积只降到 3.1MB，最终选了校准集方案。

**问 3：端侧部署的和训练的是同一个模型吗？**
不是同一个文件但同一次训练的权重：PyTorch checkpoint → ONNX（opset 17）→ INT8。注意预处理必须对齐（归一化均值方差、resize 插值方式），否则会出现「PyTorch 上 0.954、ONNX 上 0.87」这类问题。我用同一批 200 张图对齐了两次推理输出，最大概率差 < 1e-3。

### 14.7.4 P4 工业设备时序异常检测与告警收敛（W22–W23，进阶）

**问 1：为什么用 AE + Isolation Forest 两路融合？**
AE 重建误差对连续型漂移敏感，Isolation Forest 对孤立点敏感，两者互补。加权 0.6/0.4 是按验证集 F1 网格搜索得到的；单用 AE 点级 F1 0.68，单用 iForest 0.64，融合 0.79。

**问 2：阈值怎么定？**
不用拍脑袋：在验证集上扫描阈值，取 F1 最大的点；同时约束误报率上限（业务要求 < 15%）。测试集上点级 F1 0.61 → 0.79，误报率 41% → 12%。

**问 3：告警收敛的规则会不会漏掉真故障？**
会，所以做了两层保护：同源合并只在同一服务、同一模板、5 分钟窗口内合并；静默窗只对同源告警生效，不同源告警不静默。收敛后日均告警 1,240 → 186 条（-85%），同时人工回看 30 天历史，确认漏报 0 起。

### 14.7.5 P5 日志模板挖掘与 LLM 告警摘要 + 根因候选排序（W23–W24，进阶）

**问 1：Drain3 的压缩比与实际用途？**
168 万行日志 → 214 个模板（约 1:7,850）。用途有三个：作为告警聚合的键、作为 LLM 摘要的输入（只摘要模板与计数，不喂原始日志）、作为根因特征。

**问 2：LLM 编造服务名怎么解决？**
摘要前先做实体白名单校验：摘要里出现的服务名必须来自拓扑表，否则重生成一次，仍失败就回退到模板拼接。编造率 9.5% → 0.5%。同时把摘要输入从原始日志改成「模板 + 计数 + 时间分布」，单条成本从 0.003 元降到 0.0012 元。

**问 3：根因 Top-3 命中率怎么评的？**
用历史故障工单（200 条，人工标注真实根因）评测。三路打分：服务拓扑距离、时间共现强度、模板相似度，权重 0.5/0.3/0.2。Top-3 命中 0.47 → 0.78。要主动说明局限：只有 200 条标注数据，且工单本身可能标错。

### 14.7.6 P6 端侧小模型部署平台（W20–W21，进阶）

**问 1：三后端的延迟对比数据？**
MobileNetV3 INT8：ONNX Runtime 11.8ms（P99 18.4ms）、TensorRT FP16 7.2ms（P99 11.9ms），加速比 1.6×。7B GGUF Q4_K_M：34 tok/s、首 token 0.62s、显存 5.1GB。全部基于预热 10 次、测 100 次的流程。

**问 2：既然 TensorRT 更快，为什么不全用它？**
engine 与显卡架构、CUDA/TensorRT 版本强绑定，换机器要重编（10–20 分钟），团队里其他人用不了；ONNX Runtime 跨平台可移植。所以把 ONNX 作为主链路，TensorRT 作为本机加速分支，用 Docker 双镜像固化两套环境。

**问 3：怎么保证性能不回退？**
把基准脚本进 CI：每次提交跑固定输入、固定计时的 benchmark，结果写 JSON 并对比上一次，延迟或显存超过 10% 就失败。注意 CI 机器与本地显卡不同，所以只看相对变化，不看绝对值。

### 14.7.7 P7 企业知识库 RAG 问答系统（W15–W16，简历级）

**问 1：0.62 到 0.87 的每一步增益来自哪？**
分解：仅向量召回 Recall@5 0.62；加 BM25 + RRF 到 0.78（+16pt）；加 bge-reranker-v2-m3 到 0.87（+9pt）；切块从 1024 改 512 + 128 重叠保持 0.87 并把 P95 从 3.2s 降到 1.4s（检索缓存）。每一步只动一个变量。

**问 2：评测集怎么保证不「过拟合」？**
1,200 条里 900 条用于调参、300 条只在最后跑一次（held-out）；题目类型分布：事实型 55%、多跳 20%、拒答 15%、表格 10%。表格类目前是短板，召回只有 0.61，已在改进清单里。

**问 3：8GB 显存怎么塞下整条链路？**
reranker 走 ONNX Runtime CPU（单条 42ms）、生成走 GGUF Q4_K_M、KV Cache 用 q8_0，显存峰值 5.9GB。另外关掉浏览器硬件加速与本地 LLM 服务（内屏本身占 0.3–1GB）。

### 14.7.8 P8 垂直领域大模型微调与对齐（W13–W14，简历级）

**问 1：7B QLoRA 在 8GB 上的显存账本？**
4bit NF4 权重约 4.0GB + LoRA 适配器与 8bit 优化器 0.6GB + 激活（seq 512、batch 1、梯度检查点）约 2.1GB + 临时缓冲 0.7GB，峰值实测 7.4GB。开启 `expandable_segments:True` 后碎片导致的 OOM 从偶发变成 0。

**问 2：r=16 是怎么定的，r=32 为什么不用？**
r ∈ {8, 16, 32}：准确率 0.695 / 0.720 / 0.727，显存 7.1 / 7.4 / 7.8GB（r=32 开始频繁 OOM），训练时间 +60%。r=32 只多 0.7pt 但把稳定运行的余量吃掉了，所以选 16，并把 alpha 设为 32（scaling = 2）。

**问 3：数据从 5k 加到 10k 为什么不涨？**
2k → 0.681、5k → 0.720、10k → 0.723。5k 之后边际收益几乎为零，说明瓶颈在数据质量与任务多样性，不在数量。做法：用 10k 里质量最高的 5k（按人工评分 + 去重 + 长度过滤）训练，指标 0.726，比用全量 10k 还高。

### 14.7.9 P9 多智能体协作系统（W18–W19，简历级）

**问 1：Planner–Executor–Critic 各自负责什么，为什么不是两个角色？**
Planner 拆任务并产出步骤；Executor 按步调工具；Critic 校验 Executor 的输出是否满足当前步骤的成功条件，不满足就打回。去掉 Critic 时成功率 0.58 → 0.66，平均步数从 4.9 涨到 6.8（无校验会反复重试）。三角色都保留后成功率 0.81。

**问 2：任务成功率的判定标准是什么？**
120 条任务集，每条有确定性的成功条件（答案包含关键实体、SQL 结果匹配、文件生成并含指定字段），脚本判定；另抽 40 条人工复核，与脚本一致率 0.93。不用 LLM 做最终判定，避免评委偏差。

**问 3：失败模式是怎么分类的，分布如何？**
5 类：工具参数错误 38%（改进前 23% 无效调用降到 6%）、上下文缺失 24%、多步规划错误 18%、工具超时 12%、模型拒答 8%。针对参数错误加了 JSON Schema 约束与重试上限（2 次后转人工确认）。

### 14.7.10 P10 Agent 工具调用与 MCP 服务化（W17–W18，亮点级）

**问 1：工具选择准确率 0.71 → 0.93 做了什么？**
三件事：一，重写工具卡片（一句用途 + 参数说明 + 正反例各 2 条）；二，把 9 个工具按场景分组，先选组再选工具（两级选择）；三，给参数加 Schema 校验与默认值。评测集 300 条（含 60 条「应该不调用任何工具」的负样本）。

**问 2：MCP 与自写 JSON Schema 注册表的差别？**
MCP 是协议层标准化，工具与客户端解耦，同一个 Server 能被不同客户端（IDE、聊天客户端）复用；自写注册表要自己定义发现、调用、错误约定。我两种都实现了，MCP 版用 stdio 与 HTTP 两种传输，压测下网关 P99 额外延迟 12ms。

**问 3：非法参数怎么做到 100% 拦截？**
三层：JSON Schema 类型与枚举校验、业务层白名单（如 SQL 只允许 SELECT、路径必须在数据目录下）、执行超时（3 秒）与限流（20 QPS，超出返回 429 并熔断）。三层都在执行前，所以非法请求根本不进模型工具链。

### 14.7.11 P11 大模型评测与红队平台（W21–W22，亮点级）

**问 1：LLM Judge 与人工的一致率怎么量？**
抽 200 条让 Judge 与人工各打一次分，算 Spearman 相关 0.82；同时看混淆：Judge 在「拒答是否合理」这一维偏差最大。做了位置交换（双序评测）后一致率从 0.68 提到 0.85。

**问 2：拒答率从 0.42 到 0.88 是怎么做到的？**
先分类攻击类型（提示注入 96 条、越狱 78 条、隐私套取 66 条），再针对性加系统提示的边界声明与输出前过滤器（敏感模式正则 + 二次分类器）。副作用也测了：正常问题的误拒率从 2% 涨到 4.5%，通过给过滤器加「正常业务白名单」压回 2.8%。

**问 3：单次全量评测成本从 46 元压到 12 元？**
三招：结果缓存（同题同模型同参数直接复用）、两阶段评测（先用 0.5B 小模型筛掉明显正确/错误的题，只把边界题交给大模型 Judge）、抽样评测（1,500 题固定随机抽 600 题作为日常回归，全量只在上线前跑）。成本按 token 单价折算，1,500 题约占 12 元。

### 14.7.12 P12 论文复现与改进（W21–W22，亮点级）

**问 1：复现结果与论文差多少，差异从哪来？**
论文报的平均分比我的高 1.8pt。查下来两处：一是论文用了更大的训练集（我用 60% 数据复现）；二是缩放因子实现不同——论文文字写 `1/sqrt(d)`，官方代码里是 `1/sqrt(d/2)`。把这一点写成博客后阅读量 4,300+。

**问 2：显存 -54% 的对照是否公平？**
同一 batch、同一序列长度 512、同一优化器，只换注意力实现：标准注意力训练显存 6.8GB、轻量注意力 3.1GB（-54%），吞吐 1.9×。要注意：显存节省主要来自不做 `n×n` 物化，不是精度换来的。

**问 3：蒸馏的效果与代价？**
教师模型蒸馏到 0.5B 学生（温度 2.0、硬标签与软标签损失加权 0.7/0.3）：下游三项任务平均分 0.63 → 0.71，体积 1.9GB → 0.98GB。代价是训练时间增加约 40%（要跑教师前向），且教师模型的推理成本不能省。

### 14.8.3 优缺点怎么答

| 问题 | 答法结构 | 示例（可直接改） |
| --- | --- | --- |
| 你最大的优点 | 一个特质 + 一个证据 + 对岗位的价值 | 我的优点是能把模糊问题拆成可量化的实验。做 RAG 时我把召回率拆成四步逐步验证，每步只动一个变量，最后拿到 0.62 → 0.87。这个习惯对需要反复调优的检索与 Agent 工作直接有用。 |
| 你最大的缺点 | 真实且不致命的缺点 + 正在采取的具体措施 + 已有改善证据 | 我早期的毛病是「先写代码再想指标」。吃了两次亏后我改成先写评测脚本再写实现，现在每个项目都先落评测集。最近一次微调项目，评测集就是第一天先建的。 |

| 你和别人合作有冲突怎么处理 | 事实 + 你的让步或依据 + 结果 | 做设备异常检测时，业务方要求误报率低于 5%、我算出的方案最低 12%。我拉了一次对齐会，把 F1 与误报的权衡曲线摆出来，最后约定 12% 加人工复核流程，上线后人工复核命中率 0.78。 |

### 14.8.5 反问面试官的 15 个问题（按对象分组）

**问技术面试官（一面 / 二面）**

1. 这个岗位现在最主要的两个技术难点是什么？
2. 团队现在有评测体系吗？是自建评测集还是用公开榜单？
3. 模型是在线服务还是离线批量？大概的 QPS 与延迟要求是多少？
4. 团队的 GPU 资源是什么规模？实习生能拿到多少？
5. 代码是自研为主还是大量依赖开源？有没有内部的训练/推理框架？

**问主管（三面）**

6. 这个岗位半年内最重要的交付是什么？
7. 团队现在最缺的是哪类人：做算法、做工程还是做评测？
8. 实习生的产出一般怎么衡量？有转正名额吗、比例大概多少？
9. 团队和业务方是怎么协作的？需求从哪来？
10. 您觉得我这个背景进来，最需要补的是什么？

**问 HR**

11. 这个岗位的职级与培养路径是怎样的？
12. 转正流程与时间点是什么时候？
13. 团队在哪个城市、是否需要出差？
14. 薪资结构是怎样的（基本 + 绩效 + 补贴）？
15. 后面的流程大概什么时候会有结果？

:::tip 反问的三个纪律
每个面试官最多问 3 个问题；问完要能接住对方的回答（不要说「好的我了解了」就结束）；不要在第一轮就问薪资与加班。把「加班」换成「团队一般的交付节奏是怎样的」。
:::

### 14.9.1 四个关键节点的补强说明

**节点一：2028 年 3–6 月 暑期实习**

- 这是全年最重要的一段：暑期实习既是转正通道，也是秋招简历上最有分量的经历。
- 3 月开始投递不早：大厂暑期实习多为 3 月开网申、4 月面试、5 月发意向。
- 投 30–50 家，命中 1 份即可；没拿到就 6 月补录，同时把目标下调到研究所/中小厂。

**节点二：2028 年 7–8 月 提前批**

- 提前批常在实习期间启动，特点：免笔试或简化笔试、面试轮次少、给意向早。
- 关键动作：把实习期间的新产出（数字）当天更新进简历，投递前一晚改一版。
- 提前批拿到的意向可以作为保底，避免 9 月秋招被焦虑牵着走。

**节点三：2028 年 9–11 月 秋招正式批**

- 9 月是网申高峰（很多公司在 9 月第一周开放、9 月中截止），10 月是面试高峰。
- 节奏建议：9 月投 40–60 家，10 月投 20–30 家并集中面试，11 月补录。
- 手上同时进行 3–5 家流程是健康状态，少于 2 家要立刻加投。

**节点四：国企银行 9 月初网申截止**

- 国企、银行、运营商、研究院的网申时间普遍早于互联网大厂，多集中在 9 月上旬截止。
- 材料准备更繁琐（成绩单、四六级、获奖证明、党员材料等），要提前两周备齐扫描件。
- 笔试内容与互联网不同：行测 + 专业知识 + 英语，需单独准备 3–4 周。

### 14.9.2 时间线的三条纪律

1. **每周固定 2 小时做求职事务**（更新台账、投递、复盘），不要攒到周末突击。
2. **实习期间不停投递**：提前批机会窗口短，等实习结束再投会错过。
3. **论文与求职并行**：2028 年 9–11 月既要跑秋招又要推论文进度，提前在 8 月把实验做完。
