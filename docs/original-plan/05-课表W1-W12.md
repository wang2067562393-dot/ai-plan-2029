# 第5章 24 周详细计划（上）：第 1–12 周（2026-10-05 → 2026-12-27）

这半段课表（W1–W12）解决的是「地基 + 视觉 + NLP 基础」三件事：把你手里的 RTX 4060 Laptop 8GB 变成一个能稳定跑训练、能出可视化报告、能交付 GitHub 仓库的工作站，并让你在 W12 结束时已经亲手写过反向传播、ResNet、U-Net、YOLO、多头注意力和一个小 GPT。读完这 12 周，你应该能做到：拿到一个公开数据集，从清洗、训练、评测到导出 ONNX 全流程自己走一遍，并把结果写成有指标、有截图、有 README 的仓库。

## 这套课表怎么用

每一周都按**四段式**推进，顺序不能换：

1. **输入**：看课 / 读文档，带着「看完要能回答的问题」去看，看完立刻把答案写进当周笔记。
2. **动手**：敲代码、跑实验。凡是代码块，都要自己手敲一遍，不要复制粘贴完事——手敲能暴露你对 shape、dtype、设备不一致的盲区。
3. **产出**：当周交付物推到 GitHub。没有推到远程仓库、没有指标数字、没有截图的成果，一律不算完成。
4. **复盘**：周日写当周笔记（`notes/W0X.md`），写清「做了什么、指标多少、卡在哪、下周怎么避」。

| 时段 | 内容 | 时长 |
| --- | --- | --- |
| D1 | 输入为主（看课 + 记问题） | 2.5h |
| D2–D4 | 动手为主（敲代码 + 跑实验） | 各 2.5h |
| D5 | 动手 + 中途排错 | 2.5h |
| D6 | 产出为主（整理仓库 + 跑最终指标） | 3h |
| D7 | 复盘（笔记 + 自检题 + 补漏） | 1.5h |

**时间不够怎么办（0.7 系数放慢）**：把「一周」当「约 1.4 周」用，总时长从 24 周拉到 **34 周**，顺序完全不变。具体做法是：

- 每天的动作编号（D1–D7）保持不动，只把每天的时长按 0.7 缩放：2.5h → 1.75h，3h → 2h，1.5h → 1h。
- 一周只做「输入 + 一半动手」，下一周做「另一半动手 + 产出 + 复盘」，**但绝不允许跳过当周的核心代码小节**。
- 里程碑不能延后：M1 环境与地基、M2 深度学习与视觉、M3 视觉工程与端侧入门、M4 NLP 与大模型基础 的验收标准一个都不能降。
- 放慢后先砍「加分项」（比如额外的消融实验、额外的可视化），再砍输入时长，最后才砍动手时长。

**进度存在哪**：下面所有 `- [ ]` 勾选框由本机浏览器保存进度（localStorage），换电脑、换浏览器、清缓存都会丢。所以每周的交付物必须同时提交到 GitHub 仓库，GitHub 才是真正的进度记录。

```python
# scripts/check_torch.py —— 验证 CUDA 可用性、算力与显存
import torch, time

print("torch:", torch.__version__, "| cuda:", torch.version.cuda, "| available:", torch.cuda.is_available())
print("device:", torch.cuda.get_device_name(0))
print("capability:", torch.cuda.get_device_capability(0))          # 4060 应为 (8, 9)
print("total VRAM: %.1f GB" % (torch.cuda.get_device_properties(0).total_memory / 1024**3))

torch.backends.cuda.matmul.allow_tf32 = True                       # Ada 支持 TF32，默认吃满算力
a = torch.randn(4096, 4096, device="cuda", dtype=torch.float16)
b = torch.randn(4096, 4096, device="cuda", dtype=torch.float16)
torch.cuda.synchronize(); t0 = time.time()
for _ in range(20):
    c = a @ b
torch.cuda.synchronize(); dt = (time.time() - t0) / 20
print("fp16 4096^3 matmul: %.1f ms | %.1f TFLOPS" % (dt * 1000, 2 * 4096**3 / dt / 1e12))
print("peak VRAM: %.2f GB" % (torch.cuda.max_memory_allocated() / 1024**3))
```

预期结果：`capability: (8, 9)`；`total VRAM: 8.0 GB`；fp16 matmul 单次约 10–25ms，等效 **30–60 TFLOPS**（4060 Laptop 标称 FP16 Tensor 算力约 60 TFLOPS×，实测受功耗与内屏占用影响很大，低于 20 TFLOPS 说明你用的是 CPU 或没插电）。

#### D6（周六，3h）：写第一个真正的脚本并推上去

写 `scripts/bench_gpu.py`：测三种精度下的矩阵乘法，并输出「显存预算表」。这就是你要推上 GitHub 的第一份代码。

```python
# scripts/bench_gpu.py —— 8GB 显存预算与精度吞吐基准
import argparse, json, time, pathlib
import torch

def bench(dtype: torch.dtype, n: int, iters: int, device: str) -> dict:
    a = torch.randn(n, n, device=device, dtype=dtype)
    b = torch.randn(n, n, device=device, dtype=dtype)
    for _ in range(3):
        a @ b
    torch.cuda.synchronize()
    t0 = time.time()
    for _ in range(iters):
        a @ b
    torch.cuda.synchronize()
    dt = (time.time() - t0) / iters
    return {"dtype": str(dtype), "n": n, "ms": round(dt * 1000, 2),
            "tflops": round(2 * n**3 / dt / 1e12, 2)}

def vram_budget() -> dict:
    free, total = torch.cuda.mem_get_info()
    return {"total_gb": round(total / 1024**3, 2), "free_gb": round(free / 1024**3, 2),
            "used_by_screen_and_others_gb": round((total - free) / 1024**3, 2)}

def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--device", default="cuda")
    ap.add_argument("--out", default="outputs/w01_bench.json")
    args = ap.parse_args()
    assert torch.cuda.is_available() or args.device == "cpu", "CUDA 不可用，先查驱动"
    torch.backends.cuda.matmul.allow_tf32 = True
    torch.backends.cudnn.allow_tf32 = True
    results = [bench(dt, 4096, 20, args.device)
               for dt in (torch.float32, torch.float16, torch.bfloat16)]
    payload = {"cuda": torch.version.cuda, "gpu": torch.cuda.get_device_name(0),
               "budget": vram_budget(), "results": results}
    out = pathlib.Path(args.out); out.parent.mkdir(parents=True, exist_ok=True)
    out.write_text(json.dumps(payload, ensure_ascii=False, indent=2), encoding="utf-8")
    print(json.dumps(payload, ensure_ascii=False, indent=2))

if __name__ == "__main__":
    main()
```

运行它：

```powershell

```

预期结果：生成 `outputs/w01_bench.json`，里面 fp32 约 8–15 TFLOPS、fp16 约 30–60 TFLOPS、bf16 与 fp16 接近；`used_by_screen_and_others_gb` 大约 0.3–1.0。**把这个 json 提交进仓库**（它是你的硬件基线，后面每章都要对比）。

```python
# src/device.py —— 统一的设备与显存工具
import gc
import torch

def get_device() -> torch.device:
    if torch.cuda.is_available():
        return torch.device("cuda")
    return torch.device("cpu")

def report_vram(tag: str = "") -> None:
    if not torch.cuda.is_available():
        return
    alloc = torch.cuda.memory_allocated() / 1024**3
    peak = torch.cuda.max_memory_allocated() / 1024**3
    print(f"[VRAM {tag}] allocated={alloc:.2f}GB peak={peak:.2f}GB")

def free_vram() -> None:
    gc.collect()
    if torch.cuda.is_available():
        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()
```

### 自检题（答不上来就不算学会）

1. 为什么不许手动装 CUDA Toolkit？
   答：PyTorch 官方 wheel 里已经打包了它编译时用的 CUDA runtime 与 cuDNN，运行时只需要**驱动**提供的驱动层。手动装 Toolkit 会改 `PATH` 与 `LD_LIBRARY_PATH`，容易出现版本冲突（典型报错 `undefined symbol: cudnnGetVersion`）。判断依据只看 `torch.version.cuda`。
2. `torch.cuda.is_available()` 为 False 的三种最常见原因？
   答：驱动太旧或没装；装成了 CPU 版 wheel；在 WSL2 里手动装了 Linux 显卡驱动把直通搞坏。
3. `total_memory` 显示 8.0GB，为什么你实际只能用约 7GB？
   答：笔记本内屏、Windows 桌面合成、浏览器硬件加速都会占用同一块显存；`torch.cuda.mem_get_info()` 的 `free` 才是可用上限，本周边界值要写进笔记。
4. `uv.lock` 的作用是什么，为什么它必须入库？
   答：它把「这次解析出的精确版本 + hash」固定下来，别人（和三个月后的你）`uv sync` 能复现完全一致的环境；删了它就只剩版本区间，训练结果会不可复现。
5. WSL2 里为什么不能直接访问 `C:\` 的路径？
   答：能访问，映射为 `/mnt/c/`；但跨文件系统的 IO 走 9P 协议，慢 3–10 倍，所以数据与虚拟环境应放 WSL 原生目录（`~/`）。
6. TF32 是什么，为什么要在 Ada 上打开？
   答：TF32 是 Ampere 起支持的张量核心格式，fp32 输入下用 19 位精度做乘法但保留 fp32 累加，矩阵乘法可提速约 2–3 倍、精度损失对训练基本无感；`torch.backends.cuda.matmul.allow_tf32=True` 才启用。

```python
import pandas as pd

cols = ["age", "workclass", "fnlwgt", "education", "edu_num", "marital",
        "occupation", "relationship", "race", "sex", "gain", "loss", "hours", "country", "income"]

df = pd.read_csv(url, names=cols, na_values="?", skipinitialspace=True)

report = {"raw_rows": len(df), "dup_rows": int(df.duplicated().sum())}

for c in num_cols:                                  # 数值列：中位数填充 + 记录填充比例

df = df[df["hours"].between(1, 99)]                 # 业务规则过滤：每周工时 1–99
```

```python
# src/split.py —— 分层划分 + 泄漏检查
import pandas as pd
from sklearn.model_selection import train_test_split

def make_split(df: pd.DataFrame, target: str, seed: int = 42):
    """返回 train/val/test 三份，类别比例保持一致。"""
    train, temp = train_test_split(df, test_size=0.3, stratify=df[target], random_state=seed)
    val, test = train_test_split(temp, test_size=0.5, stratify=temp[target], random_state=seed)
    return train.reset_index(drop=True), val.reset_index(drop=True), test.reset_index(drop=True)

def check_leakage(train: pd.DataFrame, test: pd.DataFrame, key: str = "id") -> int:
    """划分是否有重叠主键，返回重叠条数，必须为 0。"""
    return len(set(train[key]) & set(test[key]))
```

### 自检题（答不上来就不算学会）

1. 广播什么时候会失败？
   答：从最右侧维度向左对齐时，某个维度既不相等也不为 1 就失败。例如 `(3,2)` 与 `(3,)` 相加：`(3,)` 被当成 `(1,3)` 与 `(3,2)` 的末维 2 冲突。
2. `groupby` 之后为什么要 `dropna=False`？
   答：默认会把分组键为空的行整组丢掉，导致总数对不上，做异常分析时会漏掉「未知类别」这一整块证据。
3. 类别特征缺失值为什么优先填 `Unknown` 而不是众数？
   答：缺失本身常常携带信息（例如「未登记职业」的人往往收入偏低），填众数会人为抹掉这个信号；填 `Unknown` 让它成为独立类别，由模型自己学。
4. 画图时为什么在服务器/脚本里必须 `matplotlib.use("Agg")`？
   答：没有显示环境时默认后端可能尝试打开窗口并阻塞，脚本会卡住或报 `TclError`；`Agg` 是纯文件后端。
5. 为什么 notebook 里不许保留最终结论逻辑？
   答：notebook 单元格执行顺序不可控、不能 diff、不能单测；结论逻辑必须落到 `.py` 模块里，notebook 只做调用和展示。
6. `SettingWithCopyWarning` 说明什么？
   答：你对一个切片（可能是视图也可能是副本）做了赋值，pandas 无法保证原 DataFrame 被改到。解法是显式 `.copy()` 或直接用 `.loc[row, col]` 的赋值形式。

```python
# scripts/w03_linalg.py —— 手算 vs torch 对照
import torch

torch.manual_seed(0)
A = torch.tensor([[1., 2.], [3., 4.]])
B = torch.tensor([[5., 6.], [7., 8.]])

# 手算：C[i][j] = sum_k A[i][k] * B[k][j]
C_manual = torch.tensor([[sum(A[i, k] * B[k, j] for k in range(2)) for j in range(2)] for i in range(2)])
print("manual:", C_manual.tolist())          # 预期 [[19, 22], [43, 50]]
print("torch :", (A @ B).tolist())
assert torch.allclose(A @ B, C_manual)

print("det:", torch.linalg.det(A).item())    # 预期 -2.0000
print("inv@A:", torch.linalg.inv(A) @ A)     # 预期单位阵
```

```python
# scripts/w03_grad.py —— 数值梯度 vs autograd vs 手推
import torch

def f(x: torch.Tensor) -> torch.Tensor:
    return (x ** 3 + 2 * x).sum()

x = torch.tensor([1.0, 2.0], requires_grad=True)
y = f(x); y.backward()
print("autograd:", x.grad.tolist())          # 解析解 3x^2+2，预期 [5.0, 14.0]

# 中心差分数值梯度
eps = 1e-4
num = []
for i in range(2):
    xp = x.detach().clone(); xp[i] += eps
    xm = x.detach().clone(); xm[i] -= eps
    num.append(((f(xp) - f(xm)) / (2 * eps)).item())
print("numeric :", [round(v, 4) for v in num])

# 链式法则手推：z = (a*b + c)^2
a = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(3.0, requires_grad=True)
c = torch.tensor(1.0, requires_grad=True)
z = (a * b + c) ** 2
z.backward()
# dz/da = 2(ab+c)*b = 2*7*3 = 42；dz/db = 2*7*2 = 28；dz/dc = 2*7 = 14
print("dz/da,dz/db,dz/dc =", a.grad.item(), b.grad.item(), c.grad.item())
```

预期结果：autograd 与数值梯度在小数点后 4 位一致；`42.0 28.0 14.0`。手推的三行公式要写进笔记。

```python
# scripts/w03_gd.py —— 手写线性回归的梯度下降
import numpy as np

rng = np.random.default_rng(42)
X = rng.normal(size=(500, 1))
w_true, b_true = 3.0, -1.5
y = w_true * X[:, 0] + b_true + rng.normal(scale=0.3, size=500)

w, b, lr = 0.0, 0.0, 0.1
for step in range(1, 201):
    y_hat = w * X[:, 0] + b
    err = y_hat - y
    loss = (err ** 2).mean()
    dw = 2 * (err * X[:, 0]).mean()          # dL/dw 的手推结果
    db = 2 * err.mean()                      # dL/db 的手推结果
    w -= lr * dw; b -= lr * db
    if step % 50 == 0:
        print(f"step {step:3d} loss={loss:.5f} w={w:.4f} b={b:.4f}")
print("final:", round(w, 4), round(b, 4), "| 真值", w_true, b_true)
```

预期结果：loss 从约 21 单调降到 0.09 附近；`w` 收敛到约 3.0、`b` 到约 -1.5（误差 < 0.05）。把 `lr` 改成 1.1 再跑，观察 loss 变成 `nan` 或爆炸，把这条曲线记入笔记（学习率上限 ≈ 1/最大特征值）。

### 自检题（答不上来就不算学会）

1. 为什么 `softmax([1000,1001,1002])` 直接算会得到 `nan`？
   答：`exp(1000)` 超出 fp32 上限（约 3.4e38）变成 `inf`，`inf/inf` 得到 `nan`。稳定写法是减去最大值：`exp(x - max(x))`，结果不变。
2. 特征值分解和 SVD 的关系是什么？
   答：SVD 对任意矩阵都存在（`M = UΣVᵀ`）；矩阵对称正定时 SVD 与特征分解等价（奇异值 = 特征值）。SVD 的奇异值总是非负实数，这是它做低秩近似的前提。
3. 数值梯度为什么用中心差分而不是前向差分？
   答：中心差分误差是 O(ε²)，前向差分是 O(ε)，同样步长下中心差分精度更高；但两者都要小心 `eps` 太小被浮点舍入淹没（一般取 1e-4 到 1e-5）。
4. 梯度下降学习率过大会发生什么，理论上限怎么估？
   答：参数会来回震荡并最终变成 `nan`/`inf`。对二次损失，稳定上限约为 `2/λ_max`（λ_max 是 Hessian 最大特征值），工程上经验取 `1/λ_max` 更安全。
5. `torch.linalg.eigh` 与 `torch.linalg.eig` 该用哪个？
   答：对称（厄米）矩阵一律用 `eigh`：数值更稳、保证实特征值、结果按升序排列；`eig` 返回复数，且对非对称矩阵数值误差更大。
6. 为什么「期望的线性性」在深度学习里极其常用？
   答：它不需要独立性假设，所以 mini-batch 的梯度期望等于全量梯度期望——这是随机梯度下降成立的数学基础。

### 踩坑提醒

:::warn `RuntimeError: mat1 and mat2 shapes cannot be multiplied`
形状不匹配的原始报错。排查顺序：`A.shape` 与 `B.shape` 的最内维必须相等，即 `(m,k) @ (k,n)`。把两个形状打印出来，写在纸上对齐一次，比盯着代码看快得多。
:::

:::warn `element 0 of tensors does not require grad`
`backward()` 调用的张量不在计算图里，通常是前面用了 `.detach()`、`.item()` 或 `with torch.no_grad()`，或者忘了给叶子张量设 `requires_grad=True`。
:::

:::warn `RuntimeError: one of the variables needed for gradient computation has been modified by an inplace operation`
对需要梯度的张量做了原地修改（如 `x += 1`、`x[0] = 0`、`relu(inplace=True)` 后又用到原值）。改成 `x = x + 1` 或调整 `inplace` 参数。
:::

:::danger 别在 CUDA tensor 上调 `.numpy()`
`TypeError: can't convert cuda:0 device type tensor to numpy. Use Tensor.cpu()...`。必须先 `.detach().cpu().numpy()`，且不要在训练循环里每个 step 都做（会把 GPU 同步拖慢十倍）。
:::

```python
y = (df["income"].astype(str).str.strip() == ">50K").astype(int).to_numpy()
Xnum = df[["age", "edu_num", "hours", "gain", "loss"]].to_numpy(float)
Xs = StandardScaler().fit_transform(Xnum)

def sigmoid(z): return 1.0 / (1.0 + np.exp(-z))

w = np.zeros(Xs.shape[1]); b = 0.0
lr, l2, epochs, n = 0.1, 1e-4, 3000, len(Xs)
for e in range(1, epochs + 1):
    p = sigmoid(Xs @ w + b)
    grad_w = Xs.T @ (p - y) / n + l2 * w      # dL/dw = X^T(p-y)/n + lambda*w
    grad_b = (p - y).mean()                   # dL/db
    w -= lr * grad_w; b -= lr * grad_b
    if e % 600 == 0:
        loss = -(y * np.log(p + 1e-9) + (1 - y) * np.log(1 - p + 1e-9)).mean()
        print(f"epoch {e:4d} loss={loss:.4f} auc={roc_auc_score(y, p):.4f}")

sk = LogisticRegression(max_iter=2000).fit(Xs, y)
print("手写 AUC:", round(roc_auc_score(y, sigmoid(Xs @ w + b)), 4))
print("sklearn AUC:", round(roc_auc_score(y, sk.predict_proba(Xs)[:, 1]), 4))
print("权重余弦相似度:", round(float(w @ sk.coef_[0] / (np.linalg.norm(w) * np.linalg.norm(sk.coef_[0]))), 4))
```

预期结果：两者 AUC 差 < 0.01，权重余弦相似度 > 0.95（说明你推的梯度方向是对的）。若手写版 AUC 明显偏低，优先检查是否忘了标准化、是否 `lr` 太大（loss 打转）。

```python
from sklearn.metrics import (accuracy_score, f1_score, roc_auc_score,
                             average_precision_score, confusion_matrix)

def binary_report(y_true, proba, threshold: float = 0.5) -> dict:

    tn, fp, fn, tp = confusion_matrix(y_true, pred, labels=[0, 1]).ravel()

        "f1": round(f1_score(y_true, pred), 4),

        "pr_auc": round(average_precision_score(y_true, proba), 4),
        "recall": round(tp / (tp + fn + 1e-9), 4),
        "precision": round(tp / (tp + fp + 1e-9), 4),
        "tn_fp_fn_tp": (int(tn), int(fp), int(fn), int(tp)),
    }
```

### 自检题（答不上来就不算学会）

1. 为什么 `StandardScaler` 必须放在 Pipeline 内部？
   答：如果先在全集上 `fit_transform` 再划分，测试集的均值方差信息泄漏进了训练，CV 分数会虚高。放进 Pipeline 后，`fit` 只在每折的训练部分统计。
2. 类别不平衡时该看 accuracy 还是 PR-AUC？
   答：看 PR-AUC（或 F1 / recall@固定 precision）。本例多数类基线 accuracy 就有 0.76 但 F1 = 0，accuracy 完全无法反映「能不能揪出少数类」。
3. `StratifiedKFold` 解决了什么问题？
   答：保证每折的类别比例与全集一致。类别比例 24% 时，普通 `KFold` 可能出现某折只有 12% 正类，导致 AUC 方差极大。
4. `GridSearchCV` 的 `refit=True` 做了什么？
   答：用最优参数在整个训练集上重新拟合一次，之后可以直接 `gs.best_estimator_.predict`；设成 `False` 就只能拿到参数、拿不到可用模型。
5. 手写梯度下降里 L2 正则项加在哪里，为什么不在 `b` 上加？
   答：加到 `grad_w`（`+ l2 * w`）；偏置不参与正则化，正则化偏置会把决策边界强行拉向原点、损害拟合能力。
6. 为什么 `class_weight="balanced"` 会提高 recall？
   答：它把少数类样本的损失权重乘以 `n/(2*n_minority)`，等价于让模型对少数类错分更敏感，决策边界向多数类偏移，recall 上升、precision 下降。

```python
# src/train_loop.py —— 通用训练循环（分类任务）
import time, torch, torch.nn as nn
from torch.optim import AdamW

def train_one_epoch(model, loader, opt, crit, device, max_batches: int | None = None) -> tuple[float, float]:
    model.train(); total_loss = correct = seen = 0
    for i, (x, y) in enumerate(loader):
        if max_batches and i >= max_batches: break
        x, y = x.to(device, non_blocking=True), y.to(device, non_blocking=True)
        opt.zero_grad(set_to_none=True)           # 比 zero_grad() 省一次写显存
        out = model(x); loss = crit(out, y)
        loss.backward(); opt.step()
        total_loss += loss.item() * y.size(0)
        correct += (out.argmax(1) == y).sum().item(); seen += y.size(0)
    return total_loss / seen, correct / seen

@torch.no_grad()
def evaluate(model, loader, crit, device) -> tuple[float, float]:
    model.eval(); total_loss = correct = seen = 0
    for x, y in loader:
        x, y = x.to(device, non_blocking=True), y.to(device, non_blocking=True)
        out = model(x); total_loss += crit(out, y).item() * y.size(0)
        correct += (out.argmax(1) == y).sum().item(); seen += y.size(0)
    return total_loss / seen, correct / seen
```

```python
sys.path.insert(0, ".")
from src.data_mnist import build_loaders

from src.seed import set_seed

class MLP(nn.Module):
    def __init__(self, hidden: int = 512) -> None:
        super().__init__()
        self.net = nn.Sequential(
            nn.Flatten(),
            nn.Linear(28 * 28, hidden), nn.ReLU(), nn.Dropout(0.2),
            nn.Linear(hidden, hidden // 2), nn.ReLU(),
            nn.Linear(hidden // 2, 10),
        )
    def forward(self, x): return self.net(x)
```

```python
import pathlib, torch

def save_ckpt(path: str, model, opt, epoch: int, best_acc: float, extra: dict | None = None) -> None:
    p = pathlib.Path(path); p.parent.mkdir(parents=True, exist_ok=True)
    torch.save({"model": model.state_dict(), "opt": opt.state_dict(),
                "epoch": epoch, "best_acc": best_acc, "extra": extra or {}}, p)

def load_ckpt(path: str, model, opt=None, map_location: str = "cuda"):
    ckpt = torch.load(path, map_location=map_location, weights_only=False)
    model.load_state_dict(ckpt["model"])
    if opt is not None and "opt" in ckpt:
        opt.load_state_dict(ckpt["opt"])
    return ckpt
```

```python
import torch

def count_params(model: torch.nn.Module) -> dict:
    total = sum(p.numel() for p in model.parameters())
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
    return {"total": total, "trainable": trainable,
            "fp32_weights_MB": round(total * 4 / 1024**2, 2),
            "adamw_states_MB": round(total * 8 / 1024**2, 2)}   # AdamW 一阶+二阶

def grad_check(model: torch.nn.Module, x: torch.Tensor) -> None:
    model.zero_grad(); model(x).sum().backward()
    for n, p in model.named_parameters():
        flag = "OK" if (p.grad is not None and p.grad.abs().sum() > 0) else "无梯度"
        print(f"{n:40s} {tuple(p.shape)} {flag}")
```

### 自检题（答不上来就不算学会）

1. 为什么 `optimizer.zero_grad()` 必须在 `loss.backward()` 之前？
   答：PyTorch 的梯度是**累加**的。不清零的话这一步的梯度会叠加到上一步，等效于把梯度放大，训练立刻发散。
2. `model.train()` 与 `model.eval()` 改变了什么？
   答：Dropout 与 BatchNorm 的行为。`train()` 时 Dropout 随机置零并用当前 batch 统计量更新 BN 的 running stats；`eval()` 时 Dropout 关闭、BN 用 running stats。忘了 `eval()` 会让验证指标随机波动。
3. `pin_memory=True` 有什么用？
   答：把 CPU 侧数据放进锁页内存，`non_blocking=True` 的 H2D 拷贝可以真正异步，GPU 不等数据。CPU 训练或显存不是瓶颈时收益很小。
4. 为什么 `zero_grad(set_to_none=True)` 更快？
   答：默认 `zero_grad()` 把梯度写成 0 张量（一次显存写），`set_to_none=True` 直接置为 `None`，反向传播时按需分配，省一次写且省显存。
5. checkpoint 里为什么要存优化器状态？
   答：AdamW 有一阶/二阶动量，不恢复的话续训前几十步的更新方向是错的，指标会掉一截再爬回来。
6. MNIST MLP 的参数量大概多少，显存里都装了什么？
   答：约 0.53M（`784×512 + 512×256 + 256×10` 加偏置约 53 万）。显存里主要是权重、梯度、AdamW 两个动量、激活（batch 越大越大）；MLP 上总共不到 200MB。

### 踩坑提醒

:::warn Windows 上 `num_workers>0` 报 “An attempt has been made to start a new process before the current process has finished its bootstrapping phase”
多进程 DataLoader 在 Windows 上需要 `if __name__ == "__main__":` 保护，且 `num_workers` 先从 0 试起。稳妥写法是把训练入口全部放进 `main()` 并在文件底用 `if __name__ == "__main__": main()`。
:::

:::warn `RuntimeError: Expected all tensors to be on the same device`
模型在 GPU、数据在 CPU（或反之）。统一在循环里 `.to(device, non_blocking=True)`，创建新张量时显式写 `device=device`（例如 `torch.zeros(..., device=x.device)`）。
:::

:::warn `CUDA out of memory` 在 MLP 阶段就出现
不是模型太大，多半是显存没释放：上一次循环里保留了带梯度的张量（例如把 `loss` append 到 list 而不是 `loss.item()`）。用 `loss.item()`，并在排查时 `torch.cuda.empty_cache()`。
:::

:::warn 验证集准确率比训练集高很多
只有两种可能：训练用了强 Dropout/增强而验证没有，或者验证集与训练集有重叠（数据泄漏）。先查 `check_leakage`，再查 `drop_last` 与 `shuffle` 配置。
:::

#### D1（周一，2.5h）：手写 micrograd 风格 Value

```python
# src/micrograd.py —— 200 行的自动求导引擎（自己敲，不要复制）
import math

class Value:
    def __init__(self, data: float, _children: tuple = (), _op: str = "") -> None:
        self.data = float(data)
        self.grad = 0.0
        self._backward = lambda: None       # 反向传播时我要给父节点加多少梯度
        self._prev = set(_children)
        self._op = _op

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad += 1.0 * out.grad     # 加法：梯度原样回传
            other.grad += 1.0 * out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():
            self.grad += other.data * out.grad   # 乘法：回传另一路的值
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def __pow__(self, k: float):
        out = Value(self.data ** k, (self,), f"**{k}")
        def _backward():
            self.grad += k * (self.data ** (k - 1)) * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,), "tanh")
        def _backward():
            self.grad += (1 - t ** 2) * out.grad
        out._backward = _backward
        return out

    def relu(self):
        out = Value(max(0.0, self.data), (self,), "relu")
        def _backward():
            self.grad += (1.0 if out.data > 0 else 0.0) * out.grad
        out._backward = _backward
        return out

    def exp(self):
        e = math.exp(self.data)
        out = Value(e, (self,), "exp")
        def _backward():
            self.grad += e * out.grad
        out._backward = _backward
        return out

    def backward(self) -> None:
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for c in v._prev:
                    build(c)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for v in reversed(topo):                # 逆拓扑序 = 反向传播
            v._backward()

    def __radd__(self, o): return self + o
    def __rmul__(self, o): return self * o
    def __neg__(self): return self * -1
    def __sub__(self, o): return self + (-o)
    def __truediv__(self, o): return self * (o ** -1 if isinstance(o, Value) else Value(o) ** -1)
    def __repr__(self): return f"Value(data={self.data:.4f}, grad={self.grad:.4f})"
```

```python
# scripts/w06_micrograd_train.py —— 用自己写的引擎训练一个小网络
import random
from src.micrograd import Value

random.seed(42)
xs = [[Value(2.0), Value(3.0), Value(-1.0)], [Value(3.0), Value(-1.0), Value(0.5)],
      [Value(0.5), Value(1.0), Value(1.0)], [Value(1.0), Value(1.0), Value(-1.0)]]
ys = [1.0, -1.0, -1.0, 1.0]

W1 = [[Value(random.uniform(-1, 1)) for _ in range(3)] for _ in range(4)]
W2 = [Value(random.uniform(-1, 1)) for _ in range(4)]

def forward(x):
    h = [sum((wi * xi for wi, xi in zip(row, x)), Value(0.0)).tanh() for row in W1]
    return sum((w * hi for w, hi in zip(W2, h)), Value(0.0))

for step in range(200):
    preds = [forward(x) for x in xs]
    loss = sum(((p - y) ** 2 for p, y in zip(preds, ys)), Value(0.0))
    for p in [*[w for row in W1 for w in row], *W2]:
        p.grad = 0.0
    loss.backward()
    for p in [*[w for row in W1 for w in row], *W2]:
        p.data -= 0.1 * p.grad
    if step % 50 == 0:
        print(f"step {step:3d} loss={loss.data:.4f} preds={[round(p.data,2) for p in preds]}")
```

预期结果：loss 从约 4 降到 0.1 以下，预测值逼近 `[1, -1, -1, 1]`。注意这里的 `p.grad = 0.0` 就是「手动 zero_grad」——和 W5 的 `optimizer.zero_grad()` 是同一件事，把这句话写进笔记。

```python
b2 = torch.zeros(128, device=device, requires_grad=True)

b3 = torch.zeros(10, device=device, requires_grad=True)

        h1 = torch.relu(x @ W1 + b1)
        h2 = torch.relu(h1 @ W2 + b2)

        loss = F.cross_entropy(logits, y)
        opt.zero_grad(set_to_none=True); loss.backward(); opt.step()

    print(f"ep{ep} train_acc={correct/seen:.4f}")
```

```python
# src/cnn_from_scratch.py —— 手写卷积（用 unfold 实现 im2col，理解卷积的矩阵本质）
import torch

def conv2d_manual(x: torch.Tensor, w: torch.Tensor, b: torch.Tensor, stride: int = 1, pad: int = 0):
    """x:[N,C,H,W] w:[OC,IC,KH,KW] -> [N,OC,H',W']；用 unfold 展开成矩阵乘法。"""
    N, C, H, W = x.shape
    OC, IC, KH, KW = w.shape
    x = torch.nn.functional.pad(x, (pad, pad, pad, pad))
    cols = torch.nn.functional.unfold(x, kernel_size=(KH, KW), stride=stride)   # [N, C*KH*KW, L]
    out = w.reshape(OC, -1) @ cols                                              # [N, OC, L]
    out = out + b.reshape(1, -1, 1)
    H_out = (H + 2 * pad - KH) // stride + 1
    W_out = (W + 2 * pad - KW) // stride + 1
    return out.reshape(N, OC, H_out, W_out)

if __name__ == "__main__":
    import torch.nn as nn
    x = torch.randn(2, 3, 32, 32)
    conv = nn.Conv2d(3, 16, 3, padding=1)
    mine = conv2d_manual(x, conv.weight.data, conv.bias.data, stride=1, pad=1)
    print("mine:", mine.shape, "torch:", conv(x).shape)          # 都是 [2, 16, 32, 32]
    print("allclose:", torch.allclose(mine, conv(x), atol=1e-4))
```

预期结果：`allclose: True`（误差 < 1e-4）。这一步让你真正理解「卷积 = 带权重共享的矩阵乘法」，也是后面 ONNX/TensorRT 里 im2col 优化的原理来源。

```python
# src/shape_utils.py —— 卷积/池化输出尺寸与感受野
def conv_out(size: int, k: int, stride: int = 1, pad: int = 0, dilation: int = 1) -> int:
    return (size + 2 * pad - dilation * (k - 1) - 1) // stride + 1

def receptive_field(layers: list[tuple[int, int]]) -> tuple[int, int]:
    """layers: [(kernel, stride), ...] 返回 (rf, jump)"""
    rf, jump = 1, 1
    for k, s in layers:
        rf += (k - 1) * jump
        jump *= s
    return rf, jump

if __name__ == "__main__":
    print(conv_out(28, 3, 1, 1))                 # 28
    print(conv_out(28, 2, 2))                    # 14
    print(receptive_field([(3, 1), (3, 1), (2, 2), (3, 1), (3, 1), (2, 2)]))  # 约 (14, 4)
```

### 自检题（答不上来就不算学会）

1. 反向传播为什么必须先做拓扑排序？
   答：每个节点的梯度必须等所有下游节点都回传完才完整（梯度是累加的）。拓扑序保证「处理某节点时它的所有依赖已处理」，逆拓扑序就是正确的回传顺序。
2. 加法门和乘法门在反向时分别做什么？
   答：加法门把上游梯度**原样复制**给两个输入；乘法门把上游梯度**乘以另一路的输入值**再回传（`∂(xy)/∂x = y`）。
3. `p.grad +=` 里的 `+=` 能不能写成 `=`？
   答：不能。一个变量可能出现在多个分支里（例如 `x` 同时参与两个乘法），必须累加。写成 `=` 会丢掉其他分支的贡献，梯度就错了。
4. 为什么 `im2col` 能让卷积变快？
   答：它把卷积转成一次大的矩阵乘法（GEMM），可以直接调用高度优化的 `cuBLAS`，GPU 利用率从百分之几提升到几十个百分点；代价是展开后的内存放大约 `KH*KW` 倍，所以现代实现会用分块。
5. `BatchNorm` 在 CNN 里放在卷积后面、激活前面，为什么？
   答：先归一化卷积输出的分布，再让 ReLU 作用在标准正态附近，避免大量神经元落入 ReLU 的负半轴「死掉」；同时归一化让各通道尺度一致，可以用更大的学习率。
6. P1 的验收线是 MNIST ≥ 98%，为什么还要手写 MLP 版本？
   答：手写版能证明你理解前向/反向的每个张量形状与梯度来源；「会用 `nn.Linear`」和「知道 `nn.Linear` 在算什么」是两种水平，面试会问后者。

### 踩坑提醒

:::warn micrograd 训练时 loss 变成 `nan`
`tanh` 或 `**2` 的输入数值太大导致溢出，或学习率过大。先把 `lr` 从 0.1 降到 0.01，再检查数据范围（本例输入在 ±3 内是安全的）。
:::

:::warn `RuntimeError: Trying to backward through the graph a second time`
对同一个计算图调用了两次 `backward()` 且没有 `retain_graph=True`。在每个 step 里重新前向、或改用手写引擎（每次前向都重建图）。
:::

:::warn 手写卷积 `unfold` 结果与 `nn.Conv2d` 不一致
三个高频原因：忘了 `padding`、把 `w.reshape(OC, -1)` 前后的维度顺序搞错（必须是 `[OC, IC*KH*KW]`，与 `unfold` 的输出顺序一致）、`bias` 广播维度写错（应为 `[1, OC, 1]`）。
:::

:::warn CNN 验证准确率停在 0.9x 上不去
常见原因是没做归一化（MNIST 要用 `mean=0.1307, std=0.3081`）或 BatchNorm 放在了池化之后。按「卷积 → BN → ReLU → 池化」的顺序检查一遍。
:::

```python
import torch

from torchvision import datasets, transforms

ROOT = Path("data/raw")
MEAN, STD = (0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616)   # CIFAR-10 官方统计量

def build_loaders(batch_size: int = 128, num_workers: int = 0, augment: bool = True):
    train_tf = [transforms.RandomCrop(32, padding=4),
                transforms.RandomHorizontalFlip(),
                transforms.ToTensor(), transforms.Normalize(MEAN, STD)]
    if augment:
        train_tf.insert(2, transforms.RandAugment(num_ops=2, magnitude=9))
    test_tf = [transforms.ToTensor(), transforms.Normalize(MEAN, STD)]

                            transform=transforms.Compose(train_tf))
    test = datasets.CIFAR10(ROOT, train=False, download=True,
                            transform=transforms.Compose(test_tf))
    val_len = 5000
    train, val = random_split(full, [len(full) - val_len, val_len],
                              generator=torch.Generator().manual_seed(42))
    kw = dict(num_workers=num_workers, pin_memory=True)
    return (DataLoader(train, batch_size=batch_size, shuffle=True, drop_last=True, **kw),
            DataLoader(val, batch_size=256, **kw),
            DataLoader(test, batch_size=256, **kw))

if __name__ == "__main__":
```

```python
# src/amp_train.py —— 带 AMP 与梯度裁剪的通用训练函数
import torch, torch.nn as nn

scaler = torch.amp.GradScaler("cuda", enabled=torch.cuda.is_available())

def train_epoch_amp(model, loader, opt, crit, device, sched=None, clip: float = 1.0) -> tuple[float, float]:
    model.train(); loss_sum = correct = seen = 0
    for x, y in loader:
        x = x.to(device, non_blocking=True); y = y.to(device, non_blocking=True)
        opt.zero_grad(set_to_none=True)
        with torch.autocast(device_type=device.type, dtype=torch.float16, enabled=device.type == "cuda"):
            loss = crit(model(x), y)
        scaler.scale(loss).backward()
        if clip > 0:
            scaler.unscale_(opt)
            torch.nn.utils.clip_grad_norm_(model.parameters(), clip)
        scaler.step(opt); scaler.update()
        if sched is not None: sched.step()
        loss_sum += loss.item() * y.size(0)
        correct += (model(x).argmax(1) == y).sum().item() if False else 0
        seen += y.size(0)
    return loss_sum / seen, correct / seen
```

注意上面 `correct` 那行是为了强调「不要在 AMP 里重复前向」：正确写法是把 `model(x)` 的输出提前存到变量里复用，重复前向会让速度掉一半。改成：

```python
        out = model(x)
        loss = crit(out, y)
        ...
        correct += (out.argmax(1) == y).sum().item()
```

#### D3（周三，2.5h）：ResNet-18 从零实现（含 BasicBlock）

```python
# src/resnet.py —— CIFAR 版 ResNet-18（3x3 首层，无 7x7/maxpool）
import torch, torch.nn as nn

class BasicBlock(nn.Module):
    def __init__(self, in_ch: int, out_ch: int, stride: int = 1) -> None:
        super().__init__()
        self.conv1 = nn.Conv2d(in_ch, out_ch, 3, stride, 1, bias=False)
        self.bn1 = nn.BatchNorm2d(out_ch)
        self.conv2 = nn.Conv2d(out_ch, out_ch, 3, 1, 1, bias=False)
        self.bn2 = nn.BatchNorm2d(out_ch)
        self.short = nn.Sequential()
        if stride != 1 or in_ch != out_ch:
            self.short = nn.Sequential(nn.Conv2d(in_ch, out_ch, 1, stride, bias=False),
                                       nn.BatchNorm2d(out_ch))
    def forward(self, x):
        out = torch.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        return torch.relu(out + self.short(x))

class ResNet18(nn.Module):
    def __init__(self, num_classes: int = 10) -> None:
        super().__init__()
        self.stem = nn.Sequential(nn.Conv2d(3, 64, 3, 1, 1, bias=False),
                                  nn.BatchNorm2d(64), nn.ReLU())
        chans = [64, 128, 256, 512]
        blocks, in_ch = [], 64
        for i, c in enumerate(chans):
            for j in range(2):
                blocks.append(BasicBlock(in_ch, c, stride=(2 if (i > 0 and j == 0) else 1)))
                in_ch = c
        self.blocks = nn.Sequential(*blocks)
        self.head = nn.Sequential(nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(512, num_classes))
    def forward(self, x): return self.head(self.blocks(self.stem(x)))
```

梯度累积（显存不够时用它换等效大 batch）：

```python
# src/grad_accum.py —— 梯度累积：等效 batch = micro_batch * accum_steps
import torch, torch.nn as nn

def train_with_accum(model, loader, opt, crit, device, accum: int = 4, scaler=None) -> float:
    model.train(); opt.zero_grad(set_to_none=True); total = 0.0
    for i, (x, y) in enumerate(loader):
        x, y = x.to(device, non_blocking=True), y.to(device, non_blocking=True)
        with torch.autocast(device_type=device.type, dtype=torch.float16, enabled=device.type == "cuda"):
            loss = crit(model(x), y) / accum          # 关键：除以累积步数
        (scaler.scale(loss) if scaler else loss).backward()
        if (i + 1) % accum == 0:
            if scaler:
                scaler.step(opt); scaler.update()
            else:
                opt.step()
            opt.zero_grad(set_to_none=True)
        total += loss.item() * accum
    return total / len(loader)
```

显存占用实时记录（训练中打印，不要事后猜）：

```python
# src/vram_probe.py —— 训练过程中每 N 步打印显存
import torch

class VRAMProbe:
    def __init__(self, every: int = 50) -> None:
        self.every, self.step_id = every, 0
    def tick(self, tag: str = "") -> None:
        self.step_id += 1
        if torch.cuda.is_available() and self.step_id % self.every == 0:
            a = torch.cuda.memory_allocated() / 1024**2
            r = torch.cuda.memory_reserved() / 1024**2
            p = torch.cuda.max_memory_allocated() / 1024**2
            print(f"[step {self.step_id:5d}] {tag} alloc={a:.0f}MB reserved={r:.0f}MB peak={p:.0f}MB")
```

### 自检题（答不上来就不算学会）

1. 残差连接为什么能训练更深的网络？
   答：它给梯度提供了一条恒等通路径（`∂(x+F(x))/∂x = 1 + F'(x)`），梯度不会在多层连乘中消失；同时让网络只需学习「残差」，优化目标更容易。
2. `GradScaler` 解决什么问题？
   答：fp16 的动态范围小，小梯度会下溢成 0。`GradScaler` 先把 loss 放大，反向后把梯度缩回，遇到 `inf/nan` 自动跳过这一步并降低缩放系数。
3. `label_smoothing=0.1` 改变了什么？
   答：把 one-hot 目标改成 `[0.9/0.1 分布]`，抑制模型对单一类别的过度自信，通常提升 0.5–1.5 个点并改善校准。
4. `OneCycleLR` 的 `total_steps` 写错会怎样？
   答：调度器会在训练中途把 LR 降到接近 0（写小了）或到结束还没降下来（写大了），两种情况都会明显掉点。它必须等于 `epochs * len(train_loader)`（按 step 调度时）。
5. 为什么 CIFAR 版 ResNet 的首层用 `3x3, stride=1` 而不是 ImageNet 版的 `7x7 + maxpool`？
   答：CIFAR 只有 32×32，用 7×7 步长 2 加池化会直接把分辨率降到 8×8，信息损失过大；改成 3×3 保持分辨率，最后用 `AdaptiveAvgPool2d(1)` 降维。
6. AMP 为什么偶尔掉点？
   答：部分算子在 fp16 下精度不足（尤其 LayerNorm、softmax、大 reduce），或 `GradScaler` 初始缩放不当导致频繁跳过 step。可对少数层强制 fp32（`torch.autocast` 里加 `enabled=False` 块）。
7. 8GB 显存训练 ResNet-18 到 92%，batch size 能开到多少？
   答：batch=128 + AMP 峰值约 1.5–2.5GB，可以开到 256；开到 512 时激活显存约翻倍，需回到 128 或用梯度累积。

### 踩坑提醒

:::warn `RuntimeError: Input type (torch.cuda.FloatTensor) and weight type (torch.cuda.HalfTensor) should be the same`
手工把模型 `.half()` 了，但输入还是 fp32。用 AMP 时**不要**手动 `.half()`，交给 `torch.autocast` 管理；只有纯 fp16 推理才手动转。
:::

:::warn `CUDA out of memory. Tried to allocate ...` 在第二个 epoch 才出现
典型原因是验证阶段没加 `torch.no_grad()`，验证集的计算图一直挂着。所有评估函数必须 `@torch.no_grad()`。
:::

:::warn 训练准确率一直停在 0.10
CIFAR-10 有 10 类，0.10 就是随机猜。检查：标签有没有被当成输入、`CrossEntropyLoss` 的输入是不是 logits（不要再手动 softmax）、`DataLoader` 的 `shuffle` 与 `drop_last` 是否正常。
:::

:::warn Windows 上 `RandAugment` 让训练慢一倍
数据增强默认在 CPU 上串行执行。方案：把 `num_workers` 提到 4–8（Windows 下必须放在 `if __name__ == "__main__":` 里且函数在模块顶层），或把增强算子数降到 1–2 个（`RandomCrop` + `HorizontalFlip` 已经能贡献大部分收益）。
:::

:::danger 不要同时开着 Ollama / LM Studio 训 CIFAR
本地 LLM 服务常驻 2–4GB 显存，你的可用显存会从 7GB 掉到 3–4GB，直接 OOM。训练前用 `nvidia-smi` 确认没有其他 Python 进程占用显存。
:::

#### D4（周四，2.5h）：U-Net 小尺寸分割

```python
# src/unet.py —— 轻量 U-Net（base=32，适合 8GB 显存）
import torch, torch.nn as nn

def double_conv(in_ch: int, out_ch: int) -> nn.Sequential:
    return nn.Sequential(nn.Conv2d(in_ch, out_ch, 3, padding=1, bias=False),
                         nn.BatchNorm2d(out_ch), nn.ReLU(inplace=True),
                         nn.Conv2d(out_ch, out_ch, 3, padding=1, bias=False),
                         nn.BatchNorm2d(out_ch), nn.ReLU(inplace=True))

class UNet(nn.Module):
    def __init__(self, in_ch: int = 3, out_ch: int = 1, base: int = 32) -> None:
        super().__init__()
        c = [base, base * 2, base * 4, base * 8, base * 16]
        self.d1, self.d2, self.d3, self.d4 = (double_conv(in_ch, c[0]), double_conv(c[0], c[1]),
                                              double_conv(c[1], c[2]), double_conv(c[2], c[3]))
        self.bottleneck = double_conv(c[3], c[4])
        self.pool = nn.MaxPool2d(2)
        self.up4 = nn.ConvTranspose2d(c[4], c[3], 2, 2); self.u4 = double_conv(c[4], c[3])
        self.up3 = nn.ConvTranspose2d(c[3], c[2], 2, 2); self.u3 = double_conv(c[3], c[2])
        self.up2 = nn.ConvTranspose2d(c[2], c[1], 2, 2); self.u2 = double_conv(c[2], c[1])
        self.up1 = nn.ConvTranspose2d(c[1], c[0], 2, 2); self.u1 = double_conv(c[1], c[0])
        self.head = nn.Conv2d(c[0], out_ch, 1)
    def forward(self, x):
        x1 = self.d1(x); x2 = self.d2(self.pool(x1)); x3 = self.d3(self.pool(x2))
        x4 = self.d4(self.pool(x3)); b = self.bottleneck(self.pool(x4))
        y = self.u4(torch.cat([self.up4(b), x4], 1))
        y = self.u3(torch.cat([self.up3(y), x3], 1))
        y = self.u2(torch.cat([self.up2(y), x2], 1))
        y = self.u1(torch.cat([self.up1(y), x1], 1))
        return self.head(y)
```

用 `Oxford-IIIT Pet` 的 trimap 做二值分割（前景=宠物），先下采样到 128×128 控制显存：

```python
# scripts/w08_unet_pet.py —— 小尺寸分割训练（128x128，base=32）
import sys, torch, torch.nn as nn, torch.nn.functional as F
from torch.utils.data import DataLoader
from torchvision.datasets import OxfordIIITPet
from torchvision import transforms
sys.path.insert(0, ".")
from src.unet import UNet
from src.seed import set_seed

class PetSeg(OxfordIIITPet):
    def __getitem__(self, idx):
        img, mask = super().__getitem__(idx)
        m = (mask != 1).float()                      # trimap: 1=前景
        return img, m.unsqueeze(0)

set_seed(42); device = torch.device("cuda")
tf = transforms.Compose([transforms.Resize((128, 128)), transforms.ToTensor(),
                         transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225])])
ds = PetSeg("data/raw", "trainval", target_types="segmentation", transform=tf,
            download=True)
# 注意：mask 也需要 Resize，这里用 target_transform 简化处理
loader = DataLoader(ds, batch_size=16, shuffle=True)
model = UNet(base=32).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)
for ep in range(1, 21):
    tot = iou_num = iou_den = 0
    for x, m in loader:
        x, m = x.to(device), m.to(device)
        logits = model(x)
        loss = F.binary_cross_entropy_with_logits(logits, m)
        opt.zero_grad(set_to_none=True); loss.backward(); opt.step()
        tot += loss.item()
        p = (logits.sigmoid() > 0.5).float()
        iou_num += (p * m).sum().item(); iou_den += ((p + m) > 0).sum().item()
    print(f"ep{ep:02d} loss={tot/len(loader):.4f} IoU={iou_num/max(iou_den,1):.4f} "
          f"peak={torch.cuda.max_memory_allocated()/1024**2:.0f}MB")
```

预期结果：20 epoch 后 IoU 达 **0.80 以上**（宠物与背景对比度大，容易分）；128×128 + base=32 的峰值显存约 **1.2–2.5GB**。注意 `target_transform` 要加 `Resize((128,128))` 与 `ToTensor()`，否则 mask 尺寸与输出不一致会报形状错误。

```python
# src/yolo_label.py —— Pascal VOC 框 <-> YOLO 归一化标签
def voc_to_yolo(x1: float, y1: float, x2: float, y2: float, w: int, h: int) -> tuple[float, ...]:
    cx, cy = (x1 + x2) / 2 / w, (y1 + y2) / 2 / h
    bw, bh = (x2 - x1) / w, (y2 - y1) / h
    return round(cx, 6), round(cy, 6), round(bw, 6), round(bh, 6)

def yolo_to_voc(cx: float, cy: float, bw: float, bh: float, w: int, h: int) -> tuple[float, ...]:
    return ((cx - bw / 2) * w, (cy - bh / 2) * h, (cx + bw / 2) * w, (cy + bh / 2) * h)

if __name__ == "__main__":
    print(voc_to_yolo(100, 200, 300, 400, 640, 640))    # (0.3125, 0.46875, 0.3125, 0.3125)
    print(yolo_to_voc(0.3125, 0.46875, 0.3125, 0.3125, 640, 640))
```

### 自检题（答不上来就不算学会）

1. YOLO 标签里的 4 个数值分别是什么，分母是什么？
   答：`x_center, y_center, width, height`，都是**相对图片宽高归一化**后的值（除以图片宽或高），范围 0–1。
2. `imgsz` 从 640 降到 512，显存和精度怎么变？
   答：激活显存大致按面积比下降（约 0.64 倍），速度提升约 1.5 倍；小目标 mAP 会掉几个点，因为特征图分辨率降低。
3. U-Net 的跳跃连接解决什么问题？
   答：编码器下采样丢掉了空间细节，跳跃连接把同分辨率的高分辨率特征直接拼到解码器，让边界更细；没有它，上采样出来的 mask 边缘会明显糊。
4. `ConvTranspose2d(2, 2)` 与 `Upsample(scale_factor=2)` 的区别？
   答：前者有可学习参数（会学出上采样核，可能产生棋盘格伪影），后者是固定的插值（更快、更稳）。分割里两者都用，棋盘格明显时改用 `Upsample + Conv`。
5. 小数据集上检测模型最容易出的问题是什么？
   答：过拟合与漏检小目标。对策：用预训练权重、`imgsz` 别调太小、加 `mosaic`/`scale` 增强、`patience` 早停、把 `val` 里同一场景的图与训练图分开。
6. 为什么 P3 选 `mobilenetv3_small_100` 而不是 `resnet18`？
   答：参数量 1.5M vs 11.2M（约 7 倍差距），边缘设备推理延迟与模型大小直接相关；MobileNetV3 用 depthwise 卷积 + SE 模块，在 INT8 量化下精度损失更小，且 1 epoch 就能到 0.85+。

#### D1（周一，2.5h）：三种迁移学习策略对照

```python
# scripts/w09_strategies.py —— 全量微调 / 冻结主干 / 差分学习率
import sys, json, time, torch, torch.nn as nn, timm
sys.path.insert(0, ".")
from src.data_cifar import build_loaders
from src.amp_train import train_epoch_amp
from src.train_loop import evaluate
from src.seed import set_seed

def build(strategy: str):
    set_seed(42); device = torch.device("cuda")
    model = timm.create_model("mobilenetv3_small_100", pretrained=True, num_classes=10).to(device)
    if strategy == "frozen":
        for n, p in model.named_parameters():
            p.requires_grad = "classifier" in n
        opt = torch.optim.AdamW(filter(lambda p: p.requires_grad, model.parameters()), lr=1e-3)
    elif strategy == "full":
        opt = torch.optim.AdamW(model.parameters(), lr=1e-4)
    else:  # diff_lr：主干 1e-5，头部 1e-3
        head = [p for n, p in model.named_parameters() if "classifier" in n]
        backbone = [p for n, p in model.named_parameters() if "classifier" not in n]
        opt = torch.optim.AdamW([{"params": backbone, "lr": 1e-5},
                                 {"params": head, "lr": 1e-3}], weight_decay=1e-4)
    return device, model, opt

if __name__ == "__main__":
    tr, va, te = build_loaders(batch_size=128, augment=True)
    crit = nn.CrossEntropyLoss(label_smoothing=0.1)
    out = []
    for strategy in ("frozen", "full", "diff_lr"):
        device, model, opt = build(strategy)
        t0 = time.time(); torch.cuda.reset_peak_memory_stats()
        for ep in range(1, 9):
            train_epoch_amp(model, tr, opt, crit, device)
        _, vacc = evaluate(model, va, crit, device)
        out.append({"strategy": strategy, "val_acc": round(vacc, 4),
                    "sec": round(time.time() - t0, 1),
                    "peak_MB": round(torch.cuda.max_memory_allocated() / 1024**2, 1)})
        print(out[-1])
    json.dump(out, open("outputs/w09_strategies.json", "w"), indent=2)
```

预期结果：三行结果，典型形态是 `frozen` 收敛最快但上限略低（0.92–0.94），`full` 上限最高但前期慢（0.94–0.96），`diff_lr` 兼顾（0.95–0.97）。把「策略 → 指标 → 耗时」表写进 P3 README。

```python
# scripts/w09_quantize.py —— 静态 INT8 量化（带校准）
import numpy as np, torch, sys
from onnxruntime.quantization import (quantize_static, CalibrationDataReader,
                                      QuantType, QuantFormat)
sys.path.insert(0, ".")
from src.data_cifar import build_loaders

class CalibReader(CalibrationDataReader):
    def __init__(self, n_batches: int = 20) -> None:
        tr, _, _ = build_loaders(batch_size=32, augment=False)
        self.it = iter(tr); self.left = n_batches
    def get_next(self):
        if self.left <= 0: return None
        x, _ = next(self.it); self.left -= 1
        return {"input": x.numpy().astype(np.float32)}

quantize_static(
    model_input="outputs/p3_mobilenet.onnx",
    model_output="outputs/p3_mobilenet_int8.onnx",
    calibration_data_reader=CalibReader(),
    quant_format=QuantFormat.QDQ,      # QDQ 格式对 TensorRT/ORT 都友好
    per_channel=True,
    activation_type=QuantType.QUInt8,
    weight_type=QuantType.QInt8,
)
print("done")
```

```python
# scripts/w09_bench_latency.py —— 延迟/吞吐/精度三合一报告
import time, json, numpy as np, onnxruntime as ort, torch, sys
sys.path.insert(0, ".")
from src.data_cifar import build_loaders

def make_sess(path: str, threads: int = 4) -> ort.InferenceSession:
    so = ort.SessionOptions(); so.intra_op_num_threads = threads
    return ort.InferenceSession(path, so, providers=["CPUExecutionProvider"])

def bench(path: str, batch: int = 1, iters: int = 50, warmup: int = 10) -> dict:
    sess = make_sess(path)
    name = sess.get_inputs()[0].name
    x = np.random.randn(batch, 3, 32, 32).astype(np.float32)
    for _ in range(warmup): sess.run(None, {name: x})          # 必须 warmup
    ts = []
    for _ in range(iters):
        t0 = time.perf_counter(); sess.run(None, {name: x}); ts.append((time.perf_counter() - t0) * 1000)
    ts = np.array(ts)
    return {"model": path, "batch": batch, "mean_ms": round(ts.mean(), 2),
            "p50_ms": round(np.percentile(ts, 50), 2), "p99_ms": round(np.percentile(ts, 99), 2),
            "throughput_ips": round(batch * 1000 / ts.mean(), 1)}

def accuracy_onnx(path: str) -> float:
    sess = make_sess(path); name = sess.get_inputs()[0].name
    _, _, te = build_loaders(batch_size=256, augment=False)
    correct = seen = 0
    for x, y in te:
        out = sess.run(None, {name: x.numpy().astype(np.float32)})[0]
        correct += (out.argmax(1) == y.numpy()).sum().item(); seen += y.size(0)
    return round(correct / seen, 4)

if __name__ == "__main__":
    report = [{"metrics": bench(p), "acc": accuracy_onnx(p)}
              for p in ("outputs/p3_mobilenet.onnx", "outputs/p3_mobilenet_int8.onnx")]
    print(json.dumps(report, indent=2))
    json.dump(report, open("outputs/w09_latency.json", "w"), indent=2)
```

预期结果：CPU 上 batch=1 时 fp32 约 **6–15ms**、INT8 约 **3–8ms**（提速 1.5–2.5 倍）；INT8 精度掉 **0.3–1.5 个点**。若 INT8 精度掉超过 3 个点，改用 `per_channel=True` + `QuantFormat.QDQ` + 更多校准数据，或对首尾层做排除（`nodes_to_exclude`）。

### 自检题（答不上来就不算学会）

1. 静态量化与动态量化的区别，什么时候用哪个？
   答：静态量化需要校准数据集，把激活也量化成 INT8，速度快但掉点风险高；动态量化量化权重、激活在推理时动态量化，无需校准、掉点更小但提速有限。边缘端追求延迟用静态，追求稳妥先用动态。
2. `per_channel=True` 为什么能减少掉点？
   答：逐通道量化给每个输出通道单独的 scale/zero_point，避免某个通道的权重量级被整体拉偏；卷积/线性层的权重量化基本都该开。
3. `opset_version` 选多少合适？
   答：17 是当前主流运行时都支持、且覆盖 `LayerNormalization` 等算子的稳妥版本；18 更新但部分推理引擎支持不全。W11 手写 Transformer 导出时优先 17。
4. 为什么测延迟必须 warmup？
   答：首次推理包含图优化、内存分配、算子内核选择等一次性开销，不 warmup 测出的数字会偏高好几倍。一般 warmup 10 次再测 50–100 次。
5. p50 与 p99 延迟在端侧部署里各代表什么？
   答：p50 是中位体验（大多数请求的感受），p99 是尾部延迟（决定用户投诉与超时率）。服务化时必须同时报，只看均值会被长尾掩盖。
6. INT8 量化为什么对 MobileNetV3 特别合适？
   答：它以 depthwise 卷积为主，权重分布集中、激活动态范围小，量化误差小；同时 depthwise 卷积在 INT8 上能拿到接近 2 倍的加速。

### 踩坑提醒

:::warn `torch.onnx.export` 报 “ONNX export failed: Couldn't export operator aten::xxx”
用了 ONNX 不支持的自定义算子，或 PyTorch 版本与 `opset_version` 不匹配。先降到 17，仍报错就把该算子换成等价的标准实现（例如用 `nn.functional.scaled_dot_product_attention` 替代手写的多头注意力导出）。
:::

:::warn `quantize_static` 报 “Calibration data reader returns None too early”
校准样本太少（少于模型需要的观察次数）。把 `CalibReader` 的批数提到 50–100，并确保 `get_next` 返回的 key 与 ONNX 输入名（`input`）完全一致。
:::

:::warn INT8 精度掉超过 3 个点
先确认校准集与训练集同分布（别用做了强增强的 batch 做校准）；再试 `QuantFormat.QDQ` + `per_channel=True` + `activation_type=QuantType.QUInt8`；仍不行就用 `nodes_to_exclude` 排除首层卷积与最后的分类层。
:::

:::warn ONNX Runtime 默认把所有核吃满导致笔记本卡死
设置 `so.intra_op_num_threads = 4` 与 `so.inter_op_num_threads = 1`，并给进程设低优先级；测延迟时关掉其他负载，否则 p99 会被其他进程拉爆。
:::

:::danger 不要在同一台机器上同时跑训练与延迟测试
训练进程会抢占 GPU/CPU，测出的 p99 会虚高 3–10 倍。延迟测试必须单独跑，并在报告里写明「测试时无其他负载」。
:::

```python
# src/textcnn.py —— TextCNN（多尺寸卷积核）
import torch, torch.nn as nn, torch.nn.functional as F

class TextCNN(nn.Module):
    def __init__(self, vocab_size: int, emb_dim: int = 128, num_classes: int = 10,
                 kernel_sizes: tuple[int, ...] = (2, 3, 4), num_filters: int = 128,
                 dropout: float = 0.3) -> None:
        super().__init__()
        self.emb = nn.Embedding(vocab_size, emb_dim, padding_idx=0)
        self.convs = nn.ModuleList([nn.Conv1d(emb_dim, num_filters, k) for k in kernel_sizes])
        self.drop = nn.Dropout(dropout)
        self.fc = nn.Linear(num_filters * len(kernel_sizes), num_classes)
    def forward(self, x):
        e = self.emb(x).transpose(1, 2)                       # [B, emb, L]
        feats = [F.relu(c(e)).max(dim=2).values for c in self.convs]   # 全局最大池化
        return self.fc(self.drop(torch.cat(feats, dim=1)))
```

```python
# scripts/w10_bert_cls.py —— bert-base-chinese 中文分类微调
import sys, numpy as np, torch, evaluate
from datasets import load_dataset
from transformers import (AutoTokenizer, AutoModelForSequenceClassification,
                          TrainingArguments, Trainer, DataCollatorWithPadding)
sys.path.insert(0, ".")

MODEL = "bert-base-chinese"
ds = load_dataset("thu-coai/THUCNews", split="train[:5000]").train_test_split(test_size=0.2, seed=42)
tok = AutoTokenizer.from_pretrained(MODEL)

def preprocess(batch):
    return tok(batch["text"], truncation=True, max_length=128)

ds = ds.map(preprocess, batched=True)
labels = sorted(set(ds["train"]["label"]))
model = AutoModelForSequenceClassification.from_pretrained(MODEL, num_labels=len(labels))

def compute_metrics(eval_pred):
    logits, refs = eval_pred
    preds = np.argmax(logits, axis=-1)
    return {"acc": float((preds == refs).mean()),
            "macro_f1": float(evaluate.load("f1").compute(predictions=preds,
                                                          references=refs, average="macro")["f1"])}

args = TrainingArguments(
    output_dir="outputs/w10_bert_cls", learning_rate=2e-5, per_device_train_batch_size=32,
    per_device_eval_batch_size=64, num_train_epochs=3, weight_decay=0.01,
    warmup_ratio=0.1, fp16=torch.cuda.is_available(), eval_strategy="epoch",
    save_strategy="epoch", load_best_model_at_end=True, metric_for_best_model="macro_f1",
    logging_steps=50, report_to="none", seed=42,
)
trainer = Trainer(model=model, args=args, train_dataset=ds["train"], eval_dataset=ds["test"],
                  tokenizer=tok, data_collator=DataCollatorWithPadding(tok),
                  compute_metrics=compute_metrics)
trainer.train()
print(trainer.evaluate())
trainer.save_model("checkpoints/w10_bert_cls")
```

```python
# scripts/w10_ner_bert.py —— BERT + 线性头做 token 分类（NER）
import numpy as np, torch
from datasets import load_dataset
from transformers import (AutoTokenizer, AutoModelForTokenClassification,
                          TrainingArguments, Trainer, DataCollatorForTokenClassification)

MODEL = "bert-base-chinese"
ENTITIES = ["address", "book", "company", "game", "government", "movie",
            "name", "organization", "position", "scene"]
labels = ["O"] + [f"{p}-{e}" for e in ENTITIES for p in ("B", "I")]
l2i = {l: i for i, l in enumerate(labels)}
tok = AutoTokenizer.from_pretrained(MODEL)

def encode(example):
    text, ann = example["text"], example["label"]
    chars = list(text)
    tags = ["O"] * len(chars)
    for ent, spans in ann.items():
        for s, e in spans:
            tags[s] = f"B-{ent}"
            for i in range(s + 1, e + 1):
                tags[i] = f"I-{ent}"
    enc = tok(chars, is_split_into_words=True, truncation=True, max_length=256)
    word_ids = enc.word_ids()
    prev, enc["labels"] = None, []
    for wid in word_ids:
        if wid is None: enc["labels"].append(-100)
        elif wid != prev: enc["labels"].append(l2i[tags[wid]])
        else: enc["labels"].append(l2i[tags[wid]])     # 中文单字，通常无子词问题
        prev = wid
    return enc

ds = load_dataset("cluener2020")
ds = ds.map(encode, remove_columns=ds["train"].column_names)
model = AutoModelForTokenClassification.from_pretrained(MODEL, num_labels=len(labels))
args = TrainingArguments(output_dir="outputs/w10_ner", learning_rate=3e-5,
                         per_device_train_batch_size=32, num_train_epochs=3,
                         fp16=torch.cuda.is_available(), eval_strategy="epoch",
                         logging_steps=50, report_to="none", seed=42)
trainer = Trainer(model=model, args=args, train_dataset=ds["train"], eval_dataset=ds["validation"],
                  data_collator=DataCollatorForTokenClassification(tok))
trainer.train()
```

预期结果：`cluener` 训练集约 10748 条，实体 10 类；`bert-base-chinese` 微调 3 epoch 后实体级 F1 约 **0.75–0.82**（BIO 逐 token 准确率会到 0.96+，因为 `O` 占绝大多数，**不要用 token accuracy 汇报 NER 效果**）。

```python
# src/text_vocab.py —— 词表构建与编码（从零实现，不依赖 tokenizers）
from collections import Counter
import jieba, torch

PAD, UNK = 0, 1

def build_vocab(texts: list[str], max_size: int = 30000, min_freq: int = 2) -> dict[str, int]:
    cnt = Counter(w for t in texts for w in jieba.lcut(t))
    words = [w for w, c in cnt.most_common(max_size) if c >= min_freq]
    return {"<pad>": PAD, "<unk>": UNK, **{w: i + 2 for i, w in enumerate(words)}}

def encode(text: str, vocab: dict[str, int], max_len: int = 128) -> torch.Tensor:
    ids = [vocab.get(w, UNK) for w in jieba.lcut(text)][:max_len]
    return torch.tensor(ids + [PAD] * (max_len - len(ids)), dtype=torch.long)
```

### 自检题（答不上来就不算学会）

1. BERT 的 `[CLS]` 向量为什么能用于分类？
   答：预训练时 `[CLS]` 位置参与了 NSP 与整句表示的学习，注意力机制让它聚合全句信息；微调时接一个线性头即可，通常效果优于句向量平均。
2. 为什么要保留 `token_type_ids` 和 `attention_mask`？
   答：`attention_mask` 让 padding 位置不参与注意力（否则会稀释有效信息）；`token_type_ids` 用于句对任务区分两段文本，单句分类里全为 0。
3. NER 的 `-100` 标签是什么？
   答：PyTorch 的 `CrossEntropyLoss(ignore_index=-100)` 默认忽略的标签值。给 padding、`[CLS]`、`[SEP]` 与子词的非首片段标 `-100`，让它们不产生 loss。
4. 为什么 NER 要用实体级 F1 而不是 token 准确率？
   答：`O` 标签通常占 90% 以上，全部预测为 `O` 也有高 token 准确率；实体级 F1 要求边界与类别都正确，才反映真实能力。
5. `max_length` 从 128 提到 512，显存与速度怎么变？
   答：注意力是 O(L²)，显存与计算量约按 16 倍增长（512²/128²）。8GB 显存上 `bert-base` 的 `max_length=512` 需要把 batch 降到 4–8 并使用梯度累积。
6. `fastText` 与 `TextCNN` 在什么场景下还值得用？
   答：数据量小（< 1 万条）、要极低延迟（< 1ms）、或要做蒸馏教师/基线对照时。它们训练快、部署简单，且能快速验证数据标注质量。

数据里残留了 `text` 等字符串列，Trainer 会把它们当输入传给模型。必须在 `map` 时 `remove_columns=ds["train"].column_names`，或设置 `remove_unused_columns=True`（Trainer 默认如此，冲突时显式删列）。

:::warn `cluener` 的实体索引是闭区间还是半开区间？
原数据里 `[start, end]` 是**闭区间**（含 end），所以 `I-` 标签要标到 `end`（`range(s+1, e+1)`）。写成半开会让每个实体少一个字，F1 会整体掉 3–8 个点。

:::

`cluener` 的 `validation` 用来选 epoch，`test` 只在最后评一次。用测试集反复挑参数会让报告出来的 F1 虚高 2–5 个点，面试一问就露。

#### D1（周一，2.5h）：缩放点积注意力

```python
# src/attention.py —— 缩放点积注意力（含掩码）
import math, torch, torch.nn as nn, torch.nn.functional as F

def scaled_dot_product_attention(q, k, v, mask=None, dropout_p: float = 0.0):
    """q:[B, H, Lq, D] k:[B, H, Lk, D] v:[B, H, Lk, Dv] mask:[B,1,1,Lk] or [B,1,Lq,Lk]"""
    d_k = q.size(-1)
    scores = q @ k.transpose(-2, -1) / math.sqrt(d_k)      # [B,H,Lq,Lk]
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    attn = F.softmax(scores, dim=-1)                        # 每行和为 1
    if dropout_p > 0:
        attn = F.dropout(attn, p=dropout_p, training=True)
    return attn @ v, attn                                   # [B,H,Lq,Dv], [B,H,Lq,Lk]

if __name__ == "__main__":
    torch.manual_seed(0)
    q = torch.randn(2, 4, 6, 16); k = torch.randn(2, 4, 8, 16); v = torch.randn(2, 4, 8, 16)
    out, attn = scaled_dot_product_attention(q, k, v)
    print(out.shape, attn.shape)            # [2,4,6,16] [2,4,6,8]
    print("attn 行和:", attn.sum(-1)[0, 0, 0])   # 预期 1.0000

    # 因果掩码（下三角）
    L = 6
    causal = torch.tril(torch.ones(1, 1, L, L))
    out_c, attn_c = scaled_dot_product_attention(q[:, :, :L], k[:, :, :L], v[:, :, :L], mask=causal)
    print("上三角是否全 0:", bool((torch.triu(attn_c, diagonal=1) == 0).all()))   # True
```

预期结果：`attn` 每行和为 1；因果掩码下上三角为 0。把 `d_k` 从 16 改成 4、64 各跑一次，观察注意力分布变得更尖锐/更平滑，解释 `sqrt(d_k)` 的作用（点积方差随维度线性增长，不缩放会让 softmax 饱和、梯度消失）。

```python
# src/mha.py —— 从零实现多头注意力
import math, torch, torch.nn as nn, torch.nn.functional as F

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model: int = 256, n_heads: int = 8, dropout: float = 0.1) -> None:
        super().__init__()
        assert d_model % n_heads == 0, "d_model 必须能被 n_heads 整除"
        self.d_model, self.n_heads, self.d_head = d_model, n_heads, d_model // n_heads
        self.w_q = nn.Linear(d_model, d_model, bias=False)
        self.w_k = nn.Linear(d_model, d_model, bias=False)
        self.w_v = nn.Linear(d_model, d_model, bias=False)
        self.w_o = nn.Linear(d_model, d_model, bias=False)
        self.drop = nn.Dropout(dropout)
    def _split(self, x: torch.Tensor) -> torch.Tensor:
        B, L, _ = x.shape
        return x.view(B, L, self.n_heads, self.d_head).transpose(1, 2)   # [B,H,L,D]
    def forward(self, q, k, v, mask=None):
        B, Lq, _ = q.shape
        Q, K, V = self._split(self.w_q(q)), self._split(self.w_k(k)), self._split(self.w_v(v))
        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_head)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float("-inf"))
        attn = self.drop(F.softmax(scores, dim=-1))
        out = attn @ V                                              # [B,H,Lq,D]
        out = out.transpose(1, 2).contiguous().view(B, Lq, self.d_model)
        return self.w_o(out), attn
```

```python
# src/pos_encoding.py —— 正弦位置编码 + 可学习位置编码对照
import math, torch, torch.nn as nn

class SinusoidalPositionalEncoding(nn.Module):
    def __init__(self, d_model: int, max_len: int = 512) -> None:
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        pos = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
        div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(pos * div)
        pe[:, 1::2] = torch.cos(pos * div)
        self.register_buffer("pe", pe.unsqueeze(0))          # [1, max_len, d_model]
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return x + self.pe[:, : x.size(1)]

class LearnedPositionalEmbedding(nn.Module):
    def __init__(self, d_model: int, max_len: int = 512) -> None:
        super().__init__()
        self.emb = nn.Embedding(max_len, d_model)
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        pos = torch.arange(x.size(1), device=x.device)
        return x + self.emb(pos).unsqueeze(0)
```

预期结果：把 `pe` 画成热力图（`outputs/w11_pos_encoding.png`）能看到「波长随维度变长」的条纹结构。解释为什么正弦编码能让模型外推到比训练更长的序列（相对位置可由线性变换表达），而可学习编码不能。

#### D4（周四，2.5h）：Encoder 与 Decoder 层

```python
# src/transformer.py —— Encoder/Decoder 层与完整模型
import torch, torch.nn as nn
from src.mha import MultiHeadAttention
from src.pos_encoding import SinusoidalPositionalEncoding

class FeedForward(nn.Module):
    def __init__(self, d_model: int = 256, d_ff: int = 1024, dropout: float = 0.1) -> None:
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d_model, d_ff), nn.GELU(),
                                 nn.Dropout(dropout), nn.Linear(d_ff, d_model))
    def forward(self, x): return self.net(x)

class EncoderLayer(nn.Module):
    def __init__(self, d_model: int = 256, n_heads: int = 8, d_ff: int = 1024, dropout: float = 0.1):
        super().__init__()
        self.attn = MultiHeadAttention(d_model, n_heads, dropout)
        self.ff = FeedForward(d_model, d_ff, dropout)
        self.n1, self.n2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
        self.drop = nn.Dropout(dropout)
    def forward(self, x, mask=None):
        a, _ = self.attn(x, x, x, mask)
        x = self.n1(x + self.drop(a))          # Post-LN（原论文写法）
        return self.n2(x + self.drop(self.ff(x)))

class DecoderLayer(nn.Module):
    def __init__(self, d_model: int = 256, n_heads: int = 8, d_ff: int = 1024, dropout: float = 0.1):
        super().__init__()
        self.self_attn = MultiHeadAttention(d_model, n_heads, dropout)
        self.cross_attn = MultiHeadAttention(d_model, n_heads, dropout)
        self.ff = FeedForward(d_model, d_ff, dropout)
        self.n1, self.n2, self.n3 = (nn.LayerNorm(d_model), nn.LayerNorm(d_model), nn.LayerNorm(d_model))
        self.drop = nn.Dropout(dropout)
    def forward(self, x, memory, self_mask=None, cross_mask=None):
        a, _ = self.self_attn(x, x, x, self_mask)
        x = self.n1(x + self.drop(a))
        c, _ = self.cross_attn(x, memory, memory, cross_mask)     # Q 来自解码器，K/V 来自编码器
        x = self.n2(x + self.drop(c))
        return self.n3(x + self.drop(self.ff(x)))
```

预期结果：`EncoderLayer` 与 `DecoderLayer` 前向无报错，输出 shape 与输入一致。**必须自己画出 shape 变化表**（见下文核心小节），并逐行注释 `cross_attn` 的 Q/K/V 来源——这是面试最常被追问的点。

```python
# scripts/w11_seq2seq.py —— 序列反转任务：验证 Encoder-Decoder 能学会
import sys, math, torch, torch.nn as nn
sys.path.insert(0, ".")
from src.transformer import EncoderLayer, DecoderLayer
from src.pos_encoding import SinusoidalPositionalEncoding
from src.seed import set_seed

V, D, H, L, N = 32, 128, 8, 12, 2        # 词表 / 维度 / 头数 / 长度 / 层数

class Seq2Seq(nn.Module):
    def __init__(self) -> None:
        super().__init__()
        self.emb = nn.Embedding(V, D)
        self.pos = SinusoidalPositionalEncoding(D, L + 2)
        self.enc = nn.ModuleList([EncoderLayer(D, H, D * 4) for _ in range(N)])
        self.dec = nn.ModuleList([DecoderLayer(D, H, D * 4) for _ in range(N)])
        self.head = nn.Linear(D, V)
    def forward(self, src, tgt):
        mem = self.pos(self.emb(src))
        for l in self.enc: mem = l(mem)
        x = self.pos(self.emb(tgt))
        causal = torch.tril(torch.ones(1, 1, tgt.size(1), tgt.size(1), device=src.device))
        for l in self.dec: x = l(x, mem, self_mask=causal)
        return self.head(x)

set_seed(0)
dev = "cuda"
model = Seq2Seq().to(dev)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)
crit = nn.CrossEntropyLoss(ignore_index=0)
for step in range(1, 301):
    src = torch.randint(1, V, (32, L), device=dev)
    tgt_in = torch.cat([torch.zeros(32, 1, dtype=torch.long, device=dev), src.flip(1)[:, :-1]], 1)
    tgt_out = src.flip(1)
    logits = model(src, tgt_in)
    loss = crit(logits.reshape(-1, V), tgt_out.reshape(-1))
    opt.zero_grad(set_to_none=True); loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0); opt.step()
    if step % 50 == 0:
        acc = (logits.argmax(-1) == tgt_out).float().mean().item()
        print(f"step {step:3d} loss={loss.item():.3f} token_acc={acc:.3f}")
```

```python
# src/masks.py —— padding 掩码与因果掩码
import torch

def padding_mask(ids: torch.Tensor, pad_id: int = 0) -> torch.Tensor:
    """ids:[B,L] -> [B,1,1,L]，1 为有效位置，0 为 pad。"""
    return (ids != pad_id).unsqueeze(1).unsqueeze(2).long()

def causal_mask(L: int, device=None) -> torch.Tensor:
    """[1,1,L,L] 下三角为 1（可见），上三角为 0（屏蔽）。"""
    return torch.tril(torch.ones(1, 1, L, L, device=device)).long()

def combine(*masks: torch.Tensor) -> torch.Tensor:
    """多个掩码取交集（都必须可见）。"""
    out = masks[0]
    for m in masks[1:]:
        out = out * m
    return out
```

### 自检题（答不上来就不算学会）

1. 为什么要除以 `sqrt(d_k)`？
   答：`q·k` 的方差随 `d_k` 线性增长，不缩放会让 softmax 输入量级过大而饱和（一个位置拿到接近 1 的权重），梯度趋近 0；除以 `sqrt(d_k)` 把方差拉回 1 附近，保持梯度健康。
2. 多头注意力相比单头多了什么能力？
   答：每个头在自己的子空间里学不同的对齐关系（例如语法依赖、指代、位置邻近），最后拼接再投影；单头只能学一种平均化的关系。参数量与单头相同（都是 4*d_model²）。
3. Decoder 的交叉注意力里 Q/K/V 分别来自哪里？
   答：Q 来自解码器当前层（已生成的前缀表示），K 和 V 都来自编码器输出 `memory`；这保证解码时能「查询」源序列信息。
4. 因果掩码为什么必须在 softmax 之前加？
   答：softmax 之后再屏蔽会把行和变得不为 1，破坏注意力的概率语义；正确做法是把被屏蔽位置的分数设为 `-inf`，softmax 后它们自然为 0。
5. Post-LN 与 Pre-LN 的区别，哪个更好训？
   答：Post-LN 是「残差 + LayerNorm 在子层之后」（原论文），深层时梯度不稳、需要 warmup；Pre-LN 把 LayerNorm 放在子层之前，训练更稳，现代大模型多用 Pre-LN 或 RMSNorm。
6. `.contiguous()` 在多头合并时为什么必须调用？
   答：`transpose` 之后张量在内存里不连续，`view` 会报 `RuntimeError: view size is not compatible with input tensor's size and stride`；`.contiguous()` 先把数据排成连续布局再用 `view`（或用 `reshape`，它内部会按需拷贝）。

### 踩坑提醒

:::warn `RuntimeError: view size is not compatible with input tensor's size and stride`
`transpose` 后直接 `view`。改用 `.transpose(1,2).contiguous().view(B, L, D)`，或直接 `.reshape(B, L, D)`。
:::

:::warn 注意力权重整行变成 `nan`
`masked_fill(mask == 0, -inf)` 之后某一**整行**都被屏蔽（常见于 padding 掩码构造错误，例如某个样本全是 pad），`softmax(-inf)` 得到 `nan`。解法：保证每条序列至少有一个有效位置，或对全屏蔽行做特殊处理。
:::

:::warn 训练 loss 完全不降（序列反转任务）
三个高频原因：`tgt_in` 没有右移（把目标当输入，模型直接抄答案，loss 会突然很低随后崩）；因果掩码没传给自注意力（信息泄漏，测试时崩）；学习率 3e-4 配 `AdamW` 时忘了 warmup（前 50 步 loss 抖动）。
:::

:::warn 显存随序列长度爆掉
注意力是 O(L²)。`L=512, H=8, batch=32` 时分数矩阵就是 `[32,8,512,512]` ≈ 67M 个 fp16 元素（约 134MB）单层，多层叠加很快就 OOM。对策：`batch=8` + 梯度累积，或用 `torch.nn.functional.scaled_dot_product_attention`（FlashAttention，显存 O(L)）。
:::

#### D3（周三，2.5h）：中文小 GPT 训练（约 1M 参数，8GB 显存轻松跑）

```python
# src/minigpt.py —— Decoder-only 小 GPT（复用 W11 的注意力与位置编码）
import torch, torch.nn as nn
from src.mha import MultiHeadAttention
from src.pos_encoding import SinusoidalPositionalEncoding

class Block(nn.Module):
    def __init__(self, d_model: int, n_heads: int, dropout: float = 0.1) -> None:
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)   # Pre-LN
        self.attn = MultiHeadAttention(d_model, n_heads, dropout)
        self.ff = nn.Sequential(nn.Linear(d_model, 4 * d_model), nn.GELU(),
                                nn.Linear(4 * d_model, d_model), nn.Dropout(dropout))
    def forward(self, x, mask=None):
        h, _ = self.attn(self.ln1(x), self.ln1(x), self.ln1(x), mask)
        x = x + h
        return x + self.ff(self.ln2(x))

class MiniGPT(nn.Module):
    def __init__(self, vocab_size: int, d_model: int = 256, n_heads: int = 8,
                 n_layers: int = 6, block_size: int = 128, dropout: float = 0.1) -> None:
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, d_model)
        self.pos = SinusoidalPositionalEncoding(d_model, block_size)
        self.blocks = nn.ModuleList([Block(d_model, n_heads, dropout) for _ in range(n_layers)])
        self.ln_f = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, vocab_size, bias=False)
        self.head.weight = self.tok_emb.weight          # 权重绑定，省参数
    def forward(self, idx):
        B, L = idx.shape
        assert L <= self.block_size, f"序列长度 {L} 超过 block_size {self.block_size}"
        x = self.pos(self.tok_emb(idx))
        causal = torch.tril(torch.ones(1, 1, L, L, device=idx.device))
        for b in self.blocks:
            x = b(x, causal)
        return self.head(self.ln_f(x))
```

```python
# scripts/w12_train_gpt.py —— 训练中文小 GPT
import sys, json, time, torch, torch.nn as nn, numpy as np
sys.path.insert(0, ".")
from src.minigpt import MiniGPT
from src.seed import set_seed

BLOCK, BATCH, STEPS = 128, 32, 3000
set_seed(42); device = torch.device("cuda")

# 用 D2 的 tokenizer 把语料编成一个长 id 序列
from tokenizers import Tokenizer
tok = Tokenizer.from_file("outputs/w12_tokenizer.json")
text = open("data/raw/zh_corpus.txt", encoding="utf-8").read()
ids = np.array(tok.encode(text).ids, dtype=np.int64)
print("总 token 数:", len(ids))
n = int(0.98 * len(ids)); train_ids, val_ids = ids[:n], ids[n:]

def get_batch(split: str):
    d = train_ids if split == "train" else val_ids
    ix = np.random.randint(0, len(d) - BLOCK - 1, size=BATCH)
    x = np.stack([d[i:i + BLOCK] for i in ix])
    y = np.stack([d[i + 1:i + 1 + BLOCK] for i in ix])
    return torch.from_numpy(x).to(device), torch.from_numpy(y).to(device)

vocab = tok.get_vocab_size()
model = MiniGPT(vocab).to(device)
print("参数量:", sum(p.numel() for p in model.parameters()) / 1e6, "M")   # 预期 8–12M（d_model=256, 6 层）
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, betas=(0.9, 0.95), weight_decay=0.1)
scaler = torch.amp.GradScaler("cuda")
hist = []
for step in range(1, STEPS + 1):
    x, y = get_batch("train")
    with torch.autocast("cuda", dtype=torch.float16):
        loss = nn.functional.cross_entropy(model(x).view(-1, vocab), y.view(-1))
    opt.zero_grad(set_to_none=True)
    scaler.scale(loss).backward(); scaler.unscale_(opt)
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(opt); scaler.update()
    if step % 250 == 0:
        model.eval()
        with torch.no_grad():
            xv, yv = get_batch("val")
            with torch.autocast("cuda", dtype=torch.float16):
                vl = nn.functional.cross_entropy(model(xv).view(-1, vocab), yv.view(-1)).item()
        model.train()
        hist.append({"step": step, "train_loss": round(loss.item(), 4), "val_loss": round(vl, 4),
                     "peak_MB": round(torch.cuda.max_memory_allocated() / 1024**2, 1)})
        print(hist[-1])
json.dump(hist, open("outputs/w12_gpt_hist.json", "w"), indent=2)
torch.save({"model": model.state_dict(), "vocab": vocab, "block": BLOCK}, "checkpoints/w12_minigpt.pt")
```

预期结果：`d_model=256, n_layers=6, block_size=128, batch=32` 时参数量约 **8–12M**，峰值显存约 **2–4GB**（完全在 7GB 可用范围内），3000 步约 15–30 分钟。`val_loss` 应从约 9.0（`ln(8000)`）降到 **5.5–7.0**。若 `val_loss` 不降：`lr` 降到 1e-4、检查因果掩码、确认 `y` 是右移一位的目标。

#### D4（周四，2.5h）：采样策略对比

```python
# scripts/w12_sampling.py —— greedy / temperature / top-k / top-p 对比
import sys, torch, torch.nn.functional as F, pathlib
sys.path.insert(0, ".")
from src.minigpt import MiniGPT
from tokenizers import Tokenizer

tok = Tokenizer.from_file("outputs/w12_tokenizer.json")
ck = torch.load("checkpoints/w12_minigpt.pt", map_location="cuda", weights_only=False)
model = MiniGPT(ck["vocab"], block_size=ck["block"]).cuda().eval()
model.load_state_dict(ck["model"])

@torch.no_grad()
def generate(prompt: str, max_new: int = 60, temperature: float = 1.0,
             top_k: int | None = None, top_p: float | None = None) -> str:
    ids = tok.encode(prompt).ids
    idx = torch.tensor([ids], device="cuda")
    for _ in range(max_new):
        logits = model(idx[:, -ck["block"]:])[:, -1, :] / max(temperature, 1e-5)
        if top_k:
            v, _ = torch.topk(logits, top_k)
            logits[logits < v[:, [-1]]] = float("-inf")
        if top_p:
            s, si = torch.sort(logits, descending=True)
            cum = torch.cumsum(F.softmax(s, dim=-1), dim=-1)
            remove = cum - F.softmax(s, dim=-1) > top_p
            s[remove] = float("-inf")
            logits = torch.full_like(logits, float("-inf")).scatter(1, si, s)
        probs = F.softmax(logits, dim=-1)
        nxt = torch.multinomial(probs, 1) if temperature > 0 else logits.argmax(-1, keepdim=True)
        idx = torch.cat([idx, nxt], dim=1)
    return tok.decode(idx[0].tolist())

prompt = "深度学习"
for name, kw in [("greedy", dict(temperature=0.0)),
                 ("temp0.7", dict(temperature=0.7)),
                 ("top-k50", dict(temperature=0.8, top_k=50)),
                 ("top-p0.9", dict(temperature=0.8, top_p=0.9))]:
    out = generate(prompt, **kw)
    pathlib.Path("outputs").mkdir(exist_ok=True)
    open(f"outputs/w12_gen_{name}.txt", "w", encoding="utf-8").write(out)
    print(f"--- {name} ---\n{out}\n")
```

预期结果：4 个 `outputs/w12_gen_*.txt` 生成。**这是关键观察**：greedy 输出重复、死循环；`temperature=0.7` 更自然；`top-p=0.9` 在多样性与连贯性之间最平衡。每个策略的文字各挑 30 字贴进笔记并点评。

生成阶段的 KV Cache 手写版（理解 `past_key_values` 为什么能加速推理）：

```python
# src/kv_cache.py —— 极简 KV Cache（对比有无 cache 的生成速度）
import time, torch, torch.nn.functional as F

def generate_with_cache(model, idx: torch.Tensor, max_new: int = 50) -> torch.Tensor:
    """朴素实现：每步只喂最后一个 token，缓存历史 K/V（示例用假 K/V 结构说明思路）。"""
    cache = []
    for _ in range(max_new):
        x = idx[:, -1:] if cache else idx
        logits = model(x)
        nxt = logits[:, -1, :].argmax(-1, keepdim=True)
        idx = torch.cat([idx, nxt], dim=1)
        cache.append(nxt)          # 真实实现里缓存的是每层的 K/V 张量
    return idx

# 速度对比：一次性喂全序列 vs 只喂新 token（cache）
```

### 自检题（答不上来就不算学会）

1. GPT 为什么只用 Decoder 不用 Encoder？
   答：自回归语言建模只需要「根据前文预测下一个 token」，因果自注意力天然满足这一点；Encoder-Decoder 用于输入输出都是序列且需要双向理解的任务（翻译、摘要）。
2. `head.weight = tok_emb.weight`（权重绑定）省了什么？
   答：词表 8000、`d_model=256` 时输出层与嵌入层各约 2.05M 参数，绑定后省掉一份（约 25% 的参数），还通常带来轻微的正则化效果。
3. `temperature`、`top-k`、`top-p` 各控制什么？
   答：`temperature` 缩放 logits 控制整体分布的平坦程度（越小越确定）；`top-k` 只保留概率最高的 k 个候选；`top-p` 保留累积概率达到 p 的最小候选集合（候选数动态变化）。实战常配合：`temperature=0.7–0.8` + `top_p=0.9`。
4. `val_loss` 从 9.0 降到 6.5 意味着什么？
   答：困惑度从 `e^9 ≈ 8103`（等于随机猜 8000 词表）降到 `e^6.5 ≈ 665`，即模型对下一个 token 的预测能力提升了约 12 倍；这对 1M–10M 参数的玩具模型是合理的水平。
5. KV Cache 为什么能加速推理，代价是什么？
   答：自回归生成时历史 token 的 K/V 不随新 token 变化，缓存后可避免每步重算，复杂度从不加 cache 的 O(L³) 降到 O(L²)。代价是显存随序列长度线性增长（`2 × 2 字节 × KV 头数 × 头维 × 层数 × L × batch`），长上下文时成为主要显存开销。
6. 为什么 W12 的小 GPT 能在 8GB 显存上轻松跑，而 7B 模型不行？
   答：参数量差 3 个数量级。小 GPT 约 10M 参数，fp16 权重仅 20MB；7B 的 fp16 权重就要约 14GB，直接超过显存，必须用 4bit 量化（QLoRA）把权重压到 3.9–4.3GB 才有机会。

### 踩坑提醒

:::warn GPT 生成结果是乱码或全是特殊 token
分词器的 `[PAD]` / `[UNK]` 被采样到了。生成时用 `repetition_penalty=1.1`，并把 `pad_token_id` 设为 `eos_token_id`；手写采样时把 `[PAD]` 的 logits 手动设为 `-inf`。
:::

:::warn `val_loss` 明显低于 `train_loss`
说明验证集的片段与训练集高度重叠（语料是连续文本、切片方式导致泄漏），或训练时用了强 Dropout 而验证没有。先用 `train/val` 按**文档级**切分（不是按 token 随机切），再核对 `model.eval()`。
:::

:::warn `AssertionError: 序列长度 200 超过 block_size 128`
位置编码只定义了 128 个位置。要么把 `block_size` 调到 256（并把 `SinusoidalPositionalEncoding(max_len=256)` 一起改），要么生成时用 `idx[:, -block:]` 截断。
:::

:::warn 加载 4bit 模型报 `bitsandbytes` 相关错误
Windows 原生环境下 `bitsandbytes` 支持不完整，会报 `CUDA Setup failed despite GPU being available` 或找不到 `.dll`。解法：在 **WSL2 Ubuntu** 里安装（`uv add bitsandbytes`），或使用 Windows 编译版（`pip install bitsandbytes-windows`，功能受限）。W13 的 QLoRA 一律在 WSL2 里做。
:::

:::danger 不要用 `wikitext` 英文语料训练「中文小 GPT」
`wikitext` 是英文维基数据，用它训出来的模型不会说中文。必须准备中文语料（自己下载的公开新闻/小说/论文摘要，注意版权与用途），放到 `data/raw/zh_corpus.txt`，行数与字符数写进笔记。
:::
