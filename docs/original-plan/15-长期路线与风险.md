# 第15章 长期路线、风险清单与止损规则

24 周课表解决「从 0 到能做出项目」，这一章解决「什么时候做什么事才不至于错过节点」。**2029 届的秋招在 2028 年 9–11 月，暑期实习在 2028 年 3–6 月投递**——这两个日期是你整条时间线上最不能错过的。

## 15.1 从研一到入职的完整时间轴

| 时间 | 阶段 | 要做的事 | 本阶段目标 |
| --- | --- | --- | --- |
| 2026.10 – 2027.03（研一上·寒假） | 第一阶段：24 周密集地基 | 执行第 5、6 章 W1–W24 | 4 个能演示的项目 + 训练模板 + 显存账单笔记 |
| 2027.03 – 2027.08（研一下 + 暑假） | 第二阶段：把一个方向做深 | 从四方向里选定一个主攻（建议 Agent 应用或边缘部署），把项目从 demo 做到「有评测、有对比、有性能数字」；同时投日常实习（每周 3 天，门槛远低于暑期实习） | 1 个简历级项目 + 第一段实习经历 |
| 2027.09 – 2028.02（研二上） | 第三阶段：深化 + 论文或亮点项目 | 主攻方向做到亮点级；把实验室横向任务或论文选题与求职项目一鱼多吃；开始收集提前批信息 | 1 个亮点级项目 + 1 篇论文投稿（CCF-C 保底）+ 实习线索 |
| 2028.03 – 2028.06（研二下） | 第四阶段：暑期实习冲刺 | **3 月集中投递、4–6 月面试、6 月定 offer**；大厂暑期实习是转正主通道 | 大厂/优质公司暑期实习 offer |
| 2028.06 – 2028.09 | 第五阶段：实习 + 提前批 | 实习中主动争取「能写进简历、能量化」的任务；7–8 月大厂提前批开放（不影响正式批，一定要投） | 实习转正意向 + 提前批面试机会 |
| 2028.09 – 2028.11 | 第六阶段：秋招主战场 | 正式批投递 **80–150 家**，保持每周 10–20 场笔试/面试节奏；国企/银行/运营商网申通常 9 月初截止 | 拿到 2–3 个可比较的 offer |
| 2028.12 – 2029.04 | 第七阶段：补录、春招与毕业论文 | 秋招不理想就继续春招与补录（简历只留最相关的 2 个项目）；同步推进毕业论文 | 确定去向 + 论文初稿完成 |
| 2029.05 – 2029.09 | 第八阶段：入职准备 | 补齐目标岗位的工程技能（C++ / K8s / Go 等）；提前了解团队技术栈 | 顺利入职或升学 |

:::warn 三个最容易错过的截止日期
- **2028 年 3 月**：暑期实习集中开启投递，晚两周好岗位就没了。
- **2028 年 7–8 月**：大厂提前批，很多人以为「等正式批」而白白错过一次机会。
- **2028 年 9 月初**：国企、银行、运营商的网申截止，通常比互联网正式批还早。
:::

## 15.2 每季度的固定动作（写进日历）

- [ ] **每季度末**：打开本页，核对上一季度承诺的产出是否交付（项目、笔记、投递），没有就写清原因。
- [ ] **每季度末**：更新一次简历，把新项目的数字填进去（哪怕只更新一行）。
- [ ] **每季度末**：清理一次 GitHub 仓库（补 README、把没写完的项目标成 WIP 或删掉）。
- [ ] **每半年**：检查工具链是否有必要升级（半年内不换主线的纪律可以在这时解除）。
- [ ] **每年 3 月 / 9 月**：对一次求职日历（暑期实习、提前批、秋招、春招节点）。

## 15.3 风险清单与对策

| 风险 | 触发信号 | 后果 | 对策 |
| --- | --- | --- | --- |
| 只有代码没有数字 | 项目 README 里没有结果表 | 简历无法通过技术筛 | 每个实验必须记录峰值显存、时长、指标，写进结果表模板（第 7、8 章都有） |
| 只调 API 不懂原理 | 面试被问「LoRA 为什么有效」答不上来 | 卡在二面 | 第 5 章 W6、W11 的手写反向传播与 Transformer 不许跳 |
| 项目全是教程复刻 | 面试官问「你改了什么」答不上来 | 被认为没有独立能力 | 每个项目至少做一个「自己的改动 + 消融对比」 |
| 显存焦虑导致停滞 | 一直在研究怎么优化而不动手 | 时间耗尽，零产出 | 按第 2 章替代路径降级，先跑通再优化 |
| 数据获取不了 | 卡在「没有数据集」 | 项目做不成 | 每个项目在第 7、8 章都给了公开数据集与获取方式，实在没有就用 API 合成 500–1000 条 |
| 论文与求职撞车 | 2028 年下半年论文与秋招同时压过来 | 两边都做不好 | 2027.09–2028.02 就把论文主体做完，秋招期只做修改 |
| 实习没拿到 | 2028 年 6 月仍无暑期实习 | 秋招竞争力不足 | 立刻转投日常实习补经历；同时把亮点项目做到能独立讲 20 分钟 |
| 投递量不足 | 秋招投了不到 30 家 | 面试机会太少 | 按第 14 章 14.10 的节奏表，每周固定投 10–20 家 |
| 面试不复盘 | 同一个问题连续三次答错 | 重复挂 | 每次面试当天填第 14 章的复盘表 |
| 方向摇摆 | 每两个月换一次主攻方向 | 什么都学不深 | 主攻方向一旦确定，12 个月内不再更改 |

## 15.4 中止与降级规则（达不到就换路，别硬扛）

:::danger 三个检查点，达不到就降级
- **W13（2027-01-03）**：能否从零写出多头注意力与 6 层小 GPT？能否在 8G 上完成一次 7B QLoRA（seq 512）并说清显存去向？达不到 → 主线降为「≤4B 模型 + 推理部署」。
- **W19（2027-02-14）**：能否独立设计多工具 Agent 并给出评测集、成功率、失败模式分类？达不到 → 求职主攻改为「RAG 应用开发」单点突破。
- **W21（2027-02-28）**：能否交出量化前后的延迟/显存/精度对比报告？达不到 → 差异化技能改为「RAG 工程 + 评测」。
:::

**降级不是失败。** 把「7B 微调」降级为「4B 微调 + 完整评测」，你的简历一样成立，而且更容易讲清楚。

## 15.5 如果进度落后了怎么办

| 落后程度 | 处理方式 |
| --- | --- |
| 落后 1–2 周 | 全表乘 0.7 系数顺延，顺序不变，不要跳周 |
| 落后 3–5 周 | 保留每周的「动手」与「交付物」，砍掉「输入」里的视频课，只留必做作业 |
| 落后 6 周以上 | 压缩到「最小可行路线」：W1–W9（地基与视觉）→ W10–W13（NLP 与大模型）→ W15–W21（RAG、Agent、部署），AIOps 只做 P4 一半 |
| 只剩 8 周就要投递 | 停止学新东西，只做三件事：把一个项目做到有评测、把简历重写、把手撕代码刷熟 |

:::ok 最小可行路线（实在赶不上时用这个）
W1–W2 环境与 Python 工程化 → W5 训练循环 → W11 手写 Transformer → W13 一次 7B QLoRA → W15–W16 RAG + 评测 → W17–W19 Agent → W20–W21 部署压测 → W24 简历与投递。
一共约 14 周，产出 3 个可写简历的项目（微调、RAG、部署），足够投应用与工程岗。
:::

## 15.6 心理与节奏（说点实话）

- **状态不是等出来的。** 每周固定 15–18 小时的三个时间块，比「等有空再学」的产出高一个数量级。
- **允许有低效周。** 24 周里有 3–4 周效率低是正常的，别因为一周没做完就放弃整条路线。
- **不要在工具上过夜。** 装环境超过 2 小时就停下来查第 3、4 章的报错表，或者换一条更简单的路。
- **公开输出会反向逼你学扎实。** 每周推到 GitHub、每月一篇笔记，是成本最低的自律手段。
